# 작업 로그 작성

## 범위

`docs/log/young/` 는 **강제**. `jimin/`·`seeun/` 는 폴더 소유자가 각자이므로 규약을
**제안으로만** 제시하고 강요하지 않는다 (로그 38 §8).

## 먼저 읽는다

**`docs/log/README.md` 「서식 규약」** — 규약 본문은 거기가 유일한 출처다. 이 스킬은 규약을
다시 적지 않는다. 판별선·골격·머리말·절별 규칙은 전부 그 문서를 따른다.

한 줄로 줄이면: **로그는 다른 문서가 가질 수 없는 것만 담는다.** git · `results/` · `spec/` ·
`workflow/` 가 답할 수 있으면 로그에 쓰지 않는다. 남는 건 셋 — 왜 그렇게 정했나 · 무엇을
버렸나 · 무엇이 아직 안 정해졌나.

## 절차

1. **번호** — `ls docs/log/young/` 로 다음 번호를 잡는다. 결번(`docs/log/README.md`
   「결번」 줄)은 재사용하지 않는다.
2. **뼈대** — 이 폴더의 `TEMPLATE.md` 로 시작한다.
3. **본문** — 규약대로 쓴다. `## 결정` 은 결론의 유일한 자리이고 `## 근거` 는 결론을
   되풀이하지 않는다.
4. **추기** — 머리말 `관련` 에 적은 로그를 **열어 본다.** 이번 로그가 뒤집거나 닫은 결정이
   있으면 **그 로그의 그 자리에** 인용구로 추기한다. 닫은 로그에만 적으면 원 로그를 읽는 쪽은
   끝난 안건을 살아 있는 것으로 읽는다.
5. **등재** — `docs/log/README.md` 목록 표에 한 줄 추가한다. **가장 잘 빠지는 단계다** —
   규약을 확정한 로그 38 자신이 이 단계에서 누락됐다.

## 검사

작성 후 돌린다. 출력이 비어 있어야 정상인 것과 목록이 나와야 정상인 것이 섞여 있다.

```bash
# 골격 누락 — 결과가 비어야 한다 (규약 이전 로그 1~37 은 소급 대상이 아니라 걸려도 무시)
grep -L '^## 결정' docs/log/young/*.md

# 추기 전수 — 뒤집힌 결정에 표시가 붙었는지 눈으로 확인
grep -rn '^\s*> \*\*20' docs/log/young/*.md

# 목록 등재 — 방금 쓴 번호가 잡혀야 한다
grep -c '](young/<번호>\.' docs/log/README.md
```

## 자주 틀리는 것

- **작업 실적을 적는다** — "무엇을 만들었다"는 git 이 더 정확하다. 로그가 남길 건 **경위**다:
  가정이 깨진 순간, 두 문제가 겹쳐 오진한 대목.
- **절차·재현법을 적는다** — `workflow/` 로 보낸다. 로그는 갱신되지 않는 문서라 절차를 담으면
  반드시 거짓말이 된다. AI 는 그 낡은 절차를 검색으로 찾아 **실행한다.**
- **수치를 싣는다** — `results/`·`spec/`·`chip_registry.md` 와 이중 출처가 된다. 그 수치가
  **결정을 흔든 경위**만 로그에 남긴다.
- **로그 번호만 쓴다** — 첫 등장에 경로를 함께 단다. AI 는 "로그 23" 에서 파일명을 못 맞힌다.
