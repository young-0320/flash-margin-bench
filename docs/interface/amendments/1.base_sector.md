## 1. 왜 필요한가

현재 `flash_spi_ctrl.v`는 읽기 순번 `idx`를 그대로 페이지 주소로 발행한다
(`sh <= {8'h0B, 4'd0, idx, 8'h00}`). 즉 **읽기 창이 페이지 0에 고정**이며 N=100이면
언제나 페이지 0~99만 읽힌다.

9월 마모 실험은 일부 섹터만 마모시키고 나머지를 대조군으로 쓴다. 읽기 창이 고정이면
마모군과 대조군이 **읽기 100회를 나눠 가져야** 하는데, 나누면 양쪽 다 검정력이 무너진다.

| 구성 | 읽기 | 기대 에러 수 (θ=10⁻⁴) | 사전 등록 규칙(≥20) |
| ---- | ---- | --------------------- | ------------------- |
| 온전한 100회 | 100 | 20.5 | 통과 |
| 마모군 몫 | 64 | 13.1 | **미달** |
| 대조군 몫 | 36 | 7.4 | **미달** |

(기대 에러 = 읽기 × 2,048비트 × θ)

N을 200으로 올려도 **마모군은 64회 그대로**다 — 마모 섹터 수가 안 늘었으므로 늘어나는
것은 대조군뿐이다. 읽기 창을 옮길 수 있어야만 각 그룹을 독립 스윕으로 재게 되고,
양쪽 다 N=100 full strength가 된다.

부수 효과가 더 크다. 한 칩 안에 마모량이 다른 그룹을 여러 개 두고 각각 온전히 측정하면
**교정 곡선 전체를 단일 개체에서** 얻는다. 교정 곡선의 최대 오염원인 개체 산포가 통째로
사라져, 곡선의 형태(칩 내)와 개체 산포(칩 간)를 분리해 보고할 수 있다.

## 2. 변경 내역 (승인 시 `contract.md`에 반영)

### 2.1 §2 core ↔ flash 신호 — 1행 추가

| 신호 | 방향 (core 기준) | 폭 | 의미 |
| ---- | ---------------- | -- | ---- |
| `cfg_base_sector` | out | 11 | 읽기 시작 섹터 (0..2,047). start 시점에 flash가 래치 |

### 2.2 §3 AXI-Lite 레지스터 맵 — 1행 추가 (0x28은 현재 미사용)

| 오프셋 | 이름 | 접근 | 리셋값 | 내용 |
| ------ | ---- | ---- | ------ | ---- |
| 0x28 | `BASE_SECTOR` | RW | 0 | [10:0] 읽기 시작 섹터 (0~2,047). **0 = 종전과 완전히 동일 동작** |

### 2.3 §4 규약 — R12 신설

> **R12 읽기 창 위치**: 읽기 i (i = 0..N−1)가 접근하는 페이지 번호는
> **`page(i) = BASE_SECTOR × 16 + i`** 이고, 칩에 발행하는 바이트 주소는 `page(i) × 256`이다.
> PRBS 시드 index는 **같은 `page(i)`의 하위 14비트**를 쓴다(§5 측정 패턴 정의 그대로).
> **주소와 시드는 반드시 같은 `page(i)`에서 유도한다** — 한쪽만 옮기면 전 위상 BER≈0.5가
> 되어 칩 불량으로 오인하기 쉽다. `BASE_SECTOR`는 start 시점 래치이며(R6와 동일 취급),
> 측정 도중 레지스터 변경은 진행 중 측정에 무영향이다.
>
> 읽기 순번(e_i 버퍼 주소, `log_rd_addr`)은 **i 그대로**이며 본 변경의 영향을 받지 않는다.
> 섹터 단위로 정의하는 이유: 마모는 섹터 단위로만 일어나므로 읽기 창이 섹터 경계에
> 정렬돼야 한다. 페이지 단위 레지스터로 두면 16의 배수가 아닌 오설정이 표현 가능해진다.

### 2.4 §4 R11 설정 검증 — 조건 1개 추가

기존 검사(1 ≤ N ≤ 2,048, 8 ≤ B ≤ 65,528, B는 8의 배수)에 다음을 추가한다.

> **`BASE_SECTOR × 16 + N − 1 ≤ 32,767`** (칩 최종 페이지). 위반 시 측정을 시작하지 않고
> `STATUS.CFG_ERR`를 켠다.

**이 검사가 없으면 주소가 칩 끝을 넘어 랩어라운드해 전혀 다른 섹터를 조용히 읽는다** —
스윕은 정상 완주하고 `valid=1`이 뜨는데 마모 신호만 안 보이는 침묵 실패가 된다.
계약 결정 3-2("랩어라운드는 곡선 어깨를 조용히 오염")가 주소 경로에도 적용되는 사례다.

참고 — 상한은 N에 따라 움직인다. **정밀 측정 모드 N=112**(수정안 #2)에서는
`BASE_SECTOR ≤ 2,041`이고, 이때 마지막 읽기가 닿는 페이지는 `2,041×16 + 111 = 32,767` —
**칩의 마지막 페이지에 정확히 떨어진다. 도달 못 하는 페이지가 없다.**

(수정안 #2 이전의 N=100에서는 읽기 창이 100페이지 = 6.25섹터라 어떤 설정으로도 마지막
12페이지에 닿지 못했다. 읽기 횟수를 마모 단위인 16의 배수로 맞추면서 해소됐다.)

전수 스캔 모드처럼 N이 작으면 상한은 더 올라간다 — N ≤ 16이면 `BASE_SECTOR = 2,047`이
유효해 칩 최종 섹터에서도 스윕을 시작할 수 있다.

### 2.5 §5 수치 계약 — 1행 추가, 측정 패턴 행은 **문구 변경 없음**

| 항목 | 값 |
| ---- | -- |
| 읽기 도달 범위 | **페이지 0~32,767 = 섹터 0~2,047 = 8MB 전역** (24비트 주소 프레임이 페이지 65,536개까지 표현 가능하므로 칩 전역이 여유롭게 들어온다) |

측정 패턴 행은 이미 *"실칩: 페이지 주소 하위 14비트"* 로 쓰여 있어 **수정이 불필요하다.**
`page(i)`의 정의만 `i` → `BASE_SECTOR×16 + i`로 바뀌며, 시드 규칙 자체는 그대로다.

### 2.6 §6 스윕 CSV 스키마 — 열 1개 추가

| 열 | 타입 | 출처 |
| -- | ---- | ---- |
| `base_sector` | int | 설정값 (전 행 반복) |

**어느 구역을 잰 데이터인지가 파일에 남지 않으면 사후에 구분할 방법이 없다.** 마모군과
대조군 CSV가 파일명만으로 구분되면 라벨 오독에 그대로 노출된다(등록부가 UID를 정본
식별자로 삼은 것과 같은 논리).

### 2.7 §7 결정 요약표 — 1행 추가

| # | 항목 | 결정 | 크리티컬 이유 |
| - | ---- | ---- | ------------- |

## 3. 구현 메모 (박지민)

고칠 곳은 세 군데이고, 셋이 **같은 `page(i)`를 봐야 한다**는 것이 유일한 함정이다.

| 파일 | 현행 | 수정 |
| ---- | ---- | ---- |
| `fpga/rtl/core/` AXI 레지스터 | 0x28 미사용 | `BASE_SECTOR` RW 추가 → `cfg_base_sector[10:0]` 출력 |
| `flash_spi_ctrl.v:120` | `sh <= {8'h0B, 4'd0, idx, 8'h00}` | `sh <= {8'h0B, page, 8'h00}` where `page = {bs_lat, 4'd0} + idx` (16비트) |
| `flash_rx.v:65` | `.seed({1'b1, 2'b00, idx})` | `.seed({1'b1, page[13:0]})` — **동일한 page** |

- **시프트 레지스터 폭은 그대로다.** 명령 8 + 페이지 16 + 채움 8 = 32비트로 현행 `sh[31:0]`에
  정확히 들어맞는다. 기존 `4'd0` 패딩 4비트가 페이지 필드로 흡수된다
- `flash_spi_ctrl`에 `bs_lat` 래치 추가 (`n_lat`·`b_lat`과 같은 자리)
- `cfg_ok`에 2.4의 범위 조건 추가
- 읽기 순번 `idx`(12비트)와 페이지 번호(16비트)를 **분리**한다. 현재는 한 레지스터가
  순번·주소·시드 인덱스 3역을 겸하고 있고, 이 겸직이 "시드도 함께 옮겨야 한다"는 함정의
  원인이다
- 자원·타이밍: 12→16비트는 플립플롭 4개·자리올림 4칸 수준이고 코어가 25MHz라 영향 없음

### 패턴 반복(aliasing)에 대하여

시드 index가 14비트이므로 패턴은 **16,384페이지(=1,024섹터)마다 반복**된다. 이는 계약 v1이
이미 허용한 성질이며(`§5` 하위 14비트), `ps/src/flash_prep.c:45`도 이미 `page & 0x3FFF`로
마스킹해 짜여 있다.

한 번의 스윕은 **연속된 페이지 N개(≤2,048)** 만 읽으므로 16,384 떨어진 두 페이지가 같은
스윕에 함께 들어올 수 없다. 따라서 실사용상 무해하다.

단 하나의 구멍: 주소가 **정확히 1,024섹터의 배수만큼** 어긋나는 버그는 패턴이 맞아떨어져
조용히 통과한다. 그 외 모든 어긋남은 전 위상 BER≈0.5로 시끄럽게 실패한다. 이 구멍은
2.4의 범위 검사와 아래 인수 기준 A2(먼 구역 실측)로 좁힌다.

## 4. 인수 기준 (판정: 한영웅)

넷 다 통과해야 승인된 구현으로 본다. **G1 시뮬레이션 환경 없이도 판정 가능하도록** 실측
기반으로 구성했다.

### A1. 하위 호환 회귀 — 기존 동작을 안 깨뜨렸는가

`BASE_SECTOR = 0`, chip01, 25MHz, N=100 스윕 1회.

- verify: `width@θ=1e-2` 가 기준값 **39,737.3ps ± 3σ(≈2ps)** 이내
- 주의: D 트랙(6주 공백 드리프트 확인)이 먼저 수행됐다면 그 재측정값이 기준이다.
  D 미수행 상태라면 7월 기준값을 쓰되, **불일치 시 원인이 이번 변경인지 드리프트인지
  분리되지 않으므로** D를 먼저 돌린다

### A2. 읽기 창 이동 — 주소와 시드가 함께 옮겨졌는가

`flash_prep`으로 해당 구역에 PRBS를 기록한 뒤, 세 지점에서 스윕.

| BASE_SECTOR | 확인 목적 |
| ----------- | --------- |
| 249 | 종전 주소 폭(12비트)의 상한 부근 — 회귀 확인용 |
| 1,024 이상 한 점 | **상위 주소 비트 경로** — 종전 12비트로는 표현 불가했던 영역 |
| 2,041 | N=112 기준 **유효 최댓값** — 마지막 읽기가 칩 최종 페이지 32,767에 정확히 떨어짐 |

- verify: 세 지점 모두 정상 욕조 곡선 — 중앙부 BER≈0, 양끝 포화
- **전 위상 BER≈0.5가 나오면 실패다.** 이는 시드가 주소를 따라오지 않았다는 서명이며
  (런북 3 표 E), 칩 불량이 아니다
- 선행: `flash_prep` 파라미터화(B-0, 장세은). 미완이면 지민이 `N_PAGES`·시작 페이지를
  임시로 고쳐 해당 구역을 한 번 굽고 진행해도 무방하다

### A3. 범위 거부 — 랩어라운드가 막히는가

`BASE_SECTOR = 2,042`, N=112로 START (2,042×16+111 = 32,783 > 32,767).

- verify: `STATUS.CFG_ERR` = 1, `MEAS_BUSY` 상승 에지 없음, 측정 미시작.
  R11의 "유효 START" 정의대로 이전 플래그를 지우지 않을 것

### A4. 무결성 층 유지

A1·A2의 모든 스텝에서 R8 3항(Σe_i == ERR_BITS / count(e_i>0) == ERR_READS / 모든 e_i ≤ B)
이 성립하고, CSV에 `base_sector` 열이 전 행 기록될 것.

## 5. 함께 상정 — UID를 측정 데이터에 남기기

성격이 같아(측정 대상의 신원 기록) 워크플로 5의 결정대로 묶어 올린다. 단 **계약 변경분은
CSV 헤더 한 줄뿐**이며 RTL 변경은 이번 범위에 넣지 않는다.

- 칩의 개체 식별자는 `4Bh`(Read Unique ID)로 읽는 **64비트 UID**다. JEDEC ID(`9Fh` →
  `EF 40 17`)는 모델 식별자라 10개가 전부 같아 개체 식별이 불가능하다
- **단기안(RTL 변경 0, 채택 제안)**: `flash_prep.c`에 `4Bh` 추가 → `#PREP UID <16hex>` 출력.
  `sweep_uart_capture.py`가 그 값을 스윕 CSV 헤더 주석 `#UID <16hex>`로 기입.
  `flash_prep`은 모든 스윕 직전에 반드시 실행되므로 세션마다 자동으로 찍힌다
- **정석안(보류)**: PL이 `4Bh`를 발행해 레지스터로 노출. `flash_spi_ctrl`이 0x0B 전용 고정
  시퀀서라 프레임 구조가 다른 `4Bh`(주소 없음, 더미 4바이트)에는 별도 one-shot FSM이
  필요하다. BASE_SECTOR 인수 후 별건으로 상정
- 단기안의 한계: 스윕 중에는 PS가 칩과 통신할 수 없어(스윕은 PL 경로, prep은 PS SPI 경로)
  UID와 스윕의 연결이 **같은 세션**이라는 절차적 근거에 의존한다

§6 스키마 변경분: 스윕 CSV 선두에 주석 행 `#UID <16hex>` 1줄. 열 구조는 불변이므로
`bathtub_analysis.py`의 파서는 주석 행 스킵만 확인하면 된다.

사양서에 양쪽을 병기한다.
