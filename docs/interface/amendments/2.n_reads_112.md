## 1. 변경 요지

위상 스텝당 읽기 횟수 **N을 100에서 112로 올린다.**

이유 한 줄: **읽기 단위와 마모 단위가 어긋나 있어서, 마모시켰지만 한 번도 측정하지 않는
페이지가 그룹마다 12개씩 남는다.**

## 2. 왜 112인가 — 물리 단위 정합

플래시는 **읽기는 페이지(1개) 단위, 지우기는 섹터(16페이지) 단위**다. 지우기 단위가 16의
배수로 묶여 있으므로 마모 영역의 크기는 항상 16의 배수이며, **100페이지짜리 마모 영역은
물리적으로 만들 수 없다.**

마모 그룹을 7섹터(112페이지)로 정한 것은 로그 16 §4.8d의 결론이다 — 6섹터(96페이지)로
줄이면 읽기 96~99회가 마모되지 않은 섹터를 읽어 **마모군 데이터에 신품이 섞인다.**

```
마모 영역:  [섹터 0~6] = 112페이지
페이지:      0 ──────────────────── 99  100 ─── 111
읽기 N=100:  0 ──────────────────── 99   └─ 12페이지: 지웠지만 안 읽음
읽기 N=112:  0 ──────────────────────────── 111   빈틈 0
```

N을 그룹 크기와 같게 두면 어긋남 자체가 사라진다. 세 가지가 동시에 해결된다.

**① 미측정 구간 소거** — 그룹마다 남던 12페이지(그룹의 10.7%)가 측정 대상에 들어온다.
노화 곡선을 그리는 목적에서는 100페이지 표본으로도 충분하므로 이 자체는 무해했으나,
**가장 약한 셀을 찾는 목적에서는 안 본 12페이지가 구멍**이다. 프로젝트가 표방하는 것이
진단 장비인 이상 "구조적으로 못 보는 영역"은 서사의 약점이 된다.

**② 읽기 창이 섹터 경계에 정렬** — N=100은 6.25섹터라 어중간하다. 112 = 7×16이므로 창의
시작과 끝이 모두 섹터 경계에 떨어진다. `BASE_SECTOR`를 페이지가 아닌 섹터 단위로 정의한
것(수정안 #1 §2.3 — 오설정 자체를 표현 불가능하게)과 같은 논리다.

**③ 칩 최종 페이지 도달** — 수정안 #1의 범위 규칙 `BASE_SECTOR×16 + N − 1 ≤ 32,767`에서
N=112일 때 상한은 `BASE_SECTOR = 2,041`이고, 이때 마지막 읽기가 닿는 페이지는
`2,041×16 + 111 = 32,767` — **칩의 마지막 페이지에 정확히 떨어진다.** N=100에서는 마지막
12페이지가 어떤 설정으로도 도달 불가였다.

## 3. 원래 100이었던 근거는 유효한가 — 유효하며, 오히려 개선된다

N=100은 실측 전 몬테카를로로 사전 등록한 값이다(로그 1). 근거는 "θ 3단계가 모두 유효
검정력을 갖는 최소 N"이었고, 유효 조건은 **기대 에러 수 ≥ 20**이다.

| θ | N=100 기대 에러 | N=112 기대 에러 | 판정 |
| --- | --- | --- | --- |
| 10⁻² | 2,048 | 2,294 | 여유 |
| 10⁻³ | 205 | 229 | 여유 |
| **10⁻⁴** | **20.5** | **22.9** | 둘 다 통과, **마진 개선** |

(기대 에러 = N × 2,048비트 × θ)

**112는 100보다 크므로 사전 등록 조건을 자동으로 만족한다.** 상향은 통계적으로 항상
안전한 방향이며, 이 변경으로 약해지는 검정은 없다.

R6(N ≤ 2,048, e_i 버퍼 깊이)도 그대로 만족한다.

## 4. 변경 내역 (승인 시 `contract.md`에 반영)

### 4.1 §3 레지스터 맵 — `N_READS` 리셋값 (선택)

| 오프셋 | 이름 | 리셋값 (현행) | 리셋값 (변경) |
| --- | --- | --- | --- |
| 0x0C | `N_READS` | 100 | **112** |

**이 변경은 선택 사항이다.** 호스트(PS)가 모든 스윕 전에 N을 명시적으로 써 넣으므로,
리셋값을 100으로 두어도 실동작에는 영향이 없다. 다만 리셋값과 운용값이 다르면 브링업 중
"레지스터를 안 썼을 때 어떤 값으로 도는가"가 헷갈리므로 맞추기를 권한다. RTL 변경은
이 한 줄이 전부다.

### 4.2 §5 수치 계약 — N 행 수정

현행:

> | N (위상당 읽기 수) 기본값 | **100** (G0 실측 σⱼ로 재확인 예정 — 레지스터로 변경 가능) |

변경:

> | N — 전수 스캔 모드 | **별도 정의** (§4.3). 정밀 측정과 비교하지 않으므로 값이 달라도 무방 |

### 4.3 §5 — 측정 모드 개념 신설

N은 하나로 못 박는 값이 아니라 **측정 목적별로 고정하는 값**임을 명문화한다.
서로 비교하지 않는 측정끼리는 N이 달라도 되며, **비교할 데이터끼리는 반드시 같아야 한다.**

| 모드 | N | 목적 | 비교 대상 |
| ---- | -- | ---- | --------- |
| **정밀 측정** | **112** | 마모 곡선·신품 기준선·드리프트 | 서로 비교함 → N 고정 필수 |
| **전수 스캔** | 미정 (16 검토) | 약한 섹터 탐색 — "어디가 의심스러운가"만 판별 | 정밀 측정과 비교 안 함 |
| **아카이브** | 100 | 2026-07-08 이전 수집분 | §5에 따라 별도 계열로 취급 |

스캔 모드의 N은 10월 확장 착수 시 별건으로 정한다. 참고로 N ≤ 16이면
`BASE_SECTOR = 2,047`(칩 최종 섹터)이 유효해져 칩 전역이 스캔 대상이 된다.

## 5. 기존 N=100 데이터 — 보존한다, 폐기하지 않는다

**2026-07-08 수집분(chip01 계열)을 삭제하거나 무효 처리하지 않는다.** 파일명·경로·유래
문서를 모두 그대로 둔다. 조건이 달라진 것이지 데이터가 틀린 것이 아니다.

**혼동 위험은 구조적으로 없다.** 계약 §6 CSV 스키마에 이미 `n_reads` 열이 있어
(전 행 반복) **모든 파일이 자기 측정 조건을 스스로 들고 있다.** 파일명이나 기억에
의존하지 않으므로, 분석 스크립트도 `n_reads`로 계열을 가를 수 있다.

취급 규칙:

- 7월 데이터는 **N=100 계열**로 유지. `docs/results/`의 게재분도 그대로 둔다
- 유래 md에 "측정 조건: N=100 (수정안 #2 이전)" 한 줄을 덧붙인다 — 파일 자체는 불변
- N=100 기준값 **39,737.3 ± 0.61ps** 는 폐기하지 않는다. 아래 §6의 비교 분석에서
  기준점 역할을 한다
- 두 계열을 한 그래프에 겹칠 때는 N을 범례에 명시한다

## 6. N=100 vs N=112 비교 분석 — 하되, 할 수 있는 것만 주장한다

조건 전환은 그 자체로 **측정 시스템을 들여다볼 기회**다. 다만 이 비교로 답할 수 있는 질문과
답할 수 없는 질문이 나뉘므로 구분해서 적는다.

### 6.1 답할 수 있는 것 — 폭 추정의 계통 편향

**질문**: N을 바꾸면 측정된 폭이 체계적으로 달라지는가?

물리적으로는 달라질 이유가 없다. 폭은 칩과 장비의 성질이지 몇 번 읽었는지의 함수가
아니다. 그런데 폭은 "BER이 θ를 가로지르는 지점"으로 **추정**되는 값이고, 추정 알고리즘이
표본 크기에 편향돼 있으면 값이 움직인다.

- **차이가 σ(0.61ps) 범위 안** → 편향 없음. 두 계열을 직접 비교해도 된다
- **차이가 σ를 벗어남** → `bathtub_analysis.py`의 경계 판정이 표본 크기에 의존한다는 뜻.
  **분석 코드의 결함 발견이며 그 자체가 성과다.** 이 경우 환산 계수를 실측으로 세운다

같은 칩·같은 세션·같은 장착 상태에서 두 조건을 재면 N 이외의 변수가 전부 공통이 되므로,
차이가 나면 그 원인이 N이라고 귀속할 수 있다. 스윕 2회(약 10분)면 된다.

### 6.2 답할 수 없는 것 — 노이즈의 정체 (이 대비로는 검정력이 없다)

**질문**: 우리 측정의 반복성 0.61ps는 통계적 표본 잡음인가, 아니면 계통 요인의 바닥인가?

이건 MSA의 핵심 질문이고 PE 직무의 정중앙이다. 이론적 예측은 **σ ∝ 1/√N** 이므로
N=112에서는 `0.61 × √(100/112) = 0.58ps`가 나와야 한다. 실측이 예측을 따르면 노이즈가
순수 통계적(N을 늘리면 계속 좋아짐), 안 따르면 계통 요인이 바닥을 만들고 있다는 뜻이다.

**그런데 이 대비로는 검정이 성립하지 않는다.** 예측 차이가 5.5%인데, 반복 5회로 추정한
σ 자체의 불확실도가 약 35%다(n=5에서 σ의 상대 표준편차 ≈ 1/√(2(n−1))). **재려는 효과보다
자의 눈금이 6배 굵다.** 0.61과 0.58을 구분할 수 없다.

이 질문을 제대로 답하려면 **대비를 크게 벌려야 한다.**

| 비교 | 예측 σ 비 | n=5의 분해 능력 | 성립? |
| ---- | --------- | --------------- | ----- |
| 112 vs 100 | 1.06배 | ±35% | **불가** |
| 112 vs 448 (4배) | **2.0배** | ±35% | **가능** |

- **N=448 스윕 1회 ≈ 20분**, 반복 5회면 약 1.7시간. 오늘 일정에는 넣지 않는다
- 시점: 복귀 후, 또는 M 트랙(신품 전수) 세션에 얹는다
- 결과의 쓸모: 노이즈가 통계적이면 **N을 늘리는 것이 개선 경로**로 열리고, 계통적이면
  N을 아무리 늘려도 소용없으므로 온도·지터·위상 스텝 비선형 쪽을 봐야 한다. 어느 쪽이든
  이후 자원 배분이 달라진다

**§6.1은 지금(D 트랙에서) 하고, §6.2는 별도 실험으로 뒤에 한다.** 6.1의 결과를 6.2의
결론처럼 쓰지 않는다.

## 7. 전환 절차 — 다리를 놓고 바꾼다

조건 변경 자체가 위험한 것이 아니라, **근거 없이 바꾸는 것**이 위험하다. D 트랙에서
두 조건을 같은 세션에 재두면 이후 모든 비교의 환산 근거가 남는다.

```
D 트랙 (chip01, 재장착 없이 연속)
  1. N=100 스윕 1회   → 7월과 동일 조건. 6주 공백 드리프트 판정 (기준 39,737.3±0.61ps)
  2. N=112 스윕 1회   → 전환 기준점 + §6.1 편향 검사
  3. flash_prep 출력에서 UID 확보 → docs/chip_registry.md 기입
```

- **순서를 지킨다.** N=100을 먼저 재야 드리프트 판정이 7월과 같은 조건에서 이뤄진다.
  N=112를 먼저 재면 차이가 드리프트인지 조건 변경인지 분리되지 않는다
- 추가 비용은 스윕 1회(약 5분)
- 이후 모든 측정(M 트랙 신품 전수 10개 포함)은 **N=112**

## 8. 선행 조건 — 몬테카를로 재실행 (한영웅)

`host/analysis/monte_carlo_sweep_params.py`를 **N=112로 재실행**해, 폭 추정 편차가 사전
등록 규칙 **σ_width ≤ Δφ/2 (= 7.9ps)** 를 만족하는지 확인하고 그 수치를 S-1 사양서와
본 문서에 기록한다.

N=100에서 이미 통과한 조건이고 112는 그보다 크므로 통과가 예상되지만, **사전 등록의
요지는 "예상되니 생략한다"를 하지 않는 것**이다. 확인 결과를 아래에 채운다.

**재실행 결과** (2026-08-23, trials=4000, seed=42, Δφ=15.87ps, σ_j=11ps — 로그 15의
실측 상한):

| θ | σ_width @ N=112 | σ_width @ N=100 | 규칙 한계 |
| - | --------------- | --------------- | --------- |
| 10⁻² | **0.16 ps** | 0.17 ps | 7.9 ps |
| 10⁻³ | **0.34 ps** | 0.35 ps | 7.9 ps |
| 10⁻⁴ | **1.35 ps** | 1.38 ps | 7.9 ps |

**통과.** 세 θ 모두 한계의 1/6 이하이며, N=100 대비 전 구간에서 소폭 개선된다.

부기 — 이 규칙은 N 선택을 전혀 구속하지 않는다(N=64에서도 최악 1.13ps). N의 실질 하한을
정하는 것은 **θ=10⁻⁴의 유효 조건**(N × B × θ ≥ 20)이며, 이는 스크립트 docstring이 이미
명시한 바와 같다. 로그 17 §4 참조.
