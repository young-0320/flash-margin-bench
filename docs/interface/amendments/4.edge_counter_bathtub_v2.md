## 1. 변경 요지

1. **에지 계수기** — 지금 `flash_rx.v` 는 정렬 3개(`t0 + 3/4/5`)의 오류 수 중 최솟값 `e_i` 만 낸다. 틀린 비트가 상승 에지에서 났는지 하강 에지에서 났는지가 남지 않는다. 정렬마다 카운터를 정답 비트 0 · 1 로 나눠(3 × 2 = 6개) 읽기마다 **여섯 값을 전부** 남긴다 — 정렬별 총 오류 수 `e_c`(c = 0 · 1 · 2)와 정렬별 정답 1 오류 수 `e1_c`. 「승자」 는 없다 — PC 가 읽기마다 이웃한 두 정렬의 짝을 골라 해석한다(R14 · 로그 55 [D55-19]). 정답 0 오류 수는 `e_c − e1_c` 로 파생한다(§6 「파생량은 저장하지 않는다」). `e_i`(= min)는 그대로 낸다 — v1 이 쓴다.
2. **욕조 v2 파일** — 벽 집중 스윕은 바닥 대부분을 1회 훑기로만 지나간다. v1 의 「전 스텝 같은 N · 결측 금지」 와 맞지 않아 **파일 이름부터 따로 둔다**(`bathtub2_*`). v1 파일(`sweep_*`)과 v1 소비자는 그대로다([D55-10]).
3. **캡처 완주 검사** — v2 는 스텝 수가 실행 중에 정해진다. BEGIN 의 `steps × n` 대신 END 줄에 실제로 보낸 행 수를 싣고, 캡처는 스텝마다 읽기 행을 대조한다.

## 2. 변경 내역 (승인 시 `contract.md` 에 반영)

### 2.1 §2 core ↔ flash 신호 — 1행 추가

| 신호 | 방향 (core 기준) | 폭 | 의미 |
| ---- | ---------------- | -- | ---- |
| `log_rd_cand` | in | 96 | `log_rd_addr` 가 가리키는 읽기의 32비트 낱말 셋 — [31:0] = {`e1_c0`, `e_c0`} · [63:32] = {`e1_c1`, `e_c1`} · [95:64] = {`e1_c2`, `e_c2`}. 낱말 n 은 [15:0] `e_cn` · [31:16] `e1_cn` 로 `LOG_Cn` 과 같은 배치다. `log_rd_data` 와 같은 사이클에 유효 |

e_i 버퍼 옆에 같은 깊이(2,048)의 버퍼를 하나 더 둔다(2,048 × 96b — BRAM 약 6개, Zynq-7020 은 140개).

### 2.2 §3 레지스터 맵 — 4행 추가, `ID` 는 그대로

| 오프셋 | 이름 | 접근 | 리셋값 | 내용 |
| ------ | ---- | ---- | ------ | ---- |
| 0x2C | `LOG_C0` | RO | 0 | `LOG_ADDR` 가 가리키는 읽기의 [15:0] `e_c0` · [31:16] `e1_c0` |
| 0x30 | `LOG_C1` | RO | 0 | 같은 형식, 정렬 1 |
| 0x34 | `LOG_C2` | RO | 0 | 같은 형식, 정렬 2 |
| 0x38 | `FEATURE` | RO | 비트스트림 고정값 | bit0 = 에지 계수기 있음 · bit1 = `BASE_SECTOR`(수정안 #1) 있음 · 나머지 0. 이 둘을 같이 구현하므로 새 비트스트림은 0x3 |

- `ID`(0x00)는 **0x4D42_0100 그대로** 다([D55-18]). 올리면 v1 ELF(`g0_sweep.c` 의 `ID_MAGIC` 검사)와 v1 시뮬레이션이 전부 새 값을 받아야 해 「v1 그대로」([D55-10])가 깨진다. 기능 유무는 `FEATURE` 로 본다 — 옛 비트스트림은 0x38 을 디코드하지 않아 0 을 읽는다(`core_axil_regs.v` 의 읽기 `default`). v2 펌웨어는 bit0 = 0 이면 측정하지 않는다(무효 ⑪).
- 0x28 은 수정안 #1 의 `BASE_SECTOR` 자리다. `LOG_DATA`(0x24)는 바꾸지 않는다 — v1 펌웨어가 그대로 돈다. 남는 자리는 0x3C 하나다(주소 6비트).

### 2.3 §4 규약 — R8 확장 · R14 신설

- **R8** 무결성 검사에 셋을 더한다. 어기면 무효 ④ 다. v1 펌웨어는 ④⑤⑥을 보지 않는다(읽지 않으므로).
  - ④ 모든 읽기에서 `min(e_c0, e_c1, e_c2) == e_i`
  - ⑤ 모든 c 에서 `e1_c ≤ e_c`
  - ⑥ 모든 읽기 · 모든 정렬 쌍 (c, c′)에서 `|(e_c − 2·e1_c) − (e_c′ − 2·e1_c′)| ≤ |c − c′|`. `e_c − 2·e1_c` 는 (정답 0 오류) − (정답 1 오류) = (창 안에 받은 1 의 수) − (정답 1 의 수)다. 정답 쪽은 세 정렬이 같은 PRBS 2,048비트라 같고, 받은 쪽 창은 정렬 번호 하나에 한 샘플씩 밀리므로 차이가 `|c − c′|` 를 넘을 수 없다. 정답 0 · 1 을 뒤바꿔 세거나 정렬끼리 카운터가 엇갈리면 깨진다
- **R14 정렬별 계수**: 정렬 c 는 0 = `t0 + 3`, 1 = `t0 + 4`, 2 = `t0 + 5` 출발로 맞댄 비교다 — `flash_rx.v` 는 `cc = k` 의 샘플을 정렬 0 은 `prbs[k−3]`, 1 은 `prbs[k−4]`, 2 는 `prbs[k−5]` 와 맞댄다. 그래서 **같은 샘플을 정렬 c − 1 은 정렬 c 보다 한 비트 뒤의 정답과 맞댄다** — 정렬 c 가 「지금 비트」 면 c − 1 이 「다음 비트」 다. `e_c` 는 그 정렬의 불일치 수, `e1_c` 는 그중 **기대 비트가 1 인 자리의 불일치 수** 다. 정렬 번호는 위상에 따라 옮겨 가므로(실칩 프리앰블은 `flash_spi_shim.v` 가 `pay_s` 로 합성해 `t0` 가 `pay` CDC 지연으로 정해진다) 계약은 번호에 의미를 주지 않는다. 짝 고르기 · 방향 해석(상승 · 하강, 먼저 온 · 아직 안 온)은 계약이 아니라 호스트 분석의 몫이다(S-6 §5) — 해석이 틀려도 RTL 을 고치지 않는다.

R13 은 수정안 #3(UID 없이 생성 거부)이 이미 쓴다.

### 2.5 §6 스키마 — 욕조 v2 파일 신설

- **파일**: `bathtub2_<target>_<UID>_<stamp>.csv` + 동반 `bathtub2_<target>_<UID>_<stamp>_reads.csv`. 접두사가 달라 v1 소비자(`sweep_*` glob)가 읽지 않는다. 메타 열(`target` · `uid` · `generated_at` · `git_rev` · `reseat` · `repeat_idx` · `batch_id` · `reason`)은 v1 과 같다.
- **메인 CSV — 행 = (단계, 위상 스텝) 하나.** v1 열 전부 + 아래 열.

| 열 | 타입 | 뜻 |
| -- | ---- | -- |
| `pass` | str | `scan`(훑기) · `ceil`(천장 한 묶음) · `wall`(벽 집중) · `rescan`(끝 훑기) |
| `base_sector` | int | 읽기 창 시작 섹터(수정안 #1). BEGIN 값, 전 행 반복. 루프백은 0 |
| `mode` | str | END 줄의 값 — 펌웨어가 실제로 쓴 벽 N 으로 정한다(8,064 = `std` · 2,064,384 = `deep` · 그 밖은 `n<N>`). 캡처가 END 를 받은 뒤 전 행에 채운다 |
| `flags` | str | 빈 값 또는 `;` 로 이은 식별자 — 런 표시(END 줄의 값, 전 행 반복) + 그 행의 스텝 표시(`reads_gap`, §2.6) |

- **결측 규약(v2)**: `scan` 과 `rescan` 은 `phase_step` 0 부터 UI 끝까지 **연속 · 결측 금지**. `ceil` · `wall` 은 잰 스텝만 있다 — 한 스텝이 여러 단계에 나올 수 있고, `(pass, phase_step)` 은 겹치지 않는다. `n_reads` 는 행마다 다르다(훑기 1 · 천장 112 · 벽 N).
- **동반 `_reads.csv`**: 열 `phase_step, pass, read_idx, err_count, e_c0, e_c1, e_c2, e1_c0, e1_c1, e1_c2`. 초심부도 필수다([D55-9]) — 약 4,000만 행, 스윕당 약 1.7GB.
  - `read_idx` 는 START(묶음)마다 0 부터 다시 센다(묶음 112회면 0-111). 읽은 쪽은 `base_sector × 16 + read_idx` 다(루프백은 `read_idx` 그대로 — 시드 인덱스). 한 `(pass, phase_step)` 안의 묶음 순서는 행 순서다
  - `pass` 는 한 글자 부호(`s` 훑기 · `c` 천장 · `w` 벽 · `r` 끝 훑기)로 적는다. UART 의 R 줄에는 싣지 않는다 — R 줄 묶음 뒤에 그 `(pass, phase_step)` 의 M 줄이 오므로 캡처가 순서로 붙인다. 초심부는 UART 가 병목이라 R 줄 한 글자가 곧 시간이다(S-6 §4)
- **BEGIN 줄**: `#G0 SWEEP BEGIN fmt=bathtub2 steps=<UI 스텝> b=<B> f_sclk_hz=<f> dphi_ps=<Δφ> base_sector=<s>`. `n=` 키는 싣지 않는다(단계마다 다르다). v1 캡처는 `fmt` 키가 있으면 BEGIN 에서 끊는다(v1 캡처에 한 줄 — 지금도 `run_sweep_chip.py` 를 거치면 `n` 이 없어 「기대 N」 검사에서 끊긴다). v2 캡처는 `fmt=bathtub2` 가 아니면 끊는다.
- **무효 런 — v1 ⑦⑧ 의 v2 정의**:
  - ⑦ `line_dead_*` — 훑기 단계에서 v1 과 같은 검사(연속 두 스텝 `e_i` 동일 + 전 읽기 유오류, 저오류 스텝을 보기 전까지만). 훑기는 N = 1 이라 비교하는 값이 하나이고, 극성 분류도 그 한 읽기의 쪽(`base_sector × 16`)으로 한다. 천장 스텝은 결정론적으로 같은 값을 내므로 덩어리가 스텝 0 에 걸치면 거짓 경보가 날 수 있다 — S-6 §6 시험 2 에서 확인한다
  - ⑧ `no_window` — 훑기에 오류 0 스텝이 하나도 없다(바닥 없음). v1 의 「저오류 스텝 부재」 보다 엄격하다 — v2 는 덩어리를 바닥으로 정의하기 때문이다
- **무효 런 추가**:
  - ⑨ `multi_block` — 훑기에서 오류 덩어리 사이 0 틈이 K 이상(덩어리 둘 이상)
  - ⑩ `wall_cap` — 벽 집중이 덩어리 경계에서 바깥으로 상한(명세 S-6)까지 갔는데도 0 오류 K 연속이 안 왔다
  - ⑪ `no_feature` — `FEATURE` bit0 = 0 (에지 계수기가 없는 비트스트림)
  - ⑫ `contact_collapse` — 벽 집중의 바깥 스텝(훑기 덩어리 밖) 묶음에서 읽기당 평균 오류가 천장 문턱(S-6) 이상. 바닥이었던 자리가 천장 높이로 튀는 것은 벽이 아니라 접촉 붕괴다 — 상한까지 걷지 않고 그 자리에서 끝낸다
  - ⑬ `no_block` — 훑기 전 스텝이 오류 0 (덩어리 없음). 실칩 · 루프백 모두 위상 한 바퀴에 전이를 반드시 지나므로 계수 경로 고장이다
  - ⑭ `short_floor` — 바닥(가장 긴 원형 0 구간)이 128스텝 미만. 좌우 바깥 걷기(각 최대 64스텝)가 겹칠 수 있어 절차가 정의되지 않는다
- **유효 런의 주의 표시(`flags`)**: 표시가 붙어도 분석 입력에서 빼지 않는다 — 판단은 분석이 한다.
  - `block_out_of_range` — 덩어리 중심이 이력 범위 밖(범위는 명세)
  - `drift` — `rescan` 의 천장 양 끝(훑기 오류가 천장 문턱 이상인 스텝의 처음 · 끝)이 `scan` 과 1스텝 넘게 다르다. 1회 읽기의 덩어리 경계는 BER 1e-4 근처라 흔들려 쓰지 않는다
  - `rescan_multi_block` — `rescan` 에서 덩어리가 둘 이상. 무효가 아니다 — 측정은 `scan` 기준으로 이미 끝났다
  - `reads_gap` — 스텝 표시(그 행에만). §2.6

### 2.6 §6 캡처 완주 검사

v2 의 END 줄은 `#G0 SWEEP END valid=<0|1> reason=<…> main_rows=<n> reads_rows=<m> mode=<…> flags=<…>` 이다. 캡처는 셋을 본다.

1. 받은 메인 행 수 = `main_rows`. 다르면 **무효 ⑤**(미완주 · 결측) — 메인 행이 하나라도 빠진 런만 무효다
2. `(pass, phase_step)` 마다 받은 R 행 수 = 그 메인 행의 `n_reads`, Σ`err_count` = 그 메인 행의 `bit_errors`. 어긋나면 그 메인 행 `flags` 에 `reads_gap` 을 붙이고 **런은 유효로 둔다** — 메인 행(스텝 집계)은 PS 가 R8 을 통과시킨 값이라 그대로 쓸 수 있고, 분석은 그 스텝의 읽기별 값만 쓰지 않는다
3. 받은 R 행 총수 ≠ `reads_rows` 이면 2 가 그 스텝을 찾아낸다. 2 에 안 걸렸는데 총수만 다르면(어느 스텝에도 속하지 않는 R 행) 무효 ⑤

v1 은 그대로 BEGIN 의 `steps × n` 으로 본다.

## 4. 인수 기준

### A1. 하위 호환 회귀 — 새 비트스트림에서 v1 이 그대로인가

- **같은 장착 A/B**: 기지 칩 하나를 장착한 채 옛 비트스트림 → 새 비트스트림 → 옛 비트스트림 순으로 v1 스윕을 1회씩 뜬다. 새 비트스트림의 덩어리 양 끝 스텝과 폭이 옛 · 옛 두 번의 반복 차이 안에 들면 통과다. 장착 · 배선이 바뀌면 25MHz 덩어리도 수백 ps 움직이므로(로그 55 §8 추기) 이력 범위가 아니라 같은 장착의 반복으로 잰다
- 루프백 v1 스윕 1회 — CSV 열 · 행 수 · R8 이 v1 과 같다
- 통과하면 그 뒤의 스윕은 v1(마모 체크포인트)이든 v2 든 새 비트스트림으로 뜬다. 어느 비트스트림인지(빌드한 커밋의 git rev)는 세션 로그에 남긴다 — v1 CSV 열은 늘리지 않는다([D55-21])

### A2. 계수기 시뮬레이션 — 해석이 주입한 정답을 되찾는가

`flash_top_spi` 경로(SPI 마스터 + `flash_spi_shim.v` 의 합성 프리앰블 + `flash_rx.v`)로 돌린다 — 실칩의 `t0` 는 데이터 에지가 아니라 `pay` CDC 지연이 정하므로 루프백 경로로는 정렬 번호의 이동을 재현하지 못한다. 가짜 플래시 모델에 상승 · 하강 에지의 평균 시각과 지터를 따로 넣고(예: 상승 σ 8ps · 하강 σ 20ps, 평균은 상승이 이른 칩과 하강이 이른 칩 둘), 위상을 덩어리 전체에 걸쳐 쓸어 여섯 값을 받는다. 확인할 것:

- S-6 §5 의 해석(읽기마다 합이 쪽 전이 수인 이웃 짝 → 「지금 비트」 정렬의 정답 0 · 1)으로 되찾은 에지별 (평균, 폭)이 주입값과 맞는다. 허용 오차는 시뮬레이션 전에 적어 둔다
- 모든 읽기에서 그런 짝이 정확히 하나 있다. 짝의 번호가 바뀌는 위상(`pay` CDC 의 `t0` 이동)을 기록한다
- 천장에서 두 정렬이 모든 읽기에서 비기거나 쪽 경계 전이 몫(0-1)만 다르다
- N = 1 START(훑기)에서도 여섯 값 · R8 이 맞다
- R8 ④⑤⑥ 이 전 읽기에서 성립한다
- **극성 검사**: MISO 를 0 에 묶으면 모든 c 에서 `e1_c == e_c`(틀린 자리가 전부 정답 1)

> **2026-11-11 — A2 를 돌려 보니 두 문장이 틀렸다 (AI 기록, 영웅님 확인 필요 · 로그 55 §11).** ① 「모든 읽기에서 그런 짝이 정확히 하나」 는 성립하지 않는다 — 오류 0 정렬이 1 인 바닥에서는 짝 (0,1) · (1,2) 가 둘 다 맞고 둘 다 참이며, 꼬리의 오류 1개 읽기도 43-92% 가 두 짝 모두 맞는다. ② 합에서 쪽 안 전이 수를 뺀 값은 0-1 이 아니라 0-2 다(짝 (1,2) 에 쪽 머리 상승이 더해진다). 해석 규칙은 「합 차가 0-2 인 짝이 하나면 그 짝, 둘이면 훑기 덩어리 중심의 왼쪽은 지금 비트 = 정렬 1 · 오른쪽은 정렬 2」 로 고친다(리뷰 H1 · H2 — RTL A2 11묶음 53k 읽기에서 100% 맞음). 허용 오차는 시뮬레이션 전에 적지 않았다 — 관측 최대 평균 0.146ps · σ 0.086ps 는 결과이지 기준이 아니다. 리뷰 제안은 통계 표준오차(약 0.04-0.06ps)의 3배다.

> **2026-11-11 — 구현에서 더한 무효 사유 · 검사 (AI 기록, 영웅님 확인 필요 · 리뷰 M1 · M2 · M6).** 펌웨어: `no_base_sector`(base sector 가 0 이 아닌데 `FEATURE` bit1 = 0) · `base_sector_mismatch`(0x28 되읽기 불일치, BEGIN 의 `base_sector=` 는 되읽은 값) · `cfg_err`(DONE 을 기다리다 CFG_ERR 가 서면 바로 끝냄 — 전에는 `done_stuck` 으로 보였다). 캡처: scan · rescan 이 0 부터 끝까지 정확히 하나씩이 아니거나 (pass, phase_step) 가 겹치거나 R 행이 다 왔는데 Σ`err_count` ≠ `bit_errors` 면 무효 `row_mismatch`.

### A3. 루프백 v2 완주

루프백으로 v2 스윕(`std`)을 끝까지 돌려 `scan` · `rescan` 결측이 없고, END 행 수 대조를 통과하는지 본다. 일부러 메인 줄 하나를 버린 캡처는 무효 ⑤ 가, R 줄 하나를 버린 캡처는 그 스텝에만 `reads_gap` 이 붙고 런은 유효로 남는지 본다.

### A4. 실칩 25MHz

기지 칩 하나로 v1 스윕과 v2 스윕(`std`)을 같은 장착에서 연달아 뜬다.

- v2 의 `scan` 덩어리 위치가 v1 과 같다
- **천장 대조**: `ceil` 스텝의 읽기별 `err_count` 가 `base_sector` 로 계산한 쪽별 한쪽 방향 전이 수(하강 **또는** 상승)와 112/112 일치한다. 쪽 0-111 이면 합이 하강 56,572 또는 상승 56,460 이다 — v1 25MHz 395런 중 386런이 하강, chip07 2026-09-20 런은 상승(56,460)이었다
- 모든 읽기에서 합이 쪽 전이 수인 이웃 짝이 하나 있다
- **25MHz 방향 대조**: 천장 = 쪽별 상승 수이면 하강이 먼저 온 칩이라 천장 스텝에서 계수기가 정답 1 쪽(`e1_c = e_c`)이어야 하고, 하강 수이면 정답 0 쪽(`e1_c = 0`)이어야 한다. 쪽 끝 비트가 0 인 쪽(쪽 0-111 은 전부)에서만 갈린다 — 상승이 먼저면 쪽 끝 상승이 「먼저 온」 쪽에 더해져 두 정렬이 하강 수로 비기고, 하강이 먼저면 「아직 안 온」 상승 쪽이 1 작다(유도 — A2 에서 확인)

> **2026-11-11 — A4 의 「짝이 하나」 와 25MHz 방향 대조는 고쳐야 한다 (AI 기록, 영웅님 확인 필요 · 리뷰 H3).** 짝은 위 A2 추기의 규칙으로 고른다. 방향 대조는 「천장 = 상승 수냐 하강 수냐」 로 판정하면 틀린다 — 하강이 먼저인 칩도 읽기 전 선이 0 이고 짝이 (1,2) 이면 천장이 하강 수(56,572)로 비긴다(A2 `fall_first`). 방향은 천장에서 고른 짝의 「지금 비트」 정렬이 `e1 = 0` 이냐 `e1 = e` 이냐로 정한다. 「395런 중 386런이 하강 수」 는 방향을 말해 주지 않는다.

### A5. 75MHz 실칩 대조 — 계수기 해석이 선반의 이력 부류와 맞는가

75MHz 비트스트림(사다리 빌드 경로 `fpga/scripts/build_g3_chip.tcl`)과 75MHz 파라미터 묶음(S-6 §2)으로 칩 1-2개에 v2 스윕(`std`)을 1회씩 뜬다. 장의 데이터가 아니라 계수기 검증에만 쓴다 (2026-11-11, 한영웅).

**정답은 같은 런 안에서 오류 수로 정한다**([D55-20]). 선반마다 읽기별 `err_count`(= min)를 PRBS 이력 부류의 쪽별 개수와 맞춰(`host/analysis/bathtub_isi_shelf.py` 의 방식, 112/112 읽기 일치) 부류를 정하고, 그 부류가 정하는 원값이 나와야 통과다. 「왼쪽 1 0 1 · 오른쪽 1 1 0」 같은 고정 라벨은 쓰지 않는다 — chip07 2026-09-29 75MHz 는 배선 사고 뒤 두 선반이 다 하강 부류였고, 45MHz 왼쪽 선반은 「0 0 1」 상승(28,620, 112/112)이다.

| 선반 | 오류가 적은 쪽 정렬(RTL 의 min) | 상승 부류면 | 하강 부류면 |
| ---- | ------------------------------- | ----------- | ----------- |
| 왼쪽 | 「지금 비트」 c | `e1_c` 약 0, `e_c − e1_c` = 부류 개수 | `e1_c` = 부류 개수, `e_c − e1_c` 약 0 |
| 오른쪽 | 「다음 비트」 c − 1 | `e1` = 부류 개수, `e − e1` 약 0 | `e1` 약 0, `e − e1` = 부류 개수 |

- 짝 (c − 1, c) 안에서 오류가 적은 쪽이 왼쪽 선반은 c, 오른쪽 선반은 c − 1 이다 — 그 사이에 `t0` 이동이 없으면 왼쪽 → 오른쪽으로 정렬 번호가 1 줄어든다
- 흔한 경우(왼쪽 「1 0 1」 상승 · 오른쪽 「1 1 0」 하강)에는 두 선반 모두 오류가 적은 쪽 정렬의 `e1` 이 0 근처이고, 쪽별 `e − e1` 이 부류 개수와 같다
- 실칩 대조는 이것만이 아니다 — A4 의 천장 대조와 25MHz 방향 대조가 25MHz 에서도 한 번 맞춰 본다
