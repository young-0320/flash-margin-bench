## 1. 무엇을 가르나

마모는 엔진이 돌리고, **체크포인트에서 재는 것은 호스트 도구**다(§5 가 스윕을 부른다).
둘이 만나는 지점이 이 경계다.

```
[엔진 — PS C, 무상태]                        [호스트 · TB]
사이클링 (§6 루프)                             체크포인트 준비(flash_prep)·스윕 (§5)
tally 기록·판독 (§8)            ◄──UART──►    로그 수신·파일화 (§9)
무결성 검사 (§7)                               재개 판단·중단 (§8.3 · §10)
복구 원자료·재소거 (§8.3)                      등록부·chip_pe 기입 (§8.4)
```

**로그는 경계를 건너온다.** §6 ⑥ 가 「호스트로 `#WEAR` 행 출력」이므로 A·B·R 로그(§9)는
엔진이 뱉고 호스트가 받아 파일로 갖는다 — **호스트가 가진 것을 엔진에 되묻지 않는다.**

**엔진은 무상태다.** 체크포인트마다 스윕이 보드를 리셋하므로(`g0_sweep.c` 는 부팅 1회에
1회) 엔진의 메모리는 구간마다 사라진다. 이어 가는 데 필요한 것은 전부 `wear_start` 의
인자로 들어오거나 칩(tally)에 있다 — 로그 44 §2.

### 2.1 값의 규약

- **`cycle` 은 누적 현재값, `delta` 는 이번 구간에 추가로 돌릴 횟수다** (`[D44-1]`). 첫
  시작은 `cycle=0`, 첫 체크포인트(300) 뒤는 `cycle=300 delta=345`, 복구 뒤는 호스트가
  §8.3 으로 채택한 값이다. `delta` 만큼 돌면 §6 ⑤ 대로 **엔진은 거기까지만 돌고 멈춘다.**
  A 행의 `cycle` 은 `cycle+1` 부터 이어진다. 누적 목표값을 넣는 해석은 없다
- **`cycle` 은 tally 와 맞아야 받는다.** `d = cycle − tally×100` 이 `0 ≤ d < 100` 밖이면
  `E_CYCLE` 로 거부한다 (§8.3 의 `d` 규칙과 같은 식이다). tally 가 비어 있지 않은데
  `cycle=0` 이면 `E_DIRTY` — 재개를 신규로 착각해 X축을 지우는 것을 막는 자물쇠다.
  **tally 가 비어 있지 않다는 이유만으로 거부하지 않는다** (`[D44-10]`)
- **`session` 은 호스트가 준다.** 엔진에 비휘발 카운터가 없어 리셋마다 `req` 가 0 으로
  돌아가므로, `req` 의 단조 증가는 세션 안에서만 정의하고 `#WEAR H` 행이 `session` 을
  되돌린다 (`[D44-5]`)
- **`pattern` 은 시작할 때 한 번만 받는다.** 로그 29 `[D29-7]` 이 「한 wear 그룹 안에서
  패턴 변경 금지」를 못박았다 — `0x00` 은 셀당 8비트, `0x55` 는 4비트라 사이클당 스트레스가
  2배 다르다. 파일럿 고정값은 `0x00`(§1, 2026-09-18 개정)
- **보호 범위는 엔진 상수다.** tally(512·1,536)에 더해 근접·원격 대조군(파일럿 7~13 ·
  2,041~2,047)과 겹치는 구간은 `E_CTRL_OVERLAP` 으로 거부한다. 배치가 바뀌면 ELF 를 다시
  빌드한다 — 「ELF 재빌드 없이」는 `wear_start` 의 인자에만 거는 조건이다 (`[D44-2]`)
- **`state` 는 여섯이다** — `idle` · `running` · `checkpoint_due` · `recovering` · `halted` ·
  `error`. `checkpoint_due` 가 §6 ⑤ 의 신호다. `recovering` 은 `wear_resume()` 뒤의 상태로,
  마지막 `blank_check` 결과를 들고 있으며 **`reerase()` 는 이 상태에서만 받는다** (`[D44-3]`).
  전이는 `idle → resume → recovering → blank_check → reerase → blank_check → wear_start(cycle=채택값)`
- **`checkpoint_due` 로 가는 조건** (지민 회신 §2) — 마지막 P/E 의 WIP 가 0 · 마지막 정상
  사이클의 카운터 증가 완료 · 그 사이클의 A 행 7개 송신 완료 · 플래시 idle(CS high · SCLK low).
  이후 호스트의 다음 명령까지 P/E 도 로그 출력도 하지 않는다
- **`halt()` 는 다음 사이클 경계에서 멈춘다** — 진행 중인 P/E 를 끊지 않는다. `halted` 에서
  이어 가는 길은 `wear_start(cycle=마지막 완료값)` 이다 (`[D44-4]`)
- **`defect_seen`** 은 §7 의 조밀화 트리거(결함 비트 1회 검출 → 주기 100→10)를 호스트가
  알기 위한 것이다. 호스트는 이것으로 체크포인트 배치(§11 ×1.47)를 다시 계산한다
- **`tally_read()` 는 2벌을 따로 돌려준다.** 엔진이 큰 쪽만 고르면 호스트가 불일치를 볼 수
  없고, §8.2 의 「불일치를 로그에 기록한다」를 지킬 수 없다
- **`wear_resume()` 은 채택하지 않고 플래시를 바꾸지 않는다.** tally 2벌의 원본값과 다음
  바이트, write 가능 여부만 돌려주고 **「어느 값을 쓸지」는 호스트가 정한다** — 로그 41
  `[D41-20]`·§12. 엔진은 호스트 로그를 모르므로(§1) 「세 값 대조」의 세 번째 값을 엔진 안에서
  구할 수 없다. `next_tally_byte` 는 `d ≥ 100` 의 두 경우를 가르고, `write_ok` 는 「플래시가
  안 써진다」를 가른다 (`[D41-21]`)
- **`reerase()` 는 별도 경계다** (지민 회신 §3.3, 제안-9 ⓑ). 조건 — `recovering` 상태 ·
  가장 최근 `blank_check` 에서 그 섹터의 부분 소거 확인 · 요청 섹터가 검출 주소로 계산한
  섹터와 일치 · 보호 범위 밖 · 다른 P/E 없음. 뒤에 WIP 완료를 확인하고 같은 영역을 다시
  읽어 잔류가 없는지 본다. **자동 재시도는 없다.** 카운터에도 `area_cumulative_cycles` 에도
  더하지 않고 **사건 행 `R` 로 남긴다** (§3.4 · `[D44-6]`). 호스트는 `docs/chip_pe.md` 에
  증분 행을 비고 「reerase · ±1」로 남긴다
- **`blank_check` 는 부를 때 실제로 읽어서 센다.** 마지막 결과를 캐시하지 않는다.
  **합 불변식 `erase_residual + program_fail = 전량` 은 패턴 `0x00` 이고 같은 읽기일 때만
  참이다** (`[D44-7]`, 지민 회신 §5.1). 체크포인트에서 호스트가 이 경계를 불러 세는 경로가
  살아 있는지 보는 `probe` 의 기대값은 `program_fail = 바이트 수 × popcount(~pattern)` 이다.
  B 행의 두 값은 서로 다른 두 읽기(프로그램 직후 · 소거 직후)라 **B 행에는 이 식을 적용하지
  않는다**
- **`addrs[]`** 는 §7 대로 최대 64개 + 총 개수다 (페이지·바이트·비트). `worst_page_*` 는
  64개를 넘겨 잘린 뒤에도 최악 페이지가 남게 하는 것이다. B 행은 이 묶음을 **phase 별로
  두 벌**(`p_*` 프로그램 직후 · `e_*` 소거 직후) 싣는다 (`[D44-13]`)
- **`cycle` 은 마모 루프 사이클이다.** 체크포인트의 소거+PRBS 기록은 여기에 **넣지
  않고** §9 C 로그의 `area_cumulative_cycles` 로 간다. A5 의 네 경로(카운터 · A행수÷7 ·
  B 의 cycle · tally×100)가 **전부 이 정의 위에 서므로** 하나라도 다른 것을 세면 A5 가
  성립하지 않는다

## 3. 경계 밖 — 넣지 않은 것

| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

## 4. 층위

**PS C** 다 (`[D44-8]`, 지민 회신 §6). 경계 뒤를 **mock 엔진**으로 채운 것이 `host/tests/` 이고,
실엔진은 같은 경계를 UART 텍스트 명령(S-4 §5.2)으로 채운다. 밖에서 보이는 모양은 같다.
