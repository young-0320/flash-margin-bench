## 1. 무엇을 가르나

마모는 엔진이 돌리고, **체크포인트에서 재는 것은 호스트 도구**다(§5 가 스윕을 부른다).
둘이 만나는 지점이 이 경계다.

```
[엔진]                                    [호스트 · TB]
사이클링 (§6 루프)                         체크포인트 스윕 (§5)
tally 기록·판독 (§8)          ◄───────►   로그 수신·파일화 (§9)
무결성 검사 (§7)                           판정·중단 (§10)
재개 복원 (§8.3)                           등록부 기입 (§8.4)
```

**로그는 경계를 건너온다.** §6 ④ 가 「호스트로 `#WEAR` 행 출력」이므로 A·B·C 로그(§9)는
엔진이 뱉고 호스트가 받아 파일로 갖는다 — **호스트가 가진 것을 엔진에 되묻지 않는다.**

## 2. 경계 — 7개

| # | 서명 | 근거 조항 | 없으면 |
| - | ---- | --------- | ------ |
| 1 | `wear_start(base_sector, n_sectors, pattern, cycles)` | §5 · §6 ⑤ · §1 | 루프를 시작할 수 없다 |
| 2 | `wear_status() → (cycle, state, defect_seen)` | §13 A1 · §6 ⑤ · §7 | 호스트가 스윕 시점을 모른다 |
| 3 | `wear_resume() → (tally_a, tally_b, mismatch, next_tally_byte, write_ok)` | §13 B · §8.3 | B 를 판정할 수 없다 |
| 4 | `blank_check(base_sector, n_sectors) → (erase_residual_bits, program_fail_bits, defect_addrs[], worst_page_idx, worst_page_bits)` | §7 · §6 ④ · §8.3 4 · §13 A3 | 부분 소거를 못 잡는다 |
| 5 | `tally_read() → (count_a, count_b, mismatch)` | §13 A4·**A5** · §8.2 · §8.3 2 | **A5 가 성립하지 않는다** |
| 6 | `tally_dump() → 4,096B × 2벌` | §8.5 | `0x00`/`0xFF` 외의 값을 못 본다 |
| 7 | `uid_read() → 16 hex` | §8.3 1 · §13 A7 | 중단 판단을 호스트가 못 한다 |

### 2.1 값의 규약

- **`pattern` 은 시작할 때 한 번만 받는다.** 로그 29 `[D29-7]` 이 「한 wear 그룹 안에서
  패턴 변경 금지」를 못박았다 — `0x00` 은 셀당 8비트, `0x55` 는 4비트라 사이클당 스트레스가
  2배 다르다. 파일럿 고정값은 `0x00`(§1, 2026-09-18 개정)
- **`cycles` 는 다음 체크포인트까지의 수** 다. §6 ⑤ 가 체크포인트에서 §5 로 나가므로,
  엔진은 거기까지만 돌고 멈춘다
- **`state` 는 다섯이다** — `idle` · `running` · `checkpoint_due` · `halted` · `error`.
  `checkpoint_due` 가 §6 ⑤ 의 신호다
- **`defect_seen`** 은 §7 의 조밀화 트리거(결함 비트 1회 검출 → 주기 100→10)를 호스트가
  알기 위한 것이다. 호스트는 이것으로 체크포인트 배치(§11 ×1.47)를 다시 계산한다
- **`tally_read()` 는 2벌을 따로 돌려준다.** 엔진이 큰 쪽만 고르면 호스트가 불일치를 볼 수
  없고, §8.2 의 「불일치를 로그에 기록한다」를 지킬 수 없다
- **`wear_resume()` 은 채택하지 않는다.** tally 2벌의 원본값과 다음 바이트, write 가능
  여부만 돌려주고 **「어느 값을 쓸지」는 호스트가 정한다** — 로그 41 `[D41-20]`·§12.
  엔진은 호스트 로그를 모르므로(§1) 「세 값 대조」의 세 번째 값을 엔진 안에서 구할 수 없다.
  `next_tally_byte` 는 `d ≥ 100` 의 두 경우를 가르고, `write_ok` 는 「플래시가 안 써진다」를
  가른다 (`[D41-21]`)
- **`defect_addrs[]`** 는 §7 대로 최대 64개 + 총 개수다 (페이지·바이트·비트).
  `worst_page_idx`·`worst_page_bits` 는 §9 B 로그가 요구하는 필드다 — 64개를 넘겨
  잘린 뒤에도 최악 페이지는 남는다
- **`cycle` 은 마모 루프 사이클이다.** 체크포인트의 소거+PRBS 기록은 여기에 **넣지
  않고** §9 C 로그의 `area_cumulative_cycles` 로 간다. A5 의 네 경로(카운터 · A행수÷7 ·
  B 의 cycle · tally×100)가 **전부 이 정의 위에 서므로** 하나라도 다른 것을 세면 A5 가
  성립하지 않는다. §1 계수 문구(「체크포인트의 소거+PRBS 기록도 1사이클로 계수」)는
  **영역별 누적 P/E 의 계수 규칙**으로 읽는다 — S-1 §1 에 그 구분을 명시해야 한다

## 3. 경계 밖 — 넣지 않은 것

| 안 넣은 것 | 왜 |
| ---------- | -- |
| `wear_times()` | **이중 출처다.** §9 A 로그가 `t_erase_us`·`t_program_us` 를 매 사이클 섹터별로 남긴다. 같은 값이 두 경로로 나오면 어긋났을 때 어느 쪽이 맞는지 알 수 없다 |
| `log_tail()` | **로그는 호스트가 갖는다**(§6 ④). 엔진에 되물으면 「엔진이 뱉었다」와 「호스트가 받았다」의 차이가 가려진다 — UART 행 유실이 실제로 있었다 (`docs/log/young/8.vivado_integration_and_sweep_sw.md` `[D8-6]`) |
| 온도 읽기 | §9 가 `die_temp_c` 를 B·C 로그에 담게 했다. 엔진 내부 동작이고 결과는 로그로 나온다 |
| 체크포인트 실행 | §5 는 호스트 도구다. 엔진은 `checkpoint_due` 로 시점만 알린다 |

## 4. 층위와 무관하다

`[D29-1]`(RTL 엔진 / PS C / PS C + 핀 mux)이 어느 쪽으로 가도 이 경계는 그대로다 —
**레지스터 write 로 채우든 PS C 함수로 채우든 밖에서 보이는 모양만 같으면 된다.**

로그 29 §9 가 그 구조를 먼저 적어 두었다. 이 경계 뒤를 **mock 엔진**으로 채우면
`[D29-1]` 확정 전에도 호스트·TB 쪽을 전부 짤 수 있다.

## 5. 이 경계로 무엇이 판정되나

| A4 tally 바이트 | 5 |

| B 전원 장애 복구 | 3 + 4 |
