# 로그 서식 규약

2026-09-17 확정. **한영웅 로그에 적용** 하고, 새 로그는 물론 **옛 로그도 소급이 가능하다** —
한 편씩 옮기면 되고 한 번에 다 옮길 것 없다. 아직 안 옮긴 로그는 제목 밑에 「규약 이전 서식」
표시를 달아 둔다. 표시가 없으면 검색으로 착지한 AI 가 옛 서식을 현행으로 읽는다.
`jimin/`·`seeun/` 는 폴더 소유자가 각자이므로 강제가 아니라 제안이다.
근거와 전 로그 계측은 [로그 38](young/38.log_format_convention.md) ·
[로그 39](young/39.log_convention_enforcement.md). 로그 목록은 `README.md`.

**로그는 다른 문서가 가질 수 없는 것만 담는다.** git · `results/` · `spec/` · `workflow/` 가
답할 수 있으면 로그에 쓰지 않는다. 로그에만 있는 것은 셋이다 — 왜 그렇게 정했나 · 무엇을
버렸나 · 무엇이 아직 안 정해졌나.

읽는 쪽이 둘이고, 규약은 거기서 나온다. **AI** 는 프로젝트 컨텍스트로 안 되는 세부를 여기서
찾고, **사람** 은 몇 달 뒤 맥락을 되찾으러 온다. 둘 다 목차를 안 거치고 검색으로 본문 한가운데
착지한다 — 그래서 결정마다 날짜·사람이 그 줄에 붙어 있어야 하고, 뒤집힌 자리에는 반드시
표시가 있어야 한다. 표시 없는 낡은 결정을 사람은 날짜 보고 거르지만 **AI 는 현행으로 읽고
실행한다.**

### 골격

```
머리말
## 결정    3~5줄. 각 줄에 근거 절 링크와 위치.  절은 항상 둔다
## 근거    결정마다 한 절 — 후보 · 탈락 이유 · 경위. 뒤집히면 그 자리에 인용구 추기
## 산출물  신설·이전이 있을 때만. `# | 산출물 | 위치` 표
## 미결    미결 "결정"만. 닫히면 위 본문의 그 자리에 추기
```

### 머리말

| 필드 | 내용 |
| ---- | ---- |
| `작성일` | `2026-09-17` |
| `발단` | 무슨 일이 있어 이 작업이 시작됐나. 2~3줄 |
| `목적` | 이 로그가 답하려는 질문. **물음표로 끝낸다** — 목적은 질문이고 `## 결정` 이 답이다 |
| `측정일` | **실칩을 만졌고 그 날짜가 작성일과 다를 때만.** 로그 22 는 2주 차이가 났다. 측정일이 여럿이면 날짜를 나열하지 않고 `chip_registry.md` 로 넘긴다 — 칩별 이력은 등록부가 정본이고, 범위로 적어도 어느 칩이 어느 날인지는 거기를 봐야 안다 |
| `관련` | 문서 경로 · 로그 번호. 로그 번호는 첫 등장에 **마크다운 링크로** — `[로그 23](23.sweep_wrapper_and_uid_design.md)`. 본문에서도 같다. 사람은 눌러서 가고, AI 는 경로를 얻고, 없는 파일을 가리키면 검사에 걸린다 |

글쓴이는 적지 않는다 — 사람별 하위 폴더가 이미 답한다. 로그의 종류(`성격`)도 적지 않는다 —
`발단` 과 `목적` 이 이미 그 말을 하고 있다.

### 절별 규칙

- **`## 결정`** — **절을 생략하지 않는다.** 정해진 것이 없으면 "정해진 것 없음 — 이유"를
  한 줄 적는다. 없다는 것도 정보이고, 생략하면 규약 이전 로그와 구분이 안 된다. 보류도 결정이다
  (로그 22 는 "판정을 내리지 않는다"·"승격하지 않는다" 둘을 정했다).
  결론 문장이 있는 **유일한 자리**다. 본문에서 복사해 오지 않는다. `## 근거`
  절은 결론을 되풀이하지 않고 후보·탈락 이유·경위만 적는다 — 같은 문장이 두 군데 있으면 본문을
  다듬을 때 한쪽만 낡고, 검색으로 착지한 AI 는 둘 중 아무거나 읽는다 (`## 산출물` 의 수치 금지와
  같은 이유). 각 줄 끝에 근거 절과 위치: `— §2-3 · host/run/run_sweep_chip.py`. 결정에
  날짜·사람이 필요하면 그 줄에 붙인다.
  불릿마다 **ID 를 단다** — `- [D40-1] 라벨을 사람이 입력하지 않는다 — §2 · `host/…``.
  이 결정을 뒤집는 로그는 `[D40-1] 뒤집음` 으로 그 ID 를 인용하고, 검사기가 **인용된 ID 와
  추기가 붙은 ID 를 빼서** 추기 누락을 잡는다. 미결의 `U` 와 같은 장치이고 검사도 같다 —
  추기는 사람이 가장 잘 빠뜨리면서 빠뜨린 줄도 모르는 자리다
- **`## 근거`** — 채택안만 적으면 반쪽이다. **탈락한 후보와 탈락 이유**가 로그의 핵심 재산이고,
  이것이 없으면 AI 가 폐기된 안을 다시 제안한다. 어떻게 그 결론에 닿았는지(경위)도 여기다 —
  가정이 깨진 순간, 두 문제가 겹쳐 오진한 경위 같은 것
- **`## 산출물`** — 수정만 있는 로그는 이 절을 만들지 않고 `## 결정` 불릿에 경로를 붙인다.
  표에 **수치를 싣지 않는다**(`results/` 와 이중 출처가 된다). `build/` 경로도 쓰지 않는다
  (`.gitignore` 라 가리키는 대상이 없다)
- **`## 미결`** — 미결 *결정* 만. 미결 *작업* 은 `workflow/` 로 보낸다. 불릿마다 ID 를 단다
  — `- [U38-1] 옛 로그의 닫힌 미결에 추기를 달 것인가 …`. 나중에 이 미결을 닫는 로그가
  `grep -rn U38-1 docs/log/` 로 추기할 자리를 찾는다. 기억이 아니라 검색으로 닫는다

### 뒤집힌 결정 — 그 자리에 인용구

목차형 정오표를 따로 두지 않는다. 읽는 쪽이 본문으로 바로 오기 때문에, 뒤집히거나 닫힌 결정
**바로 밑**에 붙인다 (로그 23 부록 A · 로그 36 §5 가 실물).

```
> **2026-09-16 — 조건이 도래해 구현했다 (로그 36).** 이름은 `flash_id`,
> 소비자는 `run_sweep_chip.py --mode sweep` 의 세션 1이다.
```

첫 줄은 `> **YYYY-MM-DD — …**` 로 시작하고, 끝에 **무엇이 이 결정을 바꿨는지**(로그 번호·절)를
괄호로 단다. 사람은 본인이 아닐 때만, 폴더명으로 — `jimin`·`seeun`. 형식이 제각각이면
"표시가 다 붙어 있나"를 셀 수 없다 — 이 형식이면 전수 점검이 한 줄이다 (불릿 밑에 들여써도 된다).

```
grep -rn '^\s*> \*\*20' docs/log/young/*.md
```

바꾼 쪽 로그에서는 `## 결정` 줄에 상대 ID 를 인용한다 — 결정은 `[D23-2] 뒤집음`,
미결은 `[U38-1] 닫음`. 위 `grep` 이 추기를 세는 것이라면 ID 인용은 **분모** 다.
이 두 짝이 맞는지가 검사기가 대조하는 전부다.

미결이 나중에 닫혔을 때도 같다. 닫은 로그에만 적고 원 로그를 안 고치면, 원 로그만 읽는 쪽은
끝난 안건을 살아 있는 것으로 읽는다.

### 새 로그를 추가하면

**`README.md` 목록 표에 한 줄 추가한다.** 사람은 그 목록을 거쳐 로그에 닿으므로, 등재되지
않은 로그는 검색으로 오는 AI 에게만 보인다. 번호는 결번을 재사용하지 않는다.

### 쓰지 않는 것

| 쓰지 않는 것 | 어디로 |
| ------------ | ------ |
| 절차·재현 방법 | `workflow/` (런북·게이트 지도). 로그는 갱신되지 않는 문서라 절차를 담으면 반드시 거짓말이 된다 |
| 측정 수치·현황 | `results/` · `spec/` · `chip_registry.md`. 단 **그 수치가 결정을 흔든 경위** 는 로그 |
| 바뀐 파일 목록 | git. 로그가 남길 것은 목록이 아니라 **결정 ↔ 위치** 매핑이다 |
| 작업 실적 (`## 작업 내용`) | 어디에도. "무엇을 만들었다"가 아니라 "설계대로 됐나, 어디서 어긋났나"로 쓴다 |

### 본문

- 한 문단 5줄을 넘기지 않는다
- 문장 속 강조 볼드는 한 문단에 하나. 문장 전체가 아니라 **명사구만** 감싼다.
  표 셀·불릿 머리의 라벨 볼드는 이 셈에 넣지 않는다
- 길이는 규제하지 않는다. 로그 17 이 597줄인 것은 모든 수치의 채택 근거가 거기 있기 때문이다
