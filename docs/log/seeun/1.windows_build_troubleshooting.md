# FPGA/Vitis Windows 환경 빌드 트러블슈팅 및 수동 빌드 가이드

## 1. 자동화 스크립트(한 줄 빌드) 시도 및 실패 기록

프로젝트 가이드 문서에 명시된 파이썬 자동화 스크립트(`reproduce.py`)를 Windows 환경에서 실행했을 때 발생한 문제들과 우회 시도 기록입니다.

해당 자동화 스크립트는 Ubuntu/Linux 환경을 기준으로 작성되어 있어 Windows에서는 시뮬레이터, 문자 인코딩, 서브프로세스 실행 방식 등의 차이로 인해 여러 문제가 발생했습니다.

### 1-1. 스모크 시뮬레이션 툴 부재

- **명령어**
  ```cmd
  python reproduce.py
  ```

- **에러**
  ```text
  PATH 에 없음: ['iverilog', 'vvp']
  ```

- **원인**  
  Windows 환경에 Icarus Verilog(`iverilog`, `vvp`)가 설치되어 있지 않아 RTL 스모크 시뮬레이션 단계에서 중단됨.

- **해결**
  ```cmd
  python reproduce.py --no-sim
  ```

  `--no-sim` 옵션을 추가하여 시뮬레이션 검증 단계를 생략함.

---

### 1-2. Windows 터미널 인코딩(cp949) 충돌

- **명령어**
  ```cmd
  python reproduce.py --no-sim
  ```

- **에러 예시**
  ```text
  UnicodeEncodeError: 'cp949' codec can't encode character ...
  ```

- **발생 위치**  
  selftest 단계에서 발생.

- **원인**  
  Python 스크립트가 UTF-8 특수 문자를 출력하려 했으나 Windows CMD의 기본 인코딩인 CP949와 충돌함.

- **시도**
  ```cmd
  python -X utf8 reproduce.py --no-sim
  ```

  그러나 일부 자식 프로세스에서는 UTF-8 옵션이 그대로 전달되지 않아 동일 문제가 계속 발생함.

- **우회**
  ```cmd
  python reproduce.py --no-sim --no-selftest
  ```

  `--no-selftest` 옵션을 추가해 selftest 단계까지 생략함.

---

### 1-3. 서브프로세스 OS 호환성 에러

- **명령어**
  ```cmd
  python reproduce.py --no-sim --no-selftest
  ```

- **에러**
  ```text
  [WinError 2] 지정된 파일을 찾을 수 없습니다
  ```

- **발생 위치**  
  g0 Vivado 빌드 진입 시점.

- **원인**  
  `reproduce.py`가 Python `subprocess`를 통해 `vivado`를 실행하려 했으나 Windows 환경에서 해당 실행 파일을 정상적으로 생성/호출하지 못함.

- **최종 결론**  
  Windows에서는 `reproduce.py` 자동 빌드를 중단하고, 프로젝트 문서에 명시된 **수동 빌드 파이프라인**을 CMD에서 직접 실행하는 방식으로 전환함.

---

## 2. 수동 빌드 전환 후 발생한 Windows OS 환경 문제

### 2-1. 폴더 잠금(Lock) 에러

- **에러 예시**
  ```text
  Failed to remove the directory...
  The directory might be in use by some other process.
  ```

- **원인**  
  이전 빌드의 `build` 폴더를 Vivado/Vitis가 삭제 또는 재생성하려 했으나, CMD, Vivado, Vitis, VS Code, 파일 탐색기 등의 다른 프로세스가 해당 폴더 또는 내부 파일을 잡고 있어 삭제에 실패함.

- **해결**
  1. Vivado/Vitis/CMD/편집기 등을 종료
  2. 필요하면 파일 탐색기도 해당 디렉터리에서 빠져나옴
  3. Windows 탐색기에서 `build` 폴더를 수동 삭제
  4. 새 CMD를 열어 다시 빌드

---

### 2-2. OneDrive 클라우드 동기화 충돌

- **에러**
  ```text
  .../synth already exists, is a directory, but is not writable.
  ```

- **원인**  
  프로젝트가 `OneDrive\Desktop` 아래에 위치해 있었고, Vivado가 많은 임시 파일을 생성하는 동안 OneDrive 실시간 동기화가 일부 파일/폴더를 잠그면서 쓰기 권한 충돌이 발생함.

- **해결**  
  프로젝트 전체를 OneDrive 영향이 없는 경로로 이동함.

  ```text
  C:\error_ATE\flash-margin-bench
  ```

- **권장 사항**  
  Vivado/Vitis 프로젝트는 OneDrive, Dropbox 등 실시간 동기화 폴더 밖에 두는 것이 안전함.

## 3. Windows 수동 빌드 환경 준비

### 단계 1. 프로젝트 루트로 이동

```cmd
cd C:\error_ATE\flash-margin-bench
```

### 단계 2. Xilinx 2025.2 환경 변수 로드

터미널을 새로 열 때마다 먼저 실행한다.

```cmd
E:\Xilinx\2025.2\Vitis\settings64.bat
```

이 설정을 통해 `vivado`, `vitis`, `xsct` 등을 CMD에서 직접 호출할 수 있게 된다.

가능하면 다음 명령으로 정상 등록 여부를 확인한다.

```cmd
where vivado
where vitis
where xsct
```

## 4. Vivado → Vitis 자동 연동 실패 문제 및 해결

### 4-1. 증상

예를 들어 g0를 다음 명령으로 빌드하면:

```cmd
vivado -mode batch -source fpga/scripts/build_g0_loopback.tcl
```

Vivado의 `.bit`, `.xsa`는 생성되지만, Vivado 스크립트 내부에서 Vitis를 자동 호출하는 단계에서 다음과 같은 문제가 발생할 수 있다.

```text
child process exited abnormally
```

이 경우 Vivado 하드웨어 빌드는 완료되었지만 Vitis 소프트웨어 빌드(`.elf`)가 생성되지 않을 수 있다.

---

### 4-2. CMD 문자 인코딩을 UTF-8로 변경

Windows CMD의 기본 코드페이지가 CP949인 경우 Vitis/Python 스크립트에서 UTF-8 문자를 처리하다 실패할 수 있으므로, 빌드 전에 CMD 코드페이지를 UTF-8로 변경한다.

```cmd
chcp 65001
```

정상 적용되면 다음과 유사하게 표시된다.

```text
Active code page: 65001
```

---

### 4-3. Python 파일 읽기 인코딩 문제 추가 대응

g3 수동 Vitis 빌드 과정에서는 다음과 같은 에러가 실제로 발생하였다.

```text
UnicodeDecodeError: 'cp949' codec can't decode byte ...
```

이는 Vitis 내부 Python이 `g0_sweep.c` 등의 UTF-8 소스 파일을 Windows 기본 인코딩 CP949로 읽으려 할 때 발생한다.

따라서 Vitis 빌드 전 다음 환경 변수를 추가로 설정하는 것이 안전하다.

```cmd
set "PYTHONUTF8=1"
```

`PYTHONUTF8=1`을 설정하면 해당 CMD 세션에서 Python의 기본 텍스트 인코딩을 UTF-8 우선으로 사용할 수 있다.

> `chcp 65001`은 터미널 입출력 코드페이지 변경이고, `PYTHONUTF8=1`은 Python의 텍스트 처리 인코딩에 영향을 준다. 두 설정은 역할이 다르므로 Windows에서는 함께 사용하는 것이 안전하다.

---

### 4-4. g0 Vitis 소프트웨어 빌드 수동 실행

Vivado 빌드 후 Vitis 자동 연동이 실패했을 경우, 다음 명령을 직접 실행한다.

```cmd
vitis -s ps/scripts/build_g0_sweep.py
```

정상적으로 완료되면 다음 ELF 파일이 생성되어야 한다.

```text
build\vitis\g0_sweep\build\g0_sweep.elf
```

따라서 g0에서 Windows 수동 빌드의 기본 흐름은 다음과 같다.

```cmd
cd C:\error_ATE\flash-margin-bench
E:\Xilinx\2025.2\Vitis\settings64.bat
chcp 65001
set "PYTHONUTF8=1"

vivado -mode batch -source fpga/scripts/build_g0_loopback.tcl
vitis -s ps/scripts/build_g0_sweep.py
```

## 5. g2 / flash_prep 수동 빌드

### 5-1. g2 Vivado 빌드

```cmd
vivado -mode batch -source fpga/scripts/build_g2_jedec.tcl
```

기대 산출물:

```text
build\vivado_g2\g2_jedec.xsa
build\vivado_g2\g2_jedec.runs\impl_1\g2_wrapper.bit
```

---

### 5-2. flash_prep Vitis 빌드

```cmd
vitis -s ps/scripts/build_flash_prep.py
```

기대 산출물:

```text
build\vitis_prep\flash_prep\build\flash_prep.elf
```

Vitis 실행 중 CP949 관련 오류가 발생하면 먼저 다음을 적용한다.

```cmd
chcp 65001
set "PYTHONUTF8=1"
```

## 6. g3 클럭별 수동 빌드

g3는 25 MHz, 45 MHz, 75 MHz 각각 별도의 Vivado/Vitis 산출물이 생성된다.

### 6-1. g3-25

Vivado:

```cmd
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs all 25
```

Vivado 내부 Vitis 호출이 실패하거나 ELF가 생성되지 않은 경우:

```cmd
set "G3_MHZ=25" && vitis -s ps/scripts/build_g3_sweep.py
```

UTF-8 관련 오류가 발생하는 경우:

```cmd
set "PYTHONUTF8=1"
set "G3_MHZ=25" && vitis -s ps/scripts/build_g3_sweep.py
```

기대 ELF:

```text
build\vitis_g3_25\g3_sweep\build\g3_sweep.elf
```

---

### 6-2. g3-45

Vivado:

```cmd
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs all 45
```

Vitis 수동 빌드:

```cmd
set "G3_MHZ=45" && vitis -s ps/scripts/build_g3_sweep.py
```

기대 ELF:

```text
build\vitis_g3_45\g3_sweep\build\g3_sweep.elf
```

---

### 6-3. g3-75

Vivado:

```cmd
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs all 75
```

Vitis 수동 빌드:

```cmd
set "G3_MHZ=75" && vitis -s ps/scripts/build_g3_sweep.py
```

기대 ELF:

```text
build\vitis_g3_75\g3_sweep\build\g3_sweep.elf
```

---

### 6-4. `g3_gen_25`, `g3_gen_45`, `g3_gen_75` 폴더

g3 빌드 과정에서 다음과 같은 폴더가 추가로 생성될 수 있다.

```text
build\g3_gen_25
build\g3_gen_45
build\g3_gen_75
```

이들은 g3 빌드 과정에서 사용되는 생성/중간 산출물 디렉터리이며, 실제 보드 프로그래밍에 사용하는 최종 산출물은 다음 디렉터리의 `.bit`, `.xsa`, `.elf`이다.

```text
build\vivado_g3_<MHz>\
build\vitis_g3_<MHz>\
```

따라서 `g3_gen_*` 폴더가 생기는 것 자체는 이상 현상이 아니다.

## 7. 최종 산출물 확인

### 7-1. 파일 존재 여부 확인

CMD에서 다음 파일들이 모두 존재하는지 확인한다.

```cmd
dir build\vivado\g0_loopback.runs\impl_1\g0_wrapper.bit
dir build\vitis\g0_sweep\build\g0_sweep.elf

dir build\vivado_g2\g2_jedec.xsa
dir build\vitis_prep\flash_prep\build\flash_prep.elf

dir build\vivado_g3_25\g3_chip_25.runs\impl_1\g3_wrapper.bit
dir build\vitis_g3_25\g3_sweep\build\g3_sweep.elf

dir build\vivado_g3_45\g3_chip_45.runs\impl_1\g3_wrapper.bit
dir build\vitis_g3_45\g3_sweep\build\g3_sweep.elf

dir build\vivado_g3_75\g3_chip_75.runs\impl_1\g3_wrapper.bit
dir build\vitis_g3_75\g3_sweep\build\g3_sweep.elf
```

---

### 7-2. Timing Constraint 확인

다음 네 개의 timing report에서 timing constraint 만족 여부를 확인한다.

```cmd
findstr /C:"All user specified timing constraints are met" build\vivado\g0_loopback.runs\impl_1\g0_wrapper_timing_summary_routed.rpt
findstr /C:"All user specified timing constraints are met" build\vivado_g3_25\g3_chip_25.runs\impl_1\g3_wrapper_timing_summary_routed.rpt
findstr /C:"All user specified timing constraints are met" build\vivado_g3_45\g3_chip_45.runs\impl_1\g3_wrapper_timing_summary_routed.rpt
findstr /C:"All user specified timing constraints are met" build\vivado_g3_75\g3_chip_75.runs\impl_1\g3_wrapper_timing_summary_routed.rpt
```

각 명령에서 다음 문구가 출력되면 timing constraint를 만족한 것이다.

```text
All user specified timing constraints are met
```

## 8. 현재 Windows 권장 수동 빌드 루틴 요약

새 CMD를 열었을 때:

```cmd
cd C:\error_ATE\flash-margin-bench
E:\Xilinx\2025.2\Vitis\settings64.bat
chcp 65001
set "PYTHONUTF8=1"
```

이후 빌드는 다음 순서로 진행한다.

```cmd
:: g0
vivado -mode batch -source fpga/scripts/build_g0_loopback.tcl
vitis -s ps/scripts/build_g0_sweep.py

:: g2
vivado -mode batch -source fpga/scripts/build_g2_jedec.tcl

:: prep
vitis -s ps/scripts/build_flash_prep.py

:: g3-25
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs all 25
set "G3_MHZ=25" && vitis -s ps/scripts/build_g3_sweep.py

:: g3-45
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs all 45
set "G3_MHZ=45" && vitis -s ps/scripts/build_g3_sweep.py

:: g3-75
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs all 75
set "G3_MHZ=75" && vitis -s ps/scripts/build_g3_sweep.py
```

> Vivado에서 Vitis까지 자동으로 정상 연동된 경우에는 동일한 Vitis 빌드를 한 번 더 실행할 필요는 없다.  
> 따라서 각 단계 후 `.elf` 파일 존재 여부를 먼저 확인하고, 없을 때만 Vitis 수동 명령을 실행하는 방식이 가장 안전하다.

## 9. 문제 발생 시 우선 확인 체크리스트

1. 프로젝트가 OneDrive 밖에 있는가?
2. 현재 경로가 `C:\error_ATE\flash-margin-bench`인가?
3. 새 CMD를 연 뒤 `settings64.bat`을 실행했는가?
4. `where vivado`, `where vitis`, `where xsct`가 정상 경로를 가리키는가?
5. `chcp 65001`을 적용했는가?
6. `set "PYTHONUTF8=1"`을 적용했는가?
7. 이전 `build` 폴더를 다른 프로세스가 잡고 있지 않은가?
8. Vivado 빌드 후 `.bit`와 `.xsa`가 실제로 생성됐는가?
9. Vitis 빌드 후 `.elf`가 실제로 생성됐는가?
10. g3 빌드 시 `G3_MHZ` 값이 현재 빌드하려는 25/45/75 MHz와 일치하는가?
11. 최종 timing report에 `All user specified timing constraints are met`가 출력되는가?

이 체크리스트를 위에서부터 확인하면 Windows 환경에서 발생하는 대부분의 빌드 문제를 빠르게 분리할 수 있다.
