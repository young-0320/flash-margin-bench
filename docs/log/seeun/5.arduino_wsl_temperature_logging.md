# Arduino 온도 로그를 WSL Ubuntu에서 확인하는 방법

Arduino의 USB 시리얼을 Windows에서 WSL로 넘기고, Ubuntu에서 온도 로거를 실행하는 절차이다. Arduino IDE 시리얼 모니터를 실행하는 명령은 아니며, 같은 시리얼 데이터를 별도 프로그램으로 읽는 방식이다.

## 1. 어떤 터미널을 사용하는가

| 명령 | 실행할 터미널 | 사용하는 상황 |
| --- | --- | --- |
| `usbipd list` | Windows PowerShell | Arduino의 BUSID와 공유·연결 상태 확인 |
| `usbipd bind --busid 1-7 --force` | **관리자 Windows PowerShell** | Arduino를 WSL에 공유할 때. 이미 공유돼 있으면 생략 |
| `usbipd attach --wsl --busid 1-7` | Windows PowerShell | 공유된 Arduino를 WSL에 연결할 때 |
| `ls -l /dev/ttyACM*` | Ubuntu 터미널 | Linux 시리얼 포트 이름 확인 |
| `wsl -d Ubuntu-24.04 -u root -- chmod a+rw /dev/ttyACM0` | Windows PowerShell | Ubuntu 시리얼 포트에 읽기·쓰기 권한 부여 |
| `cd /mnt/c/Users/418cj/flash-margin-bench` | Ubuntu 터미널 | 프로젝트 폴더로 이동 |
| `uv run python hw/temp_logger.py ...` | Ubuntu 터미널 | 온도 로거 실행 |
| `usbipd detach --busid 1-7` | Windows PowerShell | Arduino를 Windows에서 다시 사용할 때 |

`PS C:\...>`가 보이면 PowerShell이고, `사용자@컴퓨터:경로$`가 보이면 보통 Ubuntu 셸이다. 같은 Windows Terminal 창 안에서도 탭마다 셸이 다를 수 있다.

**`1-7`, `Ubuntu-24.04`, `/dev/ttyACM0`, 프로젝트 경로는 PC와 연결 상태에 따라 바꿔야 하는 예시값이다.** 특히 Arduino와 FPGA 보드가 함께 연결돼 있다면, `usbipd list`에서 Arduino 행을 선택한다. 기존 보드 연결 기록의 BUSID를 그대로 사용하지 않는다.

## 2. 시작 전 준비

1. Arduino에 온도 제어 스케치를 업로드한다.
2. Windows Arduino IDE의 시리얼 모니터와 플로터를 닫는다.
3. Ubuntu-24.04가 WSL 2로 설치되어 있고, Windows에는 `usbipd`, Ubuntu에는 `uv`가 준비되어 있어야 한다.
4. 로거 실행 중에는 USB 분리, Arduino 재업로드, PC 절전·재부팅을 피한다.

Windows PowerShell에서 배포판을 확인하고 Ubuntu 터미널을 연다.

```powershell
wsl --list --verbose
wsl -d Ubuntu-24.04
```

두 번째 명령을 실행한 탭은 이제 Ubuntu 셸이다. 이후 Windows 명령은 **별도의 PowerShell 탭**에서 실행한다. Ubuntu 탭은 열린 상태로 둔다.

## 3. Windows에서 Arduino를 WSL로 연결

### 3.1 BUSID 확인 — Windows PowerShell

```powershell
usbipd list
```

Arduino에 해당하는 행의 BUSID를 확인한다. 아래에서는 `1-7`이라고 가정한다.

### 3.2 공유 설정 — 관리자 Windows PowerShell

처음 공유하거나 장치가 `Not shared`일 때 실행한다. 먼저 일반 공유를 시도한다.

```powershell
usbipd bind --busid 1-7
```

기존 실험에서 강제 공유가 필요했던 경우의 명령은 다음과 같다. `--force`는 강제 공유 옵션이며, 일반 공유가 되면 넣을 필요가 없다.

```powershell
usbipd bind --busid 1-7 --force
```

`bind`는 공유 설정이고 아직 Ubuntu에 연결한 상태는 아니다. 공유 설정은 재부팅 뒤에도 유지되므로, 이미 공유되어 있으면 보통 반복하지 않는다. 관리자 권한이 필요한 단계는 이 공유 설정이다. [usbipd 공식 연결 안내](https://github.com/dorssel/usbipd-win/wiki/WSL-support)

### 3.3 WSL에 연결 — Windows PowerShell

Ubuntu 탭이 열린 상태에서 PowerShell 탭으로 돌아와 실행한다.

```powershell
usbipd attach --wsl --busid 1-7
usbipd list
```

Arduino 행의 상태가 `Attached`이면 WSL에 연결된 것이다. 연결 중에는 Windows에서 해당 Arduino를 사용할 수 없으므로 IDE 업로드나 Windows 시리얼 모니터와 병행하지 않는다. [usbipd 공식 연결 안내](https://github.com/dorssel/usbipd-win/wiki/WSL-support)

## 4. Ubuntu 포트와 접근 권한 확인

### 4.1 포트 확인 — Ubuntu 터미널

```bash
ls -l /dev/ttyACM*
```

`/dev/ttyACM0`이 표시되면 이후 명령에서 그 이름을 사용한다. `/dev/ttyACM1` 등 다른 번호가 나오면 실제 번호로 바꾼다. Arduino의 USB 변환 칩에 따라 `ttyUSB`로 나타날 수도 있다.

```bash
ls -l /dev/ttyUSB*
```

### 4.2 읽기·쓰기 권한 부여 — Windows PowerShell

```powershell
wsl -d Ubuntu-24.04 -u root -- chmod a+rw /dev/ttyACM0
```

이것은 **PowerShell에서 Ubuntu의 명령을 대신 실행하는 형태**이다.

- `-d Ubuntu-24.04`: 명령을 실행할 WSL 배포판
- `-u root`: Ubuntu 관리자 계정으로 실행
- `-- chmod a+rw ...`: 해당 장치 파일에 모든 사용자의 읽기·쓰기 권한 부여

이 명령은 포트를 만들거나 USB를 연결하지 않는다. 반드시 attach 및 포트 생성 후에 실행한다. USB 재연결로 장치 파일이 다시 만들어지면 권한 설정을 다시 해야 할 수 있다.

이미 Ubuntu 터미널에 있다면 다음 명령으로 같은 권한을 줄 수 있다. **둘 중 하나만 실행하면 된다.**

```bash
sudo chmod a+rw /dev/ttyACM0
```

## 5. 온도 로거 실행 — Ubuntu 터미널

### 5.1 프로젝트 폴더 이동

사용자가 제시한 실험 PC 경로:

```bash
cd /mnt/c/Users/418cj/flash-margin-bench
```

Windows의 `C:\Users\418cj\flash-margin-bench`가 WSL에서 위와 같이 보인다. 현재 이 문서를 작성한 작업 폴더 `C:\error_ATE\flash-margin-bench`를 사용할 경우에는 다음 경로이다.

```bash
cd /mnt/c/error_ATE/flash-margin-bench
```

두 경로를 연달아 실행하는 것이 아니라, **로거 파일이 있는 실제 프로젝트 경로 하나를 선택**한다.

```bash
ls hw/temp_logger.py
```

파일이 존재해야 다음 명령을 실행할 수 있다. 문서 작성 시 현재 작업 폴더에는 이 파일이 없었다. 실험 PC의 로거가 있는 복사본을 사용하거나, 실제 저장 위치를 확인해야 한다.

### 5.2 실행

```bash
uv run python hw/temp_logger.py \
  /dev/ttyACM0 \
  --label chip16_65C
```

한 줄로 입력해도 같다.

```bash
uv run python hw/temp_logger.py /dev/ttyACM0 --label chip16_65C
```

- `uv run python`: 프로젝트 Python 환경으로 프로그램 실행
- `hw/temp_logger.py`: 사용할 로거 프로그램
- `/dev/ttyACM0`: 읽을 Arduino 시리얼 포트
- `--label chip16_65C`: 사용자가 제시한 기록 식별용 라벨

여러 줄 명령의 `\`는 **Ubuntu 셸의 줄 이어쓰기**이다. PowerShell에 그대로 붙여 넣지 않는다. `\` 뒤에는 공백을 넣지 않는다.

`--label chip16_65C`는 온도를 65°C로 설정하는 명령이 아니다. 제어기의 목표 설정 명령은 `T65`이다. 다만 로거가 키보드 입력을 Arduino로 전달하는지는 로거 구현을 확인해야 하므로, 로거 실행 창에 `T65`를 입력하면 전달된다고 가정하지 않는다. 같은 포트를 다른 시리얼 프로그램과 동시에 열지 않는다.

현재 작업 폴더에서 로거 소스를 확인하지 못했으므로, 기본 통신 속도·저장 폴더·명령 전달 기능은 이 문서에서 확정하지 않는다. 실행 전에 아래 도움말과 실험 PC의 소스를 확인한다. 제어 스케치의 시리얼 속도는 **115200 baud**이다.

```bash
uv run python hw/temp_logger.py --help
```

## 6. 정상 동작 확인과 종료

로거가 원래 CSV 행을 출력한다면 다음과 같은 데이터를 확인할 수 있다. 아래 숫자는 설명용 예시이며 실제 측정값이 아니다.

```text
ms,target_c,temp_c,pwm,duty_pct,state,fault
12000,65.00,62.500,180,70.6,RUN,NONE
```

`target_c`는 설정 온도, `temp_c`는 센서 측정 온도, `pwm`은 출력값, `state`는 운전 상태, `fault`는 오류이다. `OFF`이면 자동으로 가열을 시작하지 않으며, `FAULT`이면 정상 제어 기록과 구분해야 한다. 로그 저장 여부와 저장 경로는 프로그램 안내 및 실제 생성 파일로 확인한다.

**로거 종료와 히터 정지는 별개다.** `Ctrl+C`로 Python을 끝내거나 WSL을 분리해도 Arduino의 제어가 정지한다고 가정하지 않는다. 실험 종료 시 확인된 방법으로 `OFF`를 보내거나 히터용 전원 출력을 먼저 끄고, Ubuntu의 로거 창에서 `Ctrl+C`로 기록을 종료한다.

Windows Arduino IDE에서 다시 업로드·확인하려면 PowerShell에서 실행한다.

```powershell
usbipd detach --busid 1-7
usbipd list
```

이후 Windows IDE에서 현재 COM 포트를 다시 선택한다. USB를 뽑거나 WSL을 재시작해도 연결은 해제되므로, 다음 실험 때 다시 attach해야 한다. [usbipd 공식 연결 안내](https://github.com/dorssel/usbipd-win/wiki/WSL-support)

## 7. 자주 발생하는 문제

| 증상 | 확인할 내용 |
| --- | --- |
| PowerShell에서 `usbipd`를 찾을 수 없음 | Windows에 usbipd-win이 설치되어 있는지 확인 |
| `bind`에서 권한 오류 | 관리자 PowerShell로 실행 |
| WSL 배포판이 없다고 나옴 | `wsl --list --verbose`로 배포판 이름과 현재 Windows 계정 확인. 폴더 이동만으로 Windows 계정이 바뀌지는 않음 |
| `/dev/ttyACM0`이 없음 | attach 상태, 실제 ACM 번호, `ttyUSB` 여부 확인 |
| `Permission denied` | 실제 포트에 chmod 실행. 재연결 후 권한 재확인 |
| `Device or resource busy` | 해당 포트를 연 다른 로거·시리얼 프로그램 종료 |
| `can't open file ...temp_logger.py` | 프로젝트 경로와 로거 파일 존재 여부 확인 |
| `uv`를 찾을 수 없음 | Ubuntu에 uv가 설치되어 있고 PATH에 있는지 확인. Windows 설치와 별개 |
| 로그가 깨져 보임 | 로거 통신 속도가 스케치의 115200과 일치하는지 확인 |
| 다시 연결한 뒤 실행 안 됨 | BUSID 확인 → attach → 포트 확인 → 권한 확인 순서 반복 |
