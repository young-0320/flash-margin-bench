# 7. flash 블록 RTL 구현 (G0 루프백 프런트엔드 — 프레이밍 재정렬 포함)

- **작성일**: 2026-07-07
- **발단**: core 가 끝나고 flash 차례인데, 착수해 보니 G0 최대 기술 난제가 물리가 아니라
  **장부** 에 있었다 — TX 와 RX 가 주파수는 같고 위상만 다르니 RX 샘플열의 "몇 번째

- **목적**: 배선이 멀쩡한데 BER 0.5 가 나오는 경로를 어떻게 막나?
- **관련**: `fpga/rtl/flash/flash_rx.v` · `docs/interface/contract.md` §2·1-1·R8·R10·R11 ·
  `docs/concepts/7.framing_alignment.md` · [로그 6](6.core_rtl_implementation.md)
- **참고**: `fpga/rtl/flash/` 는 README 상 팀원 A 소유다. 중간보고서 총력전의 배정 유동

  소유자 복귀 시 이 로그가 인수인계 문서다

## 결정

- [D7-1] 버스트마다 **±1 오프셋 3중 병렬 비교** 로 정렬을 푼다 — 페이로드 시작 후보
  `{t0+3, t0+4, t0+5}` 를 동시에 비교하고 `e_i = min(e0,e1,e2)` — §2 ·
  `fpga/rtl/flash/flash_rx.v`
- [D7-2] 푼 것의 범위를 못박는다 — **계측 아티팩트만 소거** 한다. 전이 경계의 진짜 캡처
  실패는 옳은 정렬 비교기가 그대로 센다 — §3
- [D7-3] CDC 는 제어 1비트 2개(`run`→, `rx_done`←)만 동기화한다. 멀티비트 결과는 준정적
  크로싱으로 두고, RX 는 리셋 없이 `run_s=0` 으로 초기화한다 — §4 ·
  `fpga/rtl/flash/flash_sync2.v`
- [D7-4] 버스트 파형은 갭 32 + 프리앰블 4 + PRBS B — 갭·프리앰블은 계약 미규정의 구현
  상수다 — §5
- [D7-5] PRBS 방출 컨벤션을 명문화한다 — `dout=lfsr[14]`, 시드 MSB-first —
  §6 · `fpga/rtl/flash/flash_prbs15.v`
- [D7-6] busy 는 수락된 start 의 다음 사이클에 올린다 —
  [로그 6](6.core_rtl_implementation.md) [D6-7] 이행 — §7 · `fpga/rtl/flash/flash_ctrl.v`

## 근거

### 1. 난제의 본질 — 측정기가 자기 장부를 한 칸 밀려 쓰는 사고

TX(`clk_core`)와 RX(`clk_sample`)는 주파수가 같고 위상만 다르다. 그래서 RX 샘플열은 내용은
같은데 "몇 번째 비트인가"의 정렬이 위상에 따라 통째로 밀린다.

PRBS 는 이웃 비트가 확률 1/2 로 다르므로(계약 결정 19), 한 칸 밀린 비교는 정확히 BER 0.5
다 — **배선이 멀쩡해도 오답** 이다. 위상 스윕은 15.87ps 씩 밀다 비트 경계를 넘는 순간 올바른
정렬이 한 칸 바뀌므로, 고정 정렬이면 스윕 절반이 곡선이 아니라 BER 0.5 벽지가 된다
(분석기 체크 5 가 잡는 "물리적으로 불가능한 절벽").

곡선 전체를 못 쓰게 만드는데 원인이 물리가 아니라 장부 실수다. 그래서 G0 최대 기술
난제로 다뤘다.

### 2. 해법 — 버스트별 3-오프셋 병렬 비교

`clk_core`/`clk_sample` 은 같은 VCO 라 주파수가 동일하고(드리프트 0) 위상만 다르다. 이
성질이 해법을 싸게 만든다 — 정렬 후보가 유한하고 고정된다.

버스트 파형 `[0×32][1×4][PRBS×B]` 에서 RX 가 0-run(≥8) 자격을 얻은 뒤 첫 1 샘플을 `t0` 으로
잡고, 페이로드 시작 후보 셋을 PRBS 1개 + 지연 플롭 2개로 동시에 비교한다. 프리앰블 에지
샘플이 전이 경계에서 0/1 어느 쪽으로 읽혀도 옳은 정렬이 항상 후보 안에 있다 — 고정 정렬의
"스윕 절반 BER 0.5 절벽"이 구조적으로 불가능해진다.

정직한 한계가 하나 있다. 포화 영역(진짜 BER→0.5)에서 min-of-3 는 0.5 를 약간 밑돌 수 있다
(B=2048 에서 ≈0.49). 다만 통계가 쓰는 벽 적합 영역(BER≤0.25)에서는 옳은 정렬(B·BER)과 틀린
정렬(≈B/2)이 명확히 분리되어 정확하다.

### 3. 무엇을 푼 것이고 무엇을 안 푼 것인가

정렬 착오가 비트 에러로 둔갑하는 **경로를 차단** 한 것이지 에러 자체를 없앤 것이 아니다.
전이 경계의 진짜 캡처 실패는 옳은 정렬 비교기가 그대로 센다 — 그게 재려는 욕조 벽이다.

이 구분을 못박아 두지 않으면 나중에 "재정렬이 벽을 지웠나"라는 의심이 들어온다. 곡선에
남는 것이 전부 물리가 되도록 **계측 아티팩트만** 소거한 것이다.

### 4. CDC — 동기화할 것과 안 할 것

제어 1비트 2개만 각 2FF 로 동기화했다(계약 1-1). 멀티비트 결과는 동기화하지 않는다 —
`rx_done` 을 올리기 전에 값이 멈추고 R3 가 done 이후에만 읽기를 보장하므로 준정적
크로싱이다. `e_i` 버퍼는 듀얼 클럭 BRAM 이라 포트가 도메인별로 분리돼 있다.

RX 는 리셋을 아예 받지 않는다 — `run_s=0` 이면 전부 초기화되므로 리셋 CDC 자체가
없어진다. 동기화할 신호를 줄이는 것이 CDC 를 검증 가능하게 만드는 제일 싼 방법이다.

### 5. 버스트 오버헤드는 실칩과 같은 규모로 둔다

갭 32 + 프리앰블 4 = 36사이클이다. 실칩 `0x0B` 오버헤드 40비트와 같은 규모이고 R10 의
`(B+64)×2` 여유 안이다. 계약이 규정하지 않은 구현 상수라, 실칩 SPI 프레이밍(CS·더미
사이클)으로 교체될 때 RX 검출부만 갈아끼우면 되는 구조다.

### 6. golden model 이 재현할 정의를 글로 남긴다

`dout=lfsr[14]`, 시드 MSB-first 다. 시드 규칙(계약 결정 19)만으로는 방출 순서가 결정되지
않는데, 이것이 어긋나면 golden model 과 RTL 이 전 비트에서 불일치한다. 헤더에 정의를
적어 `sim/golden/` 이 그대로 읽게 했다.

### 7. 요건을 받은 쪽에서 닫는다

[로그 6](6.core_rtl_implementation.md) §7 이 "busy 상승이 늦으면 두 번째 START 가 들어올
창이 생긴다"를 flash 구현 요건으로 남겼다. `flash_ctrl` 이 수락된 start 의 다음 사이클에
busy 를 올리는 것으로 그 창을 닫았다.
