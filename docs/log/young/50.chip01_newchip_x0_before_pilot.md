## 근거

### 1. 왜 빠졌나 — 주석의 전제가 한 칩에서만 거짓이었다

`run_wear.py` 의 `CHECKPOINTS` 주석은 "0 은 마모 전 신품 측정으로 이미 있다" 고 했다. 서베이가 전수
측정을 마쳤으니 참이었지만, chip01 만은 예외였다 — 9/20 에 받은 지민 PC 의 25MHz 4런이 전부 무효라
집계표 §1 의 width 칸이 비어 있었고 W10-A 가 "우리 리그 재측정" 으로 열려 있었다. 파일럿 실행기를
만들 때(로그 48) 이 칸을 다시 보지 않았고, 계획 화면도 장부(`chip_pe.md`)만 대조하지 집계표는 보지
않는다. 그대로 `accept` 를 쳤으면 곡선이 100 사이클부터 시작하고 0 점은 영영 없었다 — 첫
체크포인트가 이미 P/E 100 뒤이므로 나중에 채울 수 없다.

확인을 실행기에 넣지 않고 사람에게 둔 이유는 §5 미결에 있다 — 집계표 CSV 는 사람이 채우는 표라
기계 판정의 입력으로 삼기엔 아직 서식이 흔들린다.

### 2. x=0 후보 넷 — 우리 리그 newchip 만 남았다

- **7월 값 39,737.3 ± 0.61 (5회)** — 2024.2 · N=100 · 2.5개월 전 · 다른 장착. 현행 축과 조건이
  다르고, 로그 28 `[U28-1]` 이 "재측정 전엔 현행 축에 올리지 않는다" 고 이미 막았다. 탈락
- **지민 PC 25MHz 4런 참고값 39,703.4** — 계약 §6 상 무효 런이다. 집계표가 "채택하지 않는다" 고
  적어 두었다. 탈락
- **`--mode sweep` (prep 없이 읽기만)** — P/E 를 안 쓰는 장점이 있지만, chip01 의 PRBS 는 9/16
  prep 의 7일 된 데이터다. 다른 8칩은 전부 prep 직후 분 단위로 쟀다. 조건이 어긋나고 절약되는
  P/E 는 300k 앞에서 1 이다. 탈락
- **채택: `--mode newchip --mhz 25`.** 측정 범위가 같다는 점이 결정적이다 — 스윕은 모드와 무관하게
  페이지 0~111(섹터 0~6)을 재므로 신품 스윕이 그대로 마모 그룹의 0 점이다. prep 은 0~127 을 쓰지만
  tally(512·1,536)는 건드리지 않아 `accept --cycle 0` 의 `E_DIRTY` 자물쇠도 그대로 열린다

사용자가 newchip 을 두 번 돌렸다(15:32 · 15:36). 계획한 것은 아니지만 두 번째가 같은 장착 상태의
재현 증인이 되어, 앵커 없이 잰 1회 측정이라는 단서를 대신 메웠다 — 집계표 §1 에 그렇게 적었다.
값과 재현 폭은 집계표에만 둔다.

### 3. chip01 은 무난한 개체다 — 그래서 파일럿에 맞는다

파일럿의 목적은 마모로 곡선이 얼마나 움직이는지를 처음 보는 것이다. 개체 특성이 강한 칩(chip10 의
두꺼운 벽, chip03 의 느린 소거)은 그 변화가 특성에 가려질 수 있다. chip01 은 width 가 9칩 중앙값에
가장 가깝고 소거는 빠른 무리에 들며 벽은 얇은 쪽이라, 움직이면 움직인 대로 보일 칩이다. 이 판단을
집계표 §1 과 등록부 비고에 적었다(사용자 요청, 2026-09-23). 등록부의 chip02 「파일럿 칩」 표기는
9/23 결정(드리프트 앵커 · 마모 금지)과 어긋나 함께 걷었다.

### 4. 파일럿 1구간과 첫 체크포인트 — 닫힌 것과 덜 닫힌 것

세션 `1790091548`. 1구간 0→100 은 9/9 PASS 였고 probe 도 정답을 냈다. 체크포인트 100 에서
`build/vitis_prep_0_7` 의 prep ELF 가 `#PREP RANGE sectors=0-6` · 7섹터 소거 · 112페이지로 돌았고,
스윕 → 분석 → 엔진 재프로그래밍 → UID 대조 → 2구간 START 까지 사람 손 없이 이어졌다(enter 한 번).
그래서 `[U45-3]`(범위 prep ELF 실칩 확인)과 `[U48-3]`(측정 경로 실칩 확인)이 닫힌다. 체크포인트
1점의 실측 비용은 `CP_COST_S` 가정보다 짧았다 — 수치는 세션의 `checkpoints.csv` 가 들고 있다.

`[U28-1]` 은 절반이다. 재측정은 됐고, chip01 자신이 7월 대비 움직인 폭이 7월 chip01 과 9/15 chip02
사이의 106ps 대부분을 설명하므로 그 106 은 개체보다 세대·리그·장착 몫이 크다. 그러나 chip01 의
재장착 σ 는 오늘도 재지 않았다(두 런 다 장착 그대로) — 그 절반은 그대로 열어 둔다.

`[U49-1]` 은 부분이다. 마모·prep·스윕 세 ELF 모두 `UART_BAUD=921600` 이 걸린 채 `print -set` 줄을
에러 없이 지나 부팅했으니 심볼 덮어쓰기 자체는 세 ELF 에서 먹는다. 다만 값이 기본값과 같아 "다른
값으로 바뀌었다" 는 증거는 아니다 — 115200 쪽은 지민 PC 의 첫 accept 가 닫는다.

## 미결

- **[U50-1] 신품 스윕 선행을 실행기가 검사할 것인가** — `accept` 가 집계표 CSV 에서 그 UID 의
  width 행을 찾아 없으면 START 전에 멈추게 할 수 있다. 집계표 CSV 는 사람이 채우는 표라 서식이
  흔들리고, 파일럿은 이미 시작됐다. 종단 3칩 전에 정하면 된다 — 문서 확인(D50-1)으로 갈음 중
- **[U50-2] 파일럿 x=0 의 재현 폭을 어디에 적을 것인가** — 집계표는 "칩당 1회" 전제라 2차 런을
  표 밖 서사로만 두었다. 체크포인트 곡선을 그릴 때 0 점의 오차 막대로 2차 런 차이를 쓸지, 재장착
  σ(13.86ps)를 쓸지 정해야 한다
