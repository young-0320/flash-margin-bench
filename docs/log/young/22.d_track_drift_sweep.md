## 2. 수치

### chip01 (실칩)

| θ | 7/8 기준 (n=5, 재장착 없음) | 8/23 (n=1, 재장착 있음) | 차이 |
| - | --------------------------- | ----------------------- | ---- |

| 1e-3 | 39,724.2 ± 0.79 ps | 39,729.82 ps | +5.62 ps |
| 1e-4 | 39,710.6 ± 0.95 ps | 39,717.99 ps | +7.39 ps |

- 사전 등록 판정 기준은 `±3σ(≈2ps)` 이내다. **+4.35ps = +7.1σ**, 7월 5회 전 범위 밖
  (max 대비 +3.65ps)
- 체크리스트: 2(floor 상한 3.25e-09)·4(F=0.48)·5 PASS / 1 SKIP(구조적, 로그 15와 동일)

**θ-수렴폭이 좁아졌다** — 7/8 26.7ps → 8/23 23.66ps (−11%). 폭이 넓어진 방향과 꼬리가
좁아진 방향이 같이 나타난다. probit 적합점 부족으로 σ_j 직접 추출은 SKIP이나,
θ-수렴 직독(로그 15)으로는 **지터가 줄어든 쪽**이다.

## 3. 판정을 내리지 않는다 — 자(尺)가 없다

D5의 판정식은 `8/23 값`을 `39,737.3 ± 0.61ps`와 대조하는 것이다. 그런데 **그 ±0.61ps는
"재장착 없음" 연속 5회의 편차**이고, chip01은 별도 보관돼 있다가 8/23에 **다시 꽂힌**
것이다. 재장착 성분이 들어간 값을 재장착 없는 자로 재고 있다.

D5 자신이 이걸 알고 있었다 — *"재장착 편차인지, 장비 드리프트인지 먼저 분리한다."*
분리 수단이 재장착 σ인데, **그 값은 아직 아무도 재지 않았다.**

```
M 착수      ←  D 판정 필요
D 판정      ←  재장착 σ 필요
재장착 σ    ←  S-2 §8, 즉 M 트랙 안에 있다
```

**순환이다.** 로그 21 §4에서 "칩당 1회"의 근거가 순환이었다고 잡은 것과 같은 구조가
D 판정 자체에 있었다. 그때 세운 태도를 여기에도 적용한다 — 데이터를 본 뒤에 자를 고르지
않는다. **재장착 σ를 먼저 재고, 그 자로 판정한다.**

4.35ps를 "작으니 통과"로 처리하면 S-2 §6의 사전 등록 규칙 전체가 무의미해진다. 사전
등록의 요지는 유혹이 생기는 자리에서 규칙이 먼저 서 있는 것이다.

## 4. 두 경로가 반대로 움직였다 — 공통 드리프트로 읽기 어렵다

| | 폭 | 지터 |
| --- | --- | --- |
| loopback | −385 ps (축소) | **증가** (+15%) |
| chip01 | +4.35 ps (확대) | **감소** (θ-수렴폭 −11%) |

장비(보드·MMCM·클럭)가 공통으로 틀어졌다면 두 경로가 **같은 방향**으로 움직여야 한다.
반대로 움직였으므로, 각 경로의 **물리적 접촉 상태**가 지배적이라고 보는 쪽이 자연스럽다.
§0에서 확인한 "그날 배선을 다시 했다"와도 맞는다 — chip01 소켓은 다시 꽂으면서 접촉이
좋아지고, 루프백 점퍼는 느슨하게 꽂혔다면 나빠진다.

**단, 이것은 잠정 설명이며 확인되지 않았다.** 확인 방법은 하나다 — 점퍼를 제대로 꽂고
루프백을 다시 재서 34,693 근처로 돌아오는지 본다(6분). 돌아오면 8/23 루프백은 접촉 불량
런으로 확정되고, 안 돌아오면 설명이 틀린 것이므로 장비 쪽을 봐야 한다.

**확인 전에는 `_invalid` 접미를 붙이지 않는다.** 무효화는 데이터를 집계에서 빼는 행위라
가설이 아니라 근거로 해야 한다.

### 계약 §6의 공백 — 접촉 불량은 무효 런 정의에 없다

계약 §6의 무효 런 6조건은 `TIMEOUT` · `CFG_ERR` · `MMCM_LOCKED=0` · R8 불일치 · 미완주 ·
`CMD_ERR`이다. **8/23 루프백은 여섯 개를 전부 통과한 형식적으로 유효한 런**이면서 물리적
으로는 신뢰할 수 없다. 접촉 불량은 아무 에러도 내지 않고 곡선만 좁게 만든다.

로그 21 §2가 "칩 1개 = 1세션"에서 지적한 것과 같은 부류다 — **절차가 정상 완주하면서
데이터만 망가지는 경로.** S-2 §6.2는 칩 측정에 대해 "재현 안 되면 `_invalid` + 사유"로
이 층을 두었으나, 계약 §6에는 대응물이 없다.

## 5. D 트랙은 3단계 중 1단계만 끝났다

수정안 #2 §7이 정한 D 트랙 절차:

| 단계 | 내용 | 상태 |
| ---- | ---- | ---- |
| 1 | N=100 스윕 1회 — 7월과 동일 조건, 드리프트 판정 | **측정 완료 (8/23). 판정 보류 (§3)** |
| 2 | N=112 스윕 1회 — 전환 기준점 + §6.1 편향 검사 | **미실행** |
| 3 | `flash_prep` UID 확보 → 등록부 기입 | **실행 불가** — B-1b(`4Bh`) 미구현 |

2단계가 없으면 이후 M 트랙 10개(N=112)를 7월 기준선(N=100)과 비교할 환산 근거가 없다.
3단계는 장세은의 B-1b에 걸려 있어 우리가 못 연다 — `sweep_uart_capture.py`에도 UID
처리가 없어 CSV 헤더에 `#UID`가 없다(8/23분 확인).
