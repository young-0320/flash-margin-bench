## 0. 문서 원칙 신설 — 스펙은 수치, 로그는 근거

이 세션에서 정한 작성 규칙이다.

- **사양서**: 결정된 수치와 절차만. 왜 그 값인지는 쓰지 않는다
- **로그**: 그 수치를 채택한 근거를 상세히

이유는 독자가 다르기 때문이다. 사양서를 받는 사람(구현자)은 "무엇을 만들어야 하는가"만
필요하고, 근거 서술이 섞이면 지시와 설명의 경계가 흐려진다. 반대로 반년 뒤 "왜 112였지"를
묻는 사람에게는 근거가 전부다. 두 목적을 한 문서에 담으면 양쪽 다 나빠진다.

초판 S-1은 근거가 본문에 섞여 있었고, 이 원칙에 따라 건조판으로 다시 썼다.

## 1. 계약 수정안 #1 — BASE_SECTOR

### 1.1 문제 — 읽기 창이 페이지 0에 고정돼 있다

`flash_spi_ctrl.v:120`이 읽기 순번 `idx`를 그대로 페이지 주소로 발행한다
(`sh <= {8'h0B, 4'd0, idx, 8'h00}`). 그래서 마모군과 대조군이 읽기 횟수를 나눠 가져야 한다.

| 구성 | 읽기 | 기대 에러 (θ=10⁻⁴) | 사전 등록 규칙(≥20) |
| ---- | ---- | ------------------- | ------------------- |
| 온전한 100회 | 100 | 20.5 | 통과 |
| 마모군 몫 | 64 | 13.1 | **미달** |
| 대조군 몫 | 36 | 7.4 | **미달** |

N을 200으로 올려도 **마모군은 64회 그대로**다. 마모 섹터 수가 안 늘었으므로 늘어나는 것은
대조군뿐이다. 이 방향으로는 안 풀린다.

### 1.2 세션 중 발견 — 12비트는 우리가 스스로 좁힌 것

RTL을 직접 열어보니 `idx` 레지스터 하나가 **세 역할을 겸직**하고 있었다.

| 역할 | 위치 | 현재 |
| ---- | ---- | ---- |
| 읽기 순번 (로그 주소) | `flash_rx.v:116` | 12비트 |
| 페이지 주소 | `flash_spi_ctrl.v:120` | 12비트 → 페이지 0~4,095 |
| PRBS 시드 인덱스 | `flash_rx.v:65` | 12비트를 14비트에 0-패딩 |

BASE_SECTOR가 하는 일은 이 겸직을 둘로 가르는 것이다 — 로그 주소는 순번 그대로,
주소와 시드는 `base×16 + 순번`. 로그 16이 경고한 "주소와 시드 두 곳을 함께 고쳐야 한다"의
원인이 이 겸직이었다.

그리고 주소 프레임 `{8'h0B, 4'd0, idx[11:0], 8'h00}`에서 **상위 4비트가 0으로 낭비**되고
있었다. 24비트 주소 필드는 페이지 번호 16비트를 그대로 받는다. 12비트는 하드웨어 제약이
아니라 우리가 스스로 좁혀놓은 값이었다.

### 1.3 도달 범위 — 절반이 아니라 전역 (세션 중 정정)

처음에는 PRBS 시드가 14비트(계약 결정 19: `{1, index[13:0]}`)이므로 페이지 16,384 =
**섹터 1,023, 칩의 절반이 천장**이라고 판단했다. **이는 틀렸다.**

시드가 14비트면 패턴이 16,384페이지마다 반복될 뿐이고, **한 번의 스윕은 연속된 페이지
N개(≤2,048)만 읽으므로** 16,384 떨어진 두 페이지가 같은 스윕에 들어올 수 없다. 반복은
무해하다. 게다가 `ps/src/flash_prep.c:45`가 이미 `lfsr = 0x4000 | (page & 0x3FFF)`로
마스킹해 짜여 있다 — **PS 쪽은 처음부터 반복을 전제한 코드**였다.

따라서 **섹터 0~2,047, 칩 전역 8MB**가 도달 범위다. 시프트 레지스터 폭도 안 늘려도 된다 —
명령 8 + 페이지 16 + 채움 8 = 32비트로 현행 `sh[31:0]`에 정확히 들어맞는다.

한 번 여는 절차 비용(3인 합의)이 코드 수정보다 훨씬 크므로, 열 때 끝까지 여는 것이 맞다.
좁게 열면 나중에 합의를 두 번 하게 된다.

### 1.4 범위 검사를 R11에 추가 — 침묵 실패 차단

`BASE_SECTOR × 16 + N − 1 ≤ 32,767`을 R11 설정 검증에 넣는다.

없으면 주소가 칩 끝을 넘어 랩어라운드해 **전혀 다른 섹터를 조용히 읽는다.** 스윕은 정상
완주하고 `valid=1`이 뜨는데 마모 신호만 안 보이는 유형이다. 계약 결정 3-2("랩어라운드는
곡선 어깨를 조용히 오염")가 주소 경로에도 적용되는 사례.

**패턴 반복이 만드는 좁은 구멍 하나**: 주소가 **정확히 1,024섹터의 배수만큼** 어긋나는
버그는 패턴이 맞아떨어져 조용히 통과한다. 그 외 모든 어긋남은 전 위상 BER≈0.5로 시끄럽게
실패한다. 이 구멍은 범위 검사와 인수 기준 A2(먼 구역 실측)로 좁힌다.

### 1.5 검증 수단 — "오라클이 없다"는 과장이었다

처음에 "G1 미착수라 검증 수단이 없으니 RTL 착수를 미뤄야 한다"고 했는데 과장이었다.
시뮬레이션 환경 없이도 실측으로 판정 가능한 기준이 셋 있다.

1. **되돌림**: `BASE_SECTOR=0`에서 기존 chip01 기준값(39,737.3ps) 재현
2. **이동**: 다른 구역에서 정상 욕조 곡선. **시드가 안 따라오면 전 위상 BER≈0.5로 시끄럽게
   실패**하므로 놓칠 수 없다
3. **거부**: 범위 초과 값에서 CFG_ERR

### 1.6 담당과 시점 — 부재 중 작업으로

`flash_spi_ctrl.v`는 원래 한영웅이 지원으로 작성한 파일이다(로그 11). 여기서 또 고치고 또
판정하면 roles.md v2의 유일한 절대선("자기가 만든 것의 합격 판정을 자기가 내리지 않는다")이
깨진다. **박지민이 구현하고 한영웅이 판정**하면 분리가 성립한다.

동시에 이것이 부재 5일의 작업거리가 된다. 사양과 인수 기준을 문서로 못 박아 두는 것이
"남이 착수할 수 있게 만드는" 이번 국면의 목표와 정확히 맞는다.

## 2. 계약 수정안 #2 — N 100 → 112

### 2.1 근본 원인 — 읽기 단위와 지우기 단위가 다르다

| 동작 | 단위 | 방향 |
| ---- | ---- | ---- |
| 읽기 | 페이지 (원하는 만큼) | — |
| 쓰기(프로그램) | 페이지 | 1 → 0 **한 방향만** |
| 지우기 | **섹터 = 16페이지 통째로** | 0 → 1 |

되돌리려면(0→1) 지우기밖에 없고 지우기는 섹터 단위이므로, **마모 영역 크기는 항상 16의
배수**다. 100페이지짜리 마모 영역은 물리적으로 만들 수 없다.

```
마모 영역:  [섹터 0~6] = 112페이지
읽기 N=100:  0 ──────────── 99  │ 100 ─── 111  ← 12페이지 미측정
읽기 N=112:  0 ────────────────────────── 111  ← 빈틈 0
```

6섹터(96페이지)로 줄이면 읽기 96~111회가 마모 안 된 섹터를 읽어 **마모군에 신품이 섞인다.**
오염과 미측정 중에는 미측정이 낫지만, N=112면 둘 다 없앨 수 있다.

### 2.2 세 가지가 동시에 해결된다

**① 미측정 구간 소거** — 그룹의 10.7%가 측정 대상에 들어온다. 노화 곡선 목적에서는 무해
했으나, **가장 약한 셀을 찾는 목적에서는 안 본 12페이지가 구멍**이다. 진단 장비를 표방하는
이상 구조적으로 못 보는 영역은 서사의 약점이다.

**② 섹터 경계 정렬** — 100은 6.25섹터라 어중간하다. 112 = 7×16이라 창의 시작과 끝이 모두
섹터 경계에 떨어진다. BASE_SECTOR를 페이지가 아닌 섹터 단위로 정의한 것(오설정 자체를
표현 불가능하게)과 같은 논리다.

**③ 칩 최종 페이지 도달** — N=112에서 `BASE_SECTOR = 2,041`의 마지막 읽기가 페이지
`2,041×16 + 111 = 32,767`, **칩의 마지막 페이지에 정확히 떨어진다.**

### 2.3 사전 등록 조건은 오히려 개선된다

| θ | N=100 | N=112 |
| - | ----- | ----- |
| 10⁻² | 2,048 | 2,294 |
| 10⁻³ | 205 | 229 |
| 10⁻⁴ | **20.5** | **22.9** |

112 > 100이므로 사전 등록 조건(기대 에러 ≥ 20)을 자동으로 만족한다. **상향은 통계적으로
항상 안전한 방향**이며 이 변경으로 약해지는 검정은 없다.

### 2.4 기존 N=100 데이터 — 보존한다

7월 데이터를 삭제하거나 무효 처리하지 않는다. **조건이 달라진 것이지 데이터가 틀린 것이
아니다.**

혼동 위험은 구조적으로 없다 — 계약 §6 스키마에 이미 `n_reads` 열이 전 행 반복으로 들어
있어 **모든 파일이 자기 측정 조건을 스스로 들고 있다.** 파일명이나 기억에 의존하지 않는다.

### 2.5 100 vs 112 비교 — 할 수 있는 것과 없는 것

**할 수 있는 것 — 폭 추정의 계통 편향 검사.** 폭은 물리적으로 N에 무관해야 하지만,
"BER이 θ를 가로지르는 지점"으로 *추정*되는 값이라 알고리즘이 표본 크기에 편향돼 있으면
값이 움직인다. 차이가 σ(0.61ps) 안이면 두 계열 직접 비교 가능, 벗어나면
`bathtub_analysis.py`의 결함 발견이며 **그 자체가 성과**다.

**할 수 없는 것 — 노이즈의 정체 규명.** 이론상 σ ∝ 1/√N이므로 N=112에서 0.58ps가
예측되지만, **이 대비로는 검정력이 없다.**

| | 예측 효과 | n=5에서 σ의 불확실도 |
| --- | --- | --- |
| 112 vs 100 | 5.5% | **±35%** |

재려는 효과보다 자의 눈금이 6배 굵다. 이 질문(반복성 0.61ps가 통계적 잡음인가 계통 요인의
바닥인가)은 MSA의 핵심이므로 **대비를 벌려 별도 실험으로 한다** — 112 vs 448(4배)이면
예측 σ 비가 2.0배라 n=5로도 갈린다. 소요 약 1.7시간, 복귀 후 또는 M 트랙에 얹는다.

**§6.1의 결과를 §6.2의 결론처럼 쓰지 않는다.**

### 2.6 전환 절차 — 다리를 놓고 바꾼다

조건 변경 자체가 위험한 것이 아니라 **근거 없이 바꾸는 것**이 위험하다.

```
D 트랙 (chip01, 재장착 없이 연속)
  1. N=100 스윕 1회   → 7월과 동일 조건. 드리프트 판정
  2. N=112 스윕 1회   → 전환 기준점 + 편향 검사
  3. flash_prep 출력에서 UID 확보 → 등록부 기입
```

순서를 지킨다. N=112를 먼저 재면 차이가 드리프트인지 조건 변경인지 분리되지 않는다.
추가 비용은 스윕 1회(약 5분).

## 3. S-1 수치별 채택 근거

### 3.1 마모 그룹 7섹터 — 유도값

읽기 창 112페이지 ÷ 섹터 16페이지 = **7**. 근접·원격 대조군도 같은 이유로 7섹터다
(측정하려면 읽기 창이 그 안에 들어가야 한다).

- 6섹터(96페이지): 읽기가 마모 안 된 섹터를 침범 → 오염
- 8섹터(128페이지): 16페이지가 마모됐는데 미측정 → N=100 문제의 재발

### 3.2 원격 대조군 섹터 2,041 — 주소 공간의 끝

워크플로 5는 249~255로 적고 있었다. 그 값은 읽기 주소가 12비트라고 보던 시점의 "최대한
멀리"다. 수정안 #1로 제약이 풀렸으므로 원래 의도(논리적으로 최대 거리)대로 옮긴다.
N=112에서 2,041이 유효 최댓값이며 마지막 읽기가 칩 최종 페이지에 정확히 떨어진다.

### 3.3 대조군도 체크포인트마다 PRBS 재기록 — 읽기 교란 대칭성

당초 "대조군은 최초 1회만 기록"이었다. 비휘발이므로 기술적으로는 성립한다. **그러나 그러면
대조군에만 읽기 교란이 누적된다.**

| | 체크포인트 사이 읽기 | 소거로 리셋 | 11점 후 누적 |
| --- | --- | --- | --- |
| 마모 그룹 | 페이지당 약 2.5만 회 | **O** | 리셋됨 |
| 대조군 (재기록 안 함) | 페이지당 약 2.5만 회 | **X** | 약 8.3만 회 |

(스윕 1회 = 2,520위상 × 112읽기 = 282,240읽기 → 112페이지에 분산)

**대조군은 "변하지 않는 기준"이어야 하는데 혼자 다른 스트레스를 받는 셈**이고, 대조군 폭이
좁아졌을 때 인접 간섭인지 읽기 교란인지 분리할 수 없게 된다.

데이터시트에 읽기 교란 규정이 없어 크기를 알 수 없다. NOR이 NAND보다 강건한 것으로
알려져 있으나 정량 근거가 없다. **크기를 모르는 오염과 크기를 아는 미미한 오염 중에서는
후자를 택한다** — 대조군도 재기록하고, 그 누적 사이클(체크포인트 수)을 로그에 정직하게
기록한다. "마모 0"이 아니라 "마모 N"이다.

### 3.4 체크포인트의 소거+프로그램도 1사이클로 계수

측정하려고 그룹을 지우고 PRBS를 심는 것 자체가 물리적으로는 P/E 사이클이다. 안 세면
실제 마모 > 기록이 되고 이 오차는 조용하다. 11점이면 300k 대비 0.004%.

### 3.5 중단 임계 — 파일럿 없이 계산으로 확정

초판은 "blank check 실패가 측정 범위의 **절반** 초과 시 정지"였다. **절반은 근거 없는
값이었다.** 계산하면 정확히 유도된다.

결함 비트는 위상과 무관하게 항상 틀리므로 **BER 바닥(플로어)** 을 만든다. 플로어가 θ보다
높으면 욕조 바닥이 θ 아래로 안 내려가 **교차점이 없고 폭 측정이 불가능**하다.

- 스윕 1회 총 비트 = 112 × 2,048 = 229,376
- 결함 비트 D개 → 기대 패턴(PRBS)과 어긋날 확률 0.5 → 플로어 = 0.5D / 229,376

| θ | 조건 | 결함 비트 한계 |
| - | ---- | -------------- |
| 10⁻⁴ | 0.5D/229,376 < 10⁻⁴ | **46** |
| 10⁻³ | | **459** |
| 10⁻² | | **4,588** |

이는 단일 중단 임계가 아니라 **θ 단계별 유효 수명**이다. 결함 비트가 늘면 10⁻⁴ → 10⁻³ →
10⁻² 순으로 하나씩 죽고, 10⁻²마저 죽는 4,588에서 정지한다. 무결성 로그가 이미 결함 비트를
세고 있으므로 자동 판정된다.

### 3.6 조밀화 트리거 = 1회 검출, 영구/일시 판정은 하지 않음

초판은 "같은 주소·같은 비트 **연속 2회** = 영구 열화"였다. **2에 근거가 없었다.**

처음 댄 근거("소거를 거쳐도 남으면 물리적 손상")를 다시 보니 **1회로도 성립한다** — 소거
직후 검사에서 0이 남았다면 그 비트는 이미 소거를 이긴 것이다. 2회를 요구하는 진짜 이유는
물리 판정이 아니라 **측정 오류 배제**(SPI 글리치, 읽기 오류)였고, 2가 충분한지는 우리
읽기 경로의 오류율을 모르므로 답할 수 없다.

**원래 하나로 묶여 있던 것이 필요 시점이 다른 두 판단이었다.**

| 판단 | 시점 | 처리 |
| ---- | ---- | ---- |
| 검사 주기를 조밀하게 바꿀까 | **실시간** (놓치면 기회 상실) | **1회 검출로 트리거** |
| 이 결함이 영구인가 일시인가 | **사후** (실시간에 바뀌는 게 없음) | 로그로 판정 |

- 조밀화는 위양성 비용이 낮다(주기 100→10, 비용 0.43%→4.3%). **놓치는 게 훨씬 비싸므로
  1회로 트리거한다**
- 영구/일시는 실시간 판정이 실험 진행을 바꾸지 않으므로 사후에 봐도 된다

**사후 판정이 사전 등록 원칙을 어기지 않으려면**, 회수 임계를 결론의 근거로 쓰지 않아야
한다. 우리 목적은 개별 비트의 영구성 판정이 아니라 **결함 비트 수의 곡선**이고, 곡선에는
임계가 필요 없다. 보고 시에는 재현 횟수 분포를 그대로 싣고 영구/일시 이분법을 쓰지 않는다.

**전제**: 사후 판정이 가능하려면 로그에 **결함 비트 주소**가 남아야 한다. 초판 스키마는
개수만 세서 재현성을 셀 수 없었다. `defect_addrs` 추가.

### 3.7 워치독 2초 — 잠정, 방향이 중요

워치독은 "정해진 시간 안에 응답이 없으면 강제 중단"하는 타이머다. 칩이 고장나거나 배선이
빠지면 BUSY가 영원히 안 내려가고, 33시간 실험이 그 자리에서 멈춘 채 아무도 모른다.

초판의 5배(2초)도, 그 뒤 제안한 2배(800ms)도 근거가 없었다. 후자는 "계약 R10이 2배를
쓰니 일관성"이라 했지만 R10의 2배는 완전히 다른 맥락(PL 스윕의 사이클 수 계산)이다.

**다시 보니 방향이 반대였다.** 소거 시간이 400ms를 넘는 건 이미 경고로 기록된다. 워치독은
"영원히 안 끝남"만 잡으면 된다. 그런데 **소거 시간 증가는 우리가 재려는 신호 그 자체**
(마모 지표 ①)이므로, 워치독을 조이면 **느려진 칩을 고장난 칩으로 오판해 실험을 죽인다.**
800ms는 위험한 방향이었다.

- **경고는 엄격하게**: 400ms(데이터시트 max) 초과 → 기록하고 계속
- **워치독은 관대하게**: 2초. 발동해도 데이터를 잃지 않는 구조로 보완 — 정지 + 대기시간
  기록 + 자동 재시도 금지. 마모 횟수는 tally에 남아 있고 재개 절차가 있다
- 확정값은 **M 트랙 신품 소거 시간 분포 실측 후**

### 3.8 반복 측정 횟수 — 반쯤만 근거 있음

- **근거 있는 부분**: n=3은 산포를 볼 수 있는 최소값. n=1은 산포 없음, n=2는 두 점의
  차이뿐이라 추정이 거의 무의미
- **근거 없는 부분**: 왜 최소값을 택하나 → **시간뿐이다.** 스윕 5.6분 × 반복 × 영역 수 ×
  체크포인트 수로 곱해진다
- **진짜 기준은 못 쓴다**: "체크포인트 간 폭 변화 ≥ 3 × 표준오차(σ/√n)"가 옳은 기준인데
  변화량을 모른다 → 파일럿 질문 ④

n=3 → 표준오차 0.35ps, n=5 → 0.27ps. 파일럿에서 변화량이 노이즈의 3배 미만이면 5회로 상향.
3배는 3σ 유의성 관례.

**파일럿 반복 1회의 예외**: 처음·중간·끝 3개 지점만 3회로 올린다. 목적은 온도 전이 확인
(§3.11). 추가 비용 6스윕 × 5.6분 = 34분(전체의 1.5%).

### 3.9 적응적 조밀화 — 고정 격자를 버린 이유

초판은 11점, 이후 14점을 제안했으나 **둘 다 근거가 없었다.** √10 간격 사이를 채워 만든
값일 뿐이다. 진짜 결정 변수는 점의 개수가 아니라 **간격 비율**이며, 간격 비율이 곧 onset
해상도다(3.16배 간격이면 "10k와 30k 사이"까지만 좁혀진다).

**비용을 계산하니 파일럿과 본 실험이 5배 차이 났다.**

| | 재는 영역 | 반복 | 1점 비용 |
| --- | --- | --- | --- |
| 파일럿 | 3 (마모1 + 근접 + 원격) | 1회 | **17분** |
| 본 실험 | 5 (마모3 + 근접 + 원격) | 3회 | **84분** |

본 실험 기준 26점이면 측정만 36.4h로 사이클링 40.5h에 육박한다. 소켓이 하나라 전부 직렬
이고 3칩이면 231h(9.6일)다. **"비용이 결정을 안 묶는다"는 파일럿에서만 참이었다.**

그런데 이 비대칭이 오히려 **파일럿을 촘촘하게 할 근거**가 된다 — 파일럿에 5시간 더 투자해
"여기만 촘촘하면 된다"를 알아내면 본 실험 점 수를 절반으로 줄여 3칩 × 10h = 30시간을
아낀다. 5시간 써서 30시간을 아끼는 거래이며, 이것이 파일럿을 두는 이유 그 자체다.

**그리고 고정 격자보다 나은 방식이 있다** — 사전에 밀도를 못 박는 대신 데이터가 밀도를
정하게 한다. 무결성 검사에서 이미 채택한 패턴(100 → 이상 시 10)과 같은 발상이라 문서
내부 일관성도 있다.

```
기본 간격 × 2.15                      (조용할 때)
조밀 간격 × 1.47                      (직전 폭 변화 > 1.83ps = 3σ)
```

- 조용한 구간은 빠르게 지나가고, **변화가 시작된 그 지점부터 촘촘해진다.** 파일럿이 답해야
  할 질문이 "언제부터 움직이는가"이므로 필요한 곳에 해상도가 간다
- 총 점 수는 데이터가 정한다

**한계 둘**:

1. **조밀화는 앞으로만 된다.** 변화가 이미 지나간 구간에서 시작됐으면 그 구간은 성긴 채로
   남는다. 그래서 기본 격자가 너무 성기면 안 되고 2.15배가 균형점이다. 최악의 경우에도
   "이 2.15배 구간 안에서 시작됐다"까지는 확정된다
2. **실시간 폭 계산이 필요하다.** `bathtub_analysis.py` 호출이 자동화돼야 무인 조밀화가
   된다. 자동화는 한영웅 작업이며, 그 전에는 사람이 하루 두세 번 확인해 조정한다

### 3.10 tally

**목적**: 33시간 무인 실행 중 정전·USB 분리가 나면 사이클 카운트가 휘발성 메모리와 함께
사라진다. 마모는 물리적으로 진행됐는데 횟수를 모르는 칩이 되고, 비가역이라 다시 만들 수
없으므로 교정 곡선에 쓸 수 없다.

**방식**: 프로그램이 1→0 방향으로만 간다는 성질을 이용해 지우지 않고 표시만 추가한다.
초기 소거 1회 후 100사이클마다 다음 바이트에 `0x00`. 4,096바이트 → 409,600 사이클 커버.

**초판의 자기모순**: §2.2에서 "완충 폭으로 간섭을 제어한다는 발상 자체가 검증 불가능"이라
써놓고, tally에는 "100섹터 이상 떼어놓아 안전하다"는 완충 논리를 썼다. 같은 문서에서
정반대 논리를 쓴 것이다.

**정정 — 거리로 안전을 주장하지 않는다.**

- **tally는 오염되면 스스로 드러난다** — 판독 규칙이 `0x00`=센다/`0xFF`=안 씀/**그 외**=
  불확실이므로, 간섭으로 비트가 흔들리면 검출된다. 조용히 틀리지 않는다
- **주 방어는 호스트 UART 로그**다. tally는 USB가 빠지는 경우를 막는 부 방어
- 따라서 **위치는 결과에 영향을 주지 않는다.** 512·1,536은 임의이며 임의여도 무방하다

**진짜 위험은 이웃 섹터가 아니라 우리 코드였다.**

| 위험 | 크기 |
| ---- | ---- |
| 이웃 섹터 마모로 인한 간섭 | 불명, 통제 불가, 검출 가능 |
| **`flash_prep`이 tally를 지움** | **카운트 전량 소실** |
| **전수 스캔이 tally에 패턴을 심으며 지움** | **카운트 전량 소실** |

스캔은 읽으려면 패턴을 심어야 하고 심으려면 지워야 하므로, tally가 어디 있든 발생한다.
**위치보다 강력한 방어는 코드의 하드 가드**다.

**이중화**: 서로 떨어진 두 섹터에 같은 카운트를 기록한다. 비용은 0.002% → 0.004%로 여전히
0에 가깝고, 단일 실패점이 사라진다.

**"tally 섹터는 마모 테스트가 안 되지 않나"** — 두 가지로 답한다.

1. **임시 점유다.** 실험 종료 시 최종 카운트를 등록부에 확정 기입하고 tally를 해제하면 그
   섹터도 정상 섹터로 돌아온다. 사각지대가 영구적이지 않다
2. **부수 효과로 가장 순수한 대조군이 된다.** tally 섹터는 소거 1회 + 바이트당 프로그램
   1회만 받으므로 실험 후에도 사실상 신품이다. 원격 대조군조차 재기록 때문에 체크포인트
   수만큼 마모되는데 tally는 그것도 안 받는다. 종료 후 지우고 PRBS를 심어 재면
   **"300k를 돈 칩 안의 진짜 신품 섹터"** 값이 나온다

**데이터시트 확인 결과 — 회색지대 하나**: 부분 페이지 프로그램에 대해 데이터시트는
*"**In some cases**, less than 256 bytes (a partial page) can be programmed without having
any effect on other bytes within the same page"* 라고 쓴다. **보증이 아니라 유보**이며,
페이지당 부분 프로그램 횟수 제한(NOP)에 대한 규정은 데이터시트 어디에도 없다. 우리 tally는
한 페이지에 바이트를 하나씩 256번 쓴다 — 금지된 것도 보증된 것도 아니다(NOR 기반 로그
저장의 표준적 관행이긴 하다).

→ **파일럿에서 tally 자체를 검증한다.** 종료 시 tally 섹터를 전량 읽어 `0x00`/`0xFF` 외의
값이 있는지 확인하고, 있으면 마크 간격이나 페이지당 기록 바이트 수를 조정한다.

### 3.11 온도 로깅 — B·C에만

히터는 없지만 Zynq XADC로 다이 온도를 읽을 수 있다. 33시간 실험의 낮/밤 온도차가 마진과
소거 시간에 영향을 줄 수 있고, 기록이 없으면 나중에 "마모인가 온도인가"를 분리할 방법이
없다.

온도는 초 단위로 변하지 않으므로 100사이클(40.5초)마다 한 번이면 충분하다. 매 사이클
기록은 같은 값을 반복 저장할 뿐이다.

**한계**: XADC가 재는 것은 **FPGA 다이 온도지 플래시 칩 온도가 아니다.** 실온 변화는 둘 다에
공통이라 잡히지만 플래시 자기 발열은 안 잡힌다. 그걸 재려면 장세은의 DUT 보드 온도 센서가
필요하며 아직 없다.

**체크포인트 중 냉각 전이**: 체크포인트 1점이 파일럿 17분/본 실험 84분인데 그 동안
사이클링이 멈춰 칩이 식는다. 즉 **반복 3회가 냉각 전이 중에 일어나고**, 그 산포에 온도
드리프트가 섞인다. 크기는 모른다.

→ 파일럿에서 직접 확인한다. **반복 3회의 순서와 폭 값에 체계적 경향**이 있는지 보면 된다
(1회차가 항상 크거나 작으면 냉각 전이의 증거). 그래서 파일럿의 3개 지점만 3회 반복한다.

### 3.12 인수 기준 100사이클 시험 — 유도값

무결성 검사와 tally 기록 주기가 모두 100이므로, **각각 최소 1회 발생하는 최소값**이 100이다.
이보다 작으면 무결성 로그가 0행, tally가 0바이트가 되어 경로 간 교차검증(A5)이 성립하지
않는다.

**A5가 인수 기준의 핵심이다.** 카운트를 세는 경로가 넷(카운터 / 사이클 로그 행수÷7 /
무결성 로그의 cycle / tally×100)인데 서로 독립이므로, 하나가 틀리면 불일치로 드러난다.
이 교차검증이 성립하지 않으면 33시간 무인 실행을 신뢰할 근거가 없다.

## 4. 몬테카를로 N=112 재실행 — 통과, 그리고 예상 못 한 발견

실행: 2026-08-23, `monte_carlo_sweep_params.py --dphi 15.87 --n-list 112 --sigmas 11,20
--trials 4000 --seed 42`. σ_j=11ps는 로그 15에서 실측으로 세운 **상한**이다.

### 4.1 사전 등록 규칙 — 통과

| θ | σ_width @ N=112 | @ N=100 | 규칙 한계 (Δφ/2) |
| - | --------------- | ------- | ---------------- |
| 10⁻² | **0.16 ps** | 0.17 ps | 7.9 ps |
| 10⁻³ | **0.34 ps** | 0.35 ps | 7.9 ps |
| 10⁻⁴ | **1.35 ps** | 1.38 ps | 7.9 ps |

세 θ 모두 한계의 1/6 이하다. **다만 이 규칙은 N 선택을 전혀 구속하지 않는다** — N=64,
σ_j=100ps라는 최악 조합에서도 1.13ps로 통과한다. N의 실질 하한을 정하는 것은
**θ=10⁻⁴의 유효 조건**(N × B × θ ≥ 20 → N ≥ 100)이며, 스크립트 docstring이 이미
그렇게 적고 있었다. 규칙은 통과 확인용이지 선택 근거가 아니었다.

### 4.2 1/√N 법칙은 시뮬레이션에서 정확히 성립한다

| N | σ_width (σ_j=11, θ=10⁻²) | 1/√N 예측 |
| - | ------------------------ | --------- |
| 100 | 0.17 ps | (기준) |
| 112 | 0.16 ps | 0.161 |
| 224 | 0.12 ps | 0.114 |
| 448 | 0.08 ps | 0.080 |

시뮬레이션의 폭 편차는 순수 이항 통계에서 나오므로 예측과 정확히 일치한다.

### 4.3 발견 — 실측 반복성이 통계 예측의 약 3.6배다

여기서 예상 못 한 것이 나왔다.

| | 값 |
| --- | --- |
| 시뮬레이션 예측 (N=100, θ=10⁻², σ_j=11ps) | **0.17 ps** |
| **실측 반복성** (G4, n=5, 재장착 없음) | **0.61 ps** |
| 비 | **약 3.6배** |

시뮬레이션은 이항 통계만 담고 있으므로, 실측이 3.6배 크다는 것은 **반복성의 대부분이 통계
잡음이 아니라 계통 요인**이라는 뜻이다. 게다가 σ_j=11ps는 상한이므로 실제 σ_j가 더 작으면
예측값은 더 내려가고 격차는 더 벌어진다.

**함의 셋**

1. **N을 늘려도 반복성은 거의 안 좋아진다.** 통계 성분이 0.17→0.08(N=448)로 줄어도
   전체는 계통 성분(약 0.59ps)이 지배한다. 개선하려면 온도·지터·위상 스텝 균일성 쪽을
   봐야 한다
2. **수정안 #2 §6.2 실험(112 vs 448)에 예측이 생겼다.** 순수 통계라면 σ가 2배 줄어야
   하고, 계통 지배라면 거의 안 준다. **후자를 예측한다.** 예측을 먼저 문서에 박고 재는
   것이므로 사전 등록으로서 성립한다
3. **N=112 선택의 정당화는 반복성이 아니다.** 반복성은 어차피 계통이 결정한다. 112를
   택한 이유는 §2의 세 가지(미측정 구간 소거·섹터 정렬·칩 끝 도달)이며, 통계적 손해가
   없다는 것만 확인하면 충분하다

**과잉 해석 경계** — 이는 시뮬레이션과 실측의 비교이며 모델 가정(가우시안 지터 비탈,
비트 독립, σ_j=11ps)에 의존한다. 실측 0.61ps 자체도 n=5라 ±35% 불확실도를 갖는다.
**"계통 요인이 지배함을 시사한다"까지가 지금 말할 수 있는 것이고, 확정은 §6.2 실험의
몫이다.**

## 5. 근거를 못 댄 것 — 파일럿 유보로 이관

| 항목 | 왜 지금 못 정하나 |
| ---- | ----------------- |
| **본 실험 그룹 수 (3)** | 로그 16의 예시를 옮긴 값. 개수는 시간 예산에서 나오지만, 곡선을 규정하는 데 몇 개가 필요한지는 곡선 형태를 봐야 안다 |
| **마모량 배분 (10k/50k/300k)** | 폭이 언제부터 움직이는지 모르는 상태에서의 배분은 찍는 것이다 |
| 본 실험 체크포인트 배치 | 파일럿 질문 ① |
| 본 실험 반복 횟수 (3/5) | 파일럿 질문 ④ |

**3그룹 설계가 실제로 주는 것**을 정리해 두면 — 그룹 3(300k)은 한 섹터의 **종단 곡선**을,
그룹 1·2는 다른 섹터의 **마모량별 스냅샷**을 준다. 그룹 3의 10k 시점과 그룹 1의 10k 종점을
비교하면 **섹터 간 산포**가 나온다. 그런데 n=3으로는 산포를 제대로 못 잰다(반복 3회와 같은
한계).

여기에 진짜 트레이드오프가 있다 — 시간이 유한하므로 **곡선의 점을 늘릴지, 각 점의 산포를
볼지** 택해야 한다. 4그룹을 전부 50k로 돌리면 산포를 n=4로 재지만 곡선은 안 나온다.
파일럿 질문 ⑤(마모 효과 대비 섹터 간 산포의 크기)가 이 선택의 근거를 준다.
