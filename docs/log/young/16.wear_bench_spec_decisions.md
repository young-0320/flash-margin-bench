## 2. 역할 재정의 (roles.md v2)

한영웅의 정의를 "설계+PE 겸업"에서 **총괄 + PE**로 바꿨다. 문서 성격도 개별 작업 목록에서
**역할 정의 + 사례** 구조로 전환.

판단 근거: PE의 직무는 평가 계획 수립·테스트 리밋과 가드밴드 결정·MSA·게이트 판정이며,
정체성은 "장비를 만드는 사람"이 아니라 **"장비로 판정 기준을 세우고 데이터로 결론을 내는
사람"** 이다. v1의 "하지 않는 것" 목록에 이미 *flash 내부 설계·검증 환경 구축·회귀 PASS
자가 승인*이 들어 있었으므로, 7/6에 스스로 그은 선과 거의 같았고 빠진 것은 코어 RTL뿐이었다.

**협업 원칙 신설** — 폴더=소유자는 책임 소재이지 출입 금지가 아니며, 주 역할은 명확히 인지하되
팀원의 일을 돕는 것을 목표로 한다. 경계를 넘은 작업은 감점이 아니라 실행력이다(로그 11의
flash SPI RTL이 그 덕에 G3를 일정 안에 냈다). 유일한 절대선은 **"자기가 만든 것의 합격 판정을
자기가 내리지 않는다"** 이며, 이는 금지가 아니라 절차로 지킨다 — ⑴ 로그에 개입 명시
⑵ 채점자 지정 ⑶ 판정 권한 이양. 선례는 로그 11(채점자 사전 지정)과 로그 1 미결 F(자기
이해충돌 자진 기록).

RTL 겸업에 대한 입장 정리: 이력서에 두 역량을 나열하는 것이 아니라 **인과로 엮으면 PE 서사의
근거가 된다.** 런북 3 표 E(고장 서명 판독표 — 전 위상 BER 0.5 = PAY_LEAD 어긋남 등)는 계측
엔진 내부를 아는 사람만 쓸 수 있는 산출물이고, "측정 이상이 DUT 쪽인지 장비 쪽인지"를 가르는
능력이 거기서 나온다.

## 3. 데이터시트 확인 (W25Q64JV) — 사양 판단의 근거

추정으로 쓰던 값을 전부 원전으로 확정했다.

| 항목 | 값 | 출처 |
| ---- | ---- | ---- |
| 페이지 | 256 B, 32,768개 | "32,768 programmable pages of 256-bytes each" |
| **섹터** | **4 KB = 16페이지**, 2,048개 | "erased in groups of 16 (4KB sector erase)" |
| 블록 | 64 KB = 256페이지, 128개 | 동상 |
| **인듀런스** | **Min. 100K P/E cycles per sector** | 특징 절 — **섹터당**이며 **하한 보장** |
| tSE (4KB 소거) | **typ 45 ms / max 400 ms** | AC 특성표 |
| tPP (페이지 쓰기) | typ 0.8 ms / max 3 ms | 동상 |
| tBE2 (64KB 소거) | typ 150 ms | 동상 |
| **실패 플래그** | **없음** | SR1=`(R)/TB/BP3~BP0/WEL/BUSY`, SR2=`SUS/CMP/LB3~LB1/(R)/QE/SRL` |
| **Unique ID** | **4Bh, 개체별 64비트** | "factory-set read-only 64-bit number unique to each device" |

세 가지가 사양을 바꿨다.

- **tPP 정정**: 0.4 ms로 잡았던 추정이 실제 typ 0.8 ms → 사이클 시간 예산 재계산
- **실패는 침묵한다**: BUSY는 "끝났다"만 알려주고 "성공했다"는 알려주지 않는다. 소거 실패
  검출 수단은 **readback(blank check)뿐**
- **개체 ID가 하드웨어에 있다**: JEDEC ID(9Fh, `EF 40 17`)는 모델 식별자라 10개가 전부 동일해
  개체 식별이 불가능하지만, 4Bh는 개체마다 다르다

## 4. S-1 사양 결정과 근거

### 4.1 마모 범위 — 읽기 범위와 정합이 강제

스윕은 `flash_spi_ctrl.v:120`이 `addr = idx × 256`을 발행하므로 **읽기 i → 페이지 i**이고,
N=100이면 실제로 읽히는 것은 페이지 0\~99뿐이다. 반면 `flash_prep.c`는 2,048페이지(512KB,
섹터 0\~127)를 쓴다 — **쓰는 범위가 읽는 범위의 18배.**

따라서 임의 섹터를 마모시키면 스윕이 그 셀을 한 번도 읽지 않는다. 이 실패는 **침묵한다** —
스윕이 정상 완주하고 `valid=1`이 뜨는데 마모 신호만 안 보인다. 워크플로 5 함정 절에 명문화.

### 4.2 칩 내부 대조군 — 채택

**결정 근거**: 별도 칩 대조군은 "다른 칩, 다른 시각"이라 개체 산포와 측정 시각 차이가 섞인다.
같은 칩 안에서 일부 섹터만 마모시키면 온도·전원·소켓 접촉·측정 시각·개체가 전부 공통이 되어
차이가 마모 하나로 좁혀진다. 마모(소거)가 섹터 안에 갇히므로 물리적으로 성립한다.

### 4.3 BASE_PAGE 레지스터 — 상정 (계약 변경 필요)

내부 대조군을 "읽기 100회를 두 그룹이 나눠 갖는" 방식으로 구현하면 통계가 깨진다:

| 그룹 | 읽기 | θ=10⁻² | θ=10⁻³ | θ=10⁻⁴ |
| ---- | ---- | ------- | ------- | ------- |
| 마모(섹터 0\~3) | 64 | 1,310 | 131 | **13.1 ✗** |
| 대조(나머지) | 36 | 737 | 73.7 | **7.4 ✗** |

(값 = 기대 에러 수 `읽기 × 2048 × θ`, 유효 조건 ≥ 20 — N=100의 사전 등록 근거와 동일 규칙)

N을 200으로 올려도 **마모군은 64회 그대로**다(마모 섹터가 안 늘었으므로). 늘어나는 건 대조군뿐
이라 문제가 안 풀린다 — 세션 중 200 권고를 냈다가 철회한 사유가 이것.

**BASE_PAGE(읽기 시작 페이지) 레지스터를 추가하면 문제 자체가 사라진다.** 각 그룹을 독립 스윕
으로 재면 되므로 나눠 갖기가 없어지고, 양쪽 다 N=100 full strength로 θ 3점이 전부 유효하다.

여기서 더 큰 것이 열린다 — 칩 하나에 마모량이 다른 섹터 그룹을 여러 개 두고 각각 측정하면
**교정 곡선 전체를 단일 개체에서** 얻는다. 교정 곡선의 최대 오염원이 개체 산포인데 그 변수가
통째로 사라져, 곡선의 형태(같은 칩 내)와 개체 산포(칩 간)를 분리해서 보고할 수 있다.
서로 다른 3개 칩에서 같은 구조를 반복하면 개체차 도출까지 가능하다.

- 예시 배치 — 그룹당 7섹터: 섹터 0\~6(무마모 기준점) / 16\~22(10k) / 32\~38(50k) / 48\~54(300k)
- 한계: 그룹마다 다이 상 물리 위치가 달라 위치 의존성이 섞일 수 있다. 무마모 그룹을 여러
  위치에 두면 그 효과 자체를 측정 가능
- 비용: **계약 v1 변경**(레지스터 추가) — 3인 합의 사안, 박지민 작업

### 4.4 N = 100 유지

- BASE_PAGE 채택 시 그룹 분할이 없어지므로 100으로 충분(마모 그룹 7섹터=112페이지 중 앞 100을 읽음)
- **7월 데이터와 동일 조건 유지** — 드리프트 확인(D 트랙)의 기준값 39,737.3±0.61ps가 N=100
  이므로, N을 바꾸면 차이가 드리프트인지 조건 변경인지 분리되지 않는다
- 그룹당 7섹터인 이유: θ=10⁻⁴ 유효에 읽기 98회 필요 → 7섹터 = 112페이지 ≥ 100

### 4.5 마모 패턴 — 0x00, 측정 직전만 PRBS15

**마모에 최적인 패턴과 측정에 최적인 패턴이 정반대**라서 분리한다.

- 마모용 **0x00**: 프로그램은 1→0 방향으로만 가므로 all-0이 모든 비트를 끌어내려 최대 스트레스.
  PRBS는 절반만 움직여 스트레스가 절반
- 측정용 **PRBS15** (두 이유):
  ① `flash_prbs15.v`가 시드 {1, page}로 기대 패턴을 생성해 비교하므로 0x00으로는 비교 불성립
  ② 더 근본적으로 **0x00은 비트 천이가 없다.** 타이밍 마진은 0↔1 천이가 만드는 지연 퍼짐(ISI)과
     지터를 보는 것이라, 평평한 신호로 재면 **윈도우가 인위적으로 넓게 나온다.** 우리 데이터의
     천장 BER 0.2462(패턴 의존성 증거)도 all-0에서는 관측되지 않는다

비용은 체크포인트당 프로그램 1회분(90ms)뿐. 다만 본 실험의 1사이클은 데이터시트가 가정하는
조건보다 가혹하므로, **"1사이클 = all-0 program + sector erase"를 사양서에 정의로 명문화**한다.

### 4.6 무결성 검사 주기 — 100사이클

blank check 1회 ≈ 176ms(112페이지 readback × 소거 후·프로그램 후 2종, PS SPI 2.6MHz 기준).
300k 사이클 실험 대비 비용:

| 간격 | 총 비용 | 실험 대비 | onset 해상도 |
| ---- | ------- | --------- | ------------ |
| 1,000 | 53초 | 0.04% | ±1,000 |
| **100** | **8.8분** | **0.4%** | **±100** |
| 10 | 88분 | 4.3% | ±10 |
| 매 사이클 | 14.7시간 | **44%** | 완전 |

100까지는 사실상 공짜다(매 사이클만 피하면 된다). 간격을 정하는 것은 비용이 아니라 onset
해상도이며, 0.4% 비용으로 0.03% 해상도를 얻으므로 아낄 이유가 없다. **기본 100, 이상 검출 후
10으로 조밀화.** 최초 제시한 1,000은 근거 없는 값이었다.

### 4.7 실패·중단 기준

**소거 실패는 칩이 알려주지 않는다**(3절). 검출은 blank check readback뿐이며, 이는 단순
실패 검출을 넘어 **"소거 잔여 0비트 수" 곡선**이라는 노화 지표가 된다 — 마모는 갑자기 실패하는
것이 아니라 0으로 남는 비트가 하나둘 늘어나는 형태로 진행한다.

- **시간 기준은 데이터시트 max 400ms 채택.** 최초 제시한 "신품 대비 3배"는 근거 없는 임의값
  이었다. 400ms는 제조사가 보장한 상한이라 스펙 이탈의 객관적 정의가 된다
- **"잔여 비트 최초 1개 발생"은 트리거로 부적절.** 소프트 에러(알파선 등)나 출고 시점의 기존
  결함일 수 있다. 대신 **재현성으로 가른다** — 같은 주소·같은 비트가 연속 2회 이상 검출되면
  영구(열화), 1회만이면 일시(별도 기록). 반복성으로 신호와 노이즈를 가르는 프로젝트 원칙의 연장
- **잔여 비트 임계에 산업 표준은 없다.** NOR은 ECC 없이 XIP에 쓰이므로 산업적으로 zero-tolerance
  이고(NAND는 반대로 ECC 정정 가능 비트 수 기준이 존재), 참조할 값이 없다. 우리 목적은 판정이
  아니라 곡선이므로 임계로 중단하기보다 **잔여 비트 수를 계속 기록**한다. 중단은 실험이
  무의미해지는 지점(blank check 실패 페이지가 측정 범위의 절반 초과 → 기대 패턴이 무너져 폭
  측정 불가)에서만 걸고, **정확한 값은 파일럿 칩의 실측 곡선을 보고 정한다**
- 참고: 1페이지 = 256바이트 = **2,048비트**

### 4.8 chip_id — 하드웨어 Unique ID 사용

`4Bh`로 읽는 개체별 64비트 UID를 모든 로그의 `chip_id`로 쓴다. 사람이 부르는 이름(chip01 등)은
매핑 테이블로 따로 유지.

근거: 칩 10개를 소켓에 갈아 끼우며 마모 이력을 추적하는 실험에서 **라벨 오독은 데이터 전체를
조용히 오염**시키며 되돌릴 방법이 없다. UID를 CSV 헤더에 박아두면 라벨과 데이터가 어긋나도
진실이 파일 안에 남는다. 구현은 `flash_jedec.c`에 4Bh 추가(장세은, 경미).

### 4.8b UID 구현 경로와 소급 적용

**구현 2단계**

- 단기(RTL 변경 0): `flash_prep.c`에 `4Bh` 추가 → `#PREP UID <16hex>` 출력. `flash_prep`은
  모든 스윕 직전에 반드시 실행되므로(사전 쓰기 없이 스윕 금지) 세션마다 자동으로 찍힌다.
  `sweep_uart_capture.py`가 그 값을 세션에 보관했다가 스윕 CSV 헤더 `#UID <16hex>`로 기입
- 정석(계약 변경): PL이 4Bh를 발행해 레지스터로 노출 → `g3_sweep`이 직접 헤더에 기록.
  `flash_spi_ctrl`이 0x0B 전용 고정 시퀀서라 별도 one-shot FSM이 필요하므로 BASE_SECTOR와 묶음

단기안의 한계: 스윕 중에는 PS가 칩과 통신할 수 없어(스윕은 PL 경로, prep은 PS SPI 경로)
UID와 스윕의 연결이 **같은 세션**이라는 절차적 근거에 의존한다.

**소급 적용**: 7월 데이터는 UID를 읽기 전 측정분이다. **파일명은 변경하지 않는다** —
README·유래 md·로그 13·15·워크플로가 전부 `chip01`을 참조하므로 개명은 재현성 기록을 끊는다.
chip01이 별도 보관되어 있음을 확인했으므로, **D 트랙에서 다시 꽂을 때 UID를 읽어 등록부에
기입**한다. 이 기회를 놓치면 소급 복구가 불가능하다.

### 4.8c 섹터 배치 — 완충 없이, 대조군 이중화

초안에서 마모 그룹 사이에 완충 섹터 9개를 두려 했으나 철회했다. **9는 설계값이 아니라 그룹
시작을 16의 배수로 잡았을 때 남은 수**였고 근거가 없었다.

더 근본적으로, **완충 폭으로 간섭을 제어한다는 발상 자체가 검증 불가능**하다. 논리 섹터
번호와 물리 위치의 대응이 비공개라(`project_context.md` §6에서 이미 범위 밖으로 선언) 섹터
7과 8이 다이 위에서 인접한지조차 알 수 없다. "9섹터 띄우면 안전하다"에 근거를 댈 수 없다.

**회피 대신 측정한다** — 대조군을 둘로 두고 간섭 유무 자체를 관측한다.

```
섹터   0 ~   6   마모 그룹
섹터   7 ~  13   마모 그룹 2
섹터  14 ~  20   마모 그룹 3
섹터  21 ~  27   근접 대조군  ← 가장 심하게 마모된 그룹 바로 옆, 완충 0
섹터 121 ~ 127   원격 대조군  ← 논리적으로 최대한 멀리
```

근접 = 원격이면 인접 간섭 무시 가능(이후 배치 자유), 다르면 그 차이가 disturb의 크기이며
그 자체가 결과물이다. 완충을 넉넉히 두면 "간섭이 없었던 건지 완충이 가려준 건지" 구분할 수
없게 되므로, 완충은 오히려 정보를 파괴한다.

배치 결정 중 **실측 제약 하나를 발견**했다: `flash_prep.c`의 사전 쓰기 범위가 2,048페이지
(= 섹터 0\~127) 고정이므로, 그 밖에 그룹을 두면 PRBS가 없어 전 위상 BER≈0.51이 된다
(런북 3 표 E의 "사전 쓰기 없이 스윕" 서명).

이를 처음에는 제약으로 받아들여 원격 대조군을 섹터 127 이하로 옮겼으나, **`flash_prep`은 우리
코드이므로 고칠 수 있다**(사용자 지적). 데이터시트 스펙과 우리 코드를 같은 무게로 취급한 것이
오류였다. 구분하면:

| 못 고치는 것 (물리·스펙) | 고칠 수 있는 것 (우리 코드) | 절차가 필요한 것 |
| ------------------------ | --------------------------- | ---------------- |
| tSE 45ms, tPP 0.8ms | `flash_prep` 범위·패턴 | RTL 레지스터(BASE_SECTOR) |
| 섹터 = 16페이지, 인듀런스 | N, 검사 주기, 로깅 | PRBS 시드 정의 |
| UID, 주소 24비트 | 캡처·분석 스크립트 | → 계약 v1, 3인 합의 |

**결정: `flash_prep`을 그룹 파라미터화**한다(그룹 목록을 받아 해당 영역만 erase→program→
verify). 부수 효과로 사전 쓰기가 2,048페이지(약 1분) → 560페이지(약 17초)로 **3배 빨라진다.**

그 결과 원격 대조군을 **섹터 249\~255**(페이지 3,984\~4,095)로 보낼 수 있다. 이는 현재 주소
폭 `idx[11:0]`(최대 4,095)이 도달 가능한 **논리적 최원거리**다.

### 4.8d 7섹터 중 12페이지 미측정 — 무해

그룹 7섹터 = 112페이지인데 스윕은 앞 100페이지만 읽는다. 남는 12페이지는 마모는 되지만 측정
되지 않는다. 이는 **의도하지 않은 마모가 아니라 의도한 마모 중 측정하지 않는 부분**이다 —
100페이지 = 6.25섹터라 섹터 배수가 될 수 없고, 6섹터(96페이지)로 줄이면 오히려 읽기 96\~99가
마모되지 않은 섹터를 읽어 마모군에 신품이 섞인다. 7섹터는 읽기 창 전체가 마모 영역 안에
들어오게 하는 최소값이다.

### 4.9 종점 300k — 스펙 3배까지

데이터시트가 **"Min. 100K per sector"** 로 하한 보장을 명시하므로, 100k는 고장 지점이 아니라
제조사가 책임지는 지점이다. 100k에서 멈췄는데 변화가 없으면 노화 곡선이 평평한 직선이 되어
프로젝트의 핵심 주장이 데이터로 받쳐지지 않는다. **"스펙 대비 3배 지점에서 마진 X% 감소"**
쪽이 결과로서 훨씬 강하다.

### 4.10 시간 예산 (데이터시트 typ 기준)

그룹당 7섹터, 사이클 = 7×45ms(소거) + 112×0.8ms(프로그램) = **405ms**

| 목표 사이클 | 소요 |
| ----------- | ---- |
| 100k | 11.2h |
| 300k | 33.7h |
| 한 칩에 10k+50k+300k 3그룹 | 40.5h (≈1.7일) |

소켓이 하나라 직렬이며 이것이 9월의 실질 병목이다. 단 **무인 배치**이므로 사람이 붙어 있을
필요는 없다. 사용자 판단: 데이터 품질을 위해 시간 소비는 감수 가능.

주의 — tSE는 통신 시간이 아니라 칩 내부 고전압 펄스 시간이라 SPI 클럭으로 줄일 수 없다.
단일 섹터 100k의 절대 하한이 100,000 × 45ms = 1.25시간이다. 실측 소거 시간(B-1) 확보 후 재산정.

### 4.11 로깅 — 3종 파일

**마모 판정 지표는 3종**이다. ① 소거·프로그램 시간(교과서적: 갇힌 전하가 전기장을 상쇄해
소거가 느려짐) ② 데이터 무결성(소거 잔여 비트·프로그램 실패 비트) ③ 타이밍 윈도우 폭(우리 가설).

원래 계획은 *NOR 2종 / 3종 체계는 NAND 확장에서* 였으나, **blank check를 사이클 중에 로깅하면
NOR에서도 3종이 성립한다** — ②가 "위상과 무관한 비트 에러 플로어"의 NOR 버전이다.

- **A. 사이클 로그**(매 사이클): `cycle, sector, t_erase_us, t_program_us, timestamp`
- **B. 무결성 로그**(100사이클마다): `cycle, erase_residual_bits, program_fail_bits,
  worst_page_idx, worst_page_bits, timestamp` — 페이지별 최악값을 남겨 열화의 공간적 편중을 관측
- **C. 체크포인트 로그**: `cycle, sweep_csv, chip_id(UID), base_sector, n_sectors, pattern,
  git_rev, timestamp` — 스윕 CSV와 마모 이력의 연결 고리
- 공통 필수: chip_id(UID), git_rev, base_sector/n_sectors/pattern, timestamp
- 자리만 비워둘 것: 온도(히터 도착 후. 마모는 온도 의존성이 크므로 실온 수동 기록이라도 권장)

### 4.13 전원 장애 복구 — 칩 내 tally 이력

**문제**: 33시간 무인 실행 중 정전·USB 분리가 한 번이라도 나면 사이클 카운트가 휘발성 메모리
(PS DRAM)와 함께 사라진다. 마모는 물리적으로 진행됐는데 그 횟수를 모르는 칩이 되고, 비가역이라
다시 만들 수 없으므로 **교정 곡선에 쓸 수 없다.** 세션 중 가장 큰 운영 위험으로 판단.

**해법**: 프로그램이 1→0 방향으로만 간다는 성질을 그대로 이용해, 지우지 않고 표시를 계속
추가한다(벽에 작대기 긋기).

- 이력 섹터를 실험 시작 시 한 번만 소거 → 전부 `0xFF`
- 100사이클마다 다음 바이트 하나에 `0x00` 기록(부분 페이지 프로그램)
- 누적 카운트 = `0x00` 바이트 개수 × 100
- 4,096바이트 → **409,600 사이클** 커버. 기록 비용 0.002%

**각 바이트를 한 번만 쓴다.** 같은 바이트를 반복 프로그램해 비트를 하나씩 지우는 방식이 더
조밀하지만, 데이터시트가 보증하는 것은 "같은 페이지 내 다른 바이트에 영향 없음"까지이므로
명시적으로 허용된 범위 안에만 머문다.

**3중 방어**: ① 호스트 UART 로그(주) ② 칩 내 tally(부) ③ 재개 시 큰 쪽 채택. 호스트 로그만
으로는 **USB 케이블이 빠지는 경우**를 못 막는다 — PS는 계속 돌지만 기록만 끊겨 실제 마모 >
기록이 되고 이 오차는 조용하다. tally가 그 구멍을 막는다. 불확실성은 최대 100사이클(0.03%).

**판독 규칙**: `0x00`→센다 / `0xFF`→안 씀 / 그 외→프로그램 도중 중단, 세지 않되 ±1 불확실.
`0x00`이 `0xFF`로 되돌아가는 것은 물리적으로 불가능하므로 오류 방향이 한쪽뿐이다.

이는 신규 기능이 아니라 공모전 계획서 주요 기능표의 **"칩 개체 이력 관리 — 칩 ID별 누적 P/E
영속 저장(종단 추적의 실체)"** 이 앞당겨진 것이다. **UID + tally** 조합으로 칩이 자기가
누구인지와 얼마나 살았는지를 스스로 들고 다니게 되며, 이것이 "출하 이후 생애주기 전체에 걸친
반복 측정"이라는 프로젝트 주장의 물리적 실체다.

| 영역 | 섹터 | 소거 반복 | 스윕 측정 | PRBS | 목적 |
| ---- | ---- | --------- | --------- | ---- | ---- |
| 마모 그룹 1\~3 | 0\~6 / 7\~13 / 14\~20 | O (최대 300k) | O | 체크포인트마다 | 노화 곡선 |
