# 14. 세은 브링업 코드 2벌 리뷰 + 실기 검증

- **작성일**: 2026-07-08
- **발단**: 실칩의 날(런북 3 트랙 D) 착수 전, 세은이 "보드-모듈 통신 확인" 용도로 쓴 C
  코드 2벌을 리뷰·실행해 달라는 요청을 받았다
- **목적**: 이 2벌이 게재 2번 증거가 되나? 안 된다면 무엇으로 대신하나?
- **관련**: `ps/src/core_smoke.c` · `ps/src/flash_jedec.c` ·
  `docs/results/captures/g2/jedec_chip01_20260708.md` ·
  [로그 9](9.g2_jedec_bringup_prep.md) · [로그 12](12.realchip_prep_batch.md)

## 결정

- [D14-1] 2벌 모두 게재 2번이 아니다 — 둘 다 PS↔PL(core 블록) AXI-Lite 테스트로,
  보드↔W25Q64 통신 증거와 **검증 계층이 다르다** — §1
- [D14-2] PS↔PL 스모크는 유지 가치가 있다. 버전 1 을 수정본으로 채택한다 —
  §2 · `ps/src/core_smoke.c`
- [D14-3] 수정은 2건만 한다 — `%lu`→`%u` 전체 치환, 자리표시자 주소 확정(`0x43C00000`).
  나머지는 세은 원문 그대로 — §3
- [D14-4] 게재 2번용 코드를 따로 만든다 — Young 초안, 스펙·검토·캡처 소유는 장세은 —
  §1 · `ps/src/flash_jedec.c`
- [D14-5] 파일명을 고친다 — `core_bringup_test.c`→`core_smoke.c`,
  `g2_jedec_read.c`→`flash_jedec.c` — §4
- [D14-6] 버전 2 는 채택하지 않는다 — 미배치 AXI 주소(`0x40000000`)를 읽어 data abort 로
  죽는다 — §2

## 근거

### 1. 계층이 다르면 증거가 되지 않는다

게재 2번은 보드와 W25Q64 사이의 통신 증거다 — XSpiPs 로 `0x9F` 를 쏴서 `EF 40 17` 을
받는 것([로그 9](9.g2_jedec_bringup_prep.md) §3). 세은 코드 2벌은 PS 가 PL 의 core 블록을
AXI-Lite 로 읽고 쓰는 테스트라, 아무리 잘 돌아도 모듈이 연결됐는지를 말해주지 않는다.

그래서 유지할 것(PS↔PL 스모크)과 새로 만들 것(게재 2번)을 가르고, 후자는
[로그 9](9.g2_jedec_bringup_prep.md) §3 스펙 그대로 초안을 썼다. SPI 초기화·프리스케일러는
`flash_prep.c` 에서 이미 검증된 값을 재사용했다.

### 2. 실행해야만 잡히는 것이 둘 있었다

정적 대조로는 버전 1 이 깨끗했다 — 레지스터 맵·STATUS 비트·리셋 기본값·R1~R11 준수를
`contract.md` §3·§5 와 전수 대조해 전부 일치했고, TEST6(CMD_ERR 음성)의 전제도
`core_axil_regs.v` 구현과 맞았다. 자리표시자 `0x43C00000` 은 우연히 G0/G3 실제 배치와
같았다.

그런데 돌려 보니 두 가지가 나왔다.

- **버전 1** — 6/6 PASS 인데 진단 숫자가 전부 거짓말이었다(`N_READS write=2199023255602`).
  `xil_printf` 의 `%lu` 가 인자를 64비트로 소비해 u32 인자와 어긋나고 뒤따르는 인자 정렬
  까지 밀린 것이다([로그 12](12.realchip_prep_batch.md) §8 과 같은 뿌리). PASS/FAIL 판정
  자체는 u32 비교라 유효했다 — **출력만** 거짓말한 경우다
- **버전 2** — 헤더와 "접근 시도" 한 줄만 찍고 정지했다. 미배치 AXI 주소 리드는 DECERR →
  data abort 라, 코드가 준비한 `[FAIL]` 안내 분기가 그 실패 모드에서 **도달 불가능** 하다.
  고장을 안내하려던 코드가 고장 때 침묵한다

JE 점퍼가 트랙 C 이후 그대로 붙어 있어 버전 1 의 TEST4·5 는 실측정 경로(core↔flash
루프백)까지 완주했다. 보드가 버전 2 정지 상태로 끝났지만 다음 `program_*.tcl` 이
`rst -system` 으로 회복하므로 조치는 불요다.

### 3. 남의 코드는 고칠 이유가 있는 두 곳만 고친다

작성자는 세은이고 헤더에 그렇게 명시했다. `%lu`→`%u` 는 `flash_prep.c:63` 에 이미 명문화된
리포 관례라 선택의 여지가 없고, 자리표시자 주소는 G0·G3 build tcl 공통 배치를 확인해
확정한 것이다. 그 둘 말고는 손대지 않았다 — 리뷰가 재작성이 되면 소유권이 사라진다.

### 4. 이름이 수명과 가족을 드러내야 한다

`core_bringup_test.c` 의 "bringup"은 1회성 어감인데 실용도는 사다리(D4)에서 반복하는
스모크다. `_test` 접미는 리포 밖 관례다. `g2_jedec_read.c` 의 `g2_jedec` 은 하드웨어
설계(XSA·bit) 이름이라 앱 이름과 충돌하고 `_read` 는 정보량이 0이다.

`flash_prep`(굽기)·`flash_jedec`(ID 확인)을 G2 인프라 공용 `flash_*` 가족으로 묶었다.

### 5. D1 통과 — 게재 2번 증거를 확보했다

같은 날 23:42, chip01 모듈을 JB 에 암수 점퍼로 직결(보호 보드 없이, 전원 2가닥 선검증
절차)하고 `flash_jedec` 을 돌려 `EF 40 17 [OK]` 를 연속 13회 이상 안정 수신했다. 간헐
증상이 없다는 것은 `/HOLD` 풀업이 정상이라는 방증이기도 하다([로그 9](9.g2_jedec_bringup_prep.md) §2).

그 전 미배선 상태에서는 `#G2 JEDEC FF FF FF [FAIL] 응답 없음` 이 1초 주기로 반복됐다 —
런북 표 E 의 정상 서명이라, 코드 경로 종단까지 확인된 상태에서 배선만 더한 것이다.
