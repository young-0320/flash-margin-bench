## 근거

### 1. 곡선을 보기 전에 기준을 동결한다

사전등록 원칙이다. 곡선을 본 뒤에 문턱을 고르면 판정이 유효하지 않다. floor 기준 10⁻⁵ 는
스텝당 N×B = 204,800비트(BER 분해능 4.9×10⁻⁶)와 정합한다.

θ = 10⁻² 만은 잠정으로 남긴다 — G0 곡선이 체크리스트 4항을 통과하는지로 최종 판정한다
(`temp.md` 7번). **데이터가 정하는 유일한 항목** 이다.

### 2. phase_ps 는 x축에 그대로 쓰이는데 무방비였다

`bit_errors`·`err_count` 류는 R8 재검이 상호 대조로 잡는데 `phase_ps` 는 대조 상대가 없다.
UART 글자 깨짐의 마지막 미방어 통로였다. `phase_ps = phase_step × dphi_ps` 대조를 넣고
허용오차는 Δφ/2 로 뒀다 — 격자 분해능 이상으로 점을 옮기는 깨짐은 전부 검출하고, C 의 fs
절사 오차(<0.002ps)는 무해하다는 경계다.

### 3. 0x0B 통일 — 명령을 통제 변수로 고정한다

기각한 안은 둘이다. (b) 브링업용 `0x03` 병용, (c) 저클럭 `0x03` → 상향 시 전환.

계약 §5 가 이미 `0x0B` 기준이고, 클럭 사다리 간 곡선을 비교하려면 명령(더미 유무)이 통제
변수여야 한다. 브링업 단순성이라는 `0x03` 의 역할은 G2(`0x9F`, PS SPI)가 이미 대체했다.
`0x03` 병행 구현은 오히려 RTL 을 늘린다 — `0x0B` = `0x03` + 더미 카운터이기 때문이다.

### 4. 쓰기 오류가 읽기 마진으로 둔갑하는 것을 원천 차단한다

기각한 안은 (b) RTL 쓰기 기능 추가, (c) 외부 프로그래머다. 채택안은 G2 인프라(XSpiPs
~2.6MHz, `program_g2.tcl`) 재사용이고, 절차는 erase → 100페이지 PRBS page program(시드 =
페이지 주소, 계약 §5) → 같은 저속 경로 read-back 전수 비교 → 통과 시에만 스윕이다.

2.6MHz 검증 읽기는 마진 논란 자체가 없다. "중앙 위상에서 검증" 원안은 닭-달걀이라 폐기했다
— 중앙 위상은 곡선이 나와야 안다. [로그 9](9.g2_jedec_bringup_prep.md) 산출물의 수명이
덤으로 연장된다.

### 5. 풀 스윕 — 코어스 스캔이 이기는 시나리오가 없다

코어스 스캔 안(8스텝 간격)은 기각했다. 칩 1개 스프린트에서 차이는 1회성 ~20분뿐인데,
풀 스윕은 `g0_sweep.c` 무수정이고(코어스는 스트라이드 변형 C 가 필요하다) "이 클럭에서 전
스텝 에러 0"이라는 완전 증거 CSV 가 보고서 근거물로 남는다.

코어스의 놓침(8스텝보다 좁은 에러 구간)은 어차피 R² 를 통과 못 할 곡선이라 실해는 없다.
다만 이기는 시나리오가 다칩 캠페인뿐이라, 그 규모가 확정되면 재론한다.

채택 규칙 전문은 "풀 스윕 전 스텝 `bit_errors=0` → 다음 클럭 승격(25→45→75MHz), 양벽 각각
BER>θ 스텝 ≥2개 보이는 최저 클럭에서 체크리스트 통과 시 그 곡선 채택"이다.

### 6. 구현과 승인을 가른다

SPI 마스터 RTL 은 게재 1·2·3번엔 불필요하고 4번 전용 선행물이다. README 상 소유자 박지민이
7/8 오후 합류하나 cocotb 사다리가 본인 과업이라, 7/10 마감 대비 권고는 "Young 구현(총력전
연장) + 박지민 cocotb ③(W25Q64 행동 모델 JEDEC 트랜잭션)이 채점기"였다.

7/8 검증 분담으로 확정했다 — Young 이 구현을 인수하고, 박지민이 `docs/spec/s3.g1_test_plan.md`
기준으로 채점·승인한다. 승인 행위가 박지민 소유라는 것이 이 분담의 핵심이다. 읽기 목록은
워크플로 3 §B.
