## 2. 무엇을 고쳤나

### 2-1. 다섯 번째 벽 — cp949 (로그 33 이 못 닫은 자리)

로그 33 은 `.bat` 런처·셸 의존·`exec env`·경로 구분자를 닫았다. 세은은 그 뒤에도 막혔고,
문서(`docs/log/seeun/1`)에 증상이 둘로 나뉘어 기록돼 있었다.

| 증상 | 어디서 | 정체 |
| ---- | ------ | ---- |
| `UnicodeEncodeError: cp949` | selftest 단계 | 자식 파이썬이 **한글 출력을 인코딩하다** 죽는다 |
| `UnicodeDecodeError: cp949` | Vitis 빌드 | Vitis 내장 파이썬이 **`ps/src/*.c` 를 읽다** 죽는다 |

두 번째가 본체다. `build_g0_sweep.py` 의 `app.import_files()` 가 소스를 복사할 때 AMD 쪽
파이썬이 로케일(Windows 기본 cp949)로 디코드한다. 우리 PS 소스는 네 개 전부 한글을 담고 있다 —
**주석만이 아니라 `xil_printf` 문자열 리터럴에도** 있다:

| 파일 | 한글 문자열 리터럴 | 전체 한글 줄 |
| ---- | ------------------ | ------------ |
| `core_smoke.c` | 18 | 79 |
| `flash_prep.c` | 17 | 72 |
| `g0_sweep.c` | 11 | 60 |
| `flash_jedec.c` | 6 | 22 |

세은 문서 §4-1 의 `child process exited abnormally`(tcl→vitis 체인 실패)도 이것이 원인일
가능성이 높다 — `exec` 가 자식의 죽음을 그 문구로 던진다. **확인은 세은 재실행 대기.**

원인은 한글이 아니라 **읽는 쪽의 로케일 가정**이다. 그래서 주석을 ASCII 로 바꾸는 길은 택하지
않았다(문서 가치를 버리면서 원인도 안 고쳐진다). 자식 env 에 한 줄을 강제한다:

```python
env = {**os.environ, "PYTHONUTF8": "1", **st.get("env", {})}
```

`os.environ` **뒤**에 놓아 부모 셸 설정을 이긴다. 상속 경로가 `reproduce.py → cmd /c vivado.bat
→ vivado → exec vitis.bat → Vitis 파이썬` 전 구간이므로, 세은 문서 §4-2·§4-3 의 수동
`chcp 65001` · `set PYTHONUTF8=1` 두 줄이 불필요해진다.

로그 33 의 utf-8 고정(로그 **파일**)으로는 이게 안 닫힌다. 자식은 파이프에 쓰기 **전에**
인코딩하므로 부모의 파일 인코딩과 무관하다.

### 2-2. 진행 표시 — `...` 만 8분

`[3/8] g0 ...` 이 결과가 나올 때까지 그대로였다. 죽은 건지 도는 건지 알 방법이 터미널을
하나 더 열어 `tail -f` 하는 것뿐이었다. `watch()` 를 두어 같은 줄을 5초마다 다시 그린다:

```
[3/8] g0 0:55  Phase 9 Verifying routed nets       ← 5초마다 갱신 (스크롤 안 함)
[3/8] g0 PASS (113s) WNS=29.811 WHS=0.096 …        ← 끝나면 같은 자리를 덮어쓴다
```

설계 판단 셋:

- **파이프로 빨아들이지 않는다.** 자식 출력은 지금처럼 로그 파일로 보내고, 그 **꼬리에서**
  이정표 줄을 주워 온다. 파이프로 받으면 인코딩·버퍼 관리를 우리가 떠안는다 — §2-1 을 겪고도
  그 길로 갈 이유가 없다
- **`sleep` 이 아니라 `proc.wait(timeout=5)`.** 자식이 0.1초에 끝나면 그 순간 빠져나온다.
  명령 8개짜리 `sim` 이 여전히 1초다 (`real 1.076s` 실측)
- **`isatty()` 로 거른다.** 리다이렉트·CI 에서 `\r` 이 도배되지 않는다

이정표: 우리 마커(`== `) · Vivado 임플 단계(`Phase n`) · Vitis 컴파일(`[2/3]`).

## 4. 빌드 신원 관리 — 논의 정리 (결론: **보류**)

### 4-1. 문제

`.bit`·`.elf` 는 git 에 없다(용량·바이너리·비결정성). 셋이 각자 구운 산출물을 들고 있는데
**라벨이 없다.** "네 것은 어느 소스로 구운 거냐"에 아무도 답할 수 없다. 오늘 3인 공통 체감.

측정 CSV 에 `git_rev` 열이 있긴 하다. 그러나 그 값은 **캡처를 실행한 순간 호스트의 HEAD** 다
(`sweep_uart_capture.py:66`). 3일 전 구운 ELF 로 측정해도 오늘 rev 가 찍힌다. 보드 배너
(`#G0 SWEEP BEGIN steps=… n=… b=…`)에도 빌드 신원이 없다. 즉 **"이 데이터를 뽑은 계측기가
무엇이었나"를 지금 아무도 기록하지 않는다.**

### 4-2. 오늘 확인된 사실 — 네 숫자는 지문 노릇을 한다

§3 의 2회 재빌드에서 WNS/WHS/LUT/FF 가 9/14 기준값과 **소수점까지 일치**했다. `.bit` 해시
비교가 불가능한 상황에서 이 네 숫자가 실무적 지문이 된다는 근거다.

단, **네 숫자가 없는 단계가 있다**: `g2`(PL 로직 없음)와 `prep`. ELF 는 타이밍 리포트를 만들지
않는다. 신품 검사에 쓰는 `flash_prep.elf` 가 여기 속한다.

### 4-3. 후보 셋과 각자의 한계

| 후보 | 무엇의 지문 | 언제 | 한계 |
| ---- | ----------- | ---- | ---- |
| `git rev` | 커밋 | 즉시 | **문서만 커밋해도 값이 바뀐다** → 거짓 불일치 |
| 입력 내용 해시 | 빌드 입력 파일 | 즉시 | 툴·OS 차이를 못 본다 |
| WNS/WHS/LUT/FF | 빌드 **결과** | 빌드 후(9분) | g2·prep 에는 없다. 왜 다른지 못 말한다 |

거짓 불일치 시나리오(영웅 지적): `c1` 에서 빌드 → 문서만 커밋해 `c2` → 세은이 `c2` 로 빌드.
설계는 동일한데 `c1 ≠ c2` 라 다른 빌드로 보인다.

입력 내용 해시를 시제품으로 만들어 확인한 결과(31개 파일: `fpga/rtl/*/*.v` ·
`fpga/constraints/*.xdc` · `fpga/scripts/*.tcl` · `ps/src/*.c` · `ps/scripts/build_*.py`):

| 무엇이 바뀌면 | 입력 해시 | rev |
| ------------- | --------- | --- |
| 문서만 커밋 | **그대로** | 바뀜 |
| `ps/src/g0_sweep.c` 한 줄 | 바뀜 | (커밋해야) |
| `constraints/*.xdc` 한 줄 | 바뀜 | (커밋해야) |
| RTL 수정 후 **커밋 안 함** | **바뀜** | 안 바뀜 |

둘을 겹치면 원인까지 갈린다:

| 입력 해시 | 네 숫자 | 해석 |
| --------- | ------- | ---- |
| 같음 | 같음 | 같은 계측기 |
| 같음 | 다름 | **환경(툴·OS)이 결과를 바꿨다** ← 세은·지민 환경에서 나올 수 있는 경우 |
| 다름 | 같음 | 설계에 영향 없는 수정이었다 |
| 다름 | 다름 | 다른 설계 |

### 4-4. 3단계 로드맵 (구현 시 참고)

| 단계 | 무엇 | 답하게 되는 질문 |
| ---- | ---- | ---------------- |
| 0 | 실행 요약 머리말에 신원 한 줄 | "우리 셋이 같은 걸 구웠나" (사람이 대조) |
| 1 | 산출물 옆 `.provenance` + `--check-only` | "지금 내 `build/` 는 어느 소스 것인가" (빌드 없이) |
| 2 | ELF 에 rev 를 심어 보드가 배너로 말함 → CSV 열 | "이 데이터는 어느 계측기가 뽑았나" (데이터가 증언) |

0·1 은 PC 안에서 닫히고, **2 라야 "보드에 실제로 올라간 것"까지 닫힌다.**

### 4-5. 결정 — 보류

0단계(신원 한 줄)와 입력 해시를 실제로 구현해 동작까지 확인한 뒤 **되돌렸다.** 이유:

- 기능을 늘리기 전에 **Windows 경로부터 닫는 것**이 우선이다. 세은 확인이 아직 안 왔다
- 어디에 보존할지(승격처)가 안 정해졌다. `build/` 는 gitignore 라 **증발한다** — 오늘 실제로
  1회차 성공 요약이 `build/` 를 새로 만들면서 사라졌고, 채팅에 붙여둔 텍스트가 유일본이었다
- W10-B(`docs/workflow/10` §B)에 이미 트랙이 있다. 거기서 재개한다
