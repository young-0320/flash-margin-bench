## 근거

### 1. 계약과 사양서를 가르는 기준

`interface/`의 정의는 "레지스터 맵·UART 프로토콜·CSV 스키마 = 3인 병렬 개발의 계약"이다.
`s1.wear_bench_spec.md`는 이 정의에 맞지 않는다 — **수신자가 장세은 한 명이고, 인수 기준
판정으로 닫히는 문서**다. 계약은 전원이 동시에 지키는 것이고 변경에 3인 합의가 필요하지만,
사양서는 작성자가 혼자 고쳐도 되고 수신자만 영향을 받는다. **변경 절차가 다르면 다른
폴더여야 한다.**

### 2. `sim/test_plan.md`도 사양서다 — 판례는 contract.md

처음에는 `sim/`에 남기려 했다. 검증 산출물 옆에 두는 것이 자연스럽고 `sim/README.md`가
이미 참조하고 있어서다. 그러나 이 리포에는 이미 반대 판례가 있다 — **`interface/contract.md`는
`fpga/rtl/`을 규율하지만 `fpga/`가 아니라 `docs/`에 있다.**

즉 이 리포의 원칙은 "규율 대상 옆"이 아니라 "문서끼리 모은다"이며, `test_plan.md`는 워크플로 5가
명시적으로 S-3의 산출물로 지목한 문서다. S 3형제가 세 군데로 흩어지면 S-2를 쓸 때 놓을 자리가
또 즉흥적으로 정해진다.

```
S-1  docs/spec/s1.wear_bench_spec.md   장세은   작성 완료
S-2  docs/spec/s2.newchip_protocol.md  장세은   미작성 (자리만 예약)
S-3  docs/spec/s3.g1_test_plan.md      박지민   작성 완료, 미동결
```

### 3. 협업 규칙 문서가 리포와 어긋나 있었다

`CONTRIBUTING.md`가 규정하던 것과 실제:

| 문서의 주장 | 실제 |
| ----------- | ---- |
| `docs/spec/` 참조 (2곳) | 그런 폴더 없었음 → **이번에 신설되어 유효해짐** |
| `docs/`에 milestone-bathtub.md · decisions-hyw.md · decisions.md | 셋 다 없음. 실제는 project_context · roles · chip_registry |
| `concepts/` `log/` `workflow/` `ref/` `results/` | 표에 아예 없음 (results만 별도 문단) |
| `git add rtl/simple_cpu/alu.v` 예시 | `rtl/`은 `fpga/rtl/`. 템플릿 잔재 |

"폴더 = 소유자 1명"을 규칙으로 세운 문서에서 `docs/` 하위 신설 폴더 5개의 소유자가
미기재였다. S-1/S-2/S-3을 **각각 다른 사람에게** 보내는 국면이라 이 어긋남은 실제 비용이다.

### 4. `ref/`는 자기가 정한 규칙을 어기고 있었다

`ref/README.md`가 `<대상>_<문서종류>_rev<판번>.pdf`를 규정해 놓고, 정작 파일은
`W25Q64JV.PDF`(대문자 확장자, 판번 없음)와 `zybo-z7_ref.pdf`(하이픈)였다. 등록부 표는
두 파일 다 "(예정)" 상태였다 — **들어와 있는 문서가 등록부에 없었다.**

| 파일 | 판번 |
| ---- | ---- |
| `w25q64jv_datasheet_revc.pdf` | Revision C (2016-06-03) |
| `zybo_z7_refmanual_rev20180221.pdf` | 2018-02-21 개정, 보드 rev.B 대상 |

데이터시트 판번이 중요한 이유는 우리가 tSE 45ms·tPP 0.8ms·"Min. 100K per sector"를 사양서의
근거 수치로 직접 인용하고 있기 때문이다. 판이 바뀌면 그 수치가 바뀔 수 있고, 어느 판을 봤는지
기록이 없으면 나중에 대조할 방법이 없다.

### 5. 끊어진 참조 — 고친 것과 남긴 것

기존 문제 14곳 중 5종을 정정했다. `docs/workflow/1.md`→`1.midterm_report_workflow.md`(5곳) ·
`docs/milestone-bathtub.md`(미작성 문서)→`workflow/4.gate_map.md`(실제로 그 역할을 하는
문서) · `docs/interface/README.md`→`contract.md`(계약 v1 확정 시 본문으로 통합, cddfabf) ·
`concepts/6.vivado…`→`workflow/2.g0_vivado_integration_and_xdc.md` ·
`docs/reports/`→`docs/results/`(승격처 개명, d108558, 6곳).

**남긴 것 9곳**: `sim/tb/`(4곳)는 V 트랙 미착수 폴더로의 정상적인 선행 참조.
`sim/golden/`(3곳)은 `roles.md` 미결 4번이 이미 다루고 있다 — golden model이
`host/analysis/`에 통합돼 있어 폴더를 신설할지 통합을 확정할지가 미정이므로, 그 결정
전에는 참조를 고칠 대상이 정해지지 않는다. `host/analysis/mc_reads_per_phase.py`(2곳)는
개명 전 이름을 **개명 사실과 함께** 서술한 역사적 기록이라 고치면 오히려 틀린 문장이 된다.
