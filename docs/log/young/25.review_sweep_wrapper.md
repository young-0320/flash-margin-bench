## 발견 사항 (심각도 순)

### 중요

**1. `run_sweep_chip.py:120` — `#PREP ERROR`를 FAIL과 같이 즉시 중단 → 펌웨어의 전송 실패 3회 재시도가 래퍼 경로에서 무효**
- 왜: `flash_prep.c:66~74` `xfer()`는 실패마다 `#PREP ERROR spi transfer len=13`을 찍고 `-1`을 돌려주며, `:124`의 재시도 루프가 이어서 다시 시도한다. 래퍼는 그 첫 줄에서 `Abort`. 펌웨어는 계속 돌아 PASS까지 갈 수 있는데(칩은 prep됨, P/E +1 실제 발생) 래퍼는 이미 죽어 `chip_pe.md`에 기록하지 않고 등록부도 안 채운다. 원문 ④ "전송 실패 3회 재시도" 미충족. 로그 24 미결 8의 "래퍼는 FAIL/PASS만 종결 신호로 보므로 동작엔 무관"은 **사실이 아니다**.
- 재현: W1 — 가짜 시리얼에 `#PREP ERROR spi transfer len=13` 한 줄 뒤 `#PREP UID … PASS` → 래퍼 `flash_prep 실패: #PREP ERROR …` 로 exit, `session_prepfail_*.log`.
- 제안: `ERROR`를 종결 신호에서 빼고 FAIL/PASS/타임아웃만 보거나, 펌웨어가 재시도 중에는 다른 접두(`#PREP RETRY`)를 쓰게 한다. 다른 ERROR 경로(`spi init`·`busy stuck`)는 어차피 PASS가 안 오므로 15분 타임아웃이 잡는다.

**2. `run_sweep_chip.py:186~238` — `ses.open()` 전에 끝나는 경로에서 세션 로그가 어디에도 남지 않는다. prep이 이미 끝난 뒤라면 UID와 P/E +1 사실이 유실된다**
- 경로 (전부 실행 확인): ⓐ 신규 UID 라벨 오타 → `chip_registry.register()`가 `RegistryError`(SystemExit, Abort 아님) → `except Abort` 못 잡음, 파일 없음 (W2) ⓑ 라벨 프롬프트에서 Ctrl-C → `except KeyboardInterrupt`가 `ses.log`하지만 `path=None`이라 버퍼에만 남고 종료 (W7) ⓒ prep 도중 Ctrl-C (W8) ⓓ 포트 열기 실패 `serial.SerialException` → `with` 밖 예외, 트레이스백만 (W3). ⓔ `--no-prep` 미등록 UID (W6) — 헤더만 잃어 무해.
- 왜 문제: ⓐⓑ에서 `flash_prep`은 완주했다. 칩에는 P/E +1이 들어갔는데 `chip_pe.md`에는 없고, `#PREP UID`는 화면(stderr)에만 있다. 다시 돌리면 +1이 또 들어가고 첫 +1은 이력에서 영구히 사라진다 — 이력 파일의 존재 이유와 정면 충돌. 원문 "종료 시 요약을 세션 로그에 남긴다"도 미충족.
- 제안: `finally`에서 `ses.path is None`이면 `session_<batch_id>.log`(라벨 미상)로 버퍼를 내린다. `chip_pe.append_pe`를 `resolve_label` **앞**으로 옮기면(라벨 대신 UID만으로도 행은 유효) P/E 사실이 먼저 남는다 — 단 라벨 열이 비게 되므로 표 규칙 합의 필요.

**3. `sweep_uart_capture.py:116` — 세션 2 첫 줄 앞 쓰레기 방어가 없다 (B-1 상술)**
- 재현: T2. 제안: `find("#G0")`.

**4. `run_sweep_chip.py:231~236` — `Abort`·`KeyboardInterrupt` 외 예외에서 `k/N 완료` 요약이 안 찍힌다**

### 지적만

- `chip_registry._table()` (`:40~50`)은 `| 라벨 | UID…` 헤더를 가진 **첫** 표를 잡는다. 같은 헤더의 표가 앞에 생기면 그쪽을 읽는다(R2). 지금은 표 하나뿐.
- `register()`가 고친 행만 `| a | b |` 형식으로 재조립되어 빈 셀이 `|  |`(공백 2개)가 된다(R1). diff는 그 행 하나.
- `capture_sweep(batch_id="")` → `or stamp`로 stamp 대체(T4). CLI "생략 시"와 같은 뜻이라 무해.
- `input()` 프롬프트는 stdout, 나머지는 stderr. tty에선 같은 화면. `> file`로 돌리면 프롬프트가 안 보인다.
- 재장착 프롬프트에서 안 빼고 엔터 → 검출 불가. 로그 23 부록 A가 이미 인정.
- `flash_prep.c` UID FAIL 경로의 `return 1`은 JEDEC FAIL(`:115`)과 같은 구조. `xil_printf`는 TX FIFO에 넣고 반환하며 FIFO는 CPU가 멈춰도 하드웨어가 비운다 → 마지막 줄이 잘리는 새 위험은 없다. 단 재시도 중 `#PREP ERROR`가 최대 3줄 찍히는 것(미결 8)이 **중요 1**과 결합해 문제가 된다.
- `#PREP JEDEC`은 `%02x` 소문자, `#PREP UID`는 `%02X` 대문자 — 한 앱 안에서 불일치. 파서는 관대.
- `capture_sweep()`에는 데드라인이 없다. 래퍼가 timeout=2로 넘겨도 `if not line: continue`라 보드가 스윕 중 죽으면 영원히 기다린다(종전 CLI도 동일, Ctrl-C가 출구).
- exit code: `--repeat 3`에 invalid 1 → "3/3 완료 (invalid 1)" + exit 1. "그 회차만 무효로 남기고 계속"은 지켰고, exit 1은 "전부 유효는 아님"의 신호로 읽힌다. 로그 24 §6 #3에 명시돼 있어 문제 없음.
- `--blind` 행도 일자·배치·라벨은 남긴다 — 로그 23 부록 D가 "시간이 샌다"로 이미 적음.
- `program_g3.tcl:8,61`·런북 3 `:64,133`의 `--target chip01` 문구 — 로그 24 미결 5·§7이 이미 인정. 런북 3 `:64`의 `--target loopback`은 이제 **동작하지 않는 명령**(`--loopback`이 맞다)이라 역사 기록이라도 각주가 필요.
- 로그 24 커밋 제목은 "다르게 간 결정 3건", 본문은 §2~§5 4건.
