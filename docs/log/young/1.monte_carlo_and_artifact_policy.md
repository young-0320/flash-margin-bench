## 근거

### 1. 계단은 N 을 늘려도 바닥에서 멈춘다

경계 판정 후보 둘을 정면 비교했다. 계단(B안)은 N 을 늘려도 **양자화 바닥**(수 ps)에서
멈추고, 최악 지터에서는 선택 규칙 σ_width ≤ Δφ/2 자체를 탈락시킨다. 보간(C안)은 같은 N 에서
바닥이 없다. 그래서 보간을 채택했다.

집계는 비트 단위(B=2,048)로 하고, 경계는 θ 문턱을 log-BER 선형 보간으로 가로지르는 위상으로
잡는다.

### 2. N=100 — 하한을 정하는 것은 채택 θ 가 아니다

최악 지터 200ps 가정까지 커버하는 값이 N=100 이다(폭 편차 ≤ 4.7ps). 주의할 것은 하한의
출처다 — N 의 하한은 채택 θ 가 아니라 **병행 기록되는 최저 θ**(10⁻⁴)의 유효 조건
N×B×θ ≥ ~20 이 결정한다. 채택 θ 를 올려도 N 을 못 내리는 이유가 이것이다.

B_BITS=2,048 은 아직 추론값이라 스크립트에 `!!` 플래그를 달았다. 이 값이 바뀌면 FPGA 에러
카운터 폭(N×B, 오버플로 시 곡선 어깨 오염)과 N 권고값이 연쇄로 바뀐다.

시간 모델은 실제 스윕 범위(UI = 클럭 한 주기)와 정합시켜 25MHz·N=100 기준 스윕 약 23초로
정정했다. 기존 4.6초는 스팬 불일치에서 온 과소평가였다.

### 3. θ — 하나를 고르지 않고 셋을 남긴다

θ 스윕을 돌리자 θ 가 클수록 폭 편차가 단조 감소했다(10⁻² 가 10⁻³ 대비 약 2.4배 정밀).
그런데 "에러 없음"에 가까운 직관적 판정도 버릴 수 없어, 하나를 고르는 대신 10⁻²/10⁻³/10⁻⁴
셋을 **병행 기록** 한다.

그 위에서 채택 θ 를 10⁻² 로 잠정 확정했다. 근거는 노화 검출 SNR(신호/노이즈)이 비탈 위치
이동·기울기 변화 두 시나리오 모두에서 최대라는 것이다(10⁻³ 대비 1.7~2.2배). "에러 없음"
직관은 병행 기록되는 10⁻⁴ 폭이 담당한다.

### 4. 생성물의 자리 — 기계가 만든 것과 사람이 고른 것

재현 가능한 것은 전부 `build/` 하위(gitignore)에 두고, 보고서·발표에 실리는 것만 사람이
`docs/results/` 로 수동 승격한다. 승격은 기계가 하지 않는다 — 게재 판단이 사람의 일이라서다.
CSV 에는 생성 시각·git 해시 스탬프를 넣어 승격본의 출처가 남게 했다. 스크립트 출력 경로를
`build/` 로 옮기면서 기존 docs 승격본과 바이트 일치를 확인했다.

문서 관례도 같이 정했다 — 작업 로그 파일명은 영어 소문자+언더스코어, 문서 내 대제목은 한글.

### 5. probit — log 축에서는 정상 곡선도 탈락한다

체크리스트 1항을 log-BER 선형성으로 재면 **가우시안 꼬리** 는 log 축에서 2차 곡선이므로 정상
곡선까지 탈락시킨다. 척도를 probit(erfcinv) 선형으로 바꿔야 직선이 된다. 몬테카를로 쪽
docstring 도 같이 동기화했다.

### 6. 마일스톤과 게재 4단

G0∥G1 병렬 트랙을 명시하고, 마모를 시작하기 전에 통과해야 할 G5 게이트를 신설했다 — 전수
신품 측정·노이즈 플로어·체크포인트 계획이 그것이다. 확장 항목에는 제조사별 비교 축을 더했다.

게재 5항목은 무조건 필수(G0 루프백) / 조건부 필수(실칩 곡선+연속 반복 5회, 승격 조건은
7/8 모듈 도착+JEDEC ID) / 병렬 저비용(몬테카를로·cocotb) / 순수 선택(풀 반복성)으로 갈랐다.
무엇이 없으면 보고서가 안 되는지를 단으로 드러내는 것이 목적이다.
