## 근거

### 1. 규약이 제 원칙을 지키지 못한 자리가 셋이었다

[로그 38](38.log_format_convention.md) §4 는 산출물 표에서 수치를 뺐고 이유가 이중 출처였다.
`build/` 미커밋도, `CLAUDE.md` 가 README 를 임포트하는 것(`docs/CONTRIBUTING.md` §1)도 같은
원칙이다. 그런데 절별 규칙은 `## 결정` 에 본문 문장을 복사하라고 적고 있었다. 복사본은 같은
파일 안의 이중 출처이고, 외부 것보다 나쁘다 — 한쪽을 고치고 다 고쳤다고 착각한다.

갈라졌을 때 손해를 보는 쪽이 규약이 §1 에서 지목한 그 소비자다. 사람은 위에서부터 읽어
어긋남을 보지만, 검색으로 본문 한가운데 착지하는 AI 는 둘 중 하나만 본다.

추기와 미결은 종류가 달랐다. 조항은 옳은데 **지켜졌는지 셀 수가 없었다.** 추기를 단 로그를
[로그 38](38.log_format_convention.md) 은 네 편으로 셌는데, 규약이 정한 인용구 형태로 잡히는
것은 [로그 23](23.sweep_wrapper_and_uid_design.md)·[로그 36](36.flash_id_and_sweep_uid_check.md)
둘뿐이다. 나머지는 §5 가 폐기한 말미형 절이다. 형식을 구분하지 않고 센 계수였고, 그래서
"뒤집힌 자리에 표시가 다 붙어 있나"를 확인할 방법이 없었다.

미결은 실패 사례가 이미 있었다. [로그 13](13.first_loopback_bathtub_and_linedead_fix.md) 미결
①이 [로그 15](15.g3_25mhz_wall_too_narrow.md)에서 닫혔는데 13 에 표시가 없다. §5 가 이것을
인용했으므로 문제를 알고 있었고, 처방이 규칙 한 줄이었다. 실패의 원인은 규칙 부재가 아니라
기억인데 규칙을 늘린 것이라 같은 자리에서 다시 깨진다.

처방을 고르는 기준은 §6 이 이미 세워 뒀다 — 재볼 수 없는 숫자는 죽은 조문이 된다. 정량
조항(추기율 N%)을 후보에서 먼저 뺀 이유다. 볼드 상한이 실패한 것은 라벨 볼드와 강조 볼드를
가르는 기준이 분류기마다 달랐기 때문이고, 고정 문자열에는 그 판단이 들어가지 않는다.
**재는 것이 아니라 세는 것**이면 §6 의 결론을 뒤집지 않고 그대로 적용할 수 있다. 미결 ID 도
같은 전환이다 — 닫는 사람은 무엇을 닫는지 알고, 모르는 것은 그것이 어디 있느냐다.

`## 결정` 쪽에서 버린 안이 하나 있다. 결정 절을 없애고
[로그 23](23.sweep_wrapper_and_uid_design.md) 처럼 절 제목에 결론을 담는 방식인데,
[로그 36](36.flash_id_and_sweep_uid_check.md) 이 반례다 — 작업 내용이 절반 가까워서 절
제목만으로는 결정 서너 건을 한눈에 주지 못한다(계측은 [로그 38](38.log_format_convention.md)
§2). 골격은 §2 가 확정한 결정이기도 해서, 복사만 금지하는 쪽이 변경이 작다.

### 2. 집행 장치를 고르는 자리 — 읽히는 문서는 열어야 열린다

규약을 `CLAUDE.md` 에 넣으면 RTL 을 고칠 때도 CDC 를 볼 때도 따라다니고, README 에 두면 비용은
없는데 열어야 열린다. [로그 38](38.log_format_convention.md) 자신의 누락이 후자의 실물이다.

스킬은 이름과 한 줄 설명만 상주하다가 해당 작업일 때 본문이 들어온다. 가끔 필요한 긴 규약에
맞는 형태다. 다만 스킬이 규약을 복제하면 `docs/CONTRIBUTING.md` §1 이 금지한 드리프트를 규약
자신에 대해 만드는 셈이라, 스킬은 README 를 가리키기만 한다. 한 홉이 더 드는 것은 드리프트를
없애는 값으로 받아들였다.

훅도 후보였다. 하네스가 강제 실행하므로 판단이 개입하지 않지만, 지금 필요한 것은 작성 시점의
안내지 커밋 차단이 아니다. 검사기가 자리를 잡고 나서 필요해지면 그때 올린다.

적용 범위는 §8 을 그대로 따른다. 리포 스킬은 누가 이 리포에서 에이전트를 쓰든 뜨므로,
`young/` 밖에서는 제안으로만 제시하도록 스킬 본문에 못 박았다. 그러지 않으면 §8 이 의도한
구속력 차이가 도구 단계에서 뭉개진다.

### 3. 스킬로 한 편 써 보고 절반을 잘라냈다

초안을 스킬로 뽑아 보니 값을 한 것과 아닌 것이 갈렸다. 절차 체크리스트는
[로그 38](38.log_format_convention.md) 에 달아 둔 추기가 출처를 가리키지 않는 것을 잡아냈고,
기존 실물이 전부 출처를 달고 있다는 것도 그때 드러났다 — 규약은 그것을 예시로만 보여주고
규칙으로 적지 않았다.

반대로 「자주 틀리는 것」 네 줄은 아무것도 막지 못했다. 그중 "로그 번호에 경로를 함께"는
글자 그대로 적혀 있었는데, 초안은 앞의 두 건만 달고 뒤의 셋을 흘렸다. **산문 주의사항은
체크리스트가 아니다.** 게다가 그 절은 README 판별선의 요약이어서, 복제하지 않는다던 설계를
그 자리에서만 어기고 있었다. 통째로 뺐다.

경로를 손으로 붙이는 규칙 자체도 바꿨다. 마크다운 링크면 사람은 눌러서 가고, 없는 파일을
가리키면 검사에 걸린다. `docs/log/README.md` 목록이 이미 쓰는 형식이라 새로 만드는 것도
아니다. **틀린 것을 잡는 대신 틀릴 구조를 줄이는 쪽**이다.

검사 명령도 갈아엎었다. 골격 검사를 폴더 전체에 돌리게 해 뒀더니 규약 이전 로그가 전부
쏟아져 신호가 묻혔다. 새 파일 하나만 보는 검사기로 합쳤다.
