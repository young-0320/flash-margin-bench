# 46. 실칩 전 마지막 두 자물쇠 — probe 와 tally 소거, 그리고 reproduce 가 wear 를 굽는다

- **작성일**: 2026-09-21
- **발단**: 어제 세운 블랙박스 TB 와 P/E 엔진을 실칩에서 돌리려는데, 보드가 둘이라 WSL 을 쓰는 조원도
  자기 PC 에서 같은 계측기를 구워야 했다. `reproduce.py` 에는 wear 단계가 없었고, 런북 12 가 「실칩 전에

  B 행의 0 을 믿게 하는 probe 와, `E_DIRTY` 자물쇠의 열쇠(tally 소거)는 어떤 모양이어야 하나?

## 결정

- [D46-1] `reproduce.py` 기본 순서에 `tb`(블랙박스 TB 114) 와 `wear`(flash_wear.elf) 가 들어간다. `wear` 는 로그의
  `git_rev` 가 체크아웃 HEAD 와 같은지를 ⑥ 으로 대조한다 — §1 · `reproduce.py` · `docs/build_reproduction.md` §3.5·§5.3
- [D46-2] `accept` 의 verdict 9번째 줄이 `probe` 다 — 멈춘 직후 `BLANK` 를 불러 `program_fail_bits` 가 전량(229,376)이어야
  PASS. FAIL 이면 B 행의 0 을 읽지 않는다 — §2 · `host/run/run_wear.py` `judge_accept`
- [D46-3] tally 소거는 엔진 명령 `TALLY_ERASE uid=<16hex>`(경계 10) 와 실행기 `run_wear.py tally-erase` 로 한다.
  `flash_prep` 모드가 아니다 (2026-09-21, 한영웅) — §3 · `ps/src/flash_wear.c` · `host/run/run_wear.py`
- [D46-4] 자물쇠 셋 — 엔진은 `idle` 에서 UID 가 소켓의 칩과 같을 때만(`E_UID`, 범위는 상수 512·1,536), 실행기는
  `--i-approve-tally-erase` 에 더해 사람이 그 칩의 UID 를 타이핑해야 하고, 지우기 전 값을 `chip_pe.md` 에 먼저 적은
  뒤에야 명령을 보낸다 — §3 · S-4 §4 `E_UID` · S-1 §8.1
- [D46-5] WSL 의 USB 넘기기(usbipd)는 `reproduce.py` 에 넣지 않는다. `usbipd.exe attach --wsl --auto-attach` 한 줄을
  문서로 둔다 — §4 · `docs/build_reproduction.md` §1
- [D46-6] `reproduce.py` 는 확인 없이 돌려도 된다 — 덮는 것은 소스에서 다시 만들 수 있는 bit·XSA·ELF 뿐이고 측정
  원본(`build/data`·`logs`·`plots`)은 건드리지 않는다. 측정 직전만 피한다 (2026-09-21, 한영웅) — §5

## 근거

### 1. `reproduce.py` 는 wear 를 몰랐고, prep 채점 문구도 한 커밋 낡아 있었다

이 PC 에는 g2·wear ELF 가 다 있었지만 wear ELF 안의 `git_rev` 가 한 커밋 전(3a0d88f) 이었다 — 커밋
직전에 구웠기 때문이다. H 행의 `git_rev` 는 시험 기록의 신원이라, 「다시 구웠다」(③ mtime)만으로는
부족하고 「어느 커밋으로 구웠나」가 채점에 있어야 했다. 그래서 `wear` 단계의 ⑥ 은 g3 의 steps 대조와
같은 자리에 `git_rev == HEAD` 를 둔다.

기본 순서 전체를 돌리자 `prep` 이 FAIL 로 떨어졌는데 빌드는 성공이었다. 로그 45 의 체크포인트 모드
커밋(769e80d)이 `build_flash_prep.py` 의 완료 문구를 `== done:` 에서 `== done (default 0~127):` 로
바꿨고 채점 문구는 옛것이었다. 스크립트가 문서를 따른다는 규약(로그 32)대로 문서 §3.3 기대 출력과
스크립트를 함께 고쳤다. 채점 문구를 완화(`== done` 접두만)하는 길은 버렸다 — 기본 0~127 이 아닌
체크포인트 변형이 `vitis_prep/` 자리에 구워지는 것을 ⑥ 이 잡아야 하기 때문이다.

`tb` 는 gcc 를 도구 선검사에 넣는다. gcc 가 없으면 sim 케이스가 skip 되고
`test_gcc_absent_is_reported_not_hidden` 이 FAIL 하도록 이미 짜여 있어(로그 45), 선검사에서 미리 죽는
쪽이 「skip 됐는데 초록」보다 낫다. Windows 네이티브는 `build_sim.sh` 가 bash 이고 `wear_plat_host.c` 가
`poll.h` 라 ② 층이 안 된다 — 이번엔 지원하지 않고 WSL 로 안내한다 ([U46-2]).

### 2. probe — 0 은 「제대로 재고 0」과 「세는 경로가 죽어서 0」이 같아 보인다

신품 100사이클의 B 행 정답은 결함 비트 0 이다. 그런데 `program_fail_bits` 를 늘 0 으로 돌려주는
엔진(mock 의 `program_check_dead`)도 같은 B 행을 낸다. harness 의 `check_probe`([로그 42](42.blackbox_tb_gaps_and_jimin_reply.md) §7 · `[D44-7]`)
가 mock·sim 에서는 이것을 가르고 있었는데 실칩 실행기의 verdict 에만 없었다. 멈춘 시점의 마지막
동작이 소거라 `0xFF` 를 패턴 `0x00` 과 대조하면 전량이 나와야 한다는 성질을 그대로 옮겼다.

`BLANK` 자체가 거부되면 `probe` 는 `None` 으로 FAIL 이다 — 「확인 못 함」을 PASS 로 두면 시험 버튼이
안 눌리는 경보기와 같다. `judge_accept` 의 순수 함수 시험에 `program_check_dead` → `probe` FAIL 과
`None` → FAIL 두 경우를 더했다.

### 3. tally 소거 — 열쇠는 있어야 하고, 무거워야 한다

`E_DIRTY` 는 재개를 신규로 착각해 X 축을 지우는 것을 막는 자물쇠다(`[D44-10]`). 자물쇠만 있고 열쇠가
없어서, 첫 실칩 시험이 지저분하게 끝나면 같은 칩으로 0 부터 다시 할 길이 없었다. S-1 §8.1 은 「실험
시작 시 tally 섹터 2개를 각 1회 소거」라고 했고 S-4 §9 는 「실험 개시 소거가 지운다」고 했지만 그
도구는 없었다.

후보 둘. ⓐ `flash_prep` 에 tally 초기화 모드 — 엔진의 「wear 구간 밖은 지우지 않는다」를 지키고,
열쇠가 물리적으로 무겁다(다른 ELF 를 xsct 로 갈아 끼워야 한다). ⓑ 엔진 명령 — 같은 ELF 안에서 끝나고
호스트 시뮬레이션으로 TB 채점이 된다. 영웅님이 ⓑ 를 골랐다 — ⓐ 는 소거 뒤 wear ELF 를 다시 굽는
비용이 매번 붙는다. 대신 `pe_engine.md` §3 의 「한 번도 지우지 않는다」에 경계 10 예외를 명시했다.

「쉽게는 못 지우되 동의를 받으면 지운다」의 실체를 셋으로 나눴다. 엔진 쪽은 `idle` 에서만, 그리고
`uid` 인자가 부팅 때 읽은 칩 UID 와 같아야 한다 — 호스트가 소켓의 칩을 알아야 지울 수 있다는 뜻이고,
범위는 인자로 못 바꾼다. 실행기 쪽은 `y/n` 을 버리고 **UID 타이핑** 으로 했다 — `y` 는 손이 먼저
간다. 셋째가 요점이다. tally 는 칩이 스스로 기억하는 마모 눈금이니, 지우기 전 값을 `chip_pe.md` 에
512·1,536 `+1` 두 행(비고 「tally erase · 지운 값 a= b=」)으로 먼저 옮기고, 장부 기입이 실패하면
명령을 보내지 않는다. 자동 소거(`accept --cycle 0` 이 `E_DIRTY` 를 받으면 알아서 지우기)는 애초에
후보에서 뺐다 — S-4 §4 가 「자동으로 소거하지 않는 것이 핵심」이라고 못박았다.

작은 함정 하나. 명령 파서가 값을 `int(v, 0)` 으로 먼저 시도하므로 숫자로만 된 UID(`1234…`)가 정수로
새어 문자열 비교가 깨진다. `uid` 키만 문자열로 고정했고 그 케이스를 왕복 시험에 넣었다. 소문자
UID 도 같은 칩으로 받는다(엔진은 대문자로 바꿔 비교).

### 4. usbipd 를 `reproduce.py` 가 대신 쳐 줄 것인가 — 안 한다

조원이 매번 손으로 치던 것이라 넣을까 했지만 둘 다 아니었다. 첫째, `reproduce.py` 는 보드를 만지지
않는다는 범위(로그 32, §4 굽기 제외)와 같은 이유로 USB 도 범위 밖이다. 둘째, BUSID 가 PC 마다 달라
설정 파일이 하나 더 생긴다. 대신 usbipd-win 4 부터는 WSL 안에서 `usbipd.exe attach --wsl --auto-attach`
를 치면 그 터미널이 사는 동안 보드를 뺐다 꽂아도 다시 붙으므로, 세션마다 한 줄이면 된다. 이 절차는
이 PC 에서 검증할 수 없어 문서에 「미검증」으로 표시했다 ([U46-1]).

### 5. 덮어쓰기 걱정 — 되돌릴 수 없는 것만 세면 답이 나온다

전체 실행을 확인 없이 돌렸다가 「이전 build 가 지워지는 것 아니냐」는 지적을 받았다. 실제로 g0·g2·prep
이 제자리에서 덮였고 `_prev` 에 직전 1세대만 남았다. 그러나 `build/` 에서 되돌릴 수 없는 것은
측정 원본(`data`·`logs`·`plots` 의 실측분)이고, 스크립트는 그것을 건드리지 않는다 — selftest 의 합성
CSV·그림 두 장만 매번 새로 쓴다. bit·ELF 는 `rm -rf build` 뒤 다시 만들 수 있어야 재현이라는 문서
§7 의 전제 그대로다. 그래서 [D46-6] 으로 정리했고, 남는 주의는 「측정 직전엔 돌리지 말 것」과 「돌린
뒤 무엇이 덮였는지 한 줄 알릴 것」 둘이다.

  `wear_plat_host.c` 의 `poll` 을 Windows 분기로 갈라야 한다. 지금은 WSL 로 안내한다. 세은 쪽 수요가 생기면 정한다
