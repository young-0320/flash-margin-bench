# 33. `reproduce.py` Windows 대응 — 다섯 개의 벽, 그리고 빌드 신원 논의(보류)

- **작성일**: 2026-09-16
- **발단**: 세은이 Windows 에 Vivado 를 깔고 `reproduce.py` 를 돌렸는데 계속 실패했다.
  스크립트가 POSIX 셸 + Linux PATH 를 전제로 짜여 있었다([로그 32](32.reproduce_script.md)는
  Ubuntu 24 에서만 검증). 네 자리를 고치고도 세은 PC 가 막혔고, 남은 벽이 인코딩이었다.
  같은 날 "지금 내가 든 빌드가 어느 세대인지 모르겠다"가 3인 공통 체감으로 올라왔다
- **목적**: Windows 에서 왜 안 되나? 셋이 각자 구운 산출물이 같은 것인지 무엇으로 아나?
- **관련**: [로그 32](32.reproduce_script.md) · `docs/build_reproduction.md` §3·§5·§6 ·
  `docs/workflow/10.newchip_survey_completion.md` §B · `docs/log/seeun/1` · `docs/log/jimin/5`

## 결정

- [D33-1] **셸을 아예 걷어낸다** — `cmd` 를 argv 리스트(또는 리스트의 리스트)로 바꾸고 glob 은
  `Path.glob` 으로 파이썬이 편다. 따옴표 문제는 셸이 없으니 생기지 않는다 — §2-2 · `reproduce.py`
- [D33-2] `.bat`/`.cmd` 는 `cmd /c` 로 감싼다(`tool()`). Linux 에서는 `which` 결과를 그대로 쓴다 —
  §2-1 · `reproduce.py`
- [D33-3] `exec env G3_MHZ=$mhz` 를 `set ::env(G3_MHZ)` 로 바꾼다 — §2-3 ·
  `fpga/scripts/build_g3_chip.tcl` · `build_g0_loopback.tcl`
- [D33-4] 자식 env 에 `PYTHONUTF8=1` 을 강제한다. **한글 주석을 ASCII 로 바꾸는 길은 택하지
  않는다** — 원인은 한글이 아니라 읽는 쪽의 로케일 가정이다 — §2-5 · `reproduce.py` `run_step()`
- [D33-5] 진행 표시는 자식 출력을 **파이프로 빨지 않고** 로그 파일 꼬리에서 이정표를 줍는다.
  `sleep` 이 아니라 `proc.wait(timeout=5)`, 비 tty 는 `isatty()` 로 거른다 — §3 ·
  `reproduce.py` `watch()`
- [D33-6] **빌드 신원 관리는 보류** — 0단계와 입력 해시를 구현해 동작까지 확인한 뒤 되돌렸다.
  W10-B 에서 재개한다 — §4-5
- [D33-7] `program_*.tcl` 의 `exec unzip` 은 이번에 건드리지 않는다 — §4 보드 굽기라
  `reproduce.py` 범위 밖이다 — [U33-2]

## 근거

### 2. Windows 에서 깨진 다섯 자리

앞의 넷이 [로그 32](32.reproduce_script.md) 판의 이식성 결함이고, **다섯째가 그것을 다 고친
뒤에도 남은 벽**이다. 넷만 고쳤으면 g3 에서 다시 막혔고, 다섯째가 없으면 세은 PC 는 여전히
죽었다.

#### 2-1. `.bat` 런처 — 선검사는 통과하고 실행에서 죽는다

Windows 의 Vivado/Vitis 는 `vivado.bat` / `vitis.bat` 다. `shutil.which("vivado")` 는
`PATHEXT` 를 보므로 **`.bat` 를 찾아내** 도구 선검사를 통과시키는데,
`subprocess.run([...], shell=False)` 가 부르는 `CreateProcess` 는 **`.exe` 만** 자동으로
붙인다 → `WinError 2`. "도구는 다 있다고 해놓고 첫 단계에서 죽는" 증상의 정체다.

#### 2-2. 셸 문자열 — glob 과 따옴표

`sim`·`selftest` 가 `&&` 로 이어붙인 문자열이었고 `shell=True` 로 돌았다. Windows 에서는
`cmd.exe` 가 받는데, `../../fpga/rtl/core/*.v` 를 **cmd.exe 는 펴주지 않고**(bash 가 대신
해주던 일), `{log_dir}` 치환값에 인용이 없어 사용자명이 한글이거나 경로에 공백이 있으면
깨진다. 셸을 걷어내면 둘 다 없어지고, 앞이 실패하면 멈추는 `&&` 의미는 리스트의 리스트로
유지된다.

#### 2-3. `exec env G3_MHZ=$mhz` — 이게 진짜 벽이었다

`build_g3_chip.tcl` 이 Vitis 를 체인 호출할 때 클럭을 `exec env G3_MHZ=$mhz $vitis_exe …`
로 넘기고 있었다. `env(1)` 은 POSIX 코어유틸이라 **Windows 에 없다** — `reproduce.py` 를
아무리 고쳐도 g3-25/45/75 세 단계는 여기서 죽는다. Tcl 은 `::env` 배열을 자식에게 그대로
넘기므로 `set ::env(G3_MHZ) $mhz` 뒤에 `exec $vitis_exe …` 로 바꿨다. Linux 동작은
동일하고, 프로세스 하나를 덜 띄운다.

#### 2-4. 잔가지

- `-source` 경로를 `as_posix()` 로. Tcl 은 Windows 에서도 `/` 를 받고, 백슬래시는
  Tcl 이스케이프(`\b`, `\f`)와 섞일 여지가 있다
- `vitis_exe` 탐색에 `.bat` 분기 추가 — 없으면 `XILINX_VIVADO` 가 잡혀 있어도 PATH 폴백으로
  새어나간다. 로그·요약 파일 인코딩은 utf-8 로 고정, 도구 누락 안내에 `settings64.bat` 추가

#### 2-5. 다섯 번째 벽 — cp949

세은 문서(`docs/log/seeun/1`)에 증상이 둘로 나뉘어 기록돼 있었다.

| 증상 | 어디서 | 정체 |
| ---- | ------ | ---- |
| `UnicodeEncodeError: cp949` | selftest 단계 | 자식 파이썬이 **한글 출력을 인코딩하다** 죽는다 |
| `UnicodeDecodeError: cp949` | Vitis 빌드 | Vitis 내장 파이썬이 **`ps/src/*.c` 를 읽다** 죽는다 |

두 번째가 본체다. `build_g0_sweep.py` 의 `app.import_files()` 가 소스를 복사할 때 AMD 쪽
파이썬이 로케일(Windows 기본 cp949)로 디코드하는데, 우리 PS 소스는 네 개 전부 한글을
담고 있다 — **주석만이 아니라 `xil_printf` 문자열 리터럴에도** 있다(`core_smoke.c` 18개 ·
`flash_prep.c` 17 · `g0_sweep.c` 11 · `flash_jedec.c` 6).

원인은 한글이 아니라 **읽는 쪽의 로케일 가정**이다. 그래서 주석을 ASCII 로 바꾸는 길은
택하지 않았다 — 문서 가치를 버리면서 원인도 안 고쳐진다. 자식 env 에 한 줄을 강제한다.

```python
env = {**os.environ, "PYTHONUTF8": "1", **st.get("env", {})}
```

`os.environ` **뒤**에 놓아 부모 셸 설정을 이긴다. 상속 경로가 `reproduce.py → cmd /c
vivado.bat → vivado → exec vitis.bat → Vitis 파이썬` 전 구간이므로, 세은 문서 §4-2·§4-3 의
수동 `chcp 65001` · `set PYTHONUTF8=1` 두 줄이 불필요해진다. 세은 문서 §4-1 의
`child process exited abnormally`(tcl→vitis 체인 실패)도 이것이 원인일 가능성이 높다 —
`exec` 가 자식의 죽음을 그 문구로 던진다. **확인은 세은 재실행 대기**([U33-5]).

§2-4 의 utf-8 고정(로그 **파일**)으로는 이게 안 닫힌다. 자식은 파이프에 쓰기 **전에**
인코딩하므로 부모의 파일 인코딩과 무관하다.

### 4. 빌드 신원 관리 — 논의 정리 (결론: 보류)

#### 4-1. 문제

`.bit`·`.elf` 는 git 에 없다(용량·바이너리·비결정성). 셋이 각자 구운 산출물을 들고 있는데
**라벨이 없다.** 측정 CSV 의 `git_rev` 열이 있긴 하나 그 값은 **캡처를 실행한 순간 호스트의
HEAD** 다(`sweep_uart_capture.py:66`) — 3일 전 구운 ELF 로 측정해도 오늘 rev 가 찍힌다.
보드 배너에도 빌드 신원이 없다. 즉 **"이 데이터를 뽑은 계측기가 무엇이었나"를 지금 아무도
기록하지 않는다.**

#### 4-2. 오늘 확인된 사실 — 네 숫자는 지문 노릇을 한다

§3 의 2회 재빌드에서 WNS/WHS/LUT/FF 가 9/14 기준값과 **소수점까지 일치**했다. `.bit` 해시
비교가 불가능한 상황에서 이 네 숫자가 실무적 지문이 된다는 근거다. 단, **네 숫자가 없는
단계가 있다** — `g2`(PL 로직 없음)와 `prep`. ELF 는 타이밍 리포트를 만들지 않고, 신품
검사에 쓰는 `flash_prep.elf` 가 여기 속한다.

#### 4-3. 후보 셋과 각자의 한계

| 후보 | 무엇의 지문 | 언제 | 한계 |
| ---- | ----------- | ---- | ---- |
| `git rev` | 커밋 | 즉시 | **문서만 커밋해도 값이 바뀐다** → 거짓 불일치 |
| 입력 내용 해시 | 빌드 입력 파일 | 즉시 | 툴·OS 차이를 못 본다 |
| WNS/WHS/LUT/FF | 빌드 **결과** | 빌드 후(9분) | g2·prep 에는 없다. 왜 다른지 못 말한다 |

거짓 불일치 시나리오(영웅 지적): `c1` 에서 빌드 → 문서만 커밋해 `c2` → 세은이 `c2` 로 빌드.
설계는 동일한데 `c1 ≠ c2` 라 다른 빌드로 보인다. 입력 내용 해시를 시제품으로 만들어
확인한 결과, 문서만 커밋하면 해시는 그대로이고 rev 만 바뀌며, RTL 을 고치고 커밋하지
않으면 해시만 바뀐다 — 즉 **rev 가 못 보는 두 방향을 해시가 본다.**

둘을 겹치면 원인까지 갈린다.

| 입력 해시 | 네 숫자 | 해석 |
| --------- | ------- | ---- |
| 같음 | 같음 | 같은 계측기 |
| 같음 | 다름 | **환경(툴·OS)이 결과를 바꿨다** ← 세은·지민 환경에서 나올 수 있는 경우 |
| 다름 | 같음 | 설계에 영향 없는 수정이었다 |
| 다름 | 다름 | 다른 설계 |

#### 4-4. 3단계 로드맵 (구현 시 참고)

| 단계 | 무엇 | 답하게 되는 질문 |
| ---- | ---- | ---------------- |
| 0 | 실행 요약 머리말에 신원 한 줄 | "우리 셋이 같은 걸 구웠나" (사람이 대조) |
| 1 | 산출물 옆 `.provenance` + `--check-only` | "지금 내 `build/` 는 어느 소스 것인가" (빌드 없이) |
| 2 | ELF 에 rev 를 심어 보드가 배너로 말함 → CSV 열 | "이 데이터는 어느 계측기가 뽑았나" (데이터가 증언) |

0·1 은 PC 안에서 닫히고, **2 라야 "보드에 실제로 올라간 것"까지 닫힌다.**

#### 4-5. 보류의 근거

0단계와 입력 해시를 실제로 구현해 동작까지 확인한 뒤 **되돌렸다.**

- 기능을 늘리기 전에 **Windows 경로부터 닫는 것**이 우선이다. 세은 확인이 아직 안 왔다
- 어디에 보존할지(승격처)가 안 정해졌다. `build/` 는 gitignore 라 **증발한다** — 오늘 실제로
  1회차 성공 요약이 `build/` 를 새로 만들면서 사라졌고, 채팅에 붙여둔 텍스트가 유일본이었다
- W10-B(`docs/workflow/10` §B)에 이미 트랙이 있다. 거기서 재개한다

## 미결

- **[U33-1] §3.5 기준표(BASELINE)를 플랫폼별로 나눌 것인가** — 현재 값은 Ubuntu 24 +

- **[U33-4] 빌드 신원 관리를 어디까지 갈 것인가** — §4 보류. W10-B 에서 재개하며, 그때

  같이 정한다. 보존처가 없으면 0단계도 의미가 없다 (§4-5)
- **[U33-5] 세은 재실행 1건** — `PYTHONUTF8` 수정본으로 `python reproduce.py --no-sim`.

  Windows 경로가 닫힌다. 그대로면 여섯 번째 벽이 있다
