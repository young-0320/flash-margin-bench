> 정본은 `docs/build_reproduction.md` 「한 줄로 전부」다. 여기 적혀 있던 단계 목록과 소요

> 두지 말라는 이유가 이것이다.

### 2.1 채점 — 단계마다 다섯 가지

**종료 코드 하나로 판정하지 않는 것이 핵심이다.** `vitis -s` 는 빌드가 깨져도 0 을 돌려줄 수 있다.

| # | 검사 | 잡는 실패 |
| - | ---- | --------- |
| ① | 명령 종료 코드 | 명시적 실패 |
| ② | 로그의 완료 문구 (횟수까지) | 조용한 실패. 시뮬은 `PASS: all checks passed` ×4, 셀프테스트는 `selftest PASS` ×2 + 체크리스트에 `FAIL` 행 없음 |
| ③ | 산출물이 존재하고 **이번 단계 시작 이후에 생겼는지** | **옛 산출물이 남아 성공처럼 보이는 경우** — 발단이 된 그 유형이다 |
| ④ | (Vivado) 타이밍 리포트에 `All user specified timing constraints are met` | 타이밍 위반 비트로 측정하는 것. 리포트가 없어도 실패 |
| ⑤ | (Vivado) WNS/WHS·LUT/FF 를 §3.5 기준표와 대조 | 같은 커밋·같은 툴인데 배치가 다른 경우 → **FAIL 이 아니라 WARN** |
| ⑥ | (g3) 빌드 파라미터 — `== done (<mhz>MHz, steps=…, n_reads=112)` 대조 | **무엇으로 구웠는지.** ③ 은 "다시 구웠다"만 말한다 — 발단이 된 45·75MHz N=100 세대 혼합이 정확히 이 층에서만 잡힌다. 빌드 스크립트가 이미 찍는 줄이라 비용 0 |

⑤ 를 WARN 으로 둔 것은 문서를 따른 것이다 — §3.5 는 "값이 다르면 실패는 아니지만 로그에 적는다".
다른 배치가 폭 측정에 나타나는지는 측정으로만 알 수 있으므로 스크립트가 판정할 일이 아니다.

### 2.2 백업 — Vitis 가 워크스페이스를 통째로 지우기 때문

`build_flash_prep.py` 등 Vitis 빌드 스크립트는 첫머리에서 `shutil.rmtree(WS)` 로 워크스페이스를
지우고 시작한다(증분 상태가 쌓이면 Vitis 가 거부하므로 의도된 동작이다). 그래서 **C 가 컴파일
에러면 새 ELF 도 없고 옛 ELF 도 없는 상태**가 된다.

- 단계 시작 전에 그 단계의 산출물(ELF·XSA·bit)만 `build/_prev/<단계>/` 로 복사한다
- **직전 1세대만** 둔다. `manifest.txt` 에 시각을 적는다
- **복원은 사람이 한다** — 실패 요약에 경로만 찍는다. 자동 복원은 "고쳤다고 착각시키는" 쪽이라 두지 않았다

### 2.3 로그

`build/logs/reproduce_<UTC>/<단계>.log` + `summary.txt`. 각 로그 첫 줄에 실제 명령과 `cwd` 를 적어,
나중에 그 단계만 손으로 재현할 수 있게 했다.

## 3. 위치를 최상위로 정한 근거

처음 `scripts/reproduce.py` 로 두었으나 `CONTRIBUTING.md` §1 배치 기준과 부딪혔다.

| 후보 | 문제 |
| ---- | ---- |
| `scripts/` (신설) | 원칙 1 위반 — 폴더 이름은 "어디서 도는가"(`ps/` `host/` `sim/`) 또는 "무엇을 생산하는가"(`fpga/` `hw/`) 기준인데 일반명사다. 게다가 `fpga/scripts/`·`ps/scripts/` 와 이름이 겹쳐 세 곳이 된다. 원칙 2(소유자 1명)도 미지정 |
| `host/run/` | 자리는 자연스러우나 **`host/` 의 뜻이 흐려진다** — "PC 가 보드를 상대로 측정하는 코드"인데 빌드 도구가 섞인다. `run_sweep_chip` 이 `ps/scripts/program_*.tcl` 을 부르는 것은 **굽기(측정의 일부)**지만, Vivado 합성은 측정이 아니다 |
| **최상위** | **채택.** fpga·ps·sim·host 를 전부 가로지르므로 어느 하위 폴더에도 속하지 않는다. 최상위에는 이미 `README.md`·`CLAUDE.md`·`pyproject.toml` 처럼 리포 전체를 가리키는 것만 있다 |

폴더를 신설하면 규칙 개정(폴더 + 소유자 선언)이 필요하지만, 최상위 파일 하나는 §1 트리에 한 줄이면
끝난다. 진입점이 짧아지는 것도 이득이다 — `build_reproduction.md` 가 "측정하는 PC마다 이 절차로
만든다"고 말하는 문서인데, 그 실행 파일이 리포를 열자마자 보인다.

**이름은 `reproduce.py`.** 리포의 실행물은 동사(`build_*` `program_*` `run_*` `check_*`)이고
명사형은 라이브러리·데이터 성격(`chip_registry` `bathtub_analysis`)이다. `reproduction.py` 는
문서(`build_reproduction.md`)와 이름이 겹쳐 한 번 헷갈린다.

### 4.1 점검에서 고친 것 5건

| # | 증상 | 처치 |
| - | ---- | ---- |
| 1 | `--only sim --no-sim` 처럼 서로를 지우면 **빈 목록인데 종료 코드 0** — 아무것도 안 돌고 초록이 뜬다 | 시작 전 `sys.exit`. `check_coverage.py` 의 "0행 파싱 → 파서 고장", `chip_registry.py` 의 "비어 있음을 정상으로 받지 않는다"와 같은 자를 댄다 |
| 2 | `--vitis-only --only g3-25` 를 주면 `--only` 가 조용히 이겨 **Vivado 합성이 돈다** (생략하려던 의도와 정반대) | argparse 상호 배타 그룹 — 동시 지정은 rc=2 로 거부 |
| 3 | **검증(sim·selftest)이 실행 순서 맨 뒤** — RTL 이 깨져 있으면 스모크 5초로 알 수 있는 것을 Vivado 16분 태우고 알게 된다 | `FULL`·`VITIS_ONLY` 앞으로. 문서 「전체 흐름」이 이미 검증 루프를 먼저 적고 있었다 |
| 4 | Vivado 리포트 파싱이 빗나가면 note 가 `(PL 로직 없음)` 으로 찍혀 **파서 고장을 배치 변경으로 오진**한다 | 기준표가 있는 설계는 타이밍 경로가 반드시 있으므로, 파싱 실패면 `수치 파싱 실패` + 전용 경고. `(PL 로직 없음)` 은 기준표가 없는 g2 에만 |
| 5 | `--vitis-only` 의 `g0e` 가 `ps7_init.tcl` 을 확인하지 않는다 | `program_g0.tcl` 이 굽을 때 쓰는 파일이라 빠지면 굽는 순간 터진다. `g0` 단계와 같이 산출물에 포함 |

정상으로 확인한 것: 모르는 단계는 rc=1 로 시작 전 중단(`--list 참고` 안내), 도구 부재는
`shutil.which` 선검사, FAIL 시 로그 마지막 15줄 + 백업 경로 출력 후 중단(`--keep-going` 으로 계속),
종료 코드는 **FAIL 이 있거나 실행 단계 수가 요청보다 적으면 1**.

## 5. 미결 의사결정

| # | 항목 | 상태 |
| - | ---- | ---- |
| 1 | g0·g3 Vivado **전체 경로 미검증** | 완료 문구와 산출물 경로를 소스에서 대조만 했다. 8분×4 ≈ 30분이면 되므로 한 번은 실제로 통과시켜야 "돌려 확인했다"가 된다 |
| 2 | `build/_prev` 가 `build/` 아래인 것 | `rm -rf build` 로 백업도 같이 날아간다. 직전 1세대일 뿐이니 수용 가능하다는 판단이나, 명시적으로 정하지 않았다 |
| 3 | **검사 전용 모드가 없다** | 채점 ③이 "이번 실행 이후 생성"을 요구하므로 빌드 없이 현 상태만 채점할 수 없다. 그런데 이 도구의 발단("내 `build/` 가 최신인가")에는 그 모드가 가장 직접적이다. `--check-only` 를 넣으려면 ③을 "산출물이 소스보다 새로운가"로 바꿔야 한다 |
| 4 | PAY_LEAD 보험 비트(§8)를 단계로 넣을지 | 지금은 범위 밖. 다만 실칩에서 전 위상 BER≈0.5 가 뜬 순간엔 급하다 |
| 5 | 비트스트림 내용 검증은 없다 | `.bit` 은 헤더에 생성 시각이 들어가 해시 비교가 안 된다(§3.5). 채점 ⑤(타이밍·자원 수치)가 그 대용이며 그 이상은 방법이 없다 |
| 6 | CI 연결 | 지금은 사람이 부르는 도구다. 조원 PC 전개(워크플로 8 W8-T)에서 "각자 빌드 → 루프백 1회" 의 앞쪽을 이 스크립트가 대신할 수 있다 |
