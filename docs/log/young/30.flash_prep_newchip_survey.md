## 1. 산출물

본 문서가 정의하는 것은 **`ps/src/flash_prep.c` 단일 파일 변경**이다. 구현이 끝나면 다음이 생긴다.

| # | 산출물 | 위치 |
| - | ------ | ---- |
| 1 | `blank_pre` — 출고 시점 결함 비트 수 + 주소 | UART `#PREP BLANK pre` / `#PREP BLANKADDR pre` |
| 2 | `blank_post` — 소거 잔여 비트 수 + 주소 | UART `#PREP BLANK post` / `#PREP BLANKADDR post` |
| 3 | 섹터별 소거 시간 128건 + 요약 | UART `#PREP ERASE` / `#PREP ERASE SUMMARY` |

1차 착지는 세션 로그(§6). 기계가 쓰는 CSV(2단)와 사람이 쓰는 집계 md(3단)는 별도 작업이다.

## 2. 왜 이 셋인가 — 일회성의 성격이 서로 다르다

| 기능 | 복원 가능한가 | 판단 |
| ---- | ------------- | ---- |
| `blank_pre` | **불가.** 소거는 비트를 1로만 되돌리므로 첫 소거 후에는 질문 자체가 소멸 | 게이트로 유지할 값어치 있음 |
| `blank_post` | 마모 체크포인트마다 계속 잰다. 일회성인 것은 **x=0 점** 하나 | 같이 넣는다 (같은 함수) |
| 소거 시간 | 마찬가지로 x=0 점만. 1 P/E 차이는 10k 사이클 스케일 변화에 비하면 미미 | **기능은 넣되 게이트 논리로는 약하다** |

`blank_pre`의 실효는 **동일성 대조**다. 마모 후 "페이지 1,203 / 바이트 5 / 비트 3"이 나왔을 때
그 비트가 t=0에도 굳어 있었는지를 물어야 하는데, 개수만으로는 신품 3개 → 마모 후 5개에서
"그 5개가 그 3개를 포함하는지"를 알 수 없다. 그래서 주소를 남긴다.

정직한 단서: W25Q64JV는 출고 시 소거 상태로 나오므로 **10개 전부 `bits=0`이 나올 가능성이 높다.**
이것은 발견이 아니라 보험이며, 마모 후 결함 비트가 실제로 안 나오면 안 써먹은 보험으로 끝난다.
보험료가 30초라 들어둘 만하다는 판단이다.

`blank_post`는 던지는 질문이 다르다 — `blank_pre`가 *"타고난 결함이 있나"*라면 `blank_post`는
*"우리 소거가 먹었나"*다. 신품에선 둘 다 0이 나올 텐데 **그 0이 서로 다른 0**이다. 부수 효과로
**소거 검증이 처음 생긴다** (현재 prep은 소거 성공 여부를 안 보고 바로 프로그램한다).

## 3. 확정 사실 (HEAD 기준 실측)

| # | 항목 | 확인 결과 |
| - | ---- | --------- |
| A | 기존 버퍼 | `tx`/`rx` = `PAGE_BYTES + 4` = 260B (`flash_prep.c:47`). 최대 사용은 PP/READ의 260B — 여유 없음, 초과 없음 |
| B | SPI 클럭 | 프리스케일 64 ≈ **2.6MHz** (`:106`) |

| E | XTime | ~~`xtime_l.h`~~ → **`xiltimer.h`** (구현 중 정정, 2026-09-15): 2025.2 BSP는 xiltimer 라이브러리라 앱이 포함할 수 있는 헤더는 `xiltimer.h`뿐. `typedef u64 XTime`, `COUNTS_PER_SECOND = 코어클럭/2`, `void XTime_GetTime(XTime *)`는 그대로. **단, 시계(글로벌 타이머)가 자동으로 켜지지 않는다** — §4.4 참고 |

| G | 덮어쓰기 관례 | 캡처는 `open(path, "x")`로 생성한다 (`sweep_uart_capture.py:108`) — 신품 조사 파일도 같은 자를 쓴다 |

## 4. 명세

### 4.0 삽입 위치

```
:107  JEDEC 9Fh 검사                        (기존)
:118  UID 4Bh ×3회 일치 → #PREP UID          (기존)
:147  #PREP BEGIN                           (기존)
 ───► F1  blank_pre 스캔                     신규
:149  섹터 소거 루프 ×128
 ───► F3  섹터별 WIP 지속시간 계측            신규 (루프 안)
:156  #PREP erase done
 ───► F3  #PREP ERASE SUMMARY                신규
 ───► F2  blank_post 스캔                    신규
:158  페이지 프로그램 루프 ×2048             (기존)
:168  read-back 전수 비교 → #PREP PASS/FAIL  (기존)
```

### 4.1 새 상수

```c
#define CHIP_PAGES       32768u     /* W25Q64JV = 64Mbit / 256B */
#define BLANK_PRE_PAGE0  0u
#define BLANK_PRE_PAGES  CHIP_PAGES /* 전역 스캔 (S-2 §5) */
#define BLANK_ADDR_CAP   1024u      /* 주소 "출력" 상한 — 배열 크기가 아니다 */
#define ERASE_WARN_US    400000u    /* S-1 §10 */

_Static_assert(BLANK_PRE_PAGE0 + BLANK_PRE_PAGES <= CHIP_PAGES, "blank 범위가 칩을 넘는다");
_Static_assert(N_PAGES <= CHIP_PAGES, "prep 범위가 칩을 넘는다");
```

`_Static_assert`가 막는 것: `addr3()`는 3바이트 주소라 범위 상수를 손으로 키우다 페이지 32,768을
넘기면 **상위 비트가 조용히 잘려 엉뚱한 주소를 읽는다.** 에러 없이 값만 틀리는 유형이므로
빌드 타임에 죽인다 (이 파일의 loud-failure 관례와 같은 결).

### 4.2 F1 `blank_pre` — 소거 전 판독 (G-d 전반)

| 항목 | 값 |
| ---- | -- |
| 위치 | `#PREP BEGIN`(:147) 직후, 소거 루프(:149) 전 |
| 범위 | 페이지 0 ~ 32,767 (8MB 전역) |
| 명령 | `03h` @2.6MHz — 기존 verify 루프와 동일 경로 |
| 세는 것 | `0xFF`가 아닌 **비트 수**(= 0으로 굳은 비트) + 그 바이트 수 + 주소 |
| 비용 | ≈ 30초 (실측을 `t_ms`로 출력) |
| 판정 | **없음** |

**재실행 시 대량 검출은 정상이다.** 이미 prep을 돌린 칩(chip01)은 페이지 0~2,047에 PRBS가 살아
있어 수백만 비트가 나온다. 고장이 아니라 "이 칩은 신품이 아니다"라는 정상 관측이며, 여기서
FAIL을 내면 chip01 재측정이 매번 중단된다.

### 4.3 F2 `blank_post` — 소거 직후 판독 (G-d 후반)

| 항목 | 값 |
| ---- | -- |
| 위치 | `#PREP erase done`(:156) 직후, 프로그램 루프(:158) 전 |
| 범위 | **페이지 0 ~ 2,047 — 소거한 범위만** |
| 비용 | ≈ 1.6초 |
| 정의 | S-1 §7 `erase_residual_bits`와 동일. F1과 **같은 함수**를 범위만 바꿔 호출 |
| 판정 | **없음** |

**S-2 §5 문구와 어긋나는 지점.** §5는 범위를 "칩 전역"으로 적었으나, `blank_post`에 전역을
적용하면 지우지도 않은 영역을 "소거 잔여"로 세게 된다. 소거 범위 밖은 애초에 소거 직후 상태가
아니다. 구현은 소거 범위로 하고 **§5 문구를 정정 대상으로 올린다**(§8).

### 4.4 F3 섹터별 소거 시간 (G-b / B-1)

| 항목 | 값 |
| ---- | -- |
| 위치 | 기존 소거 루프(:150~155) 안 |
| 재는 것 | `SE`(20h) 전송 완료 ~ WIP(RDSR1 bit0) 해제까지의 지속시간 (S-1 §6 정의) |
| 방법 | `XTime_GetTime()` 전후차 → `COUNTS_PER_SECOND`로 us 환산 후 `u32` 캐스트 |
| 해상도 | WIP 폴링 1회 ≈ 6us (2바이트 @2.6MHz). 소거 45ms 대비 충분 |
| 비용 | **0** — 이미 도는 루프다 |
| 경고 | `ERASE_WARN_US` 초과 시 경고 1행, **계속** |

**`wait_wip_clear()`는 고치지 않는다.** 소거 루프 호출부에서 전후로 `XTime_GetTime`을 감싸면
되고, 그러면 같은 함수를 쓰는 프로그램 루프가 영향받지 않는다 (surgical 원칙).

**시계를 직접 켜야 한다 (구현 중 발견, 2026-09-15).** `XTime_GetTime()`은 CPU 안의 글로벌 타이머라는
카운터를 읽기만 하고, 이 카운터는 리셋 후 멈춰 있다. 예전 BSP는 부팅 코드가 main 전에 켜 줬는데
2025.2 BSP(xiltimer)는 `usleep()`을 처음 부를 때 켜도록 미뤄 놓았고, `flash_prep`은 usleep을 안 쓴다.
그대로 재면 에러 없이 소거 시간이 전부 0으로 나온다. 그래서 main 초입에 타이머 enable 1줄
(`Xil_Out32(XPAR_GLOBAL_TMR_BASEADDR + 0x08u, 1u)`)을 넣었다 — 명세 밖이지만 없으면 F3이 무효다.
첫 실행에서 `#PREP ERASE` 값이 0이 아니면(typ 45,000us 근처) 켜진 것이다.

**PS는 중앙값을 내지 않는다.** 128개를 담아 정렬하려면 배열이 필요하고 그게 피하려는 것이다.
PS가 들고 있는 것은 `min`·`max`·`sum` 스칼라 셋뿐이고, 중앙값·섹터 간 산포는 호스트가 낸다.

**128행을 전부 찍는 이유**: S-1의 마모 설계가 한 칩 안에서 섹터 0~6(마모) / 7~13(근접 대조) /
121~127(원격 대조)을 다르게 간다. "마모군 섹터의 소거 시간이 늘었다"를 주장하려면 그 섹터들의
신품 값이 **각각** 있어야 하고, 중앙값 하나로는 대조군 비교가 성립하지 않는다. 921600bps에서
128행은 0.02초다(전환 전 115200에서도 0.1초).

### 4.5 출력 규약

```
#PREP BLANK pre  range=<p0>-<p1> bits=<n> bytes=<m> shown=<s> t_ms=<t>
#PREP BLANKADDR pre <page> <byte> <mask>
#PREP BLANK post range=<p0>-<p1> bits=<n> bytes=<m> shown=<s> t_ms=<t>
#PREP BLANKADDR post <page> <byte> <mask>
#PREP ERASE <sector> <us>
#PREP ERASE WARN sector <sector> <us>us > 400000us — 계속 진행   (초과 섹터에만, 정규 행 다음에 1행 추가)
#PREP ERASE SUMMARY n=<k> min=<us> max=<us> mean=<us> over400ms=<k>
```

- `mask`는 그 바이트에서 0으로 굳은 비트 위치(`~rx[]`). 비트마다 행을 내면 8배가 되므로 바이트 단위
- `shown < bytes` 면 주소가 상한에서 잘렸다는 뜻 — 별도 절단 표시줄을 두지 않는다
- **`tok[1]`에 `FAIL`/`ERROR`를 쓰지 않는다.** 호스트 배치 중단 신호다 (§3-F)

## 5. 안전 규칙 (버퍼 오버플로 차단)

1. **배열을 만들지 않는다.** 결함 주소는 스캔 중 그 자리에서 UART로 흘린다. `BLANK_ADDR_CAP`은
   **찍은 줄 수를 세는 스칼라 카운터**이며 배열 크기가 아니다 → 오버플로할 대상이 없다
2. 소거 시간도 같은 원칙 — 128칸 배열 없이 즉시 출력 + 스칼라 3개
3. 새 버퍼를 만들지 않고 기존 `tx`/`rx`(260B)를 재사용한다. 기존 verify 루프(`:171~176`)와 동일 패턴
4. `_Static_assert`로 주소 절단 함정을 빌드 타임에 차단 (§4.1)
5. `u32`는 `%u`로 찍는다 — `xil_printf`가 `SUPPORT_64BIT_PRINT`라 `%lu`는 64비트 va_arg다.
   us 환산값은 `u32`로 캐스트해서 넘긴다 (400ms = 400,000us이므로 안전)
6. **새 기능은 절대 중단시키지 않는다.** prep의 합격 판정은 지금처럼 PRBS verify만이다

## 6. 산출물 저장 위치 — 3단

### 1단 (이번 구현으로 즉시) — 세션 로그

```
build/data/session_<label>_<uid16>_<batch_id>.log
```

`run_prep()`이 `#PREP` 줄을 전부 남긴다(§3-F). **호스트 파서 수정 불요.**
읽기 스윕 산출물(`build/data/sweep_<label>_<uid16>_<stamp>.csv` + `_reads.csv`)과는 완전히 별개 파일이다.

### 2단 (별도 작업 — 미구현) — 기계가 쓰는 CSV

```
build/data/survey_<label>_<uid16>_<stamp>.csv           요약 1행
build/data/survey_<label>_<uid16>_<stamp>_defects.csv   결함 비트 1개당 1행
build/data/survey_<label>_<uid16>_<stamp>_erase.csv     섹터 1개당 1행
```

- 파일명 규약은 캡처(`sweep_<label>_<uid16>_<stamp>`)와 같은 꼴이고, 생성은 **`open(..., "x")`**
  — 이름 충돌 시 예외. 덮어쓰기 경로 자체를 두지 않는다
- `<uid16>`이 파일명에 박히므로 라벨 오독이 있어도 UID가 진실이라는 등록부 원칙이 파일명 층에서
  성립한다. `<stamp>`는 그 배치의 `cap.utc_stamp`를 그대로 써서 같은 세션의 스윕 파일과 짝을 이룬다
- 같은 칩을 두 번 돌리면 stamp가 달라 **파일이 나란히 남는다.** 먼저 것이 신품 조사분이고,
  `blank_pre_bits`가 크면 그것만으로 재prep임이 드러나 파일이 자기 설명을 한다
- 요약 열: `uid, label, timestamp, git_rev, blank_pre_bits, blank_pre_range, blank_post_bits,
  blank_post_range, erase_us_min, erase_us_median, erase_us_max, n_sectors,
  defect_pre_count, defect_post_count`

### 3단 (사람) — 집계

`docs/results/data/` 집계 md + CSV (S-2 §9 산출물 3번 소거 시간 · 4번 blank), UID는 등록부.

## 7. 시간 예산

| 단계 | 현재 | 변경 후 |
| ---- | ---- | ------- |
| JEDEC + UID | <0.1s | <0.1s |
| **blank_pre (8MB)** | — | **≈30s** |
| 소거 128섹터 | ≈6s | ≈6s (계측은 비용 0) |
| **blank_post (512KB)** | — | **≈1.6s** |
| 프로그램 2,048페이지 | ≈8s | ≈8s |
| verify 2,048페이지 | ≈1.6s | ≈1.6s |
| **합계** | **≈16s** | **≈47s** |

`PREP_TIMEOUT_S = 15분`(`run_sweep_chip.py:45`) 그대로 두어도 여유가 크다.

30초 근거: 8MB × 8bit / 2.6MHz ≈ 26s + 페이지당 명령 4바이트 오버헤드 ≈ 1.5%.
S-2 §5의 "실측이 1분을 넘으면 측정 영역으로 축소" 규칙 한도 안이므로 전역으로 간다.

## 10. 실행 기록 — 2026-09-15 chip02 첫 투입 (버그 리포트)

구현분을 **실칩에 처음 돌린 결과**다. 기능은 셋 다 동작했고, **버그 2건 + 사고 1건**이 나왔다.
셋 다 같은 날 고쳤으며 아래는 근거와 처치.

### 10.1 결과 요약

| 항목 | 결과 |
| ---- | ---- |
| `blank_pre` / `blank_post` (G-d) | **동작.** 판독이 정확하다 — §10.4의 추론이 가능했던 것 자체가 증거 |
| 섹터별 소거 시간 (G-b) | 기능은 동작, **값이 정확히 4배 작다** (§10.2). G-b는 아직 못 닫는다 |
| UID (G-c) | 동작 |
| chip02 욕조 곡선 | **무효 런** — 19스텝 결측 (§10.3) |
| chip02 출고 blank | **소실** (§10.4) |

실측값(4배 보정 전): `#PREP ERASE SUMMARY n=128 min=6034 max=7790 mean=6739`,
`BLANK pre bits=2097152 t_ms=7442`, `BLANK post bits=0 t_ms=423`.

### 10.2 버그 1 — BSP 매크로에 괄호가 없어 소거 시간이 4배 작게 나온다

2025.2 BSP `xtimer_config.h`:

```c
#define XSLEEPTIMER_FREQ     XPAR_CPU_CORE_CLOCK_FREQ_HZ/2    /* 괄호 없음 */
#define COUNTS_PER_SECOND    XSLEEPTIMER_FREQ
```

`us_since()`가 이 매크로로 직접 나누면 `X/(A/2)`가 아니라 **`X/A/2`로 전개**된다 → 정확히 4배 작다.
BSP 원문을 호스트에서 재현해 확인: 8,800,000카운트 → 종전 6,599us / 수정 26,399us (배율 4.00).

**물리로 잡힌다.** `blank_post`는 2,048페이지 × 260B = 4.26Mbit를 2.6MHz SPI로 읽으므로
**최소 1.64초**인데 423ms로 찍혔다. 나오는 것이 불가능한 값이다.

| 측정 | 보고값 | ×4 | 물리적 기대 |
| ---- | ------ | -- | ----------- |
| `blank_post` | 423ms | 1.69s | 1.64s |
| `blank_pre` | 7.44s | 29.8s | 29.3s (26.2s + BLANKADDR 1,024줄 UART 3.1s) |
| 소거 median | 6.61ms | **26.4ms** | 데이터시트 typ 45ms 안쪽 |

셋 다 2% 안에서 맞는다 — 칩이 아니라 환산이 틀린 것이다.

**처치**: `flash_prep.c` `us_since()`에서 매크로를 값으로 한 번 받는다 (`const u64 cps = COUNTS_PER_SECOND;`).
대입식에서는 `A/2`가 온전히 평가된다. ELF 재빌드 완료. **소거 시간 baseline은 재측정 대상** —
보정값을 기록에 남기지 않는다(나중에 보정 여부를 알 수 없게 된다).

### 10.3 버그 2 — UART 이용률 98%, xsct 구간 미독출로 19스텝 유실

스윕이 `valid=1`인데 **2,501/2,520행**으로 끝났다(무효 ⑤). 결측은 흩어진 것이 아니라
**시작 직후 한 덩어리**다: step 7 중간 → step 26 중간(약 2초), 그리고 step 3에서 1줄.

커널 로그에 **스윕 구간 USB 이벤트 0건** — 케이블이 아니다. 실측 파일로 대역폭을 계산하면:

| | 값 |
| -- | -- |
| 스텝당 와이어 | M 1행 + R 112행 = **1,467 B** |
| 115200bps 실효 | 11,520 B/s (8N1 = 10bit/byte) |
| 이론 상한 | 7.85 steps/s → 2,520스텝 **321초** |
| 실측 | **326초** — 이용률 98% |

즉 보드가 UART에 막혀 스스로 느려지는 상태이고 여유가 0이다. 래퍼는 `xsct` **종료를 기다린 뒤**
캡처를 시작하는데, 보드는 ELF가 뜨는 순간부터 뿜으므로 그 1\~2초 동안 커널·FTDI 버퍼
(≈10KB = 6\~7스텝)가 넘쳐 그 구간이 통째로 사라진다. step 0\~6만 남은 것이 버퍼 크기와 일치한다.

**처치(A)**: `run_xsct(..., ser=ser)`가 xsct 구간에 UART를 스레드로 드레인해 반환하고,
`Drained` 래퍼가 그 바이트를 캡처에 먼저 흘려보낸다. 세션1·2 양쪽에 적용
(prep도 `BLANKADDR` 폭주 중 `#PREP BLANKADD`로 잘린 줄이 1건 있었다).
캡처 진입 전 스레드 조인을 강제하고, 5초 내 미정지면 중단한다 — 포트를 두 곳에서 읽는 상태로
측정에 들어가지 않는다. 선수신 바이트 수를 세션 로그에 남겨 다음 결측의 원인 귀속에 쓴다.

**보 레이트 상향(B)도 같은 날 적용했다** — 전 앱 4종이 첫 출력 전에 921600(실제 925,925bps, +0.47%)으로
바꾸고, 호스트 두 스크립트의 기본값도 921600. 스윕 326초 → **실측 59초**(예측 63초). 별건으로 미루려 했던 근거와 그 처리:
⑴ B 단독은 이 고장을 **악화**시킨다(같은 2초에 8배 더 쏟아지는데 버퍼는 그대로) — A를 먼저 넣고 B를 얹었다
⑵ 보 전환 핸드셰이크는 필요 없다 — xsct는 JTAG로 말하므로 ELF가 뜨기 전까지 UART는 조용하고, 호스트는 이미
   같은 보로 열려 있다. ELF 7개를 전부 재빌드해 세대도 통일했다(§9-3). 구형 ELF는 `--baud 115200`
⑶ 순수 측정 시간 약 23초가 바닥이라 921600 위로는 이득이 급감한다(1.5M에서 48초, 3M에서 35초) — 여기서 멈춘다
⑷ `xil_printf`가 새 병목이 될 수 있어 실측으로 확인할 항목이다.

**구현 형태 — 같은 커밋(`56a5ee4`) 안에서 한 번 갈아탔다.** 처음에는 분주기 레지스터
(`0xE0001018`·`0xE0001034`)를 `Xil_Out32`로 직접 썼으나, 커밋되기 전에
`XUartPs_SetBaudRate(&uart, 921600)`으로 바꿨다 — 드라이버가 TRM 절차(TX/RX 정지 → 분주비
기록 → FIFO 리셋 → 재개)를 따르고, 분주비도 기준 클럭에서 스스로 고른다
(CD=18·BDIV=5 → 100MHz/(18×6) = 925,925bps로 직접 쓰던 값과 같다). **별도 후속 커밋은 없다.**

주의: 그래서 `56a5ee4`의 **커밋 메시지에는 직접 쓰기 시절 문구**(`100MHz/(9×12)`)가 남아
있다. 실효 보 레이트는 같으며, 구현의 정본은 이 문단과 소스다.

**검증 (chip02, `--mhz 25 --n-reads 112`, 같은 날 2회차).** 전송 계층만 바꿨으므로 측정값이
움직이면 실패다 — 움직이지 않았다.

| | 115200 런 | 921600 런 | 차이 |
| -- | --------- | --------- | ---- |
| width @ θ=10⁻² | 39,633.86 ps | 39,634.31 ps | **+0.45 ps** (반복 σ 0.61ps 안) |
| 천장 BER | 0.2466 | 0.2466 | 동일 |
| 벽 폭 | 7스텝 | 7스텝 | 동일 |
| 행 수 · R8 | 2,520 / 282,240 · 통과 | 동일 · 통과 | — |
| 소요 | 326초 | **59초** | 5.5배 |

θ를 조인 쪽은 7\~9ps 벌어졌으나(@10⁻³ 39,623.8 → 39,616.4) 보 레이트 탓으로 볼 근거는 없다.
두 런 사이에 재prep(새 PRBS 기록)과 비트스트림 재프로그래밍·MMCM 재락이 끼어 **세션 간
성분**이 섞였다. chip01 의 ±0.61ps 는 같은 세션 연속 5회라 이 성분이 빠져 있다 — **세션 간
재현성은 아직 정량화되지 않은 값**이며 MSA 에서 따로 잡아야 한다.

**드레인이 B의 전제였음이 숫자로 확인됐다.** xsct 구간 선수신이 34,785B(115200) →
**167,936B**(921600)로 4.8배가 됐다. 버퍼 용량(≈7스텝)을 빼면 드레인 없이는 이번에 약
107스텝을 잃었을 양이고, 이는 115200 때의 19스텝보다 5.6배 나쁘다.

### 10.4 사고 — USB 케이블 접촉 불량 → 유령 P/E, chip02 출고 blank 소실

첫 시도(batch `20260915T150248Z`)가 `#PREP BEGIN` 직후 `SerialException`으로 죽었다.
커널 로그상 **100초 동안 FT2232 재열거 6회** — 케이블 접촉 불량이었고, 다시 꽂아 해결됐다.

문제는 **호스트만 죽고 보드는 계속 돌았다**는 것이다. 다음 런의 `blank_pre`가 그것을 증명한다:

```
#PREP BLANK pre range=0-32767 bits=2097152 bytes=522360
```

`2,097,152` = 페이지 0\~2,047 전체 비트의 **정확히 절반** = 랜덤 데이터의 서명.
비-blank 바이트 522,360/524,288도 랜덤 기대치와 맞는다(0xFF 확률 1/256 → 기대 blank 2,048B, 실측 1,928B).
**우리가 직전에 쓴 PRBS**다.

| 귀결 | 처리 |
| ---- | ---- |
| 장부에 없는 P/E 1회 | `chip_pe.md`에 행 추가 (batch `20260915T150248Z`, 근거 명시) |
| chip02 출고 blank 관측 실패 | `chip_registry.md` chip02 비고에 명시. **복원 불가** |

교훈 두 가지. ⑴ **ELF를 굽는 순간 이후로 중단점이 없다** — 보드는 자율로 돈다.
⑵ 호스트가 죽었을 때 래퍼가 P/E를 기록하지 못한다(§10.5 미결 6).
