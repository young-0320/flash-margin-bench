## 근거

### 1. 사다리 3벌이 소스 3벌이 되면 안 된다

클럭마다 C 를 포크하면 이후의 모든 수정이 3곳에 흩어진다. 그래서 원본 하나를 두고
상수 2개만 치환한 사본을 생성한다. 치환이 조용히 실패하면 25MHz 상수를 그대로 가진 ELF 가
완주하므로, 실패 시 스크립트가 죽게 했다.

빌드 쪽 대응은 `O_DIV` 파라미터화다(기본 45 — 루프백 무영향). 클럭을 바꾸는 일이 분주
파라미터 하나로 끝난다.

### 2. 니어미스 — UI 상수가 사다리에서 살아남았다

`phase_ps` 계산에 `40,000,000fs`(= 25MHz UI)가 상수로 박혀 있었다. 45/75MHz ELF 의
`phase_ps` 가 틀리게 찍힐 뻔한 것을 생성 사본 검수에서 잡았다.

Δφ 가 VCO 고정이라는 성질을 쓰면 클럭 독립식이 된다 — `step × 10⁶/63 fs` 이고, 25MHz
정수 출력과 완전히 같다(40×10⁶/2520 ≡ 10⁶/63). 2차 방어선도 이미 있었다:
[로그 10](10.realchip_sweep_decisions.md) [D10-2] 의 `phase_ps` 교차검사가 현장에서
무효 런으로 잡았을 유형이다.

### 3. 자가진단 2층 — 검출 100%인 층과 완주 후 판정하는 층을 가른다

무효 런 정의는 수정 가능함을 확인하고 B안을 채택했다.

**1층 (결정론적 죽음 → 스텝 2 조기 종료)**: 위상을 바꿨는데 `e_i` 벡터가 비트 단위로 동일
하고 전 읽기가 유에러면 위상 무반응이다. 검출은 정의상 100%이고, 극성 분류는 C 가 기대
PRBS 의 1 개수를 즉석 계산해 대조한다 — `line_dead_stuck0`/`stuck1`/`unknown`. 검사를 행
출력 뒤에 두어 중단 시점까지의 데이터와 `#G0 DIAG` 근거 줄이 캡처에 남는다. 조기 종료는
정보 손실이 0인 경우에만 한다 — 2,520스텝이 같은 행의 복사본이기 때문이다.

**2층 (애매한 고장 → 완주 후 무효)**: 저에러 스텝(BER<0.25)이 하나도 없이 완주하면
`no_window` 다. 간헐 접촉류는 전체 에러 목록을 남기고 `_invalid` 로 간다. 리뷰가 지적한
잔여 구멍(간헐 고장인데 valid=1)이 여기서 닫힌다.

루프백은 단선 = TIMEOUT 이 선행이라 1층에 오지 않고, 정상 런은 floor 스텝이 2층을
통과시킨다.

### 4. N 을 어디로 올려도 미준비 페이지가 없게 굽는다

100페이지는 지금 쓰는 N 에만 맞는 값이다. R6 상한인 2,048페이지(512KB, ~1분)를 구우면 N 을
올릴 때 사전 쓰기를 다시 생각할 일이 없다. B > 2,048 은 실칩에서 무의미하다(페이지 = 시드
경계) — `flash_prep.c` 헤더에 명기했다.

### 5. 루프백 제약을 물려 쓰면 두 가지가 동시에 썩는다

첫째, 루프백 전용 `pattern_in`/`out` false_path 가 G3 에서는 대상이 없어 빌드마다 크리티컬
워닝 2건을 "정상"으로 만들고 있었다. 둘째가 더 위험하다 — max_delay 40ns(25MHz 1주기)는
75MHz 에서 3주기 경로도 합법으로 통과시킨다. `pay` CDC 경로가 1주기를 넘으면 `PAY_LEAD`
유도 전제가 깨지는데 그게 침묵으로 붕괴한다. 전 단 공통 하한인 13.333ns(75MHz 1주기)로
조였다.

같은 파일에서 `u_rx.cap` 의 IOB 워닝도 해제했다. 실칩 top 의 진짜 캡처는 `cap_miso`(IOB)
이고 `u_rx.cap` 은 심 뒤의 내부 단이라, 무의미한 `IOB=TRUE` 가 빌드마다 크리티컬 워닝
(Place 30-73)을 남기고 있었다. `flash_rx` RTL 은 건드리지 않고 XDC 에서 풀었다.

### 6. 처방을 현장에서 실행 가능하게 만든다

[로그 11](11.spi_master_rtl.md) [D11-6] 이 "75MHz 면 `PAY_LEAD` 1 감소"를 처방했지만, 그때
구조로는 소스를 포크해야 실행할 수 있었다. `flash_top_spi` 파라미터 + `build_g3_chip.tcl`
의 클럭별 표(`array set pay_lead`)로 뺐다 — `O_DIV` 와 같은 경로다.

보험은 25MHz 에만 든다. `PAY_LEAD=5` 는 해석 유도와 시뮬 검증뿐이고 실보드 실증 전이라,
어긋나면(전 위상 BER 0.5) 현장에서 재빌드 5분을 반복하게 된다. 4/6 비트스트림 2벌을 미리
구워 두면 몇 초 만에 교체된다. 45/75 는 25MHz 실측으로 역산 보정하는 것이 정도라 미리
굽지 않는다.

### 7. 실패가 경고로 스크롤되면 XSA 가 거짓말을 물고 완주한다

FREQ_HZ 오버라이드가 `catch` 안에 있었다. 실패해도 빌드가 끝나고, 그 XSA 는 25MHz
메타데이터를 가진 채 45/75 빌드 결과물이 된다. STA 는 MMCM 파생 클럭 기준이라 타이밍은
맞지만 IP 구성을 오판하게 만든다. 기존 3벌 로그에서 오버라이드 성공을 확인한 뒤 강경화했다.

### 8. `%lu` 는 64비트를 소비한다

2024.2 BSP 의 `xil_printf` 는 `SUPPORT_64BIT_PRINT` 라 `%lu` 가 64비트 va_arg 다. u32
인자를 주면 출력값도 후속 인자 정렬도 전부 깨진다 — `#PREP FAIL` 의 페이지·바이트 수가
쓰레기로 찍힐 뻔했다. `g0_sweep.c` 는 원래 `%u` 관례였고, `flash_prep.c` 4곳을 맞췄다.

### 9. 한 번 통과한 목록을 상시화한다

smoke TB 가 이미 1회 통과한 항목들이 승인 기준 없이 떠 있었다(README TODO). `flash_top_spi`
10항목(F1~F10)·core 6항목·통합 3항목으로 고정해 cocotb 회귀의 채점표로 만들었다 —
[D10-6] 의 "박지민이 채점·승인"이 성립하려면 기준 문서가 먼저 있어야 한다.
