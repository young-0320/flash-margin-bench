## 근거

### 1. 위상 원점이 임의라 욕조 모양 가정이 깨진다

위상 원점은 MMCM 정렬에 따라 임의다. 그래서 실측에서는 윈도우가 스윕 배열 경계에 걸친
데이터(양끝 깨끗, 가운데 에러 산)가 확률적으로 발생하는데, 기존 코드는 **욕조 모양**(중앙
깨끗)만 가정해 폭·중심 판정이 깨진다.

저 BER 최장 원형 구간을 배열 중앙으로 회전하는 것으로 닫았다. 위상 원점이 임의라 이 회전은
재레이블일 뿐이고, 측정값은 하나도 바뀌지 않는다.

### 2. 체크 5 — 한 스텝의 점프는 지터로 설명되지 않는다

한 스텝(≈16ps)에 BER 이 10⁻³ 에서 0.25 로 뛰려면 σⱼ<7ps 를 요구하는데 이는 물리적으로
불가능하다. 그래서 이 점프는 지터가 아니라 **프레이밍(비트 정렬) 슬립**이고, 체크 5 는 그
전용 검출기다.

### 3. 입력 무결성은 소비자 쪽에서도 집행한다

계약이 정한 것 중 생산자만 지키면 되는 것은 없다. 동반 `_reads.csv` 의 R8 무결성 검사,
`_invalid` 파일명 거부, `phase_step` 연속성 검증은 전부 계약 조항을 분석기가 다시 확인하는
자리다. `bit_err_sq_sum` 은 계약 4 가 호스트 파생으로 재정의했으므로, 열이 없으면 원본
`_reads.csv` 에서 파생한다.

negative 검증 3종(메인 CSV 비트 오염 → R8 검출, 프레이밍 절벽 주입 → 체크 5 FAIL, `_invalid`
파일명 → 입력 거부)이 전부 정확히 동작했다.
 
### 4. selftest 를 계약 그대로의 리허설로 격상한다

계약 12열 + git 스탬프 + 동반 원본 파일로 올리고 wrap 케이스를 더했다. 하드웨어 없이
"CSV→그림" 전 파이프라인을 리허설하는 것이 목적이고, wrap 케이스는 §1 의 실버그가
재발하는지를 보는 자리다.

### 5. 게재 2번은 레지스터가 아니라 파형으로 잡는다

계약 기준으로 장세은이 착수 가능하다. 단 레지스터 맵 v0 에 JEDEC 트랜잭션 창구는 없으므로
캡처는 ILA/스코프 파형 경로가 자연스러운 산출물이고, 레지스터 기반 읽기가 필요해지면 v1
확장이다.
