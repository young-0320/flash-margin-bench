## 근거

### 1. 자가진단의 가정이 저노이즈 결정론 채널에서 깨졌다

940스텝 무에러 뒤 벽에 진입하던 중 스텝 952 = 953 의 100읽기 에러 벡터가 비트 단위로
동일해 진단이 발동했고 스윕이 중단됐다.

자가진단의 가정은 "창 밖 = 노이즈라 연속 스텝이 동일할 수 없다"였다. 루프백 같은 저노이즈
결정론 채널의 **벽 평탄부** 에서는 이 가정이 깨진다 — 엣지가 다음 Δφ 안에 없으면 틀리는
비트 집합이 불변이다.

`err_reads==N && !low_seen` 게이트로 닫았다. 죽은 라인은 저에러 스텝을 낼 수 없으므로
원 목적은 보존된다 — 설계 의도였던 "스텝 2에서 중단"도 `low_seen=0` 구간이다. 벽에 도달한
정상 스윕만 오발에서 면제된다.

### 2. 문제 두 개가 겹치면 하나를 고쳐도 증상이 남는다

세은 노트북(Windows + Vivado 2025.2)에서 xsdb 프로그래밍은 성공했으나(DONE 점등) 캡처가
BEGIN 을 못 들었다. 유력 원인은 FT2232 듀얼 채널(A=JTAG, B=UART)이 Windows 에서 구분 없이
COM 으로 잡혀 JTAG 채널을 청취한 것이다 — 다른 COM 을 시도하지 않고 철수해 미확정으로
남는다. 리눅스는 UART 만 `ttyUSB1` 로 바인딩되어 모호성이 없다.

여기에 **점퍼 접촉 불량이 중첩** 돼 있었다. 귀가 후 첫 실행이 timeout 으로 난 것이 그
증거다. 문제가 둘이면 하나를 고쳐도 증상이 남아 "재현성 문제"로 오인된다 — 측정 시스템
자체는 양쪽에서 동일하게 동작했다.

### 3. 체크리스트 — 넷은 통과, probit 직선성만 FAIL

- ② BER floor (상한 3.7e-9) PASS
- ③ σⱼ 29.1·29.2ps — MC 재실행 N=100 재확인 PASS (σ_width 0.30ps @θ=10⁻² ≪ 기준 7.5ps,
  최저 θ=10⁻⁴ 에서도 2.0ps)
- ④ 과분산 F=0.48 PASS
- ⑤ 프레이밍 슬립 없음 PASS
- ① probit 직선성 **FAIL** — 좌 0.993 / 우 0.9742 (기준 0.98)

곡선 자체는 valid=1 완주에 폭 34,693ps @θ=10⁻²(UI 40ns), 양벽 σⱼ 대칭이다. 그런데 사전
등록한 기준([로그 10](10.realchip_sweep_decisions.md) [D10-1])은 4항 통과를 요구하므로,
하나라도 FAIL 이면 θ 는 확정되지 않는다. 기준을 나중에 무르는 것이 사전등록을 깨는 일이다.
