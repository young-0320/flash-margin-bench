## 1. W3를 폐기했다 — 실패 방향이 존재하지 않았다

구 W3의 PASS 기준은 *"SCLK 유휴 low면 통과, 유휴 high로 바꾸면 실패할 것"* 이었고,
H1이 지적한 것은 **근거가 데이터시트가 아니라 추측**이라는 점이었다. 확인해 보니 추측이
틀린 정도가 아니라 **명제 자체가 성립하지 않았다.**

### 칩 쪽 — 실패하지 않는다

데이터시트 §6.1:

> SPI bus operation Mode 0 (0,0) and 3 (1,1) are supported. The primary difference between
> Mode 0 and Mode 3 concerns the normal state of the CLK signal when the SPI bus master is
> in standby… For Mode 0, the CLK signal is normally low on the falling and rising edges of
> /CS. For Mode 3, the CLK signal is normally high on the falling and rising edges of /CS.

**둘 다 지원되고, 차이는 /CS 에지에서의 유휴 레벨뿐이다.** 데이터 자체는 양쪽 모두
상승 에지 샘플·하강 에지 출력이라 프레임당 상승 에지 수도 같다. 유휴 high로 주면 모델은
mode 3로 정상 동작한다 — 실패가 나오지 않는다.

### 우리 쪽 — 바꿀 수 있는 상태가 아니다

이쪽이 더 결정적이다. `flash_spi_ctrl.v:12` 헤더:

> SCLK는 이 모듈이 만들지 않는다 — `sclk_en`을 top의 **ODDR(D1=0, D2=sclk_en)** 에 공급해
> `clk_core`를 무분주 포워딩(R9).

`sclk_en=0`이면 두 반주기가 모두 D1=0을 내므로 **유휴 low는 런타임 상태가 아니라 배선
상수**다. "유휴 high로 바꾼다"는 것은 ODDR의 상수 포트를 고친다는 뜻이고, **그렇게 고친
DUT는 채점 대상이 아니다.** 다른 설계를 통과시키고 원래 설계를 승인할 수는 없다.

### 지키려던 성질은 F2로 옮겼다

W3가 실제로 지키려던 것은 *"우리가 mode 0을 지키는가"* 였고, 그건 **와이어에서 직접
보이는 값**이다. F2에 **CS↓·CS↑ 두 시점 모두에서 SCLK=low**를 넣었다 — 데이터시트가
정의하는 mode 0 진입 조건 그 자체이므로 추측이 개입할 자리가 없다.

검증 불가능한 항목을 표에 남겨두면 **커버리지가 초록으로 뜨는데 그중 하나는 아무것도
증명하지 않는다.** 로그 19가 커버리지에 대해 경고한 위험(초록 숫자가 경계심을 낮춘다)이
항목 자체에서 발생하는 형태다. 항목이 하나 줄어드는 것보다 나쁘다.

## 2. F11의 BER 관측에 구조적 맹점이 있다 — 실측 A2가 왜 남아야 하는가

H2는 "249의 근거가 시뮬로 옮겨오지 않았다"는 지적이었는데, 지점을 다시 세우다가
**더 무거운 것**이 나왔다.

기대 패턴의 시드는 `page(i)[13:0]`이다(계약 §5). 즉 **패턴은 16,384페이지 = 1,024섹터마다
반복**된다. 그러면 주소 상위 비트 [14]가 통째로 유실되는 버그가 나도, 모델은 별칭
페이지의 **같은 내용**을 돌려주고 **BER은 0으로 통과한다.**

```
BASE_SECTOR = 1,024  →  page(0) = 16,384
비트[14] 유실 버그    →  실제로는 page 0 을 읽음
기대 시드            =  16,384 & 0x3FFF = 0  =  page 0 의 시드
                     →  일치. 에러 0. 조용히 통과
```

**하필 구본이 "상위 주소 비트 경로"를 보겠다고 고른 `1,024 이상 한 점`이 정확히 그
맹점**이다. 상위 비트를 보려고 고른 지점이 상위 비트를 못 보는 지점이었다.

수정안 #1 §3이 이 별칭을 이미 알고 있었고 *"실사용상 무해"* 라고 결론지었다 — 한 스윕이
연속 N≤2,048페이지만 읽으므로 별칭 짝이 같은 스윕에 못 들어온다는 이유로. 그건 맞다.
그러나 **검증 항목의 검출력**은 다른 문제였고, 그 구분이 F11로 넘어오면서 빠졌다.

### 해결 — 관측을 두 층으로 나눴다

| 층 | 무엇을 보는가 | 별칭에 걸리는가 |
| -- | ------------- | --------------- |
| ⑴ 와이어 주소 디코드 | MOSI의 24비트 주소 = `page(i)`×256 | **아니오** — 주소 바이트는 별칭되지 않는다 |
| ⑵ BER | 주소와 시드가 **함께** 움직였는가 | 예 (1,024 배수 지점에서 무력) |

둘을 **동등한 필수 조건**으로 두면 상위 비트도 보이고 주소·시드 동반도 보인다.
F1이 이미 주소를 오라클 V로 재고 있으므로 F11은 그것을 `BASE_SECTOR`≠0에서 재수행하는
셈이다.

### 그래도 실측 A2는 유지된다

시뮬 모델의 메모리는 **우리가 적재한 것**이다. 즉 F11이 답하는 질문은 *"RTL이 의도한
주소를 발행하는가"* 까지이고, *"칩의 그 구역이 실제로 그 데이터를 갖는가"* 는 여전히
실칩만 답한다. 수정안 #1 §4 A2의 실측 유지 결정(로그 19 §3)은 그대로다 — 다만 그 근거를
"1,024섹터 aliasing 구멍" 대신 **"모델 메모리는 우리 손을 탄 것"** 으로 다시 적었다.
앞의 것은 F11이 와이어 관측으로 좁혔고, 뒤의 것은 시뮬이 원리상 못 넘는다.

### 지점 재선정

`0 / 1 / 1,024 / 2,041`. **249를 빼고 1을 넣었다.**

- `1`은 **섹터→페이지 ×16 스케일링**만 분리한다. `page(0)=16`이므로 `BASE_SECTOR`를
  페이지로 오해해 더한 구현(`page(0)=1`)이 여기서 바로 갈린다. 큰 값에서는 다른 오류와
  섞여 원인이 안 보인다
- `249`는 *"종전 12비트 주소 폭의 상한 부근"* 이 근거였는데 시뮬에는 그 제약이 없다.
  **실측 A2에서는 종전 비트스트림과의 회귀 비교라 여전히 유효**하므로 수정안 쪽은 안 건드렸다

## 3. F12를 수정안 #2에서 떼어냈다

H3은 "N=112의 출처가 안 적혀 있다"였다. 출처를 한 줄 붙이는 것보다 **N에 무관하게
일반화**하는 쪽을 택했다 — 수정안 #2가 미승인이라, 각주를 달면 승인 여부에 따라 다시
고쳐야 한다.

```
구:  BASE_SECTOR = 2,042, N = 112   →  32,783   (초과폭 16)
신:  BASE_SECTOR = 2,047, N =  17   →  32,768   (초과폭  1)
```

**초과폭을 1로 좁힌 것이 부수 소득**이다. 비교 연산자를 `>` 대신 `>=`로 쓴 off-by-one은
초과폭 16에서는 어차피 걸려 통과하지만, 초과폭 1에서는 갈린다.

여기에 **음성 대조**를 붙였다 — `BASE_SECTOR=2,047, N=16`(= 정확히 32,767)은 `CFG_ERR`
없이 정상 시작해야 한다. 거부만 확인하면 **조건식이 항상 참인 구현**(전부 거부)과
구분되지 않는다. W2에 음성 대조를 넣은 것과 같은 이유다.

## 4. 커버리지 목록의 원전을 하나로 유지했다 (H5)

선택지는 둘이었고 실패 양상이 달랐다.

| | 실패 방식 |
| --- | --------- |
| 별도 목록 파일 | 문서와 목록이 **어긋난다.** 어긋난 쪽이 기준 행세를 하면 채점표가 둘이 된다 |
| 문서 표 파싱 | 서식이 바뀌면 **조용히 깨진다.** 0개를 파싱하고도 "누락 없음"이 될 수 있다 |

표 파싱을 택하고 **조용한 실패만 막았다.** 동결본 §5 말미의 합계 선언
(`**합계 23항목** — F 12 · W 2 · C 6 · I 3`)과 표 파싱 결과를 교차 검증한다.

```
표 파싱 = 23 (F 12 · W 2 · C 6 · I 3)
합계 선언 = 23 (F 12 · W 2 · C 6 · I 3)   → 일치
불일치 시 커버리지 판정 이전에 비영 종료
```

합계 선언은 **서식이 아니라 내용**이라 표 서식과 함께 깨지지 않는다. 파싱이 망가지면
0개가 아니라 불일치로 드러난다. 목록 파일을 안 두므로 원전은 계속 하나다.

## 5. 채점 대상을 트리로 정의했다 (H7)

H7의 질문은 *"3파일인가, `flash_rx`·`flash_logbuf`·`flash_prbs15`도 포함인가"* 였다.
**질문의 축이 잘못 놓여 있었다** — 구본의 3파일은 로그 11이 **새로 쓴** 파일들이고,
채점 대상은 신규 여부가 아니라 **계약 항목이 무엇을 재는가**로 갈린다.

- F3(주소→시드 정합)은 `flash_rx.v:65`의 시드 경로를 잰다
- F6·R8(정확 계수)은 `flash_logbuf.v`를 잰다
- F3의 기대 패턴은 `flash_prbs15.v`가 만든다

재사용 모듈이라고 빼면 **항목이 채점 대상 없이 뜬다.** 그래서 목록을 손으로 유지하지
않고 **"DUT가 인스턴스화하는 것 전부"** 로 정의하고, 현재 트리를 펼쳐 표로 적었다.
`flash_ctrl.v`·`flash_top.v`는 G0 루프백 경로라 SPI 트리에 없으므로 제외된다.

`core_mmcm.v`는 Xilinx 프리미티브를 감싸 시뮬에서 스텁으로 대체되므로 **그 부분은
채점되지 않는다**고 명시했다. 스텁을 채점 대상처럼 적어 두면 C 항목이 실제보다 넓게
보인다.

## 6. 게이트 개방 조건에 "같은 실행" 조항을 넣었다 (H8)

H8이 예시로 준 형태는 *"3블록 전부 승인 + 커버리지 24/24"* 였는데, 쓰다 보니 한 항이
더 필요했다.

> ④ ②(커버리지)와 ③(전항 PASS)이 **같은 회귀 실행**에서 나올 것

커버리지가 통과한 실행과 전항 PASS가 나온 실행이 다르면 **그 사이에 실패하는 테스트가
지워졌는지 알 수 없다.** 로그 19가 커버리지를 회귀에 넣은 이유(사람 심사는 1회 스냅샷)와
같은 논리가 게이트 판정 자체에도 적용된다.

## 7. 판정서를 기준 옆에 뒀다 (H4)

후보 셋 중 `docs/spec/s3.g1_review.md`를 택했다.

- `docs/log/young/`은 **시간순 개인 기록**이다. ③이 참조해야 하는 절차 산출물이 "언제
  적었는지 알아야 찾을 수 있는" 자리에 있으면 안 된다
- `docs/results/`는 승격된 **실측** 산출물의 자리다(plots·data·captures). 코드 열람
  기록은 측정이 아니다
- 블록마다 파일을 나누면 재판정이 반복될 때 최신본 찾기 문제가 생긴다 → **단일 누적 문서**

기준과 같은 폴더인 이유는 실용적이다. **판정 기록은 최종보고서에서 "작성자와 승인자를
분리했다"를 뒷받침하는 유일한 증거**이고, 기준과 판정을 나란히 제시할 수 있어야 한다.

## 미결 의사결정

**H 트랙 8건과 C 트랙은 닫혔다. 워크플로 6에 남은 것은 R 트랙(3인 합의)뿐이며, 정의상
혼자 진행할 수 없다.**

1. **R1·R2 계약 수정안 승인** — #1 미승인 상태에서는 커버리지가 21/21로 돌고 F11·F12가
   제외된다. 스크립트가 제외 사실을 매 실행 선두에 출력하므로 조용히 사라지지는 않는다
2. **R3 `roles.md` v2 추인 · R4 동결본 3인 추인** — 개정 2로 내용이 늘었으므로 추인
   대상은 개정 2본이다
3. **Winbond 공식 모델 미확보** — W1·W2가 전부 여기 걸려 있다. 모델이 타이밍 어서션을
   제공하지 않는 판본이면 W2의 PASS 기준을 다시 써야 한다. **H1은 이 의존에서 벗어났다**
   — 데이터시트와 우리 ODDR 배선만으로 결론이 났으므로 모델이 mode 3를 어떻게 다루든
   W3는 성립하지 않는다
4. **`check_coverage.py`의 입력 형식 미확정** — cocotb JUnit XML(`results.xml`)을
   전제했다. 박지민이 다른 러너·출력 형식을 쓰면 파서를 맞춰야 한다. 회귀 환경이 서면
   실제 XML로 한 번 돌려 확인할 것 (현재는 합성 입력으로만 검증)
