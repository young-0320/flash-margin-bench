## 근거

### 1. 무엇이 왔나 — chip16 100k, 온도 로그, chip14 · 06 보충

**chip16 묶음(`TalkFile_chip16_100k_artifacts`).** 스윕 16런(25MHz 체크포인트 13점 100 - 100k · 100k 뒤 75 · 45MHz 사다리 · newchip
`20261009T060753Z`), 세션 로그 16개, 세션 폴더 `1791523150`(97,957 → 100,000 · 1점 PASS · verdict A1-A7 · C · probe 전부 PASS), 지민 장부, 그림 17장.
**없는 것** — 장부가 말하는 앞 세션 둘: `1791434740`(0 → 97,957, 체크포인트 12점, 90k → 97,957 에서 error) · `1791523104`(resume · 섹터 0-4 reerase).
A 행의 97.9% 가 이 둘에 있다. `1791523150` 의 plan 도 「단가 출처: 이전 세션 1791434740」 · 「장부 97,957 로 덮었다」 고 적어 세션이 있었음을 말한다.

**온도 로그(`TalkFile_온도제어chip16`).** 셋 — `033716Z`(센서 FAULT 로 7행에 끝) · `034049Z`(PWM 상한 128, `T65` 무장, 15분) ·
`035828Z`(PWM 상한 220, `T65` 무장, 10-08 03:58Z → 10-09 06:17Z, 94,719행). 첫 체크포인트 스윕(04:48Z)이 무장 50분 뒤라 마모 전 구간이 로그 안이다.

**chip14 · 06 보충(`TalkFile_14번과 06번과 오류`).** 앞 세션 폴더 넷 — `1791089978`(0 → 100 PASS, 그러나 체크포인트 100 스윕이 실패해 「마모를 잇지
않는다」 로 멈춤) · `1791201309`(resume · 판정 normal · 채택 100) · `1791201358`(100 → 400 · `erase_fail@400` · 구간 FAIL) · `1791201933`(resume ·
`tally_late` · 채택 400 → 장부 399). `1791204058` 과 스윕 24런은 10-08 묶음과 같은 바이트. `nwe/` 에 **chip06 스윕 9런**(마모 중 체크포인트
1k · 3k · 10k · 12k 와 개봉 prep 5회의 스윕) 과 세션 로그 4개 · prepfail 1개가 새로 왔고(32파일), 나머지(10-01 chip14 · 16 newchip, 지민 prepfail)는
리포에 있던 것과 같다. **chip14 세션 로그 15개(10-04 - 10-07)는 이번에도 없다.** 체크포인트 100 의 「유효 스윕」 은 없는 것이 맞다 — `1791089978` 로그가
스윕 실패로 끝났고 `_invalid` 하나뿐이라 더 묻지 않는다.

### 2. 온도 로그는 65°C 를 말하는데, 히터가 꺼진 채 67°C 가 세 시간이다

마모 전 구간(10-08 04:48Z - 10-09 06:01Z) 의 칩 위 온도는 평균 63.6°C(59.7 - 67.4, 63-67°C 안 52%), 체크포인트 스윕 때는 60.7 - 66.4°C.
chip17 의 65.2°C(97% 가 63-67°C) 보다 낮고 퍼졌다. 그런데 **로그가 열 거동으로 읽히지 않는 자리가 둘이다.**

- 10-08 11 - 13Z: 상태 RUN 인데 PWM 0 — 온도가 설정을 넘어 끈 것인데, 세 시간 동안 66.8 - 67.1°C 가 **그대로** 다
- 10-09 00:50Z: `FAULT_LATCHED,SENSOR` 가 걸려 끝까지 PWM 0 — 그 뒤 5.5시간 동안 62.5 - 64.2°C

chip17 때는 히터가 55초 꺼지자 44.9°C 까지 떨어졌다(`wear_temperature_chip17.md` §1). 같은 히터 · 같은 보드 B 에서 꺼진 채 세 시간을 67°C 에
머무는 것은 (ㄱ) 센서가 칩 위에 없거나 (ㄴ) 센서 값이 고정됐거나(FAULT 뒤 값은 더욱) (ㄷ) 다른 열원이 있다는 뜻이지, 「65°C 로 닳았다」 의
증거로 그대로 쓸 수 없다. 반대로 「상온이었다」 고도 못 한다 — 무장은 분명히 했고 05 - 09Z 는 PWM 이 계속 켜져 있었다.

소거 쪽 증거는 상온 쪽을 가리킨다. 100k 체크포인트 소거 p50 116.6ms 는 신품 27.7ms(10-07 newchip) 의 **4.2배** — chip17(65°C) 의 2.44 가 아니라
상온 빠른 무리(2.80 - 3.97, chip04 119.6ms)와 닮았고, 100k 뒤 newchip 으로 돌린 현장 역산(v4 · 상온 교정 5칩)은 91,001 - 92,000(68% 87k - 100k)
으로 맞았다. 단 chip17 문서가 「65°C 효과는 개체차와 구별되지 않는다」([D48-65]) 고 했으므로 이것으로 온도를 가를 수는 없다.
폭은 13점 모두 39,781 - 39,794ps(100 대비 −8.3 - +4.6ps, 3σ 42ps 안) — 온도와 무관하게 H1′ 모양이다.

정하는 데 필요한 것은 지민의 **배치 설명**(히터 · 센서가 chip16 보드 위에 있었나, 꺼진 뒤 왜 안 식었나, 사진)과 `1791434740` 의 A 행이다 — [U53-1] · [U53-2].

### 3. 1단계는 돌렸지만 chip16 곡선은 3구간 — chip14 는 1-100,000 이 됐다

`pe_end.py --chip chip16 --from` 은 세션 1개(`1791523150`)만 찾아 1k 곡선이 97,001 - 100,000 세 구간(첫 구간 n=43)이고, 체크포인트 CSV 는
x=0(10-01 prep 26.8ms) · 100k 한 행 · 사다리 2 · newchip 뿐이다. `--temp` 는 주지 않았다 — 온도 런으로 볼지가 [U53-1] 이고, 1단계는 어느 쪽으로든
다시 돌리면 된다. 10-07 newchip(보드 A, `build/data/`)도 `data/` 로 옮겼다.

chip14 는 세션 3개(`1791089978` · `1791201358` · `1791204058`)로 다시 돌려 A 행 700,000(1 - 100,000)이 됐다 — 10-08 엔 첫 구간이 601행이었다.
체크포인트 100 행은 「결측 — C 행 없음」, 1,000 - 100,000 의 폭 · batch 는 세션 로그가 없어 그대로 빈칸이다. resume 폴더 둘(`1791201309` · `1791201933`,
A 행 없음)은 `data/wear/` 에 손으로 옮겼다. chip06 체크포인트 4점은 폭 39,663 - 39,669ps · 소거 p50 31.6 → 41.1ms(1k → 12k)인데 블라인드 판정 뒤의
자료라 수치 md 에 넣지 않았다 — v4.1 재료([D52-4] 의 12k → 100k)는 그 마모 뒤다.
