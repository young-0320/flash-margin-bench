## 근거

### 1. 조사에서 확인한 사실

- 타 PC 실행 관련 문서는 세 곳에 흩어져 있다: 런북 3 C·D절(명령),
  [로그 13](13.first_loopback_bathtub_and_linedead_fix.md) §Windows(타 머신
  4단계), CONTRIBUTING §1.5(uv). 런북 3·로그 13·`program_g3.tcl` 주석은 캡처 옵션을
  `--target`으로 적고 있으나 현행은 `--loopback`/`--uid`다
  ([로그 24](24.sweep_wrapper_uid_pipeline_impl.md)에서 바뀜) → W8-D.
- 2024.2 선택은 7/7 결정(메모리 `g0-build-decisions`)이며 "공유 편집이 필요해지면 2025.2로
  통일"이 그때 이미 예고돼 있었다. 지금이 그 시점.
- 병렬 설치는 안전하다(버전별 독립 폴더, settings64.sh를 source한 셸만 PATH 변경). 동시
  사용도 셸 단위로 가능하나 `build/`가 하나라 섞인다 → B0에서 `build_2024.2`로 분리.
- 가드는 "돌게 하는 장치"가 아니라 "한 버전 강제 장치"다. 지우면 계측기가 둘이 되므로
  `2025.2*`로 옮겨 다시 잠근다.

### 2. 재기준선 설계 — 과거 수치와 비교하지 않는다

**A/B를 같은 자리에서 교대로 잰다.** 근거는 [로그 22](22.d_track_drift_sweep.md): 7월
±0.61ps는 재장착 없는 편차이고, 재장착 1회가 +4.35ps(+7.1σ), 점퍼 접촉이 −385ps를 만들었다.
과거값과 비교하면 빌드 차이가 접촉 차이에 묻힌다. JTAG 프로그래밍은 물리 접촉과 무관하므로
칩·점퍼를 두고 A(2024.2 비트)·B(2025.2 비트)를 교대하면 남는 차이는 빌드뿐이다.

차이가 3σ를 넘어도 전환은 계속한다. 7월 게재 수치는 그 빌드로 잰 사실이므로 그대로 두고,
유래 md에 Δ를 각주로 단다. 단 σⱼ·벽 폭·천장 BER(0.2462)이 바뀌면 배선 차이가 아니라
샘플 클럭 경로 문제이므로 멈춘다.

R 통과 전에는 조원 전개(T)를 시작하지 않는다 — "PC 차이"와 "빌드 차이"를 분리하기 위해.
T의 판정은 정밀 비교가 아니다. 조원 루프백 폭은 점퍼 차이를 재는 것이므로 자릿수 일치만
본다. 대신 `g0_wrapper.bit`의 md5 일치를 선택 항목으로 두었다 — 같으면 "각자 빌드 =
같은 계측기"의 직접 증명.

### 3. 빌드 결과 — 조원 재현의 기준값 (2025.2, 영웅 PC, 2026-09-14 밤)

조원이 같은 커밋·같은 버전으로 빌드하면 같은 값이어야 한다 (가이드 §3 재현성 확인).
**수치의 정본은 `docs/build_reproduction.md` §3.5 기준표다.** 6빌드(g0 · g2 · prep ·
g3-25/45/75)가 22:50~23:06, 약 16분에 전부 통과했다.

로그에만 있는 것은 그때의 판단 둘이다.

- **2025.2 API 변경이 없었다** — g0 가 `vitis -s` ELF 단계까지 포함해 그대로 통과했다
- **PSU DDR DQS CRITICAL WARNING 4건은 보드 프리셋이라 무해**하다고 보고 넘겼다
 `.bashrc`는 2025.2 Vitis settings64.sh 한 줄로 교체(백업 `~/.bashrc.bak-2024.2`).
2024.2 설치본(53GB)은 아직 남아 있음 — 지워도 됨. 조원용 빌드 재현 문서는 `docs/build_reproduction.md`
(첫 판은 설치·측정·분석까지 섞인 범용 안내서로 썼다가 "산출물·순서·명령" 중심으로 재작성 — 요청 범위 착오).
