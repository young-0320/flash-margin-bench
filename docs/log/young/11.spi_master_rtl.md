# 11. SPI 마스터 RTL (0x0B) — 실칩 flash 프런트엔드 구현 + 스모크 통과

- **작성일**: 2026-07-08 (심야)
- **발단**: 게재 4번(실칩 곡선)의 병목 선행물이다. [로그 10](10.realchip_sweep_decisions.md)
  [D10-6] 의 권고안("Young 구현 + 박지민 cocotb 채점")을 총력전 연장으로 착수했다 —
  박지민 합류(7/8 오후) 시 이 로그가 인수인계·리뷰 기준이다
- **목적**: 루프백에서 실칩으로 넘어갈 때 무엇이 새로 풀려야 하나?
- **관련**: `fpga/rtl/flash/flash_spi_ctrl.v` · `docs/interface/contract.md` §2·R7·R9·R10·R11 ·
  [로그 7](7.flash_loopback_rtl.md) · [로그 10](10.realchip_sweep_decisions.md)

## 결정

- [D11-1] 실칩 top 은 계약 §2 인터페이스를 루프백과 동일하게(R7) 두고 루프백 `flash_top`
  과 **병존** 시킨다 — core·스윕 C·계약 무수정 — §1 · `fpga/rtl/flash/flash_top_spi.v`
- [D11-2] 프레이밍은 마스터가 데이터 도착을 예고(`pay`)하고 심이 **로컬 프리앰블을 합성**
  하는 방식으로 푼다. `flash_rx`·`flash_logbuf` 는 무수정 재사용 —
  §2 · `fpga/rtl/flash/flash_spi_shim.v`
- [D11-3] `PAY_LEAD=5` — 2FF 동기(±1)와 캡처 체인을 타이밍 산식으로 유도한 값. 산식은
  `flash_spi_ctrl.v` 헤더 — §2
- [D11-4] SCLK 는 ODDR(D1=0, D2=`sclk_en`) 포워딩으로 만든다 — §3
- [D11-5] 주소→시드 정합은 검사하지 않는다 — 구조적으로 보장되고 TB 가 암묵 검증한다 — §4
- [D11-6] 무칩·단선의 고장 서명이 루프백과 **반대** 라는 것을 현장 판독 규약으로 남긴다 — §5

## 근거

### 1. 계약을 건드리지 않고 프런트엔드만 바꾼다

실칩 경로를 열면서 계약 §2 포트가 바뀌면 core 와 스윕 C 가 따라 바뀐다. R7(읽기 전용)을
지킨 채 top 만 갈아끼우는 구조라 루프백 `flash_top` 과 병존하고, 빌드 스크립트가 어느 쪽을
넣을지만 고른다.

### 2. 프레이밍이 유일한 신규 난제다

루프백은 프리앰블이 페이로드와 같은 배선을 타서 정렬이 지연과 무관했다. SPI 칩은 프리앰블을
못 보낸다 — 슬레이브는 우리가 정한 버스트 파형을 모른다.

대신 마스터가 데이터 도착을 예고하고(`pay`) 심이 로컬에서 프리앰블 1×4 를 합성해 MISO 로
먹스한다. 그러면 `flash_rx` 의 3후보 비교기({t0+3,4,5})가 그대로 산다 — 어댑터 하나로
루프백 수신부 전체를 재사용한 것이다.

`PAY_LEAD=5`(pay 상승 = cyc 35)는 2FF 동기의 ±1 불확정과 캡처 체인 지연을 산식으로 유도해
페이로드가 후보 창 정중앙에 오게 한 값이다.

### 3. ODDR 이 셋업·홀드를 반주기씩 벌어 준다

SCLK 를 ODDR 로 포워딩하면(D1=0, D2=`sclk_en`) 상승 에지가 사이클 중앙에 온다. 에지에서
런치되는 MOSI·CS 에 반주기 셋업/홀드가 자동으로 확보된다(mode 0, 유휴 low). CS 셋업 2 ·
홀드 3 · 갭 4사이클, 읽기당 오버헤드 49사이클로 R10 여유 안이다.

### 4. 주소가 틀리면 에러 0 이 나올 수 없다

RX 가 기대하는 시드 `{1, idx}` 와 마스터가 보내는 `addr = idx×256` 이 같은 `idx` 에서
파생된다. 따로 검사기를 붙일 필요가 없다 — 주소가 어긋나면 TB 의 "위상 스윕 에러 0" 자체가
성립하지 않는다.

### 5. 무칩·단선이 TIMEOUT 이 아니라 "완주 + 대량 에러"로 나온다

합성 프리앰블이 **항상** 프레이밍을 성립시키기 때문이다. 라인이 0 에 고정되면 에러 수는
기대 PRBS 의 1 개수가 된다(B=2048이면 읽기당 ~절반). 루프백의 "단선 = TIMEOUT"과 정반대라
브링업 때 혼동하기 쉬운 자리다.

같은 이유로 클럭 상향 시 `tCLQV` + 배선 왕복이 1UI 를 넘으면(75MHz 에서 ~0.9-1.1UI 로
임계) 정렬이 후보 창을 벗어난다 — 증상은 전 위상 BER 0.5, 처방은 `PAY_LEAD` 1 감소다.
사다리 빌드 3벌을 만들 때 클럭별로 확인한다.
