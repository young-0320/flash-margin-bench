## 근거

### 1. tcl 이 소스다

Vivado 2024.2 가 로컬에 있어 배치 모드로 직접 실행·검증을 반복할 수 있다. `fpga/scripts/`
의 ".xpr 이 아니라 tcl 이 소스" 컨벤션과도 맞는다. 프로젝트 재생성 → BD 조립 →
비트스트림·XSA → ELF 까지 원샷으로 묶고(끝에서 `build_g0_sweep.py` 를 체인 호출) stage
인자로 끊어 쓸 수 있게 했다.

### 2. 재패키징 단계를 없앤다

원안은 core·flash 를 AXI IP 로 패키징하는 것이었다. BD 모듈 참조로 바꿔도 표준 신호명이라
AXI 자동 추론과 Address Editor 주소 배정은 똑같이 된다.

얻는 것은 재패키징 단계가 사라진다는 것이다 — RTL 수정이 다음 빌드에 바로 반영되므로
브링업 반복 마찰과 **재포장 망각 사고** 유형이 통째로 없어진다. 팀 배포가 필요해지면 그때
패키징하면 되고, 그건 가역적이다.

### 3. "제약을 썼다"와 "제약이 물렸다"는 다르다

CDC 제약을 구현 전용으로 두고, 클럭 조회에 실패하면 조용히 넘어가지 않고 하드 에러로
죽게 썼다. XDC 가 조용히 무시되면 제약 없는 비트스트림이 정상처럼 나온다.

라우팅된 체크포인트의 `report_exceptions` 에 max_dpo=40 양방향과 핀 false path 가 등재된
것, 그리고 국경 경로(`err_reads`→`s_axi_rdata`, `b_lat`→`flash_rx`)가 실제로 그 예외로
타이밍되는 것을 직접 확인했다. 간극을 닫아 두지 않으면 나중에 무엇이 보증됐는지 알 수 없다.

### 4. 빌드가 남의 설치본에 기대지 않게 한다

Digilent 보드파일(MIT)을 리포에 넣었다. PS7 프리셋(DDR·UART1)의 출처가 리포 안에 있어야
다른 사람이 같은 비트스트림을 만들 수 있다.

### 5. 계약 §6 의 각 항을 정확히 한 곳씩에서 집행한다

무효 ①~④·⑥ 은 PS 가 그 자리에서 판정해 `END valid=0 reason=...` 으로 중단한다. ⑤(미완주)는
END 미수신으로 PC 가 판정한다.

**커밋 전 자체 검토에서 버그가 하나 나왔다.** 초기 수신기는 `END valid=1` 수신만으로 VALID
로 저장했다. 그런데 `valid=1` 은 "PS 기준 무결"이지 "PC 까지 전부 도착"이 아니다. 수신기를
늦게 띄우거나(BEGIN·앞 행 놓침) 전송 중 행이 유실돼도 모자란 CSV 가 VALID 로 남는다.

⑤ 중 **전송 결측은 PS 가 알 수 없어 PC 수신기만이 집행 가능한 반쪽** 인데 그게 빠져
있었다. BEGIN 에서 steps·n 을 파싱해 END 에서 행수가 완전히 일치할 때만 VALID 로 하고,
불일치는 `_invalid` 로 돌리며 결측 위치를 출력한다.

### 6. PS 에는 시계도 git 도 없다

메타 3열(target/generated_at/git_rev)·타임스탬프 파일명·`_invalid` 리네임을 PC 가 맡는
이유는 하나다 — PS 가 만들 수 없는 값이다. 없는 것을 흉내 내게 하면 거짓 메타데이터가
CSV 에 박힌다.

### 7. 호스트 루프가 자기를 검사하게 만든다

스텝 0 을 리셋 위상 그대로 측정하면(INC 는 스텝 1부터) `phase_step` 과 하드웨어
`PHASE_POS` 가 1:1 이 된다. 매 스텝 대조가 공짜 자체 검사가 된다.

같은 성격의 방어가 둘 더 있다. 폴링에 소프트웨어 안전 한도(R10 T_max 16.9ms 의 수백 배)를
둬서 AXI 고장이 무한 대기로 이어지지 않게 했고, Σe_i² 는 u64 로 잡았다(최대 4.2e10 > 2³²).
`phase_ps` 는 정수 fs 연산으로 출력한다 — `xil_printf` 가 부동소수를 지원하지 않는다.

### 8. 이 설치본에서 죽는 경로는 버린다

클래식 xsct 배치 플로우(`platform create`)가 Vitis 서버 접속 타임아웃으로 재시도 포함 2회
실패했다. unified Vitis Python CLI 로 전환했다.

xsct 의 JTAG 명령(connect/fpga/dow)은 hw_server 경로라 별개이고 살아 있다 —
`program_g0.tcl` 이 그걸 쓴다. 덕분에 프로그래밍에 Vivado GUI 가 필요 없다.

### 9. 6분은 G0 에서 한 번이다

UART 115200 기준 `_reads` 전송이 스윕당 약 6분으로 본 측정 21초의 지배 항이다. G0 1회성
이라 수용한다. 거슬리면 XUartPs 로 921600 상향은 코드 몇 줄이다.
