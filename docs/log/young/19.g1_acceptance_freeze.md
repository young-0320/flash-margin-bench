## 근거

### 1. 범위 축소안을 기각했다 — 질문이 잘못 놓여 있었다

`roles.md` 미결 1번은 *"범위 축소안(Winbond 모델 상대 프로토콜 정합 1종) 채택 여부"* 였다.
처음에는 채택 쪽으로 기울었으나 **근거가 작업량이었고, 그것은 판단 기준이 될 수 없다.**
지민 혼자 하는 일도 아니고 지원 인력도 AI도 있다.

실질 기준으로 다시 보니 결론이 뒤집혔다. 기준은 **오라클의 순환 논증**이다.

`sim/smoke/tb_flash_spi_smoke.v`의 내장 슬레이브는 **우리가 짠 모델**이다
([로그 11](11.spi_master_rtl.md) — "W25Q64 행동 모델(0x0B, mode 0, PRBS 방출 컨벤션 =
flash_prbs15) 내장"). 우리가 이해한 프로토콜대로 응답하게 만들어져 있다. 그래서 **우리가
프로토콜을 잘못 이해했다면, 잘못된 RTL이 잘못된 모델을 상대로 통과한다.** 이것이 "오라클
1종 결손"의 실체다.

이 기준으로 항목을 가르면 노출/비노출이 갈린다.

| | 항목 | 왜 |
| --- | ---- | --- |
| 노출 (벤더 모델 필수) | F1 F2 F3 F5 F11 | 우리 모델이 우리 규칙대로 응답하므로 오해가 통과한다 |
| 비노출 (자기 정합) | F4 F6\~F10 C1\~C6 I1\~I3 F12 | 계약 자체가 정답을 쥔다. 칩 거동과 무관 |

그런데 cocotb는 **두 가지를 동시에** 준다.

1. **벤더 모델 상대 검증** — 순환 차단. 노출 항목에만 해당
2. **회귀 상시화** — smoke는 `sim/README.md`가 밝히듯 "cocotb 회귀 확립 전 임시 최소
   회귀"이고 **1회 통과했을 뿐 상시 실행이 아니다**

축소안은 이 둘을 뭉뚱그렸다. ②는 항목을 줄일 이유가 전혀 없다 — 오히려 전 항목이 대상이다.
축소로 얻으려던 것은 범위가 아니라 **"G1이 무엇을 증명했다고 말할 수 있는가"** 였고,
그건 항목을 줄여서가 아니라 출처를 밝혀야 얻어진다.

### 빠져 있던 항목 3개를 찾았다

기존 문서가 스왑 지점에서 *"내장 모델이 못 보는 것"* 을 셋 지목해 놓고 **정작 항목표에는
그 셋이 없었다.** 벤더 모델을 쓰는 유일한 이유인데 PASS 기준이 없었다.

W2에 음성 대조를 넣은 이유는, 정상 구간에서 어서션이 무발화하는 것만 확인하면 "어서션이
죽어 있어서 조용한 것"과 구분되지 않아서다. 의도적으로 위반시켜 발화를 확인해야 어서션이
살아 있음이 증명된다.

### 2. 판정을 셋으로 나눴다 (안 4)

#### 문제 — 문서 3개가 판정자를 다르게 지목하고 있었다

| 문서 | 판정자 |
| ---- | ------ |
| `s3.g1_test_plan.md` 구본 · [로그 10](10.realchip_sweep_decisions.md) · `sim/README` | 박지민 |
| `roles.md` v2 §검증(G1) | 한영웅 |

처음에는 "문서 충돌"로 봤으나 원문을 보니 각 문서는 자기 문맥에서 일관됐다. 시점과
지키려던 것이 달랐을 뿐이다.

- **7월**: 총력전으로 한영웅이 SPI 마스터 RTL을 급히 구현 → *RTL 작성자가 자기 RTL을
  승인하는 것*을 막으려 박지민 승인
- **8월(roles v2)**: 박지민이 cocotb를 구축할 차례 → *TB 작성자가 자기 TB를 판정하는
  것*을 막으려 한영웅 판정

**진짜 문제는 겸직이다.** 한영웅은 기준 작성자이면서 채점 대상 RTL의 실제 작성자이고,
박지민은 RTL 소유자이면서 TB 작성자다. 그래서 어느 쪽으로 몰아도 분리가 절반만 성립한다.

```
박지민 판정 → RTL 작성자(한영웅) ≠ 판정자 ✓ / TB 작성자(박지민) = 판정자 ✗
한영웅 판정 → TB  작성자(박지민) ≠ 판정자 ✓ / RTL 작성자(한영웅) = 판정자 ✗
```

3인 팀에서 완전 분리는 구조적으로 불가능하다.

#### 해소 — "RTL이 통과했는가"는 사람이 판정할 일이 아니다

어서션이 붙어 있으면 회귀가 PASS/FAIL을 자동으로 낸다. 재량이 없다. 사람의 재량이 실제로
들어가는 곳은 하나뿐이다 — **"어서션이 기준을 제대로 재고 있는가."**

| 단계 | 무엇을 | 누가 |
| ---- | ------ | ---- |
| ① | 어서션이 전 항목을 실제로 재는가 | 한영웅 (TB 비작성자) |
| ② | RTL이 통과하는가 | 회귀 (자동) |
| ③ | 블록 승인 집행 | 박지민 (RTL 소유자) |

한영웅은 자기 RTL의 통과 여부를 판정하지 않고(회귀가 한다), 박지민은 자기 TB의 충실성을
판정하지 않는다(한영웅이 한다). **겸직이 있어도 각 판정이 독립된다.**

#### 커버리지 대조를 붙인 이유 (안 3 → 안 4)

TB가 부실할 수 있는 방식은 셋이고 성질이 다르다.

```
(a) 누락        F2 테스트 함수가 아예 없다
(b) 형식 커버   함수는 있는데 항목을 안 잰다    async def test_f2(): assert err == 0
(c) 잘못 잼     재긴 재는데 기준이 틀렸다        tSHSL 최소값 오기
```

사람 심사만 두면(안 3) 셋 다 사람이 잡아야 한다. 그런데 **(a)는 가장 흔하고 가장 조용하며,
20여 개 목록 대조는 사람이 제일 못하는 종류의 일이다.** (b)(c)는 코드를 읽으면 눈에 띈다.

더 중요한 차이는 **시점**이다. 사람 심사는 판정 시점 1회짜리 스냅샷이라, 이후 TB가
리팩터링되거나 누가 실패 테스트를 주석 처리해도 다시 볼 계기가 없다. **G1은 한 번
통과하고 끝나는 게이트가 아니라 최종보고까지 유지돼야 한다.** 커버리지 대조를 회귀에
넣으면 매 실행마다 검사된다.

부수 효과로 재작업 왕복이 사라진다 — 박지민이 자기 터미널에서 (a)를 먼저 보므로,
한영웅에게 갈 때는 이미 (a)가 0이고 심사가 (b)(c)로 좁혀진다.

대조 스크립트를 한영웅 소유(`sim/check_coverage.py`)로 둔 것은 기준 쪽 산출물이기
때문이다. 채점 대상이 자기 채점 도구를 만들면 도입 취지가 사라진다. `sim/tb/`(박지민)
밖인 `sim/` 최상위에 둔다.

#### 정직한 한계를 문서에 박았다

**커버리지는 (a)만 잡는다.** `assert True`도 실행 횟수는 올라가고 covered로 표시된다.
지표가 생기면 사람은 지표만 보므로, "전 항목 covered"라는 초록 숫자가 (b)(c)에 대한
경계심을 낮출 위험이 안 3에는 없고 안 4에는 있다.

### 3. BASE_SECTOR 검증을 층으로 나눴다 (C-3)

계약 수정안 #1 §4는 인수 기준 A1\~A4를 **전부 실칩 실측**으로 썼고, 이유를 스스로 밝힌다
— *"G1 시뮬레이션 환경 없이도 판정 가능하도록."* **G1이 없다는 전제의 방편**이다.

전부 시뮬로 당기는 안(C-2)에는 함정이 있다. F11·F12를 인수 조건으로 만들면 **BASE_SECTOR
RTL 구현이 G1 완성에 종속**된다. 그런데 9월 마모는 BASE_SECTOR에 의존하고(S-1이 전제로
걸었다), G1은 워크플로 5가 *"게이트 조건이 아니라 최종보고 조건"* 이라고 명시한 항목이다.
**마모 착수가 G1에 묶인다.** 수정안이 실측으로 쓰인 것은 임시방편이자 일정 방어였다.

그래서 항목별 성질에 따라 나눴다.

| | 성질 | 처리 |
| --- | ---- | ---- |
| A1 하위 호환 | 실칩 곡선이어야만 나오는 숫자(39,737.3ps) | **실측 유지** — 시뮬 대체 불가 |
| A2 읽기 창 이동 | 로직 오류는 시뮬이 잡지만, 시뮬 모델의 메모리는 우리가 적재한 것이다 | **양쪽** — 시뮬 선행 권장 + 실측 유지 |
| A3 범위 거부 | 순수 로직. 조건식 하나 | **F12로 이관** — 실측 불요 |
| A4 R8 무결성 | 양쪽에서 의미 있음 | 양쪽 |

중복처럼 보이지만 성격이 다르다 — 실측은 *1회 인수*, 시뮬은 *상시 유지*. BASE_SECTOR는
9월 내내 마모 데이터의 근간이라 누가 나중에 `flash_rx.v`의 시드 경로를 건드리면 회귀가
잡아야 한다.

수정안 #1의 개정 폭은 A3 한 항목 + A2 한 문단으로 그쳤고, **§2 계약 변경분은 불변**이라
3인에 상정된 내용 자체는 바뀌지 않았다.

### 4. `page(i)` 표기로 승인 의존을 끊었다

동결의 최대 위험은 계약 수정안 #1이 미승인이라는 점이었다. 승인되면 F1(주소)·F3(시드)이
바뀌므로, v1 기준으로 동결하면 승인 즉시 다시 열어야 한다.

수정안 #1 §2.5가 낸 답을 그대로 썼다 — *"측정 패턴 행은 수정이 불필요하다. `page(i)`의
정의만 바뀌며 시드 규칙 자체는 그대로다."*

```
page(i) = BASE_SECTOR × 16 + i
계약 v1 = BASE_SECTOR 레지스터 부재 → page(i) = i  (특수 케이스)
```

F1·F3을 `page(i)` 기준으로 다시 쓰니 **승인 여부와 무관하게 동결 가능**해졌다. 승인 시
추가되는 것은 F11·F12뿐이고 기존 항목은 손대지 않는다.

---

여기까지가 동결이고, 아래 §5\~§11이 자체 재검토에서 나온 미비점 8건(H 트랙)과 그 선행이던
C 트랙(`check_coverage.py`)의 근거다.

### 5. W3를 폐기했다 — 실패 방향이 존재하지 않았다 (H1)

구 W3의 PASS 기준은 *"SCLK 유휴 low면 통과, 유휴 high로 바꾸면 실패할 것"* 이었고,
H1이 지적한 것은 **근거가 데이터시트가 아니라 추측**이라는 점이었다. 확인해 보니 추측이
틀린 정도가 아니라 **명제 자체가 성립하지 않았다.**

#### 칩 쪽 — 실패하지 않는다

데이터시트 §6.1:

> SPI bus operation Mode 0 (0,0) and 3 (1,1) are supported. The primary difference between
> Mode 0 and Mode 3 concerns the normal state of the CLK signal when the SPI bus master is
> in standby… For Mode 0, the CLK signal is normally low on the falling and rising edges of
> /CS. For Mode 3, the CLK signal is normally high on the falling and rising edges of /CS.

**둘 다 지원되고, 차이는 /CS 에지에서의 유휴 레벨뿐이다.** 데이터 자체는 양쪽 모두
상승 에지 샘플·하강 에지 출력이라 프레임당 상승 에지 수도 같다. 유휴 high로 주면 모델은
mode 3로 정상 동작한다 — 실패가 나오지 않는다.

#### 우리 쪽 — 바꿀 수 있는 상태가 아니다

이쪽이 더 결정적이다. `flash_spi_ctrl.v:12` 헤더:

> SCLK는 이 모듈이 만들지 않는다 — `sclk_en`을 top의 **ODDR(D1=0, D2=sclk_en)** 에 공급해
> `clk_core`를 무분주 포워딩(R9).

`sclk_en=0`이면 두 반주기가 모두 D1=0을 내므로 **유휴 low는 런타임 상태가 아니라 배선
상수**다. "유휴 high로 바꾼다"는 것은 ODDR의 상수 포트를 고친다는 뜻이고, **그렇게 고친
DUT는 채점 대상이 아니다.** 다른 설계를 통과시키고 원래 설계를 승인할 수는 없다.

#### 지키려던 성질은 F2로 옮겼다

W3가 실제로 지키려던 것은 *"우리가 mode 0을 지키는가"* 였고, 그건 **와이어에서 직접
보이는 값**이다. F2에 **CS↓·CS↑ 두 시점 모두에서 SCLK=low**를 넣었다 — 데이터시트가
정의하는 mode 0 진입 조건 그 자체이므로 추측이 개입할 자리가 없다.

검증 불가능한 항목을 표에 남겨두면 **커버리지가 초록으로 뜨는데 그중 하나는 아무것도
증명하지 않는다.** §2가 커버리지에 대해 경고한 위험(초록 숫자가 경계심을 낮춘다)이
항목 자체에서 발생하는 형태다. 항목이 하나 줄어드는 것보다 나쁘다.

### 6. F11의 BER 관측에 구조적 맹점이 있다 — 실측 A2가 왜 남아야 하는가 (H2)

H2는 "249의 근거가 시뮬로 옮겨오지 않았다"는 지적이었는데, 지점을 다시 세우다가
**더 무거운 것**이 나왔다.

기대 패턴의 시드는 `page(i)[13:0]`이다(계약 §5). 즉 **패턴은 16,384페이지 = 1,024섹터마다
반복**된다. 그러면 주소 상위 비트 [14]가 통째로 유실되는 버그가 나도, 모델은 별칭
페이지의 **같은 내용**을 돌려주고 **BER은 0으로 통과한다.**

```
BASE_SECTOR = 1,024  →  page(0) = 16,384
비트[14] 유실 버그    →  실제로는 page 0 을 읽음
기대 시드            =  16,384 & 0x3FFF = 0  =  page 0 의 시드
                     →  일치. 에러 0. 조용히 통과
```

**하필 구본이 "상위 주소 비트 경로"를 보겠다고 고른 `1,024 이상 한 점`이 정확히 그
맹점**이다. 상위 비트를 보려고 고른 지점이 상위 비트를 못 보는 지점이었다.

수정안 #1 §3이 이 별칭을 이미 알고 있었고 *"실사용상 무해"* 라고 결론지었다 — 한 스윕이
연속 N≤2,048페이지만 읽으므로 별칭 짝이 같은 스윕에 못 들어온다는 이유로. 그건 맞다.
그러나 **검증 항목의 검출력**은 다른 문제였고, 그 구분이 F11로 넘어오면서 빠졌다.

#### 해결 — 관측을 두 층으로 나눴다

| 층 | 무엇을 보는가 | 별칭에 걸리는가 |
| -- | ------------- | --------------- |
| ⑴ 와이어 주소 디코드 | MOSI의 24비트 주소 = `page(i)`×256 | **아니오** — 주소 바이트는 별칭되지 않는다 |
| ⑵ BER | 주소와 시드가 **함께** 움직였는가 | 예 (1,024 배수 지점에서 무력) |

둘을 **동등한 필수 조건**으로 두면 상위 비트도 보이고 주소·시드 동반도 보인다.
F1이 이미 주소를 오라클 V로 재고 있으므로 F11은 그것을 `BASE_SECTOR`≠0에서 재수행하는
셈이다.

#### 그래도 실측 A2는 유지된다

시뮬 모델의 메모리는 **우리가 적재한 것**이다. 즉 F11이 답하는 질문은 *"RTL이 의도한
주소를 발행하는가"* 까지이고, *"칩의 그 구역이 실제로 그 데이터를 갖는가"* 는 여전히
실칩만 답한다. §3의 실측 유지 결정은 그대로다 — 다만 그 근거를 "1,024섹터 aliasing 구멍"
대신 **"모델 메모리는 우리 손을 탄 것"** 으로 다시 적었다. 앞의 것은 F11이 와이어 관측으로
좁혔고, 뒤의 것은 시뮬이 원리상 못 넘는다.

#### 지점 재선정

`0 / 1 / 1,024 / 2,041`. **249를 빼고 1을 넣었다.**

- `1`은 **섹터→페이지 ×16 스케일링**만 분리한다. `page(0)=16`이므로 `BASE_SECTOR`를
  페이지로 오해해 더한 구현(`page(0)=1`)이 여기서 바로 갈린다. 큰 값에서는 다른 오류와
  섞여 원인이 안 보인다
- `249`는 *"종전 12비트 주소 폭의 상한 부근"* 이 근거였는데 시뮬에는 그 제약이 없다.
  **실측 A2에서는 종전 비트스트림과의 회귀 비교라 여전히 유효**하므로 수정안 쪽은 안 건드렸다

### 7. F12를 수정안 #2에서 떼어냈다 (H3)

H3은 "N=112의 출처가 안 적혀 있다"였다. 출처를 한 줄 붙이는 것보다 **N에 무관하게
일반화**하는 쪽을 택했다 — 수정안 #2가 미승인이라, 각주를 달면 승인 여부에 따라 다시
고쳐야 한다.

```
구:  BASE_SECTOR = 2,042, N = 112   →  32,783   (초과폭 16)
신:  BASE_SECTOR = 2,047, N =  17   →  32,768   (초과폭  1)
```

**초과폭을 1로 좁힌 것이 부수 소득**이다. 비교 연산자를 `>` 대신 `>=`로 쓴 off-by-one은
초과폭 16에서는 어차피 걸려 통과하지만, 초과폭 1에서는 갈린다.

여기에 **음성 대조**를 붙였다 — `BASE_SECTOR=2,047, N=16`(= 정확히 32,767)은 `CFG_ERR`
없이 정상 시작해야 한다. 거부만 확인하면 **조건식이 항상 참인 구현**(전부 거부)과
구분되지 않는다. W2에 음성 대조를 넣은 것과 같은 이유다.

### 8. 커버리지 목록의 원전을 하나로 유지했다 (H5)

선택지는 둘이었고 실패 양상이 달랐다.

| | 실패 방식 |
| --- | --------- |
| 별도 목록 파일 | 문서와 목록이 **어긋난다.** 어긋난 쪽이 기준 행세를 하면 채점표가 둘이 된다 |
| 문서 표 파싱 | 서식이 바뀌면 **조용히 깨진다.** 0개를 파싱하고도 "누락 없음"이 될 수 있다 |

표 파싱을 택하고 **조용한 실패만 막았다.** 동결본 §5 말미의 합계 선언
(`**합계 23항목** — F 12 · W 2 · C 6 · I 3`)과 표 파싱 결과를 교차 검증한다.

```
표 파싱 = 23 (F 12 · W 2 · C 6 · I 3)
합계 선언 = 23 (F 12 · W 2 · C 6 · I 3)   → 일치
불일치 시 커버리지 판정 이전에 비영 종료
```

합계 선언은 **서식이 아니라 내용**이라 표 서식과 함께 깨지지 않는다. 파싱이 망가지면
0개가 아니라 불일치로 드러난다. 목록 파일을 안 두므로 원전은 계속 하나다.

### 9. 채점 대상을 트리로 정의했다 (H7)

H7의 질문은 *"3파일인가, `flash_rx`·`flash_logbuf`·`flash_prbs15`도 포함인가"* 였다.
**질문의 축이 잘못 놓여 있었다** — 구본의 3파일은 로그 11이 **새로 쓴** 파일들이고,
채점 대상은 신규 여부가 아니라 **계약 항목이 무엇을 재는가**로 갈린다.

- F3(주소→시드 정합)은 `flash_rx.v:65`의 시드 경로를 잰다
- F6·R8(정확 계수)은 `flash_logbuf.v`를 잰다
- F3의 기대 패턴은 `flash_prbs15.v`가 만든다

재사용 모듈이라고 빼면 **항목이 채점 대상 없이 뜬다.** 그래서 목록을 손으로 유지하지
않고 **"DUT가 인스턴스화하는 것 전부"** 로 정의하고, 현재 트리를 펼쳐 표로 적었다.
`flash_ctrl.v`·`flash_top.v`는 G0 루프백 경로라 SPI 트리에 없으므로 제외된다.

`core_mmcm.v`는 Xilinx 프리미티브를 감싸 시뮬에서 스텁으로 대체되므로 **그 부분은
채점되지 않는다**고 명시했다. 스텁을 채점 대상처럼 적어 두면 C 항목이 실제보다 넓게
보인다.

### 10. 게이트 개방 조건에 "같은 실행" 조항을 넣었다 (H8)

H8이 예시로 준 형태는 *"3블록 전부 승인 + 커버리지 전항"* 이었는데, 쓰다 보니 한 항이
더 필요했다.

> ④ ②(커버리지)와 ③(전항 PASS)이 **같은 회귀 실행**에서 나올 것

커버리지가 통과한 실행과 전항 PASS가 나온 실행이 다르면 **그 사이에 실패하는 테스트가
지워졌는지 알 수 없다.** §2에서 커버리지를 회귀에 넣은 이유(사람 심사는 1회 스냅샷)와
같은 논리가 게이트 판정 자체에도 적용된다.

### 11. 판정서를 기준 옆에 뒀다 (H4)

후보 셋 중 `docs/spec/s3.g1_review.md`를 택했다.

- `docs/log/young/`은 **시간순 개인 기록**이다. ③이 참조해야 하는 절차 산출물이 "언제
  적었는지 알아야 찾을 수 있는" 자리에 있으면 안 된다
- `docs/results/`는 승격된 **실측** 산출물의 자리다(plots·data·captures). 코드 열람
  기록은 측정이 아니다
- 블록마다 파일을 나누면 재판정이 반복될 때 최신본 찾기 문제가 생긴다 → **단일 누적 문서**

기준과 같은 폴더인 이유는 실용적이다. **판정 기록은 최종보고서에서 "작성자와 승인자를
분리했다"를 뒷받침하는 유일한 증거**이고, 기준과 판정을 나란히 제시할 수 있어야 한다.
