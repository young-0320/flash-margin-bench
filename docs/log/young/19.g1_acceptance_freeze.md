## 1. 범위 축소안을 기각했다 — 질문이 잘못 놓여 있었다

`roles.md` 미결 1번은 *"범위 축소안(Winbond 모델 상대 프로토콜 정합 1종) 채택 여부"* 였다.
처음에는 채택 쪽으로 기울었으나 **근거가 작업량이었고, 그것은 판단 기준이 될 수 없다.**
지민 혼자 하는 일도 아니고 지원 인력도 AI도 있다.

실질 기준으로 다시 보니 결론이 뒤집혔다. 기준은 **오라클의 순환 논증**이다.

`sim/smoke/tb_flash_spi_smoke.v`의 내장 슬레이브는 **우리가 짠 모델**이다(로그 11 —
"W25Q64 행동 모델(0x0B, mode 0, PRBS 방출 컨벤션 = flash_prbs15) 내장"). 우리가 이해한
프로토콜대로 응답하게 만들어져 있다. 그래서 **우리가 프로토콜을 잘못 이해했다면, 잘못된
RTL이 잘못된 모델을 상대로 통과한다.** 이것이 "오라클 1종 결손"의 실체다.

이 기준으로 항목을 가르면 노출/비노출이 갈린다.

| | 항목 | 왜 |
| --- | ---- | --- |
| 노출 (벤더 모델 필수) | F1 F2 F3 F5 F11 | 우리 모델이 우리 규칙대로 응답하므로 오해가 통과한다 |
| 비노출 (자기 정합) | F4 F6\~F10 C1\~C6 I1\~I3 F12 | 계약 자체가 정답을 쥔다. 칩 거동과 무관 |

그런데 cocotb는 **두 가지를 동시에** 준다.

1. **벤더 모델 상대 검증** — 순환 차단. 노출 항목에만 해당
2. **회귀 상시화** — smoke는 `sim/README.md`가 밝히듯 "cocotb 회귀 확립 전 임시 최소
   회귀"이고 **1회 통과했을 뿐 상시 실행이 아니다**

축소안은 이 둘을 뭉뚱그렸다. ②는 항목을 줄일 이유가 전혀 없다 — 오히려 전 항목이 대상이다.

**결론: 축소가 아니라 분해.** 전 항목을 cocotb로 이관하되 항목마다 오라클 출처(V/S)를
명시한다. 축소로 얻으려던 것은 범위가 아니라 **"G1이 무엇을 증명했다고 말할 수 있는가"**
였고, 그건 항목을 줄여서가 아니라 출처를 밝혀야 얻어진다.

### 빠져 있던 항목 3개를 찾았다

기존 문서가 스왑 지점에서 *"내장 모델이 못 보는 것"* 을 셋 지목해 놓고 **정작 항목표에는
그 셋이 없었다.** 벤더 모델을 쓰는 유일한 이유인데 PASS 기준이 없었다. W1(명령 오인식
반응)·W2(tSHSL 위반 반응)·W3(mode 경계)로 신설했다.

W2에는 **음성 대조**를 넣었다 — 정상 구간에서 어서션이 무발화하는 것만 확인하면
"어서션이 죽어 있어서 조용한 것"과 구분되지 않는다. 의도적으로 위반시켜 발화를 확인해야
어서션이 살아 있음이 증명된다.

## 2. 판정을 셋으로 나눴다 (안 4)

### 문제 — 문서 3개가 판정자를 다르게 지목하고 있었다

| 문서 | 판정자 |
| ---- | ------ |
| `s3.g1_test_plan.md` 구본 · 로그 10 · `sim/README` | 박지민 |
| `roles.md` v2 §검증(G1) | 한영웅 |

처음에는 "문서 충돌"로 봤으나 원문을 보니 각 문서는 자기 문맥에서 일관됐다. 시점과
지키려던 것이 달랐을 뿐이다.

- **7월**: 총력전으로 한영웅이 SPI 마스터 RTL을 급히 구현 → *RTL 작성자가 자기 RTL을
  승인하는 것*을 막으려 박지민 승인
- **8월(roles v2)**: 박지민이 cocotb를 구축할 차례 → *TB 작성자가 자기 TB를 판정하는
  것*을 막으려 한영웅 판정

**진짜 문제는 겸직이다.** 한영웅은 기준 작성자이면서 채점 대상 RTL의 실제 작성자이고,
박지민은 RTL 소유자이면서 TB 작성자다. 그래서 어느 쪽으로 몰아도 분리가 절반만 성립한다.

```
박지민 판정 → RTL 작성자(한영웅) ≠ 판정자 ✓ / TB 작성자(박지민) = 판정자 ✗
한영웅 판정 → TB  작성자(박지민) ≠ 판정자 ✓ / RTL 작성자(한영웅) = 판정자 ✗
```

3인 팀에서 완전 분리는 구조적으로 불가능하다.

### 해소 — "RTL이 통과했는가"는 사람이 판정할 일이 아니다

어서션이 붙어 있으면 회귀가 PASS/FAIL을 자동으로 낸다. 재량이 없다. 사람의 재량이 실제로
들어가는 곳은 하나뿐이다 — **"어서션이 기준을 제대로 재고 있는가."**

| 단계 | 무엇을 | 누가 |
| ---- | ------ | ---- |
| ① | 어서션이 24항목을 실제로 재는가 | 한영웅 (TB 비작성자) |
| ② | RTL이 통과하는가 | 회귀 (자동) |
| ③ | 블록 승인 집행 | 박지민 (RTL 소유자) |

한영웅은 자기 RTL의 통과 여부를 판정하지 않고(회귀가 한다), 박지민은 자기 TB의 충실성을
판정하지 않는다(한영웅이 한다). **겸직이 있어도 각 판정이 독립된다.**

### 커버리지 대조를 붙인 이유 (안 3 → 안 4)

TB가 부실할 수 있는 방식은 셋이고 성질이 다르다.

```
(a) 누락        F2 테스트 함수가 아예 없다
(b) 형식 커버   함수는 있는데 항목을 안 잰다    async def test_f2(): assert err == 0
(c) 잘못 잼     재긴 재는데 기준이 틀렸다        tSHSL 최소값 오기
```

사람 심사만 두면(안 3) 셋 다 사람이 잡아야 한다. 그런데 **(a)는 가장 흔하고 가장 조용하며,
22개 목록 대조는 사람이 제일 못하는 종류의 일이다.** (b)(c)는 코드를 읽으면 눈에 띈다.

더 중요한 차이는 **시점**이다. 사람 심사는 판정 시점 1회짜리 스냅샷이라, 이후 TB가
리팩터링되거나 누가 실패 테스트를 주석 처리해도 다시 볼 계기가 없다. **G1은 한 번
통과하고 끝나는 게이트가 아니라 최종보고까지 유지돼야 한다.** 커버리지 대조를 회귀에
넣으면 매 실행마다 검사된다.

부수 효과로 재작업 왕복이 사라진다 — 박지민이 자기 터미널에서 (a)를 먼저 보므로,
한영웅에게 갈 때는 이미 (a)가 0이고 심사가 (b)(c)로 좁혀진다.

**대조 스크립트는 한영웅 소유**(`sim/check_coverage.py`)로 뒀다. 기준 쪽 산출물이라
채점 대상이 자기 채점 도구를 만들면 도입 취지가 사라진다. `sim/tb/`(박지민) 밖인
`sim/` 최상위에 둔다.

### 정직한 한계를 문서에 박았다

**커버리지는 (a)만 잡는다.** `assert True`도 실행 횟수는 올라가고 covered로 표시된다.
지표가 생기면 사람은 지표만 보므로, "22/22 covered"라는 초록 숫자가 (b)(c)에 대한
경계심을 낮출 위험이 안 3에는 없고 안 4에는 있다. 동결본 §4에 경고 문단을 명시해 두었다.

## 3. BASE_SECTOR 검증을 층으로 나눴다 (C-3)

계약 수정안 #1 §4는 인수 기준 A1\~A4를 **전부 실칩 실측**으로 썼고, 이유를 스스로 밝힌다
— *"G1 시뮬레이션 환경 없이도 판정 가능하도록."* **G1이 없다는 전제의 방편**이다.

전부 시뮬로 당기는 안(C-2)에는 함정이 있다. F11·F12를 인수 조건으로 만들면 **BASE_SECTOR
RTL 구현이 G1 완성에 종속**된다. 그런데 9월 마모는 BASE_SECTOR에 의존하고(S-1이 전제로
걸었다), G1은 워크플로 5가 *"게이트 조건이 아니라 최종보고 조건"* 이라고 명시한 항목이다.
**마모 착수가 G1에 묶인다.** 수정안이 실측으로 쓰인 것은 임시방편이자 일정 방어였다.

그래서 항목별 성질에 따라 나눴다.

| | 성질 | 처리 |
| --- | ---- | ---- |
| A1 하위 호환 | 실칩 곡선이어야만 나오는 숫자(39,737.3ps) | **실측 유지** — 시뮬 대체 불가 |
| A2 읽기 창 이동 | 로직 오류는 시뮬이 잡지만, 1,024섹터 배수 aliasing 구멍은 실측이 필요 | **양쪽** — 시뮬 선행 권장 + 실측 유지 |
| A3 범위 거부 | 순수 로직. 조건식 하나 | **F12로 이관** — 실측 불요 |
| A4 R8 무결성 | 양쪽에서 의미 있음 | 양쪽 |

**게이팅은 실측이 계속 하고, 시뮬은 상시 회귀로 보강한다.** 순서 의존이 생기지 않으므로
G1이 늦어도 마모 일정이 묶이지 않고, G1이 서면 그 검증이 회귀에 남는다. 중복처럼 보이지만
성격이 다르다 — 실측은 *1회 인수*, 시뮬은 *상시 유지*. BASE_SECTOR는 9월 내내 마모 데이터의
근간이라 누가 나중에 `flash_rx.v`의 시드 경로를 건드리면 회귀가 잡아야 한다.

수정안 #1의 개정 폭은 A3 한 항목 + A2 한 문단으로 그쳤고, **§2 계약 변경분은 불변**이라
3인에 상정된 내용 자체는 바뀌지 않았다.

## 4. `page(i)` 표기로 승인 의존을 끊었다

동결의 최대 위험은 계약 수정안 #1이 미승인이라는 점이었다. 승인되면 F1(주소)·F3(시드)이
바뀌므로, v1 기준으로 동결하면 승인 즉시 다시 열어야 한다.

수정안 #1 §2.5가 낸 답을 그대로 썼다 — *"측정 패턴 행은 수정이 불필요하다. `page(i)`의
정의만 바뀌며 시드 규칙 자체는 그대로다."*

```
page(i) = BASE_SECTOR × 16 + i
계약 v1 = BASE_SECTOR 레지스터 부재 → page(i) = i  (특수 케이스)
```

F1·F3을 `page(i)` 기준으로 다시 쓰니 **승인 여부와 무관하게 동결 가능**해졌다. 승인 시
추가되는 것은 F11·F12뿐이고 기존 항목은 손대지 않는다.
