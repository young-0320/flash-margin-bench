# Vivado/Vitis 전체 빌드 명령어 정리

## 1. 목적

이 문서는 `flash-margin-bench` 프로젝트에서 실제 보드 실험에 필요한 파일을 만드는
명령어를 한곳에 정리한 기록이다.

빌드 결과는 크게 세 종류다.

- `.bit`: FPGA의 PL 영역에 회로를 구성하는 파일
- `.xsa`: FPGA 하드웨어 구성을 Vitis에 전달하는 파일
- `.elf`: Zynq의 ARM 프로세서에서 실행할 프로그램

`.elf`는 Ubuntu PC에서 직접 실행하는 파일이 아니다. 나중에 `xsct`를 사용해 보드의
ARM 프로세서로 전송한다.

## 2. 작업 폴더 및 도구 설정

모든 명령은 WSL Ubuntu 터미널에서 실행한다.

```bash
cd /mnt/c/Users/418cj/flash-margin-bench

export VITIS_SETTINGS=/home/master/AMDDesignTools/2025.2/Vitis/settings64.sh
source "$VITIS_SETTINGS"

which vivado
which vitis
which xsct
vivado -version | head -1
```

확인한 버전:

```text
vivado v2025.2 (64-bit)
```

새 Ubuntu 터미널을 열었다면 빌드 전에 `source "$VITIS_SETTINGS"`를 다시 실행해야
한다.

## 3. G0 루프백 계측기 빌드

G0는 실제 Flash 대신 FPGA 내부 루프백 경로를 사용해 계측기 자체가 정상적으로
동작하는지 확인하는 단계다.

### 3.1 G0 bit/XSA 생성

```bash
vivado -mode batch \
  -source fpga/scripts/build_g0_loopback.tcl \
  -tclargs bit
```

생성 파일:

```text
build/vivado/g0_loopback.runs/impl_1/g0_wrapper.bit
build/vivado/g0_loopback.xsa
```

### 3.2 G0 ELF 생성

```bash
vitis -s ps/scripts/build_g0_sweep.py
```

생성 파일:

```text
build/vitis/g0_sweep/build/g0_sweep.elf
```

## 4. G2 Flash 준비 단계 빌드

G2는 Zynq PS의 SPI를 실제 Winbond Flash 핀으로 연결하는 단계다. 이 하드웨어 위에서
`flash_prep.elf`를 실행해 UID를 읽고 측정용 데이터를 준비한다.

### 4.1 G2 bit/XSA 생성

```bash
vivado -mode batch \
  -source fpga/scripts/build_g2_jedec.tcl
```

생성 파일:

```text
build/vivado_g2/g2_jedec.runs/impl_1/g2_wrapper.bit
build/vivado_g2/g2_jedec.xsa
```

### 4.2 flash_prep ELF 생성

```bash
vitis -s ps/scripts/build_flash_prep.py
```

생성 파일:

```text
build/vitis_prep/flash_prep/build/flash_prep.elf
```

파일이 만들어졌는지만 확인할 때는 다음 명령을 사용한다.

```bash
ls -lh build/vitis_prep/flash_prep/build/flash_prep.elf
```

파일 경로만 입력하면 ARM용 ELF를 Ubuntu PC에서 실행하려 하므로 다음 오류가 발생한다.
이 오류는 ELF 파일 자체가 잘못됐다는 뜻이 아니다.

```text
cannot execute binary file: Exec format error
```

## 5. G3 실칩 스윕 계측기 빌드

G3는 실제 Flash를 읽으면서 샘플링 위상을 이동해 타이밍 마진을 측정하는 단계다.
25, 45, 75 MHz용 하드웨어와 ARM 프로그램을 각각 만든다.

### 5.1 G3 bit/XSA 생성

```bash
vivado -mode batch \
  -source fpga/scripts/build_g3_chip.tcl \
  -tclargs bit 25

vivado -mode batch \
  -source fpga/scripts/build_g3_chip.tcl \
  -tclargs bit 45

vivado -mode batch \
  -source fpga/scripts/build_g3_chip.tcl \
  -tclargs bit 75
```

생성 파일:

```text
build/vivado_g3_25/g3_chip_25.runs/impl_1/g3_wrapper.bit
build/vivado_g3_25/g3_chip_25.xsa

build/vivado_g3_45/g3_chip_45.runs/impl_1/g3_wrapper.bit
build/vivado_g3_45/g3_chip_45.xsa

build/vivado_g3_75/g3_chip_75.runs/impl_1/g3_wrapper.bit
build/vivado_g3_75/g3_chip_75.xsa
```

### 5.2 G3 ELF 생성

```bash
G3_MHZ=25 vitis -s ps/scripts/build_g3_sweep.py
G3_MHZ=45 vitis -s ps/scripts/build_g3_sweep.py
G3_MHZ=75 vitis -s ps/scripts/build_g3_sweep.py
```

생성 파일:

```text
build/vitis_g3_25/g3_sweep/build/g3_sweep.elf
build/vitis_g3_45/g3_sweep/build/g3_sweep.elf
build/vitis_g3_75/g3_sweep/build/g3_sweep.elf
```

## 6. 전체 명령어 모음

처음부터 다시 빌드할 때 아래 블록을 위에서부터 차례로 실행한다. 각 명령이 완전히
끝나서 셸 프롬프트가 돌아온 뒤 다음 명령을 실행한다.

```bash
cd /mnt/c/Users/418cj/flash-margin-bench

export VITIS_SETTINGS=/home/master/AMDDesignTools/2025.2/Vitis/settings64.sh
source "$VITIS_SETTINGS"

# G0: 루프백 계측기
vivado -mode batch -source fpga/scripts/build_g0_loopback.tcl -tclargs bit
vitis -s ps/scripts/build_g0_sweep.py

# G2: 실제 Flash 준비용 하드웨어와 ARM 앱
vivado -mode batch -source fpga/scripts/build_g2_jedec.tcl
vitis -s ps/scripts/build_flash_prep.py

# G3: 실제 Flash 마진 스윕용 하드웨어
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs bit 25
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs bit 45
vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs bit 75

# G3: 각 주파수용 ARM 스윕 앱
G3_MHZ=25 vitis -s ps/scripts/build_g3_sweep.py
G3_MHZ=45 vitis -s ps/scripts/build_g3_sweep.py
G3_MHZ=75 vitis -s ps/scripts/build_g3_sweep.py
```

## 7. 최종 산출물 확인

다음 명령에서 모든 파일 이름이 출력되고 `No such file or directory`가 없어야 한다.

```bash
ls -lh \
  build/vivado/g0_loopback.runs/impl_1/g0_wrapper.bit \
  build/vivado/g0_loopback.xsa \
  build/vitis/g0_sweep/build/g0_sweep.elf \
  build/vivado_g2/g2_jedec.runs/impl_1/g2_wrapper.bit \
  build/vivado_g2/g2_jedec.xsa \
  build/vitis_prep/flash_prep/build/flash_prep.elf \
  build/vivado_g3_25/g3_chip_25.runs/impl_1/g3_wrapper.bit \
  build/vivado_g3_25/g3_chip_25.xsa \
  build/vitis_g3_25/g3_sweep/build/g3_sweep.elf \
  build/vivado_g3_45/g3_chip_45.runs/impl_1/g3_wrapper.bit \
  build/vivado_g3_45/g3_chip_45.xsa \
  build/vitis_g3_45/g3_sweep/build/g3_sweep.elf \
  build/vivado_g3_75/g3_chip_75.runs/impl_1/g3_wrapper.bit \
  build/vivado_g3_75/g3_chip_75.xsa \
  build/vitis_g3_75/g3_sweep/build/g3_sweep.elf
```

타이밍 제약 통과 여부는 다음 명령으로 확인한다.

```bash
grep -L "All user specified timing constraints are met" \
  build/vivado*/*.runs/impl_1/*_timing_summary_routed.rpt
```

이 명령은 **아무것도 출력하지 않는 것이 정상**이다. 파일 이름이 출력되면 해당 빌드가
타이밍 제약을 통과하지 못한 것이므로 그 비트스트림으로 측정하면 안 된다.

## 8. 보드에 올릴 때 사용하는 명령

빌드가 끝났다고 자동으로 보드에 올라가는 것은 아니다. 보드의 USB/JTAG 연결과 JP5의
JTAG 부팅 모드를 확인한 뒤 `xsct`로 전송한다.

```bash
# G0 루프백 시험
xsct ps/scripts/program_g0.tcl

# G2 Flash 준비 및 UID 확인
xsct ps/scripts/program_g2.tcl \
  build/vitis_prep/flash_prep/build/flash_prep.elf

# G3 실칩 스윕: 필요한 주파수 하나를 선택
xsct ps/scripts/program_g3.tcl 25
xsct ps/scripts/program_g3.tcl 45
xsct ps/scripts/program_g3.tcl 75
```

G3 세 명령은 동시에 실행하는 명령이 아니다. 측정하려는 주파수에 맞는 명령을 하나씩
사용한다.

## 9. 이번 빌드 확인 결과

- G0 bit/XSA 생성 및 타이밍 제약 통과
- G0 `g0_sweep.elf` 생성
- G2 bit/XSA 생성
- `flash_prep.elf` 생성
- G3 25/45/75 MHz bit/XSA 생성 및 타이밍 제약 통과
- G3 25/45/75 MHz `g3_sweep.elf` 생성

따라서 G0 루프백 시험과 G2/G3 실제 Flash 시험에 필요한 빌드 산출물이 준비됐다.
