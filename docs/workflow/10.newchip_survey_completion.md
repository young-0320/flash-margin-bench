## M. chip04\~10 전수 측정

### 칩당 절차 (약 3분)

```
1. 전원 차단 → 소켓 교체 → ESD 방전(케이스 접지) → 전원 인가
2. uv run python host/run/run_sweep_chip.py --mode newchip --mhz 25   (분석까지 자동)
3. 라벨 프롬프트에 chipNN (신규 UID면 등록부에 자동 기입)
4. uv run python host/analysis/bathtub_analysis.py data/sweep_chipNN_<uid16>_<stamp>.csv
5. 원본을 build/data/ → data/ 로 이동, 집계표에 행 추가
```

### 앵커를 끼우는 위치 (S-2 §8, 2026-09-16 개정)

```
처음        chip02  ②
            chip04 ~ chip06
중간        chip02  ③        ← 세션 전반·후반을 가른다
            chip07 ~ chip10
마지막      chip02  ④
```

```
앵커 측정:  uv run python host/run/run_sweep_chip.py --mode sweep --mhz 25 --chip 2
            (prep 없이 — 재장착 성분만 본다. P/E 불변. S-2 §8)
```

- ②③④ 3회로 **재장착 σ**를 낸다. 자유도 2가 필요해서 3회다 (2회는 표준편차가 아니라 차이 하나)
- 앵커 측정에는 **재장착이 포함된다** — 소켓에서 빼고 다시 꽂는다. 2026-09-15의 chip02 3회는
  재장착이 없어 세션 간 성분(σ 4.65ps)만 담고 있다
- 판정선: chip02 width@10⁻²가 **39,630.2 ± 3σ(≈14ps)** 밖이면 드리프트를 의심하고 멈춘다

### B. `reproduce.py` 후속 — 무엇이 남았나

**① 닫혔다 (2026-09-16).** g0·g3 의 Vivado 전체 경로를 맨바닥에서 2회 돌렸다 — 8단계
**8/8 PASS · FAIL 0 · WARN 0**, 수치는 `build_reproduction.md` §3.5 기준값과 일치. 전체 약 9분
(문서의 "20분"은 2024.2 시절 값이라 정정했다). 로그 33 §3.

**② 검사 전용 모드(`--check-only`)는 출처 기록이 선행이다.** "빌드 없이 지금 `build/` 가
쓸 만한가"를 5초에 답하는 모드인데, **mtime 으로는 제대로 못 판정한다**:

- `git checkout`·`pull` 이 내용과 무관하게 mtime 을 갱신한다 → 멀쩡한 빌드가 stale 로 뜨고
  사람이 경고를 무시하기 시작한다
- 입력 목록(RTL·xdc·tcl·C·빌드 스크립트)을 하나라도 빠뜨리면 **조용히 통과**한다
- **툴 버전은 파일이 아니다** — 2024.2 ↔ 2025.2 세대 혼합(chip01↔chip02 106ps 의 원인 후보)을
  mtime 은 영원히 못 잡는다

그래서 순서가 **출처 기록 → 검사 모드**다. 단계 성공 시 산출물 옆에 남긴다:

```
build/vitis_g3_45/.provenance
    built_utc · git_rev · git_dirty · tool(Vivado/Vitis 판번) · params · inputs_sha
```

이것은 새 발명이 아니라 **이 리포가 측정 데이터에 이미 쓰는 방식**이다 — CSV 의 `git_rev` 열,
`_prev/manifest.txt` 의 `git_rev_at_backup`. 빌드 산출물에만 없었다. 기록하는 주체는
`reproduce.py` 로 두면 `ps/scripts`·`fpga/scripts`(소유자가 다른 폴더)를 건드리지 않는다.
**③ 설계 논의는 2026-09-16 에 한 단계 진전됐고, 구현은 보류다.** 0단계(요약 머리말에 신원
한 줄)와 입력 내용 해시를 시제품까지 만들어 동작을 확인한 뒤 되돌렸다 — Windows 경로(세은 확인)가
먼저이고, **보존처가 안 정해졌기 때문**이다. `build/` 는 gitignore 라 요약이 증발한다(실제로
겪었다). 재개 시 정할 것: 0·1·2 중 어디까지인가, 어디에 남기는가. 근거와 실험 결과는 로그 33 §4 —
특히 **rev 만으로는 문서 커밋에도 값이 바뀌어 거짓 불일치가 난다**는 것과, **입력 해시 × 결과
수치의 2×2 로 원인(소스 차이 / 환경 차이)이 갈린다**는 것.

손으로 빌드하면 기록이 없을 텐데, 그때는 **"기록 없음"으로 판정**한다 — 모르는 것을 모른다고
말하는 편이 틀린 확신보다 낫다(`chip_pe.md` 의 `미상(≥1)` 과 같은 자).
