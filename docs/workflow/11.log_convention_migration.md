## 무엇을 하는 작업인가

로그 38 의 발단이 그대로 이 작업의 발단이다 — **개수보다 한 편을 읽는 비용.** 그러니 이
작업의 본체는 서식을 맞추는 것이 아니라 **지우는 것**이다. 서식은 지우고 남은 것을 담는
그릇이다.

### 자는 글자수다 — 줄수가 아니다

**줄수로 재면 일을 잘할수록 숫자가 나빠진다.** 옛 로그는 한 불릿에 300자씩 밀어넣어 줄수가
적은 것이지 짧은 것이 아니다. 규약대로 98자에서 접고 `## 결정`·`## 근거` 로 가르면 같은
내용이 더 많은 줄에 퍼진다. 로그 5 를 이행한 결과가 그렇다.

```
원본    23줄  1,645자
이행후  66줄  2,046자   ← check.py 통과.  줄 +187% / 글자 +24%
```

그래서 기준선은 **245,068자**다 (W11-A 28,226 · B 34,296 · C 57,133 · D 40,727 · E 84,686).

> **2026-09-18 — 이 블록의 숫자를 실측으로 바꿨다.** 2026-09-17 착수 시점에는 「이행후
> 39줄 1,162자 (글자 -30%)」로 적혀 있었다. 실제로 커밋된 로그 5 는 그 반대다. A·B 두
> 단계에서 같은 방향이 확인됐다 — **글자수는 이행으로 줄지 않는다.** `## 결정` 이 옛
> 로그에 없던 절이라 편당 600~900자가 통째로 새로 생기고, 그게 지운 양보다 크다.
> 아래 「단계」의 목표 재정의는 W11-B 보류 목록 [글자수] 항목에 있다.

**전체가 줄면 된다. 편당 강제는 두지 않는다.** 한 편이 늘어난 것 자체는 문제가 아니다 —
전보문처럼 압축된 불릿을 읽을 수 있게 펴면 늘 수도 있고, 그걸 FAIL 로 잡으면 오히려 품질을
깎는다. 단계 끝에 그 단계 합계를 재서 늘었으면 **왜 늘었는지만 보고** 넘어간다.

지우는 데는 네 층이 있고, 층마다 권한이 다르다.

| 층 | 무엇 | 권한 |
| -- | ---- | ---- |
| 1 | **불릿·블록 삭제** — 판별선에 걸리는 것 (절차·수치·파일 목록·작업 실적) | **바로 실행**, 단 아래 「절 이름으로 지우지 않는다」를 지킨다 |
| 2 | **로그 통째 삭제 → 결번** | **제안만.** 보류 목록에 올리고 한영웅이 정한다 |
| 3 | **다른 로그로 흡수 후 결번** | **제안만.** 어디로 옮길지까지 적어서 올린다 |
| 4 | **여러 편을 한 편으로 병합 → 결번** | **제안만.** 본체와 넣을 절까지 적어서 올린다 |

### 절 이름으로 지우지 않는다 — 불릿마다 판별선을 댄다

`## 작업 내용` 이라는 이름만 보고 절을 통째로 지우면 **로그의 본체가 같이 날아간다.**
로그 5(23줄, 가장 짧은 편)가 실물이다. 그 절 안이 이렇게 섞여 있다.

```
- 착수 전 리뷰에서 실버그 1건 발견: 위상 원점이 MMCM 정렬에 따라 임의 → …    경위    남긴다
- 업그레이드 6건: ① 원형 재중심화 — 위상 원점은 임의라 재레이블일 뿐          결정+근거 남긴다
                 ② 체크 5 신설 — 한 스텝 10⁻³→0.25 는 σⱼ<7ps 라 물리적 불가   결정+근거 남긴다
- 검증 (positive): σⱼ=80ps 복원(79.0~82.5), 폭 3,627.8ps …                   수치    지운다
- 게재 2번 확인: 레지스터 읽기가 필요해지면 v1 확장                           결정    남긴다
```

**절 이름은 실적인데 내용은 결정과 근거다.** `## 작업 내용` 을 가진 편이 15편이고 전부 이럴
수 있다. 그래서 층 1 은 **불릿 단위**다 — 절을 지우는 것이 아니라, 불릿마다 판별선을 대서
남길 것을 `## 결정`·`## 근거` 로 옮기고 **남은 껍데기를 지운다.** 절이 비면 그때 절이 없어진다.

## 회색지대는 보수적으로 — 지우지 말고 넘긴다

기준은 규약의 판별선이다. 로그에만 있는 것은 셋이다 — **왜 그렇게 정했나 · 무엇을 버렸나 ·
무엇이 아직 안 정해졌나.** 셋 중 하나라도 있으면 그 로그는 남을 값이 있다.

그런데 "이게 근거인가 실적인가"는 편마다 갈린다. 그래서 이렇게 가른다.

- **명백히 판별선 밖** (`## 작업 내용` 의 "뭘 만들었다", 재현 절차, `results/` 에 있는 수치표,
  바뀐 파일 목록) → 지운다
- **셋 중 하나에 해당하는지 헷갈림** → **남긴다.** 보류 목록에 "이거 근거인지 실적인지
  애매함"으로 적어 올린다
- **로그 전체가 비었다고 보임** → 지우지 말고 보류 목록에 **삭제 후보**로 올린다

지우는 쪽으로 기울 때만 보수적이다. 반대 방향 — "남길까 말까 애매하니 남긴다" — 은 비용이
한 편 읽는 값이지만, 잘못 지우면 복구할 근거가 git 말고는 없다.

### 삭제보다 흡수가 먼저다

리포에 선례가 둘 있다 (2026-09-17, 커밋 `4cc85b4`·`1535ad8`).

- **로그 35 → 로그 36 §5 로 흡수.** 뒤집힌 결정 하나가 본체라 그 결정이 사는 자리로 옮겼다
- **로그 37 → 해체.** 내용을 각자 자리로 보내고 로그는 없앴다

**로그에만 있는 것이 하나라도 남아 있으면 그건 옮기고 나서 지운다.** 그냥 폐기하는 것은
옮길 것이 하나도 없을 때뿐이다. 옮길 곳은 보통 그 결정이 지금 사는 자리 — 후속 로그의
해당 절, `workflow/`, `spec/`, `results/` 다.

### 하나의 작업이 여러 편에 흩어진 자리 — 층 4

편수를 줄이는 제일 큰 지렛대다. 한 편 안을 아무리 지워도 **애초에 한 편이었어야 할 것이
둘·셋으로 갈려 있으면** 읽는 쪽은 그만큼 더 연다.

무엇이 버려지나.** 셋째가 핵심이다. 병합은 흡수와 달리 같은 사안을 다루므로 중복이 나오는데,
그중 무엇을 버리는지가 곧 판단이다. 판단이 갈리면 그대로 올린다.

## 남기는 쪽의 경계 — 옮기고 지우기만, 쓰지는 않는다

지우는 것 말고 하는 일은 재배치다. **재집필이 아니다.** 로그의 값은 그때 그 판단이 그
문장으로 남아 있다는 데 있고, 서식을 맞추려다 고쳐 쓰면 규약을 지키려다 로그를 잃는다.

| | 무엇 |
| --- | --- |
| **한다** | 골격 재배치 — 본문에 있는 결정 문장을 `## 결정` 으로 올리고 경위를 `## 근거` 로 |
| | 폐지 절 제거 — `## 작업 내용` · `## 미결 의사결정`. **불릿을 갈라 남길 것을 옮기고 남은 껍데기를 지운다** |
| | 폐지 필드 제거 — 머리말 `성격` · `작성` |
| | 로그 번호 링크화 — `로그 23` → `[로그 23](23.sweep_wrapper_and_uid_design.md)` |
| | ID 부여 — `## 결정` 에 `[D<번호>-n]`, `## 미결` 에 `[U<번호>-n]` |
| **안 한다** | 없던 근거를 지어내기 |
| | 결정을 다시 해석하기 |
| | 문장을 "더 낫게" 고쳐쓰기 — 어색해도 그때 쓴 문장 그대로 |
| | 결론 바꾸기 · 뒤집힌 결정을 조용히 정정하기 (추기로 붙일 뿐) |

**검증은 diff 를 사람이 보는 것이다.** "새 문장 0줄" 같은 조항은 두지 않는다 — 지킬 수
없어서다. 전보문처럼 압축된 불릿을 `## 근거` 산문으로 펴면 연결어가 반드시 생긴다. 로그 5
시험 이행에서 규칙을 알고 쓴 사람이 원본에 없는 낱말 66개를 넣었다. **재볼 수 없는 숫자를
규약에 박으면 죽은 조문이 된다**([로그 39](../log/young/39.log_convention_enforcement.md) §6).

대신 금지선을 내용으로 둔다 — **새 사실 · 새 근거 · 새 결론을 넣지 않는다.** 문장을 잇는
말은 써도 되고, 그때 없던 판단을 넣으면 안 된다. 갈리면 그대로 보류 목록에 올린다.

추기는 예외다. 새로 쓰는 문장이지만 붙여야 할 자리가 실제로 있다 (로그 13 미결 ①이
[로그 15](../log/young/15.g3_25mhz_wall_too_narrow.md)에서 닫혔는데 13 에 표시가 없다 —
로그 38 §5 가 지목한 자리다). 대신 내용을 묶는다 — **무엇이 언제 어디서 이 결정을
바꿨나**, 그것만 적는다. 새 근거를 여기 쓰지 않는다.

삭제가 많을수록 diff 가 읽기 쉬워진다 — 지운 것은 `-` 만 남기 때문이다.

## 결정이 없는 로그는 채우지 않는다

"무엇을 했다"만 있고 "무엇을 정했다"가 문장으로 없는 편이 있다. `## 결정` 을 채우려면 읽고
**추론**해야 하는데, 그게 경계의 입구다.

**추론이 필요하면 채우지 않고 남긴다.** 골격만 세워 두고 `## 결정` 은 비운 채 보류 목록에
적는다. 혼자 판단해서 채우고 나중에 확인받지 않는다 — 틀린 결정이 로그에 박히면 그 뒤로
그것이 정본이 된다.

### 미결 *작업* 은 지우지 말고 올린다

규약은 미결 *작업* 을 `workflow/` 로 보내라고 한다. 그런데 **옛 로그의 미결 작업은 이미
해소됐을 수도, 아직 살아 있을 수도 있다.** 로그 5 의 미결 3건 중 2건이 그랬다 ("실측 CSV
확보 = 하드웨어 사슬", "실측 그림 `results/` 승격" — 둘 다 7월 것이다).

살았는지 죽었는지는 로그를 읽어서 알 수 없다. 그래서 **옮기지도 지우지도 않고** 보류
목록에 `[이관]` 으로 올린다 — 해소됐으면 지우고, 살아 있으면 어느 `workflow/` 문서로
보낼지 한영웅이 정한다. 시험 이행에서 그냥 지웠는데, 그게 틀린 처리였다.

결정이 하나도 없는 편은 위 「층 2」의 **삭제 후보**이기도 하다. 둘을 같이 올린다.

## 한 편을 옮기는 절차

1. **읽는다** — 전문
2. **통째로 필요한지 먼저 묻는다** — 로그에만 있는 셋이 하나도 없으면 **삭제 후보**로
   보류 목록에 올리고 그 편은 손대지 않는다. 다음 편으로 간다.
   위 「층 4」 묶음에 든 편이면 **묶음을 다 읽고 나서** 병합 제안을 올린다 — 한 편만 보고는
   어느 쪽이 본체인지 모른다
3. **판별선 밖을 지운다** — 명백한 것만. 헷갈리면 남기고 보류 목록에
4. **결정을 찾는다** — 이미 문장으로 있는 것만. 없으면 보류 목록으로
5. **골격을 세운다** — `docs/log/FORMAT.md` 「골격」 그대로
6. **ID 를 단다** — `[D<번호>-1]` · `[U<번호>-1]` 부터
7. **검사한다**

   ```bash
   python3 .claude/skills/log/check.py docs/log/young/<파일>
   ```

8. **diff 를 본다** — 새 사실·새 근거·새 결론이 들어갔는지. **손대지 않은 편이 diff 에
   뜨면 멈춘다** — 2026-09-17 에 로그 34 가 작업 밖에서 표 정렬이 바뀐 적이 있다. 에디터
   포매터든 다른 세션이든, 34편을 한꺼번에 만지는 중에는 알아채기 어렵다

## 로그를 지우거나 합치기로 결정되면

한영웅이 승인한 뒤에만 한다. 병합도 뒷정리는 같다 — 본체만 남고 나머지는 결번이 된다.

1. 옮길 것이 있으면 **먼저 옮긴다** (흡수·병합). 옮긴 자리에 출처를 남긴다
2. 파일을 지운다
3. `docs/log/README.md` — 목록 표에서 행을 빼고 「결번」 줄에 번호를 더한다
4. **다른 로그가 걸어 둔 링크가 깨진다.** 전편에 검사기를 돌려 잡는다

   ```bash
   for f in docs/log/young/*.md; do python3 .claude/skills/log/check.py "$f"; done | grep '깨진 링크'
   ```

5. **리포 전역 참조도 깨진다 — 검사기가 못 보는 자리다.** `check.py` 는 `docs/log/young/`
   안만 본다. 지운 번호를 전역에서 찾아 고친다

   ```bash
   grep -rn '로그 <번호>' docs/ --include='*.md' | grep -v '^docs/log/young/'
   ```

## 단계를 닫을 때

- 그 단계 전편이 `check.py` 통과 — **삭제·흡수·병합 후보로 올린 편은 제외한다.**
  승인 전에 고쳐 두면 승인이 나는 순간 그 작업이 통째로 버려진다
- **보류 목록을 한영웅에게 넘긴다** — 삭제 후보 · 흡수 제안 · 애매한 블록 · 결정 못 채운 편
- 답을 받아 반영
- **글자수를 잰다** — 그 단계 합계가 기준선 대비 얼마가 됐나. 늘었으면 왜 늘었는지만
  본다. 편당 증감은 따지지 않는다
- 커밋 — **git 이 진행 상태의 정본이다**
- 컨텍스트를 새로 하고 다음 단계

```
- [삭제] 로그 N — 로그에만 있는 셋이 없다. 무엇이 들어 있나
- [흡수] 로그 N — 무엇 하나가 남아 있다 → 어디로 옮기면 되나
- [애매] 로그 N §M — 근거인지 실적인지 갈림. 왜 갈리나

- [병합] 로그 N + M — 본체는 어느 편 / 무엇을 어느 절로 / 무엇이 버려지나
- [이관] 로그 N 미결 k — 미결 작업이다. 해소됐나, 아니면 어느 workflow/ 로 보내나
```

### 구멍 1 — 로그 번호 정규식이 오탐한다 (거짓 FAIL)

`check()` 안, 이 한 줄이다.

```python
seen = set(re.findall(r"로그 (\d+)(?!\d)", text))
```

`로그` 뒤에 숫자가 오면 **무조건 `young/N` 참조로 본다.** 그래서 셋을 오탐한다.

| 실물 | 검사기가 요구하는 것 | 실제 | 어디서 걸렸나 |
| ---- | -------------------- | ---- | ------------- |
| 「9개의 세션 로그」(원문 「세션 로그 9개」) | `young/9` 링크 | 개수 세는 말 | 로그 28 |
| 「지민 로그 2 가 이미 쓰고 있다」 | `young/2` 링크 | `jimin/2` 다 | 로그 38 |
| 「그중 13편이 로그 1~15 에 몰려 있다」 | `young/1` 링크 | 범위 표기 | 로그 38 |

**제안**: 뒤에 수량 조사나 범위 기호가 붙으면 참조로 세지 않는다.

```python
seen = set(re.findall(r"로그 (\d+)(?![\d~])(?!\s*[개편건줄])", text))
```

**정규식으로 못 가르는 것 하나** — 「지민 로그 2」는 앞의 낱말까지 봐야 `jimin/` 인지 알 수
있다. 검사기를 고쳐도 남으므로 지금처럼 `지민의 [로그 2](../jimin/2.…md)` 로 링크해 넘기는
쪽이 맞다. 링크가 걸리면 검사기는 만족하고 사람은 올바른 파일로 간다.

### 구멍 2 — `## 결정`·`## 미결` 을 표로 쓰면 ID 검사가 통째로 비켜간다 (거짓 통과)

`ids()` 와 `unlabeled()` 가 **`- ` 로 시작하는 줄만** 본다.

```python
if m := re.match(rf"^- .*?\[{kind}(\d+)-(\d+)\]", l):      # ids()
return [l.strip()[:44] for l in lines if l.startswith("- ") …]  # unlabeled()
```

그래서 두 절을 **표로 쓰면 셋이 한꺼번에 무너진다.**

| | 무슨 일이 일어나나 |
| --- | --- |
| `unlabeled()` | 잡을 불릿이 없어 **ID 를 하나도 안 달아도 통과한다** |
| `ids()` | 정의를 등록하지 않아 그 로그의 `[D…]`·`[U…]` 가 **`crossref()` 의 분모에서 빠진다** |
| 추기 | 구간이 안 열려 **`> **20…` 추기가 붙었는지 세지 않는다** |

**로그 29 에서 실제로 났다.** `## 결정` 을 12행 표로 썼고 통과했는데, `[D29-7]`(마모 패턴)이
9/15 회의에서 뒤집혀 추기를 달아야 해지자 **붙일 구간 자체가 없다**는 것이 드러났다.
열두 줄을 불릿으로 바꿔 해결했다.

**전편 훑기 결과 — 지금은 로그 29 하나뿐이었다.** 다른 31편의 `## 결정`·`## 미결` 에는 표가
없다. 확인은 이 한 줄이다.

```bash
python3 - <<'EOF'
import re, pathlib
def section(text, head):
    out, on = [], False
    for l in text.splitlines():
        if l.startswith("## "): on = l.strip() == head
        elif on: out.append(l)
    return out
for f in sorted(pathlib.Path("docs/log/young").glob("*.md")):
    t = f.read_text(encoding="utf-8")
    for h in ("## 결정", "## 미결"):
        if [l for l in section(t, h) if l.lstrip().startswith("|")]:
            print(f.name, h)
EOF
```

**제안**: 규약이 이미 불릿을 전제하므로(FORMAT 「불릿마다 ID 를 단다」) 표를 받아주는 것이
아니라 **막는 쪽**이다 — 그 두 절에 `|` 로 시작하는 줄이 있으면 FAIL 한 줄. 표를 허용하면
ID·추기·대조가 전부 두 벌이 된다.
