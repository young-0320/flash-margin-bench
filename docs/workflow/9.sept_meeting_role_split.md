- **작성일**: 2026-09-14
- **회의일**: 2026-09-15 (실칩 검증일과 같은 날 — 워크플로 7)
- **용도**: 이전 논의("지민+세은이 스트레스 테스트 스펙, 영웅이 그 테스트벤치")를 바꾸는
  안을 조원에게 설명하고, 바꾸기 전에 세 가지를 확정한다. 확정되면 이 문서의 §4 표가
  각자의 할 일이 된다.
- **번호**: 워크플로 7 = 실칩 검증일, 8 = Vivado 2025.2 통일(같은 날 다른 세션, 머지됨), 본 문서 9.

## 1. 바꾸려는 것

| | 이전 논의 | 바꾸는 안 |
| - | -------- | -------- |
| 지민 | 세은과 함께 스트레스 테스트 스펙 | **혼자** 스트레스 RTL 설계서 |
| 세은 | 지민과 함께 스펙 | **온도 벤치 구상** (히터·센서·제어) |
| 영웅 | 스트레스 RTL 테스트벤치 | 실칩 검증(워크플로 7) + 테스트벤치 |

**왜 바꿔도 되나.** 역할 문서(`docs/roles.md` v2)에 이미 그렇게 적혀 있다. 세은의 DUT 보드
트랙은 "온도 축(히터+센서) 먼저"이고, RTL은 지민 소유다. 스펙을 둘이 같이 쓰면 온도 축이
그만큼 늦어지는데, 온도는 노화 서사에 직결되는 축이라 미룰 이유가 없다.

## 2. 바꾸기 전에 정할 것 세 가지

### 2-1. "스펙"은 이미 있다 — 지민이 쓸 것은 설계서다

스트레스 벤치가 **무엇을 해야 하는지**는 `docs/spec/s1.wear_bench_spec.md`(S-1)에 다 있다.
1사이클이 뭔지, 어느 섹터를 마모하고 어느 섹터를 대조군으로 두는지, 몇 사이클마다 검사하는지,
카운트를 어디에 저장하는지, 어떤 시험을 통과해야 합격인지(§13).

비유하면 S-1은 **건축주 요구서**다 — 몇 층, 무슨 용도, 언제까지. 지민이 쓸 것은 **구조
도면**이다 — 기둥을 어디에 세우고 배관을 어떻게 돌릴지. 즉:

- 레지스터 맵 확장 (사이클 수·현재 섹터·소거 시간을 PS가 어떻게 읽나)
- 사이클 FSM (program → erase → 카운트 → 다음 섹터, 언제 멈추나)
- op_timer·error logger를 어떻게 물리나
- S-1 §13 인수 기준 A·B·C를 **어떻게 통과시킬지**

요구서를 또 쓰면 S-1과 어긋나는 문서가 하나 더 생긴다. 지민 문서는 S-1을 **인용**하고
S-1에 없는 것만 적는다. S-1이 틀렸으면 고치자고 말하면 되고, 그건 영웅이 고친다.

### 2-2. 사이클러를 RTL로 만들지 PS C로 만들지 — 아직 공식 결정이 없다

리포에 남아 있는 상정은 **PS C**다(`roles.md` 미결 — "P/E 사이클러 구현 층위"). 근거는
1사이클이 erase 45ms에 지배되니 PL에서 빨리 돌려도 이득이 없고, `flash_prep.c`의
erase/program 루프에 카운터만 더하면 된다는 것.

이전 논의에서 RTL로 기울었다면 내일 **3인 확정으로 닫고 사유를 한 줄 적는다.** 어느
쪽이든 성립한다:

| | PS C | RTL |
| - | ---- | --- |
| 장점 | 이미 있는 `flash_prep` 확장. 짧다 | 소거 시간을 재는 op_timer가 어차피 PL에 있다. 33시간 무인 실행에서 PL 루프가 단순하다 |
| 단점 | PS가 두꺼워진다. UART 서버·PID와 같이 살아야 한다 | 새 RTL + 검증. **지민이 G1 cocotb(유일한 미착수 게이트)도 안고 있다** |
| 누가 | 세은 | 지민 |

RTL로 가면 지민 손에 G1과 사이클러가 같이 들어온다. 둘 다 9월 안에는 빡빡하므로
**순서를 정해 준다.** 마모가 최종보고의 핵심이면 사이클러 먼저, G1은 최종보고 조건이지
G5 게이트 조건이 아니다(워크플로 5).

### 2-3. 세은이 온도로 가면 남는 펌웨어 잔무를 어디로 보내나

세은 트랙에 아직 이런 것이 걸려 있고, 전부 마모 개시(G5) 전에 필요하다.

| 항목 | 뭔지 | 왜 필요한지 |
| ---- | ---- | ---------- |
| B-0 | `flash_prep` 그룹 파라미터화 (전 범위 대신 필요한 섹터만) | 마모 그룹만 지우고 쓰기 |
| B-1 | 소거 시간 계측 (섹터마다 WIP-busy 시간) | 노화 이중 지표의 후자 |
| `flash_uid.c` | UID만 읽는 소형 앱 | 신품 10개 전수 측정에서 재장착마다 UID 재확인 |

셋 다 작다(각각 수십 줄). 선택지는 둘: ① 온도 구상과 병행해 세은이 그대로 갖고 간다
② 사이클러가 RTL로 가면 B-0·B-1은 그 설계에 흡수(지민), `flash_uid.c`만 세은. 정하지
않으면 아무도 안 한다.

## 5. 영웅 — 그동안 할 일, 순서대로

1. **실칩 검증 (워크플로 7).** 내일의 본 행사. chip01 1차 + 재장착 3회, 약 45분. 보드는
   영웅만 쓰므로 둘이 문서 쓰는 시간과 겹치지 않는다. 끝나면 당일 로그에 W5-D 판정까지.
2. **스트레스 RTL 테스트벤치 뼈대.** 지민 설계서를 기다리지 않는다. S-1 §13 인수 기준
   (A 100사이클 시험 · B 전원 장애 복구 · C 측정 경로 연결)에서 바로 블랙박스 TB를 뽑는다.
   설계서를 **안 보고** 짜야 작성자·판정자 분리가 선다 — G1에서 세운 원칙 그대로.
3. **N=112** 승인되면 빌드 치환 15줄 + D 2단계 스윕 6분.
4. **일정 재산정.** 워크플로 5의 8/31 목표가 2주 밀렸다. 마모는 칩당 약 34시간(300k) +
   체크포인트라, 10월 최종보고 안에 파일럿 1 + 종단 3이 들어가는지 역산한다. W5-D 판정 뒤.
