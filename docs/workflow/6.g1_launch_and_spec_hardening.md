### 기준의 정확성 — 틀리면 채점이 틀린다

**H1. W3 (mode 경계) PASS 기준 재작성**

현행: *"SCLK 유휴 high로 바꾸면 실패할 것"*

문제: **W25Q64JV는 mode 0과 mode 3를 둘 다 지원한다.** 칩이 mode 3로 정상 동작해 버리면
"실패"가 나지 않아 PASS 기준이 성립하지 않는다. 우리 캡처 경로가 mode 0 에지 정렬을
전제하므로 실제로는 실패할 가능성이 높지만, **근거가 추측이지 데이터시트가 아니다.**

→ verify: `docs/ref/w25q64jv_datasheet_revc.pdf`에서 mode 0/3 진입 조건(CS↓ 시점의 SCLK
  레벨로 칩이 모드를 판별하는 방식)을 확인하고, 우리 RTL이 어느 모드로 동작하는지를
  **양방향으로 구분 가능한** 기준으로 다시 쓴다. 구분이 불가능하면 W3를 폐기하고
  사유를 기록한다 — 검증 불가능한 항목을 표에 남겨두는 것이 더 나쁘다

**H2. F11 BASE_SECTOR 지점 재선정**

현행: `0 / 249 / 1,024 이상 한 점 / 2,041`

문제: **249는 수정안 #1 §4 A2에서 그대로 베껴 왔다.** 거기서 249를 고른 이유는
*"종전 주소 폭(12비트)의 상한 부근 — 회귀 확인용"* 인데, **시뮬에서는 12비트 제약이
존재하지 않는다**(새 RTL을 돌리므로). 실측 인수 기준의 논리를 시뮬로 옮기면서 근거가
따라오지 않았다.

→ verify: 시뮬에서 각 지점이 **무엇을 구분하는지**를 한 줄씩 적는다. 근거가 안 서는
  지점은 뺀다. 최소한 `0`(하위 호환) · `1,024↑`(상위 주소 비트 경로) · `2,041`(N=112
  유효 최댓값, 최종 페이지 정확히 도달)은 각각 다른 것을 본다

**H3. F12의 N=112 출처 명시**

현행: `BASE_SECTOR=2,042, N=112`로 START

문제: **N=112는 계약 수정안 #2**(N 100→112)에서 온 값인데 문서가 #2를 언급하지 않는다.
N은 레지스터라 시뮬 동작에는 지장이 없으나, 읽는 사람이 "왜 112인가"에서 막힌다.

→ verify: 근거를 한 줄 붙이거나, N에 무관한 형태(`BASE_SECTOR × 16 + N − 1 > 32,767`을
  만족하는 임의의 조합)로 일반화한다. 후자가 #2 승인 여부와 독립이라 낫다

### 운영 공백 — 회귀를 돌리는 순간 걸린다

**H4. §6 ① 판정의 산출물 위치**

현행: *"①은 통과·보류 중 하나를 문서로 남긴다"* — **어디에 남기는지가 없다.**

→ verify: 로그(`docs/log/young/`) · 별도 판정서(`docs/spec/`) · `docs/results/` 중
  하나로 정하고 동결본에 경로를 명시한다. **판정 기록은 최종보고서에서 "작성자와
  승인자를 분리했다"의 유일한 증거**이므로 위치가 정해져 있어야 한다

**H5. `check_coverage.py`가 항목 ID를 얻는 방법**

현행: *"본 문서 §5의 항목 목록과 대조한다"* — **어떻게 읽는지가 없다.**

마크다운 표를 파싱하면 서식이 바뀔 때 조용히 깨지고, 별도 목록 파일을 두면 문서와
목록이 어긋날 수 있다.

→ verify: 둘 중 하나를 정한다. 별도 파일을 둔다면 **동결본이 원본이고 목록은 파생**임을
  명시하고, 스크립트가 둘의 불일치를 검출하게 한다

**H6. 수정안 #1 미승인 시 F11·F12 제외 처리**

현행: *"미승인 시 본 2항목은 미적용, 커버리지 대조에서도 제외"* — **스크립트가 승인
상태를 어떻게 아는가**가 미정이다.

→ verify: 수동 플래그(`--amendment1`) · 계약 문서 파싱 · 항목별 조건부 표기 중 하나로
  정한다. 수동 플래그가 가장 단순하나 **끄고 돌리면 2항목이 조용히 사라지므로**,
  리포트가 제외 사실을 항상 출력하게 한다

## 남은 외부 의존 — 우리가 못 정하는 것

**Winbond 공식 행동 모델이 아직 확보되지 않았다** (`sim/README.md` TODO: "W25Q64 접미
확정 후 모델 파일 선택"). W1·W2가 여기 걸려 있다.

- 모델이 **타이밍 어서션을 제공하지 않는 판본**이면 W2의 PASS 기준(⑴ 무발화 ⑵ 음성
  대조)이 성립하지 않는다 → 우리가 직접 타이밍 체커를 쓰거나 W2를 재정의해야 한다
- ~~모델이 **mode 3 자동 판별을 구현하지 않으면** H1의 결론도 달라진다~~ — **해소.**
  H1은 모델 거동이 아니라 **데이터시트 §6.1과 우리 ODDR 배선**만으로 결론이 났다.
  모델이 mode 3를 어떻게 다루든 W3는 성립하지 않는다

**이것이 동결본을 다시 열게 될 가장 유력한 사유**이므로, 모델 확보 시점에 W 2항목을
일괄 재검토한다.
