## 내일 뭘 하는 건가

지난주에 스크립트를 세 개 새로 만들었다. ① 칩의 **고유 번호(UID)** 를 읽는 펌웨어,
② 그 번호로 **등록부에서 칩 이름을 찾아** CSV 파일 이름과 열에 박아 주는 캡처,
③ 이 둘을 **터미널 하나에서 이어 돌리는 래퍼**. 셋 다 가짜 시리얼로만 시험했고
실제 보드에서는 한 번도 안 돌렸다.

내일은 chip01을 꽂고 래퍼를 돌려서 세 가지를 확인한다.

1. **UID가 실제로 읽히는가** — `#PREP UID <16자리>` 줄이 찍히는가
2. **세 곳이 같은 UID를 말하는가** — 세션 로그 · CSV 파일명 · 등록부 chip01 행
3. **칩을 뺐다 꽂으면 폭이 얼마나 흔들리는가** — 3번 재장착해서 표준편차(σ)를 낸다

3번이 나와야 8/23에 미뤄 둔 "장비가 6주 동안 틀어졌나" 판정(W5-D)을 내릴 수 있고,
그 판정이 나야 신품 10개 전수 측정(W5-M)을 시작할 수 있다.

**내일 하지 않는 것**: N=112 스윕(빌드 스크립트에 아직 N 치환이 없다 — 로그 24 미결 2.
내일은 N=100만 된다), 신품 전수 측정, 마모.

## 2. 1차 실행 — 흐름 확인 + UID 확보 (약 7분)

```
.venv/bin/python host/run/run_sweep_chip.py --mode newchip --mhz 25
```

화면에 이 순서로 나온다. 어긋나는 지점이 있으면 그 지점이 곧 진단이다.

| 순서 | 화면                                                                                         | 뜻                                                                         | 걸리는 시간 |
| ---- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ----------- |
| ①   | `batch <stamp>: mhz=25 pl=None repeat=1 …`                                                | 세션 로그`build/data/session_<stamp>.log` 생성                           | 즉시        |
| ②   | `세션1 프로그래밍 (g2_jedec + flash_prep): xsct …`                                        | 비트스트림 + prep ELF 굽는 중                                              | \~30초      |
| ③   | `#PREP JEDEC ef 40 17 …`                                                                  | 칩과 통신 성립                                                             |             |
| ④   | **`#PREP UID XXXXXXXXXXXXXXXX`**                                                     | **오늘의 핵심 한 줄.** 대문자 16 hex                                 |             |
| ⑤   | `#PREP BEGIN` → (침묵) → `#PREP PASS all 2048 pages verified`                          | 지우기·쓰기·검증. 침묵 정상                                              | \~1분       |
| ⑥   | `신규 UID …. 등록부의 UID 공란 라벨: chip01 chip02 … chip10`  `이 칩의 라벨 (chipNN):` | **사람이 입력하는 유일한 지점.** `chip01` 입력. 오타면 다시 묻는다 |             |

| ⑩   | `[1/1] VALID sweep_chip01_<UID>_<stamp>.csv (2520 rows)`  `1/1 완료 (invalid 0)`         | exit 0                                                                     |             |

**④에서 `#PREP FAIL uid transfer` / `uid mismatch`** 가 나오면 래퍼가 멈춘다 — 배선(DO 노랑)
확인 후 재실행. **⑤ 없이 15분 침묵**이면 래퍼가 타임아웃으로 중단한다 — 표 E.

## 3. 세 곳 대조 — 수정안 #3 인수 기준 A4 (약 3분)

한 UID가 네 곳에 있어야 하고 전부 같아야 한다.

```
3-1. 세션 로그:  grep "#PREP UID" build/data/session_chip01_*.log
3-2. 파일명:     ls build/data/sweep_chip01_*_*.csv         → sweep_chip01_<UID>_<stamp>.csv
3-3. CSV 열:     head -2 build/data/sweep_chip01_<UID>_<stamp>.csv   → uid 열에 같은 값
3-4. 등록부:     git diff docs/chip_registry.md docs/chip_pe.md
                 → 등록부 chip01 행의 "*(D 트랙에서 확보)*" 가 UID 로 바뀐 것 1행
                 → chip_pe.md 끝에 "2026-09-15 | chip01 | <UID> | 0~127 | +1 | flash_prep (batch …)" 1행
                 → 그 외 변경 없음
```

넷이 같으면 A4 통과. **하나라도 다르면 손대지 말고** 세션 로그와 함께 그대로 기록한다 —
어느 층이 틀렸는지가 다음 수정의 근거다.

## 5. 2차 실행 — 재장착 σ (약 25분)

**시작 전에 칩을 한 번 빼서 다시 꽂는다.** 그래야 3회가 전부 1차와 다른 장착이 된다.

```
.venv/bin/python host/run/run_sweep_chip.py --mode sweep --chip chipNN --mhz 25 --repeat 3 --reseat
```

- 2·3회차 앞에서 `[k/3] chip01 을 빼고 다시 꽂은 뒤 엔터:` 가 뜬다. **뺐다 꽂고** 엔터.
- 세 파일은 같은 `batch_id`, `reseat=1`, `repeat_idx=1·2·3` 열을 갖는다 (수정안 #3 §2.2).
- 이번엔 ⑥이 안 뜬다 — 등록부에 chip01이 있으므로 `등록부: <UID> → chip01` 로 자동 통과.
  **이것이 등록 칩 경로의 첫 실측**이다 (1차는 신규 칩 경로).
- prep을 또 돌리는 이유: 사전 쓰기는 비휘발이라 `--no-prep --uid <UID>` 로 건너뛸 수 있지만,
  그 경로는 기계가 UID를 다시 확인하지 않는다(로그 24 미결 6). 1분과 P/E +1을 내고 기계
  확인 경로를 한 번 더 지나는 쪽이 오늘의 목적(래퍼 검증)에 맞다. chip_pe.md에 +1이 자동으로
  한 줄 더 붙는다 — 정상.

집계:

```
세 CSV 각각 bathtub_analysis.py → width@1e-2 세 값 → 평균 · 표준편차(자유도 2) = σ_reseat
```

## 6. W5-D 판정 — 8/23에 미룬 것을 닫는다

워크플로 5 D5의 자는 "재장착 없음" σ=0.61ps였고, 8/23 값(+4.35ps)은 재장착이 들어 있어
그 자로 잴 수 없었다(로그 22 §3). 오늘 σ_reseat이 나오면 자가 생긴다.

```
|평균(2차 3회) − 39,737.3|  ≤  3 × σ_reseat   →  드리프트 없음. W5-M 착수 (S-2 게이팅 G-a 해제)
                             >  3 × σ_reseat   →  장비 드리프트 의심. W5-M 보류, 원인 조사
```

**빌드 세대 주의.** 7월 기준값은 Vivado 2024.2 비트스트림, 오늘 값은 2025.2 비트스트림이다.
재기준선 A/B는 생략하기로 했다(로그 27 추기 — 예상 차이 수 ps). 따라서 판정이 **벗어나면**
장비 드리프트인지 빌드 차이인지 이 값만으로는 못 가른다. 그때는 같은 장착 그대로
2024.2 셸로 g3-25 를 재빌드한 뒤 (`~/Xilinx/Vivado/2024.2` 에 설치가 남아 있다, \~5분)
`BUILD_DIR=<그 폴더> … --no-prep --uid <UID>` 로 1회(6분) 더 찍는다 — 차이가 사라지면
빌드, 남으면 장비. 2024.2 산출물은 2026-09-21 삭제했으므로 즉시는 안 된다. RTL·tcl 이
`e229b04` 이후 무변경이라 재빌드본의 소스는 7·8월과 같다.

판정 문장은 **그날 로그에 쓴다** (로그 22 §0의 교훈 — 측정과 기록 사이에 멈추면 데이터가
문서 밖에 남는다). 부수 소득: σ_reseat은 S-2 §8이 M 트랙에서 재려던 값이라 §6.3의 분모로
그대로 쓰인다.

## 8. 잘못됐을 때

- 래퍼가 멈추면 **세션 로그는 이미 디스크에 있다** (`build/data/session_*.log` — 로그 24 §8
  「중요 2」 수정). 지우지 말고 그대로 둔다. `prepfail` 접미가 붙으면 prep 단계 실패.
- 스윕이 `valid=0`이면 파일이 `_invalid`로 남고 배치는 다음 회차로 넘어간다. 3회 중 하나가
  무효면 σ는 자유도 1이 되므로 **1회 추가** (`--no-prep --uid <UID> --repeat 1`, 재장착 후).
- 고장 서명 판독은 런북 3 표 E가 원전. 새 서명이 나오면 표 E에 추가할 후보로 기록.
- 재실행은 항상 래퍼 전체 — ELF만 재로드하면 `phase_pos_mismatch`로 거부된다(의도된 방어).
