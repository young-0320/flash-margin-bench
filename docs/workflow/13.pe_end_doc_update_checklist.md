## 4. 일괄 명령 — `host/analysis/pe_end.py` (2026-10-03)

```bash
uv run python host/analysis/pe_end.py --chip chip18                 # 상온 · 교정에 넣는다 (옵션 없음)
uv run python host/analysis/pe_end.py --chip chip12 --no-calib      # 상온 · 교정에서 뺀다 → 곡선 _nocal
uv run python host/analysis/pe_end.py --chip chip17 --temp          # 온도 런 → 곡선 _<마모 평균>C · 교정 밖
#   덧붙임: --drop-cycles A-B (반복) · --from <보드 B 묶음 폴더>
uv run python host/analysis/pe_end.py --chip chip18 --promote       # 1단계 산출물을 훑어본 뒤
```

- **1단계** (`build/pe_end/<chip>/` 에만 쓴다): 세션 찾기(`plan.txt` 의 칩 · 마모 섹터 0-6 · A.txt — build 와 data 를 합친다) → 0 raw 보관
  (덮지 않는다, 내용이 다르면 아무것도 옮기기 전에 멈춘다 · 온도는 로거 원본 `temp_<chip>_…Z.csv` 만) → 없는 `.analysis.json` 생성 → 4 →
  2 (상온 `wear_checkpoint_csv.py` · 온도 `temp_wear_summary.py`, T1·T2 포함) → 8 첫 · 마지막 체크포인트 bathtub 그림 → 마모 뒤 newchip 이 있으면 현장 역산 `inverse.txt` → 12 의 제안 문구
- **2단계** (`--promote`): 산출물 → `docs/results/`. 내용이 다른 파일이 있으면 멈춘다(사람이 단 note) — `--overwrite` 로만 덮는다.
  같은 칩 곡선이 다른 이름으로 있으면(`_ali` 대 `_nocal` · `_2026-09` 대 `_2026-10`) `--overwrite` 로도 넘어가지 않는다 — 교정에 두 번 든다.
  줄끝만 다른 같은 내용은 쓰지 않는다. 교정 칩이면 6 (y 축이 전 칩 공통이라 전부 다시) · 교정 칩 배율 겹침 `wear_ratio_curves_<승격한 날 YYYY-MM-DD>.png` — 교정이 바뀔 때마다 한 장, 가장 최근 날짜가 현행 → 7 → 남은 사람 몫 목록
- **하지 않는 것**: 3 수치 md · 1 보드 B 장부 · T3 25°C 사다리 행 · 한눈 표에서 칩 빼기(`SEPARATE` — 「같은 칩이 아니다」 판단).
  새 칩의 색은 두 그림 모두 회색으로 그리고 알린다 — 한눈 그림 `wear_checkpoint_table.py` 의 `COLORS` · 교정 배율 그림 `plot_wear_curves.py` 의
  `CHIP_COLORS` 에 넣고, 그 칩이 들어가는 칸의 색 전부를 dataviz 검증기 `--pairs all` 로 돌린다(chip18 `#006300` · chip15 `#d0453a` — 느린 칸 4색 검증기 기본 기준 통과, 10/5).
  **합격 기준은 이 프로젝트 기준으로 완화한다(2026-10-04, 로그 48 [D48-89])** — 정상 시각 최소 거리 12 이상(검증기 기본 15) · 색각 이상
  최소 거리 6 이상(모든 선에 끝 라벨 · 범례가 있어 검증기의 「보조 단서가 있으면 6-8 허용」 에 든다) · 명도 띠 · 채도 하한은 검증기 그대로.
  검증기가 FAILED 를 찍어도 이 셋을 넘으면 받는다. 이 기준으로 빠른 칸 7색까지 된다 — 다음 두 칩은 연보라 `#9085e9` + 노랑 `#eda100`

## 6. 사람 체크리스트

순서대로 밟는다. 각 문서 옆 「raw」 는 그 문서를 쓸 때 여는 원본 파일이다 — `data/` 는 리포 루트(커밋 안 함), `build/pe_end/<chip>/` 는 1단계 산출물.

### 6.1 상온 PE (교정에 넣는 칩)

- [ ] **1단계 전 — `--drop-cycles` 를 정한다.** 접촉 고장 · 끊김 · 가짜 행 구간
  raw: `data/wear/<세션>/session.log` · `verdict.txt` · `A.txt` · `D.txt` (보드 B 면 지민 묶음에서 먼저 확인)
- [ ] **명령** `uv run python host/analysis/pe_end.py --chip <chip> [--drop-cycles A-B ...] [--from <묶음>]`
- [ ] **1단계 요약을 본다** — 「제외」(마모 전 25MHz 스윕) · 「결측」 · cycle 이 빈 「마모 중 스윕」 · 「x=0」 경고.
  cycle 이 빈 행은 `build/pe_end/<chip>/wear_endurance_<chip>_<YYYY-MM>.csv` 에서 사람이 채운다
  raw: `data/session_<chip>_<uid>_<batch>.log` · `data/wear/<세션>/session.log`
- [ ] **1단계 bathtub 한 쌍을 연다** — `build/pe_end/<chip>/bathtub_sweep_*.png`(첫 · 마지막 체크포인트). 바닥 BER · 양쪽 벽 모양이 같은지
- [ ] **명령** `uv run python host/analysis/pe_end.py --chip <chip> --promote` — 새 칩이면 색 경고가 뜬다 → `COLORS`(한눈 그림) · `CHIP_COLORS`(교정 배율 그림)에
  넣고 검증한 뒤 다시(§4). 승격된 그림을 열어 라벨 겹침을 본다
- [ ] **2 체크포인트 CSV note** — 사건 · 장착 사유 덧붙이기 (`docs/results/data/wear/wear_endurance_<chip>_<YYYY-MM>.csv`)
