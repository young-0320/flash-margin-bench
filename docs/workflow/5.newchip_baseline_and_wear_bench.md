## S. 사양서 3건 (한영웅) — 지금 즉시

팀원이 착수할 수 없는 상태를 푸는 것이 최우선이다. 세 문서 모두 **구현 전에** 합격 조건을 못 박는 것이 핵심이며, 그래야 나중에 "돌아가는 것 같다"로 넘어가지 않는다.

### S-1. 스트레스 벤치 사양서 → 장세은

9월 마모의 실행 수단이므로 지연이 곧 일정 지연이다. 아래 결정의 근거는 로그 16에 있다.

**확정 사항**

| 항목 | 값 | 근거 |
| ---- | --- | ---- |
| 마모 그룹 크기 | **7섹터** (112페이지) | θ=10⁻⁴ 유효에 읽기 98회 필요 → 112 ≥ 100 |
| N (위상당 읽기) | **100 유지** | 7월 데이터와 동일 조건(D 트랙 기준값 보존) |
| 마모 패턴 | **0x00** | 모든 비트 1→0, 최대 스트레스. PRBS는 절반만 |
| 측정 패턴 | **PRBS15** (체크포인트 직전 1회) | RTL 비교 대상 + 0x00은 비트 천이가 없어 창이 인위적으로 넓게 나옴 |
| 1사이클 정의 | all-0 program(112페이지) → sector erase(7섹터) | 사양서에 정의로 명문화 |
| 사이클 시간 | 7×45 + 112×0.8 = **405ms** (typ) | tSE 45ms / tPP 0.8ms |
| 종점 | **300k** (스펙 3배) | 데이터시트 "Min. 100K per sector" = 하한 보장이지 고장점 아님 |
| 무결성 검사 주기 | **100사이클** (이상 검출 후 10) | 비용 0.4%로 onset 해상도 0.03% |
| 시간 기준 실패 | **tSE > 400ms** (데이터시트 max) | 제조사가 보장한 상한 = 객관적 정의 |
| 열화 판정 | 같은 주소·같은 비트 **연속 2회 재현** | 1회는 소프트 에러/기존 결함일 수 있음 |
| chip_id | **UID (4Bh, 64비트)** | 라벨 오독이 데이터를 조용히 오염시킨다 |
| 카운트 영속화 | **칩 내 tally 섹터 + 호스트 로그 2중** | 33h 무인 실행 중 전원 장애 시 마모량 소실 방지 |
| 사전 쓰기 | **`flash_prep` 그룹 파라미터화** | 전 범위 2,048페이지 → 필요한 그룹만(560페이지, 17초) |

**섹터 배치 — 완충 없이, 대조군 이중화**

논리 섹터 번호와 물리 위치의 대응이 비공개이므로 "몇 섹터를 띄우면 안전한가"에 답할 근거가
없다(`project_context.md` §6 — 논리-물리 매핑은 범위 밖). 완충으로 회피하는 대신 **간섭 유무를
측정**한다.

영역의 역할은 셋이다 — **마모 / 대조 / 기록**.

```
[측정 대상]
  섹터   0 ~   6   마모 그룹 1    지지고, 잰다
  섹터   7 ~  13   마모 그룹 2    지지고, 잰다
  섹터  14 ~  20   마모 그룹 3    지지고, 잰다
  섹터  21 ~  27   근접 대조군    안 지지고, 잰다  ← 마모 그룹 바로 옆, 완충 0
  섹터 249 ~ 255   원격 대조군    안 지지고, 잰다  ← 주소 폭 한계의 끝, 최대 거리
[측정 안 함]
  섹터 128         이력(tally)    안 지지고, 안 잰다 — 카운트만 적는다
```

| 영역 | 소거 반복 | 스윕 측정 | PRBS 기록 | 목적 |
| ---- | --------- | --------- | --------- | ---- |
| 마모 그룹 | O (최대 300k) | O | 체크포인트마다 | 노화 곡선 |
| 대조군 | X | O | 최초 1회 | 비교 기준·간섭 검출 |
| 이력 섹터 | X (최초 1회만) | X | X | 카운트 영속 저장 |

- 근접 = 원격 → 인접 간섭 무시 가능. 이후 배치 자유
- 근접 ≠ 원격 → 간섭 존재. 그 차이가 disturb의 크기이며 **그 자체가 결과물**
- 완충을 넉넉히 두면 "간섭이 없었던 건지 완충이 가려준 건지" 구분할 수 없게 된다
- 원격 대조군 섹터 249\~255 = 페이지 3,984\~4,095. 현재 주소 폭(`idx[11:0]`, 최대 4,095)이
  도달할 수 있는 **논리적 최원거리**다
- 이력 섹터를 마모 그룹에서 떼는 이유: 측정 대상은 아니지만 **tally가 손상되면 카운트를
  잃는다.** 간섭이 존재할 경우의 피해자가 되지 않게 100섹터 이상 떨어뜨린다

**작성 단계**

1. **마모 범위와 읽기 범위 정합 확인**
   → verify: `flash_spi_ctrl.v`가 읽기 i → addr = i×256을 발행하므로 N=100이면 읽히는 것은
     페이지 0\~99뿐. `flash_prep.c`는 2,048페이지를 쓴다 — **쓰는 범위가 읽는 범위의 18배**.
     임의 섹터를 마모시키면 스윕이 그 셀을 읽지 않으며 이 실패는 침묵한다
2. **BASE_SECTOR 채택 여부에 따른 분기 확정** (아래 계약 안건 참조)
   → verify: 채택 시 각 그룹이 독립 스윕으로 N=100 full strength. 미채택 시 읽기 100회를
     마모군 64 / 대조군 36으로 분할하고 그룹 분석은 θ=10⁻²·10⁻³ 2점으로 제한
3. **체크포인트 계획** — 파일럿 결과로 확정. 파일럿 잠정 11점:
   `0 / 1k / 3k / 10k / 30k / 60k / 100k / 150k / 200k / 250k / 300k`
   → verify: 각 체크포인트에서 마모군·근접 대조군·원격 대조군 3회 스윕
4. **로깅 3종 파일**
   → verify: A 사이클 로그 · B 무결성 로그 · C 체크포인트 로그 (아래 스키마)
5. **중단 조건**
   → verify: WIP가 2초(max×5) 내 미해제 = 행 → 즉시 정지. blank check 실패 페이지가 측정
     범위의 절반 초과 → 기대 패턴이 무너져 폭 측정 불가, 그 지점 기록 후 정지.
     **잔여 비트 임계에 산업 표준은 없다**(NOR은 zero-tolerance, NAND는 ECC 기준) —
     정확한 값은 파일럿 실측 곡선으로 정한다
6. **전원 장애 복구** — 아래 별도 절 참조
   → verify: 임의 시점에 전원을 끊었다 재개했을 때 카운트 오차가 100사이클 이내
7. **인수 기준**
   → verify: 100사이클 시험 실행 시 ⑴ 사이클 카운터 = 100 ⑵ 소거 시간 로그 = 100×7행
     ⑶ 무결성 로그 = 1행 ⑷ tally 바이트 = 1개 ⑸ 네 경로의 카운트가 서로 일치

**로깅 스키마**

```
A. 사이클 로그   cycle, sector, t_erase_us, t_program_us, timestamp
B. 무결성 로그   cycle, erase_residual_bits, program_fail_bits,
                 worst_page_idx, worst_page_bits, timestamp      (100사이클마다)
C. 체크포인트    cycle, sweep_csv, chip_id(UID), base_sector, n_sectors,
                 pattern, git_rev, timestamp
```

공통 필수: `chip_id(UID)`, `git_rev`, `base_sector`/`n_sectors`/`pattern`, `timestamp`.

**전원 장애 복구 — 칩이 자기 이력을 들고 있게 한다**

33시간 무인 실행 중 정전·USB 분리가 한 번이라도 나면 **"몇 번 마모됐는지 모르는 칩"** 이
되고, 마모는 비가역이라 다시 만들 수 없다. 그 칩은 교정 곡선에 쓸 수 없다.

플래시는 프로그램이 1→0 방향으로만 가므로, **지우지 않고 표시를 계속 추가**할 수 있다
(벽에 작대기 긋기). 이 성질을 그대로 쓴다.

- 이력 섹터를 실험 시작 시 **한 번만** 소거 → 전부 `0xFF`
- 100사이클마다 **다음 바이트 하나에 `0x00`** 기록 (부분 페이지 프로그램)
- 누적 카운트 = **`0x00`인 바이트 개수 × 100**

| 항목 | 값 |
| ---- | ---- |
| 이력 섹터 용량 | 16페이지 × 256B = 4,096바이트 |
| 커버 범위 | 4,096 × 100 = **409,600 사이클** (300k 충분) |
| 기록 비용 | 100사이클(40.5초)마다 0.8ms = **0.002%** |
| 이력 섹터 마모 | 소거 1회 + 바이트당 프로그램 1회 → 무시 가능 |

**각 바이트를 딱 한 번만 쓴다.** 같은 바이트를 반복 프로그램해 비트를 하나씩 지우는 방식도
물리적으로는 가능하나, 데이터시트가 보증하는 것은 "같은 페이지 내 다른 바이트에 영향 없음"
까지이므로 명시적으로 허용된 범위 안에만 머문다.

**3중 방어**

1. **호스트 UART 로그(주)** — 100사이클마다 `#WEAR cycle=NNN uid=... t_erase=...` 출력,
   호스트가 append + flush
2. **칩 내 tally(부)** — 위 방식. UART가 끊겨도, 보드가 바뀌어도 칩이 이력을 들고 간다
3. **재개 시 대조** — 두 값 중 **큰 쪽 채택**(보수적). 불일치는 로그에 기록하고 사람이 판정

호스트 로그만으로는 **USB 케이블이 빠지는 경우**를 못 막는다 — PS는 계속 돌지만 기록만
끊겨 실제 마모 > 기록이 되고, 이 오차는 조용하다. tally가 그 구멍을 막는다.

**재개 절차**

```
1. UID 읽기 → 등록부 대조 (같은 칩인지 확인)
2. tally 섹터 읽기 → 0x00 바이트 수 × 100 = 복원 카운트
3. 호스트 로그 마지막 값과 대조 → 큰 쪽 채택
4. blank check → 소거 중 정전이면 부분 소거 상태가 잡힌다. 해당 섹터 재소거
5. 이어서 진행
```

불확실성은 최대 100사이클(전체의 0.03%), 소거 중 정전이면 ±1 추가. 무시 가능하다.

**tally 판독 규칙**: 프로그램은 1→0 방향뿐이라 `0x00`이 `0xFF`로 되돌아가는 일은 물리적으로
불가능하다(오류 방향이 한쪽뿐이라 안전). 다만 프로그램 도중 정전이면 어중간한 값이 남을 수
있다 — `0x00`은 센다, `0xFF`는 안 썼다, 그 외는 세지 않되 "±1 불확실"로 기록.

> 이는 신규 기능이 아니라 공모전 계획서 주요 기능표의 **"칩 개체 이력 관리 — 칩 ID별 누적
> P/E 영속 저장(종단 추적의 실체)"** 이 필요에 의해 앞당겨진 것이다. **UID + tally** 조합으로
> 칩이 자기가 누구인지와 얼마나 살았는지를 스스로 들고 다니게 된다.

**산출물**: 벤치 사양서 (수신자 장세은, 인수 기준 포함)

### S-2. 신품 전수 측정 프로토콜 → 장세은

실행은 장세은이지만 절차 설계는 한영웅이다(`roles.md` v2 실험 설계).

1. **칩 ID 부여·라벨링 규칙** (chip01\~10) 및 시료 배분표 확정
   → verify: `project_context.md` §7 배분(전수 신품 10 / 종단 마모 3\~4 / 블라인드 2 / 무마모 대조군 2 / 예비)과 일치
2. **칩당 회차 = 1회 스윕** 및 그 근거 명시
   → verify: 반복성 0.61ps가 예상 개체 산포보다 훨씬 작다는 근거 문장이 프로토콜에 기록됨. 측정 노이즈 ≪ 산포이므로 1회로 σ 추정이 성립한다
3. **재장착 MSA를 측정 순서에 삽입** — chip01을 처음과 마지막에 각 1회 추가 측정

## 계약 변경 안건 — BASE_SECTOR + UID 읽기 (→ 3인)

두 변경이 같은 성격(계약 v1의 레지스터 추가)이므로 묶어서 상정한다.

### BASE_SECTOR — 읽기 창의 시작 위치

현재 `flash_spi_ctrl.v:120`이 `addr = idx × 256`을 발행하므로 **읽기 창이 페이지 0에 고정**
이다. 그래서 마모군과 대조군이 읽기 100회를 나눠 가져야 하고, 64:36으로 쪼개지면 양쪽 다
θ=10⁻⁴ 유효 조건(읽기 98회)이 깨진다. N을 200으로 올려도 **마모군은 64회 그대로**라 문제가
풀리지 않는다.

읽기 시작을 옮길 수 있으면 각 그룹을 **독립 스윕**으로 재므로 나눠 갖기가 사라지고 양쪽 다
N=100 full strength가 된다. 나아가 칩 하나에 마모량이 다른 그룹을 여러 개 두어 **교정 곡선
전체를 단일 개체에서** 얻을 수 있다 — 교정 곡선의 최대 오염원인 개체 산포가 통째로 사라진다.

- **페이지가 아니라 섹터 단위 레지스터로 정의한다.** 마모는 섹터 단위로만 일어나므로 읽기
  창이 섹터 경계에 정렬돼야 하는데, `BASE_PAGE`로 두면 16의 배수가 아닌 값을 넣을 수 있다.
  `BASE_SECTOR`(8비트, 섹터 0\~255)로 두고 RTL이 `page = BASE_SECTOR × 16 + i`를 계산하면
  **오설정 자체가 표현 불가능**해진다
- `BASE_SECTOR = 0`이면 현재와 완전히 동일하게 동작 — 하위 호환
- **주의: PRBS 시드도 함께 옮겨야 한다.** 계약상 시드는 `{1, page}`이고 `flash_prep`은 페이지
  번호로 시드를 만드는데, 수신부는 읽기 순번 i로 만든다. 지금은 `page = i`라 우연히 맞는
  것이므로, 주소 계산과 시드 계산 **두 곳**을 함께 고쳐야 한다. 어긋나면 전 위상 BER≈0.5
- 주소 폭 제약: 현재 `{8'h0B, 4'd0, idx[11:0], 8'h00}` 구조라 페이지 0\~4095(섹터 0\~255,
  1MB)까지만 접근 가능. 그룹 4\~5개면 충분하다

### UID 읽기

`4Bh`(Read Unique ID)를 PL에서 한 번 발행해 레지스터 2개로 노출 → `g3_sweep`이 CSV 헤더에
직접 기록. `flash_spi_ctrl`은 0x0B 전용 고정 시퀀서라 프레임 구조가 다른 4Bh(주소 없음,
더미 4바이트)를 넣으려면 별도 one-shot FSM이 필요하다.

**단기 대안(RTL 변경 0)**: `flash_prep.c`에 4Bh를 추가해 `#PREP UID <16hex>`를 출력하고,
`sweep_uart_capture.py`가 그 값을 세션에 보관했다가 스윕 CSV 헤더에 기입한다. 스윕 중에는
PS가 칩과 통신할 수 없으므로 UID와 스윕의 연결이 **같은 세션**이라는 절차적 근거에 의존한다.

### 선행 조건

두 변경 모두 **검증할 오라클이 없다** — G1(cocotb + Winbond 모델)이 미착수라 검증 수단이
스모크 TB뿐이다. 계약을 열고 RTL을 고칠 것이라면 채점기부터 세우는 것이 순서다.

조건 ③은 두 부분으로 나뉘며, 필요 시점이 다르다.

- **체크포인트 계획** — 종단 마모 개시 전에 필요. S-1에서 확정한다
- **블라인드 정답 사전 커밋** — 블라인드 마모 개시 전에 필요. 블라인드 추정은 교정 곡선이 존재해야 성립하므로(종단 마모 3\~4개의 결과물), 시점상 종단 마모보다 뒤다

따라서 9월 첫 주 마모 착수의 게이트 조건은 체크포인트 계획까지이며, 블라인드분은 그 시점에 미충족이어도 종단 마모를 막지 않는다. 단 **블라인드 칩 2개에는 그때까지 어떤 마모도 가하지 않는다.**

### 보류 — 블라인드 이해충돌 (결정 시점: 블라인드 착수 직전)

아래는 블라인드 국면에 들어갈 때 결정한다. **지금은 보류**하며, 잊지 않기 위해 기록만 남긴다.

`project_context.md` §7의 블라인드 설계는 *"마모 담당자가 횟수를 숨기고 마모, 측정자가 추정"* 이다. 그런데 `roles.md` v2에서 한영웅이 총괄이자 분석·추정자이므로, **한영웅이 정답을 사전 커밋하면 정답을 아는 채로 추정하게 되어 블라인드가 성립하지 않는다.**

해소안:

- **한영웅** — 블라인드 *절차*를 설계 (몇 개, 어떻게 봉인, 언제 개봉, 오차 산출식)
- **장세은** — 실제 마모 횟수를 정하고 봉인·사전 커밋. 개봉 전까지 한영웅에게 알리지 않음
- **한영웅** — 측정·추정 후 개봉, 오차 ±X% 산출

이 안을 채택하면 G5 조건 ③의 "블라인드 정답 사전 커밋"은 한영웅이 아니라 장세은의 일이 되고, `roles.md` v2의 한영웅 실험 설계 항목도 함께 수정해야 한다. **어느 쪽도 지금 확정하지 않는다** — 블라인드 착수가 가까워졌을 때 실제 인원 배치와 함께 결정한다.

**산출물**: 마모 개시 허가 또는 보류 사유 (문서로 기록)

## 공통 규칙·함정

기존 규칙(런북 3 표 E, 게이트 지도 4)은 그대로 유효하며, 본 국면에서 추가되는 것만 적는다.

- **수신(캡처) 먼저, 송신(xsct) 나중** — 첫 줄부터 받아야 한다 (변함없음)
- **재실행은 `program_*.tcl` 전체 경로** — ELF만 재로드하면 `phase_pos_mismatch`로 의도적 거부
- **마모 범위 ≠ 읽기 범위는 침묵 실패다** — 스윕이 정상 완주하고 `valid=1`이 뜨는데 마모 신호만 안 보인다. 몇 시간을 버리고도 원인을 못 찾는 유형이므로 S-1에서 반드시 고정한다
- **신품 소거 시간은 마모 전에만 확보 가능** — M-4를 건너뛰고 마모에 들어가면 이중 지표의 절반이 영구 소실된다
- **드리프트 확인 없이 전수 측정 금지** — D를 건너뛰면 10개 데이터의 기준점이 불명확해진다
- **사전 쓰기 범위 밖은 측정 불가** — PRBS가 없는 섹터를 스윕하면 전 위상 BER≈0.51이 된다
  (런북 3 표 E). 현재 `flash_prep`은 페이지 0\~2,047(섹터 0\~127) 고정이므로, 그 밖에 그룹을
  두려면 **파라미터화(B-0)가 선행**돼야 한다
- **주소 폭 한계는 섹터 255** — `idx[11:0]`이 페이지 0\~4,095까지만 표현한다. 그 밖의 섹터는
  현재 하드웨어로 읽을 수 없다
- **BASE_SECTOR 채택 시 PRBS 시드 정합 확인** — 주소만 옮기고 시드를 안 옮기면 전 위상
  BER≈0.5. 칩 문제로 오인하기 쉽다
- 마모는 비가역이다. G 판정 문서 없이 사이클러를 실행하지 않는다
