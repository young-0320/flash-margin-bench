## S. 사양서 3건 (한영웅) — 지금 즉시

팀원이 착수할 수 없는 상태를 푸는 것이 최우선이다. 세 문서 모두 **구현 전에** 합격 조건을 못 박는 것이 핵심이며, 그래야 나중에 "돌아가는 것 같다"로 넘어가지 않는다.

### S-1. 스트레스 벤치 사양서 → 장세은

9월 마모의 실행 수단이므로 지연이 곧 일정 지연이다.

1. **마모 범위 확정** — 4KB 섹터 0\~6
   → verify: 스윕 읽기 범위와 정합함을 코드로 확인. `flash_spi_ctrl.v`가 읽기 i → addr = i×256을 발행하고 N_READS=100이므로 실제 읽히는 것은 페이지 0\~99(0x0000\~0x63FF) = 섹터 0\~6뿐이다. `flash_prep.c`는 2048페이지(512KB = 128섹터)를 쓰므로 **쓰는 범위가 읽는 범위의 18배**다 — 임의 섹터를 마모시키면 스윕이 그 셀을 한 번도 읽지 않는다
2. **칩 내부 대조군 채택 여부 결정** — 섹터 0\~3만 마모하고 4\~6은 무마모로 남길 것인가
   → verify: 채택 시 `_reads.csv`의 `R,<step>,<i>,<e>` 행에서 읽기 i = 페이지 i로 마모/무마모 셀을 사후 분리할 수 있음을 확인. 온도·전원·소켓 접촉·측정 시각이 완전히 공통화되는 대조군이며 코드 변경은 0이다
3. **체크포인트 계획** — 0 / 10k / 30k / 100k (인듀런스 스펙 10만 회 대비 재조정)
   → verify: 각 체크포인트에서 수행할 측정 항목이 명시됨 (윈도우 폭 스윕 + 소거 시간)
4. **로깅 항목** — 사이클 카운트, 섹터별 erase WIP-busy 시간, program 시간, 타임스탬프, chip_id
   → verify: `docs/interface/` 측정 레코드 스키마와 충돌하지 않음
5. **중단 조건** — erase 실패, WIP 타임아웃, 소거 시간이 신품 기준선 대비 임계 배수 초과
   → verify: 각 조건에서 무엇을 남기고 멈출지가 정해짐 (비가역 실험이므로 사후 재현 불가)
6. **인수 기준** — 벤치가 완성됐다고 판정할 조건
   → verify: 최소 1항은 독립 경로 교차검증일 것. 예 — "사이클 카운터 값과 실제 erase 발행 수가 서로 다른 경로로 일치함을 보인다"

**산출물**: 벤치 사양서 (수신자 장세은, 인수 기준 포함)

### S-2. 신품 전수 측정 프로토콜 → 장세은

실행은 장세은이지만 절차 설계는 한영웅이다(`roles.md` v2 실험 설계).

1. **칩 ID 부여·라벨링 규칙** (chip01\~10) 및 시료 배분표 확정
   → verify: `project_context.md` §7 배분(전수 신품 10 / 종단 마모 3\~4 / 블라인드 2 / 무마모 대조군 2 / 예비)과 일치
2. **칩당 회차 = 1회 스윕** 및 그 근거 명시
   → verify: 반복성 0.61ps가 예상 개체 산포보다 훨씬 작다는 근거 문장이 프로토콜에 기록됨. 측정 노이즈 ≪ 산포이므로 1회로 σ 추정이 성립한다
3. **재장착 MSA를 측정 순서에 삽입** — chip01을 처음과 마지막에 각 1회 추가 측정
   → verify: 전수 측정이 어차피 칩을 10번 갈아 끼우는 작업이므로 별도 실험 없이 재장착 편차가 확보됨
4. **소거 시간 기준선을 같은 세션에서 동시 수집**
   → verify: 칩당 `flash_prep`(소거 시간 자동 기록) → 스윕 순서로 폭과 소거 시간이 한 번에 나옴. **마모를 시작하면 신품 소거 시간은 영원히 확보 불가**
5. **이상치 판정 기준** — 어떤 값이 재측정 대상이고 어떤 값이 진짜 개체 특성인가
   → verify: 재측정 조건이 사후 해석이 아니라 사전 규칙으로 기록됨

**산출물**: 측정 프로토콜 (수신자 장세은) + 시료 배분표 확정본

## D. 6주 공백 드리프트 확인 (한영웅) — S와 병렬

**M보다 반드시 먼저** 한다. 장비가 7/8 대비 틀어져 있으면 신품 10개 데이터가 통째로 오염된다.

```
D1. [터미널 1] 캡처 먼저 (BEGIN 행부터 받아야 함):
    .venv/bin/python host/capture/sweep_uart_capture.py --target chip01
D2. [터미널 2] 프로그램 + 실행 (전체 경로로):
    xsct ps/scripts/program_g3.tcl 25
D3. 완주 확인: "SWEEP END valid=1 reason=complete"  (~5분)
D4. 분석:
    .venv/bin/python host/analysis/bathtub_analysis.py build/data/sweep_chip01_<stamp>.csv
D5. 판정: width@θ=1e-2 를 7/8 기준값과 대조
```

기준값: **39,737.3 ± 0.61ps** (n=5, 재장착 없음, 2026-07-08). 판정 기준:

- **±3σ(≈2ps) 이내** — 드리프트 없음. M 착수
- **벗어남** — 원인 조사 후 M 보류. 재장착 편차인지(칩을 뺐다 꽂았다면 정상 범위가 다름) 장비 드리프트인지 먼저 분리한다

주의: 사전 쓰기 데이터는 비휘발이므로 `flash_prep` 재실행은 불요하다. 단 전 위상 BER≈0.51이 나오면 사전 쓰기가 지워진 것이므로 `flash_prep` 후 재시도(런북 3 표 E).

**산출물**: 드리프트 판정 1건 + MSA "일자 간 재현성" 첫 데이터 포인트


추가: 한계 극복 -> 오랜기간 사용된 메모리는 자주 사용되는 데이터 섹터가 있을 것임. 하지만 매번 섹터0~6과같이 맨 앞에서부터만 메모리 마진을 측정하면 실제 가장 약한 섹터가 아닌 영역으로 수명을 잘못 계산할 수도 있음. 메모리의 수명은 가장 강한 섹터가 아닌 가장 약한 섹터가 결정짓는 것이기 때문.

극복 제안 1 -> 빠르게 메모리 전수 조사 후 의심 지점 도출 및 의심되는 지점에서 마진 체킹 하는 방식

## M. 신품 전수 측정 (설계 한영웅 / 실행 장세은)

S-2와 D 완료가 선행 조건이다. G5 조건 ①(전수 신품 측정)을 해소하고, 교정 곡선을 선이 아닌 **띠(band)** 로 그릴 유일한 근거인 개체 산포 σ를 확보한다.

1. chip02\~10 각각: 배선 → `flash_jedec`으로 칩 식별 → `flash_prep`(소거 시간 기록) → 25MHz 스윕 1회
   → verify: 칩당 `#G2 JEDEC EF 40 17 [OK]` · `#PREP PASS` · `valid=1 reason=complete`
2. chip01 재측정 1회를 마지막에 추가 (D의 첫 측정과 쌍)
   → verify: 재장착 편차가 연속 반복 편차(0.61ps)와 분리되어 산출됨
3. 10개 폭 분포 집계 → 개체 산포 σ 산출, 이상치 판별
   → verify: S-2에 사전 등록된 이상치 기준으로 판정 (사후 해석 금지)
4. 10개 소거 시간 분포 집계 → 신품 기준선 확립

**산출물**: 개체 산포 σ · 신품 소거 시간 기준선 · 재장착 편차 (G5 조건 ① 해소)

## B. 벤치 구현 (장세은)

S-1 사양서 수신 후 착수. 두 산출물은 같은 계측 코드를 공유하므로 순서가 정해진다.

1. **소거 시간 계측** — `flash_prep.c`의 섹터 erase 루프에 XTime으로 WIP-busy 지속시간 기록
   → verify: `#PREP PASS`와 함께 섹터별 소거 시간이 출력되고, 값이 데이터시트 범위(W25Q64 4KB sector erase typ 45ms) 안에 든다
2. **P/E 사이클러** — 1번 계측 코드를 재사용해 `flash_prep.c`의 erase/program 루프에 카운터를 더한 확장
   → verify: S-1 인수 기준 통과 (사이클 카운터 ↔ 실제 erase 발행 수 독립 교차검증)
3. 마모 중 소거 시간 추이가 자동 로깅되는지 확인
   → verify: 사이클러가 erase를 돌리므로 1번의 계측이 공짜로 따라붙는다

구현 층위: **PS C로 상정**. 사이클 시간이 erase 45ms에 지배되므로 PS SPI 유틸리티 경로(2.6MHz)로 충분하며 RTL 사이클링 엔진은 과잉이다 — 3인 확정 필요(`roles.md` v2 미결).

### 마모 시간 예산 (데이터시트 typ 기준 추정)

섹터 0\~6을 100k 사이클까지: 7섹터 × 45ms + 100페이지 × 0.4ms ≈ **355ms/사이클 → 칩당 약 10시간**. 종단 마모 3\~4개면 무인 배치로 2\~3일이다. 소켓이 하나라 병렬이 불가능하므로 이것이 9월의 실질 병목이며, **9월 첫 주 착수**가 필요한 이유다.

이 값은 typ 기준이며 마모될수록 늘어난다(그것이 측정 대상이다). M-4의 실측 신품 소거 시간이 나오면 재산정한다.

**산출물**: 마모 실행 ELF + 소거 시간 계측 (G5 조건 ② 이중 지표의 후자)

②의 현재 상태: 반복성 ±0.61ps는 **재장착 없는 EV 한 조각**이다. D(일자 간)와 M-2(재장착)가 붙어야 %GRR·ndc를 논할 수 있다.

### 조건 ③의 분할 운용

조건 ③은 두 부분으로 나뉘며, 필요 시점이 다르다.

- **체크포인트 계획** — 종단 마모 개시 전에 필요. S-1에서 확정한다
- **블라인드 정답 사전 커밋** — 블라인드 마모 개시 전에 필요. 블라인드 추정은 교정 곡선이 존재해야 성립하므로(종단 마모 3\~4개의 결과물), 시점상 종단 마모보다 뒤다

따라서 9월 첫 주 마모 착수의 게이트 조건은 체크포인트 계획까지이며, 블라인드분은 그 시점에 미충족이어도 종단 마모를 막지 않는다. 단 **블라인드 칩 2개에는 그때까지 어떤 마모도 가하지 않는다.**

### 보류 — 블라인드 이해충돌 (결정 시점: 블라인드 착수 직전)

아래는 블라인드 국면에 들어갈 때 결정한다. **지금은 보류**하며, 잊지 않기 위해 기록만 남긴다.

`project_context.md` §7의 블라인드 설계는 *"마모 담당자가 횟수를 숨기고 마모, 측정자가 추정"* 이다. 그런데 `roles.md` v2에서 한영웅이 총괄이자 분석·추정자이므로, **한영웅이 정답을 사전 커밋하면 정답을 아는 채로 추정하게 되어 블라인드가 성립하지 않는다.**

해소안:

- **한영웅** — 블라인드 *절차*를 설계 (몇 개, 어떻게 봉인, 언제 개봉, 오차 산출식)
- **장세은** — 실제 마모 횟수를 정하고 봉인·사전 커밋. 개봉 전까지 한영웅에게 알리지 않음
- **한영웅** — 측정·추정 후 개봉, 오차 ±X% 산출

이 안을 채택하면 G5 조건 ③의 "블라인드 정답 사전 커밋"은 한영웅이 아니라 장세은의 일이 되고, `roles.md` v2의 한영웅 실험 설계 항목도 함께 수정해야 한다. **어느 쪽도 지금 확정하지 않는다** — 블라인드 착수가 가까워졌을 때 실제 인원 배치와 함께 결정한다.

**산출물**: 마모 개시 허가 또는 보류 사유 (문서로 기록)

## 공통 규칙·함정

기존 규칙(런북 3 표 E, 게이트 지도 4)은 그대로 유효하며, 본 국면에서 추가되는 것만 적는다.

- **수신(캡처) 먼저, 송신(xsct) 나중** — 첫 줄부터 받아야 한다 (변함없음)
- **재실행은 `program_*.tcl` 전체 경로** — ELF만 재로드하면 `phase_pos_mismatch`로 의도적 거부
- **마모 범위 ≠ 읽기 범위는 침묵 실패다** — 스윕이 정상 완주하고 `valid=1`이 뜨는데 마모 신호만 안 보인다. 몇 시간을 버리고도 원인을 못 찾는 유형이므로 S-1에서 반드시 고정한다
- **신품 소거 시간은 마모 전에만 확보 가능** — M-4를 건너뛰고 마모에 들어가면 이중 지표의 절반이 영구 소실된다
- **드리프트 확인 없이 전수 측정 금지** — D를 건너뛰면 10개 데이터의 기준점이 불명확해진다
- 마모는 비가역이다. G 판정 문서 없이 사이클러를 실행하지 않는다
