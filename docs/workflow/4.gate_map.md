# 4. 게이트 지도 — G0~G5 한눈에 (설계·명령·산출물·기대 출력)

- **작성일**: 2026-07-09
- **용도**: "g2가 뭐고 뭘 치면 되고 뭐가 나와야 하나"를 문서 한 곳에서 찾기 위한 색인.
  정의의 원전은 `docs/project_context.md` §9(게이트), 실행 절차의 원전은 런북
  (`3.realchip_day_runbook.md`) — 충돌 시 원전이 우선.
- **이름 규칙 (원전)**: 대문자 G# = 프로젝트 게이트. 소문자 `g#_*` = 그 게이트를 여는
  하드웨어 설계/앱 접두. **G1은 시뮬레이션 게이트라 g1 설계가 없다.**
- **트랙 이름 규칙 (2026-09-07 신설)**: 워크플로 문서의 트랙 문자는 **문서 로컬**이므로
  인용할 때 **문서 접두를 붙인다** — `W<번호>-<문자>`.

  ```
  G0 ~ G5                      프로젝트 게이트 — 전역·유일. 접두 없음
  W3-A ~ W3-D                  런북 3 (실칩 당일 절차)
  W5-S · W5-D · W5-M · W5-B · W5-V · W5-G    재개 워크플로 5
  W6-H · W6-R · W6-C                          G1 후속 워크플로 6
  W8-I · W8-B · W8-R · W8-T · W8-D            Vivado 2025.2 통일 워크플로 8
  W11-A ~ W11-E                                로그 전수조사 워크플로 11
  ```

  접두 없이 쓰면 충돌한다 — `D`가 둘(W3-D 실칩 곡선 / W5-D 드리프트 확인), `B`가 둘,
  `C`가 둘, 그리고 **`G`는 W5-G(게이트 판정 트랙)와 게이트 G5 자체가 겹친다.**
  대문자=전역·소문자=로컬이라는 위 규칙의 연장이며, 접두가 문서를 가리키므로 성격
  (W3=당일 런북 / W5=재개 국면 / W6=동결 후속)도 함께 드러난다.

## G0 — 루프백 곡선

```
빌드(원샷):  vivado -mode batch -source fpga/scripts/build_g0_loopback.tcl
             → build/vivado/g0_loopback.{runs/impl_1/g0_wrapper.bit, xsa}
             → build/vitis/g0_sweep/build/g0_sweep.elf  (체인 호출)
실행:        [1] .venv/bin/python host/capture/sweep_uart_capture.py --loopback
             [2] xsct ps/scripts/program_g0.tcl          # 원격: 인자 tcp:<호스트>:3121
기대:        "#G0 SWEEP BEGIN" → ~10분 → "#G0 SWEEP END valid=1 reason=complete"
산출:        build/data/sweep_loopback_<stamp>.csv (+_reads)
분석:        .venv/bin/python host/analysis/bathtub_analysis.py <csv>
스모크:      vitis -s ps/scripts/build_core_smoke.py → xsct ps/scripts/program_core_smoke.tcl
             (core 레지스터 계층 6종 PASS/FAIL — G0·G3 비트스트림 공용, 주소 0x43C00000)
```

## G3·G4 — 실칩 곡선과 반복

```
빌드:        vivado -mode batch -source fpga/scripts/build_g3_chip.tcl -tclargs all <25|45|75>
             → build/vivado_g3_<mhz>/ + build/vitis_g3_<mhz>/g3_sweep/build/g3_sweep.elf
             (보험 비트만: -tclargs bit <mhz> <k> → build/vivado_g3_<mhz>_pl<k>/)
실행:        .venv/bin/python host/run/run_sweep_chip.py --mode <newchip|sweep> --mhz <25|45|75> [--repeat N] [--reseat]
             --chip 은 선택 — 주면 flash_id 가 읽은 라벨과 대조한다. 생략하면 읽은 대로 간다
             모드: newchip(prep 포함, P/E +1) · sweep(--chip chipNN, P/E 불변)
             (한 프로세스가 세션1 flash_prep → #PREP UID → 등록부 역조회 → 세션2 스윕 ×N.
              xsct 호출 포함 — 터미널 하나. 라벨은 입력하지 않는다, 로그 23)
기대:        "SWEEP END valid=1 reason=complete" → build/data/sweep_chip01_<uid16>_<stamp>.csv
분석:        bathtub_analysis.py <csv> → 양벽 곡선이면 채택, 전구간 0이면 클럭 상향(사다리)
G4:          채택 클럭으로 5회 반복 (재장착 금지: --repeat 5) → 폭 5개 → 평균±표준편차 에러바
보관:        실칩 CSV 원본은 build/data/ → data/ 이동 (D7), 게재 그림만 docs/results/
```

## 공통 규칙·함정 (원전: 런북 3 표 E)

- **수신(캡처/miniterm) 먼저, 송신(xsct) 나중** — 첫 줄부터 받아야 한다
- miniterm과 캡처는 같은 포트(/dev/ttyUSB1) — 동시 사용 불가
- 재실행은 반드시 `program_*.tcl` 전체 경로 (ELF만 재로드 = `phase_pos_mismatch` 의도된 거부)
- 사전 쓰기 없이 스윕 = 전 위상 BER≈0.51, e_i가 PRBS 0비트 수와 일치 (7/8 실사례, 로그 14)
- 전 위상 BER≈0.5 + valid=1 = PAY_LEAD 어긋남 → 보험 비트 굽고 `program_g3.tcl 25 pl4` (칩 문제 아님)
