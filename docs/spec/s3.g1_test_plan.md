## 1. 무엇을 채점하는가

| | |
| --- | --- |
| **채점 대상** | 아래 두 DUT로 엘라보레이트되는 **인스턴스 트리 전체** (H7) |
| **기준의 원전** | `docs/interface/contract.md` — §2 신호 · §3 레지스터 맵 · §4 규약 R1\~R12 · §5 수치 |
| **한 줄로** | **이 RTL이 계약을 지키는가** |

사람을 채점하는 표가 아니다. cocotb는 검증을 **Winbond 공식 행동 모델 상대로 재현**하고
**상시 회귀로 고정**하는 층이다.

### 채점 대상 파일 (H7 — 트리로 정의한다)

목록을 손으로 유지하면 파일이 늘 때 조용히 빠진다. **DUT가 인스턴스화하는 것은 전부
채점 대상**이며, 아래 표는 2026-08-23 시점의 트리를 펼쳐 적은 것이다.

| DUT | 트리 |
| --- | ---- |
| `fpga/rtl/flash/flash_top_spi.v` | `flash_spi_ctrl.v` · `flash_spi_shim.v` · `flash_rx.v`(→ `flash_prbs15.v`) · `flash_logbuf.v` · `flash_sync2.v` ×3 |
| `fpga/rtl/core/core_top.v` | `core_mmcm.v` · `core_phase_ctrl.v` · `core_axil_regs.v` |

- 구본의 *"`flash_top_spi.v` 계열"* 은 로그 11이 신규 작성한 3파일
  (`flash_spi_ctrl` · `flash_spi_shim` · `flash_top_spi`)을 가리켰으나, **채점 대상은
  신규 여부가 아니라 계약 항목이 무엇을 재는가로 갈린다.** F3(주소→시드)은 `flash_rx.v`를,
  F6·R8은 `flash_logbuf.v`를, F3의 기대 패턴은 `flash_prbs15.v`를 직접 잰다. 재사용
  모듈이라고 빼면 항목이 채점 대상 없이 뜬다
- `flash_ctrl.v` · `flash_top.v`는 **루프백(G0) 경로**이며 SPI DUT 트리에 없다. G1 범위 밖
- 코어는 `core_mmcm.v`가 Xilinx 프리미티브를 감싸므로 시뮬에서는 `sim/smoke/unisim_stub.v`
  계열의 대체가 필요하다. **스텁으로 대체된 부분은 채점되지 않는다** — C 항목은 레지스터·
  위상 누적 로직만 본다

항목의 내력은 둘로 갈린다.

- **기존 19항목** (F1\~F10 · C1\~C6 · I1\~I3) — 이미 `sim/smoke/`의 iverilog TB로 1회 이상
  통과했다. cocotb 이관은 재현·상시화다
- **신설 4항목** (F11 F12 · W1 W2) — **smoke에서 검증된 적이 없다.** W 2항목은 내장
  슬레이브가 원리상 못 보는 영역이고(§5.2), F11·F12는 수정안 #1이 도입하는 신규 기능이다.
  이들은 cocotb가 **처음으로** 검증하는 항목이므로 "재현"이 아니라 신규 구축이다

## 2. 읽기 창 표기 — `page(i)`

주소와 시드는 **반드시 같은 `page(i)`에서 유도한다.** 한쪽만 옮기면 전 위상 BER≈0.5가
되고, 이는 칩 불량과 구분되지 않는 서명이라 오진하기 쉽다(런북 3 표 E).

```
page(i) = BASE_SECTOR × 16 + i        (i = 0 … N−1)

계약 v1        BASE_SECTOR 레지스터 없음 → page(i) = i
수정안 #1 승인 후  BASE_SECTOR 유효, 리셋값 0 → 기본 동작 동일
```

본 문서의 모든 항목은 이 표기로 쓰였으므로 **수정안 #1의 승인 여부와 무관하게 유효**하다.
승인 시 추가되는 것은 F11·F12뿐이며 기존 항목은 손대지 않는다.

## 3. 오라클 출처 — 항목마다 무엇이 정답을 쥐는가

`sim/smoke/tb_flash_spi_smoke.v`의 내장 슬레이브는 **우리가 짠 모델**이다(로그 11).
우리가 이해한 프로토콜대로 응답하게 만들어져 있으므로, **우리가 프로토콜을 잘못
이해했다면 잘못된 RTL이 잘못된 모델을 상대로 통과한다.** 이 순환을 끊는 것이 G1의
고유 주장이며, Winbond 공식 모델은 우리 손을 타지 않은 제3자다.

| 출처 | 뜻 | 해당 |
| ---- | --- | ---- |
| **V** (vendor) | 정답을 벤더 모델이 쥔다. 순환 논증에 노출된 항목 | F1 F2 F3 F5 F11 W1 W2 |
| **S** (self) | 정답이 계약 자체에서 나온다. 칩 거동과 무관하므로 자기 정합으로 충분 | 나머지 전부 |

**S 항목도 전부 cocotb로 이관한다.** smoke는 `sim/README.md`가 밝히듯 *"cocotb 회귀 확립
전 임시 최소 회귀"* 이고 1회 통과했을 뿐 상시 실행이 아니다(F12는 애초에 smoke에 없다 — §1). 출처 구분은 **G1이 무엇을
증명했다고 주장할 수 있는가**를 정하는 것이지 범위를 줄이는 것이 아니다.

## 4. 항목 ID 규약 (기계가 읽는다)

모든 테스트 함수명은 **`test_<항목ID>_<설명>`** 형식으로 쓴다.

```python
@cocotb.test()
async def test_F2_mode0_timing(dut): ...
```

`sim/check_coverage.py`(**소유: 한영웅**)가 회귀 종료 후 실행된 테스트명에서 항목 ID를
추출해 본 문서 §5의 항목 목록(23개, 수정안 #1 미승인 시 21개)과 대조한다. 누락이 하나라도 있으면 **회귀 전체가 FAIL**이다.

```
F1  frame_spec        covered ✓
F2  mode0_timing      MISSING ✗   ← 회귀 FAIL
```

대조 스크립트를 한영웅이 소유하는 이유: 이것은 기준 쪽 산출물이다. 채점 대상이 자기
채점 도구를 만들면 도입 취지가 사라진다. `sim/tb/`(박지민) 밖인 `sim/` 최상위에 둔다.

### 4.1 목록의 원전은 본 문서다 (H5)

**별도 목록 파일을 두지 않는다.** 목록 파일은 동결본과 어긋날 수 있고, 어긋난 쪽이
기준 행세를 하면 채점표가 둘이 된다.

스크립트는 **본 문서 §5의 표 행을 직접 파싱**한다(`| F1 |` 꼴의 선두 셀에서 ID 추출).
서식 변경 시 조용히 깨지는 것을 막기 위해 **§5 말미의 합계 선언 문장과 교차 검증**한다.

```
표 파싱 결과 = 23개 (F 12 · W 2 · C 6 · I 3)
합계 선언   = 23항목 — F 12 · W 2 · C 6 · I 3
→ 일치. 불일치 시 커버리지 판정 이전에 스크립트가 비영 종료한다
```

파싱이 깨지면 **0개가 아니라 불일치로 드러난다.** 합계 선언 문장은 서식이 아니라
내용이므로 표 서식과 함께 깨지지 않는다.

### 4.2 수정안 #1 미승인 시의 제외 처리 (H6)

승인 상태는 **수동 플래그**로 준다 — `--amendment1`(기본 꺼짐, 미승인 상태).
계약 문서 파싱은 승인란의 자유 서식에 의존해 더 약하다.

수동 플래그의 위험은 **끄고 돌리면 2항목이 조용히 사라지는 것**이다. 그래서
**리포트는 제외 사실을 항상 선두에 출력**하며, 제외가 0건일 때도 그렇게 적는다.

```
[amendment #1: NOT APPROVED]  excluded: F11 F12   (--amendment1 로 활성화)
covered 21/21
```

> **커버리지의 한계 — 반드시 읽을 것.** 이 리포트는 **항목 누락만** 검출한다.
> `assert True`도 실행 횟수는 올라가고 covered로 표시된다. **어서션이 항목을 실제로
> 재는지는 커버리지로 알 수 없으며, §6 ①의 코드 열람을 대체하지 않는다.**
> 초록 숫자를 리뷰의 결론으로 삼지 말 것.

#### 5.1.1 F11 지점 선정 — 각 지점이 무엇을 구분하는가 (H2)

| `BASE_SECTOR` | 이 지점이 아니면 못 잡는 것 |
| ------------- | --------------------------- |
| **0** | 하위 호환. `page(i) = i`로 계약 v1과 완전히 같은 동작 — 이 지점이 깨지면 BASE_SECTOR 도입이 기존 G0·G3 데이터를 무효화한다 |
| **1** | **섹터→페이지 ×16 스케일링.** `page(0)=16`이므로 `BASE_SECTOR`를 페이지로 오해해 더한 구현(`page(0)=1`)이 여기서만 분리된다. 큰 값에서는 다른 오류와 섞여 구분되지 않는다 |
| **1,024** | **상위 주소 비트 경로.** `page(0)=16,384` → 주소 비트 [14]가 처음으로 선다. 종전 12비트 `idx` 필드로는 표현 불가했던 영역 |
| **2,041** | **상한 경계.** N=112에서 마지막 읽기가 페이지 32,767에 정확히 떨어진다. off-by-one이면 F12의 거부 조건에 걸려 START 자체가 실패한다 |

**구본의 249를 뺐다.** 근거가 *"종전 주소 폭(12비트)의 상한 부근"* 이었는데(수정안 #1 §4 A2),
**시뮬은 새 RTL을 돌리므로 12비트 제약이 존재하지 않는다.** 실측 인수 기준의 논리를 옮기면서
근거가 따라오지 않은 자리다. 실측 A2에서는 종전 비트스트림과의 회귀 비교라 249가 여전히 유효하다.

> **BER 관측의 구조적 맹점 — F11이 A2를 대체하지 못하는 이유.**
> 기대 패턴의 시드는 `page(i)[13:0]`이므로 **패턴은 16,384페이지(=1,024섹터)마다 반복**된다
> (수정안 #1 §3). 따라서 주소 상위 비트 [14]가 통째로 유실돼도 모델은 별칭 페이지의
> **같은 내용**을 돌려주고 **BER은 0으로 통과한다.** 하필 `BASE_SECTOR`=1,024가 그 지점이다.
> 그래서 F11은 BER만으로 판정하지 않고 **⑴ 와이어 주소 디코드를 동등한 필수 조건**으로 둔다 —
> 주소 바이트는 별칭되지 않으므로 상위 비트를 직접 본다.
> 그럼에도 **실측 A2(먼 구역 실제 굽기)는 유지된다**: 시뮬 모델 메모리는 우리가 적재한
> 것이라 "칩의 그 구역이 실제로 그 데이터를 갖는가"는 여전히 실칩만 답한다.

### 5.2 Winbond 모델 고유 항목 (신설)

내장 슬레이브가 **원리상 못 보는 것**이며, 벤더 모델을 도입하는 유일한 이유다.
기존 문서가 스왑 지점에서 셋을 지목해 놓고 PASS 기준을 적지 않았던 결손을 메운다.
셋 중 mode 경계(구 W3)는 **개정 2에서 폐기**했다 — 사유는 아래.

| # | 출처 | 항목 | PASS 기준 |
| --- | --- | ---- | --------- |
| W1 | **V** | 명령 오인식에 대한 칩의 실제 반응 | 명령 바이트를 1비트 틀리게 주입(0x0B→0x0A / 0x1B)했을 때 **침묵 통과가 없을 것** — BER≈0.5 또는 TIMEOUT으로 시끄럽게 실패. 내장 모델은 0x0B만 알아 이 경우를 재현하지 못한다 |
| W2 | **V** | tSHSL 위반 시 반응 | ⑴ 정상 운전 전 구간에서 모델의 타이밍 어서션 무발화 ⑵ **음성 대조**: CS↑ 간격을 데이터시트 min 미만으로 의도적으로 좁히면 어서션이 발화할 것. ⑵가 없으면 ⑴이 "어서션이 죽어 있어서 조용한 것"과 구분되지 않는다 |

#### 폐기 — W3 mode 경계 (H1)

구 W3의 PASS 기준은 *"유휴 high로 바꾸면 실패할 것"* 이었다. **실패 방향이 양쪽 다 성립하지 않는다.**

- **칩 쪽** — 데이터시트 §6.1: *"SPI bus operation Mode 0 (0,0) and 3 (1,1) are supported.
  … For Mode 0, the CLK signal is normally low on the falling and rising edges of /CS.
  For Mode 3, the CLK signal is normally high."* 두 모드의 차이는 /CS 에지에서의 CLK 유휴
  레벨뿐이고 **둘 다 지원된다.** 유휴 high로 주면 모델은 mode 3로 정상 동작하므로 실패하지 않는다
- **우리 쪽** — SCLK는 `flash_spi_ctrl`이 만들지 않고 top의 **`ODDR(D1=0, D2=sclk_en)`** 이
  만든다(`flash_spi_ctrl.v:12`). `sclk_en=0`이면 두 반주기가 모두 0이므로 **유휴 high는
  런타임 상태가 아니라 배선 상수**다. 그것을 바꾼 DUT는 다른 설계이며, 채점 대상이 아니다

즉 W3는 **어느 쪽으로도 재현 가능한 반례가 없다.** H1의 지시대로 폐기하고,
지키려던 성질(**우리가 mode 0을 실제로 지키는가**)은 **F2로 옮겼다** — CS↓·CS↑ 시점의
SCLK 레벨은 와이어에서 직접 관측되는 값이므로 추측이 아니라 측정이 된다.

검증 불가능한 항목을 표에 남겨두면 **커버리지가 전항 초록으로 뜨는데 그중 하나는 아무것도
증명하지 않는다.** 그것이 항목을 하나 줄이는 것보다 나쁘다.

## 6. 승인 규칙 — 판정을 셋으로 나눈다

인원이 3인이라 완전 분리가 구조적으로 불가능하다. **한영웅은 합격 기준 작성자이면서
채점 대상 RTL의 실제 작성자**(`roles.md` §RTL — `flash_spi_ctrl.v` 등 3파일)이고,
**박지민은 RTL 소유자이면서 그것을 채점할 TB의 작성자**다. 어느 한 사람에게 판정을
몰면 분리가 절반만 성립한다.

판정을 성질별로 쪼개면 겸직이 있어도 각 판정이 독립된다.

| 단계 | 무엇을 | 누가 | 왜 그 사람인가 |
| ---- | ------ | ---- | -------------- |
| ① | **어서션이 §5의 23항목을 실제로 재는가** | **한영웅** | TB를 쓰지 않았으므로 독립. 기준 작성자 본인이라 각 항목의 의도를 안다 |
| ② | RTL이 그 어서션을 통과하는가 | **회귀** | 자동. 사람의 재량이 개입하지 않는다 |
| ③ | 블록 승인 집행 | **박지민** | RTL 소유자. ①②가 충족되면 형식 행위 |

- ①의 범위는 **§4 커버리지 리포트가 통과한 뒤**의 코드 열람이다. 누락(항목 부재)은
  기계가 이미 걸렀으므로, 사람은 **형식 커버**(`assert True`류)와 **잘못된 기준**
  (예: tSHSL 최소값 오기)만 본다
- ①은 통과·보류 중 하나를 **`docs/spec/s3.g1_review.md`** 에 남긴다(H4). 보류 시 사유와
  해당 항목 ID를 명시한다 — 위치는 §6.1
- ②의 결과는 사람이 해석하지 않는다. FAIL이면 FAIL이다
- **③은 ①②가 모두 충족된 뒤에만 가능하다.** ①을 건너뛴 승인은 무효

### 6.1 ① 판정의 산출물 위치 (H4)

**`docs/spec/s3.g1_review.md` — 블록별 행이 누적되는 단일 판정서.**

## 9. 2026-09-18 보충 개정 — 첫 cocotb 실행에서 드러난 모호함

기존 기준과 이력은 삭제하지 않는다. 2026-09-18 F8·F9 cocotb를 처음 실제 실행하면서
다음 두 부족한 점이 드러나 이 절을 추가했다.

1. F9의 기존 문구인 **"에러 = 기대 PRBS의 1 개수"**는 `flash_rx`가 세 정렬 후보 중
   최솟값을 보고한다는 사실을 포함하지 않아, 같은 결과를 `1,856` 또는 `1,854`로 다르게
   계산할 수 있었다.
2. 기존 `check_coverage.py`는 JUnit XML에 테스트 이름이 존재하는지만 확인했다. 따라서
   assertion이 실패한 F9도 `covered`로 표시할 수 있어, `covered`를 PASS로 오해할 위험이
   있었다.

### 9.1 F9 기대값 계산 보충

`flash_rx`의 보고값은 설계 결정 D7-1에 따라 `e_i = min(e0,e1,e2)`다. MISO가 0으로
고정되면 수신 데이터만으로 세 정렬 후보 중 실제 정렬을 구분할 수 없으므로, F9의 독립
기대값도 다음처럼 계산한다.

```text
각 page i에서 PRBS를 B+2비트 생성
candidate[d] = PRBS[d : d+B] 안의 1 개수, d = 0, 1, 2
expected_e_i = min(candidate[0], candidate[1], candidate[2])

ERR_BITS  = Σ expected_e_i
ERR_READS = count(expected_e_i > 0)
```

현재 회귀 조건 `N=2`, `B=2,048`, `BASE_SECTOR=0`의 기준값은 다음과 같다.

| page | 후보별 1 개수 | 기대 `e_i` |
| ---- | ------------- | ---------- |
| 0 | 927, 926, 926 | 926 |
| 1 | 929, 928, 928 | 928 |
| 합계 | — | `ERR_BITS=1,854`, `ERR_READS=2` |

이 보충은 포화 영역에서 3후보 최솟값이 명목 BER보다 조금 작아질 수 있다는
`flash_rx.v` 헤더의 기존 한계를 F9 oracle에 명시한 것이다. 특정 숫자만 하드코딩하지 않고
cocotb가 PRBS와 세 후보를 독립 생성하여 계산해야 한다.

### 9.2 자동 결과 표기 규칙

`PASS / NONPASS` 이분법은 실제 assertion 실패와 미구현, 선행조건 부족, 수정안 제외를
구분하지 못한다. 자동 회귀의 항목 상태는 다음 여섯 가지로 표기한다.

| 상태 | 의미 |
| ---- | ---- |
| `PASS` | 해당 ID에 연결된 모든 cocotb 테스트가 실행되어 assertion을 통과 |
| `FAIL` | 해당 ID의 테스트 중 하나 이상이 assertion 실패 또는 실행 오류 |
| `PARTIAL` | 한 ID의 하위 테스트 일부는 PASS했지만 다른 하위 테스트가 SKIPPED |
| `SKIPPED` | 테스트는 존재하지만 선행조건 부족 등으로 실행을 건너뜀 |
| `MISSING` | JUnit XML에 해당 ID의 테스트가 없음 |
| `EXCLUDED` | 승인되지 않은 수정안 등으로 이번 회귀의 요구 항목에서 제외 |

전체 상태는 다음 셋으로 표시한다.

| 전체 상태 | 조건 |
| --------- | ---- |
| `PASS` | 모든 활성 항목이 PASS이고 미등록 테스트가 없음 |
| `FAIL` | 활성 항목에 실제 FAIL이 있거나 잘못된 ID·ID 없는 테스트가 있음 |
| `INCOMPLETE` | 실제 FAIL은 없지만 PARTIAL, SKIPPED 또는 MISSING 항목이 남음 |

따라서 개발 중 `F8·F9 PASS, 나머지 MISSING`은 **실패한 회귀가 아니라 `INCOMPLETE`인
회귀**다. `check_coverage.py`는 콘솔 요약과 함께 `sim/build/g1_status.md`를 생성하며,
JUnit `results.xml`을 기계 판정의 원본으로 유지한다.

### 9.3 복합 항목의 부분 완료 표기

F2처럼 하나의 ID가 독립적인 두 조건을 함께 요구할 수 있다. F2의 wire mode 0 타이밍은
단순 cocotb SPI 응답기로 검사할 수 있지만, **공식 모델 timing assertion 무발화**는 Winbond
모델이 runner에 연결된 뒤에만 검사할 수 있다. 전자만 PASS한 상태를 F2 전체 PASS로 세지
않는다.

```text
하위 테스트가 PASS + SKIPPED → 항목 상태 PARTIAL
모든 하위 테스트가 PASS       → 항목 상태 PASS
하위 테스트 하나라도 FAIL      → 항목 상태 FAIL
```

이 규칙은 완료된 부분을 숨기지 않으면서 아직 충족하지 못한 조건도 초록색 PASS에 섞이지 않게
한다. 상태표의 테스트명 뒤에는 각 하위 테스트의 개별 상태도 함께 적는다.

### 9.4 자동 PASS와 사람 검토를 분리한다

자동 상태표의 `PASS`는 **작성된 assertion이 통과했다**는 뜻이다. 그 assertion이 §5의
의도를 충분히 검사하는지는 여전히 §6의 독립 코드 열람 대상이다. 최종 제시 표는 자동 결과와
검토 결과를 한 칸에 섞지 않고 다음처럼 분리한다.

| ID | 자동 결과 | 독립 리뷰 | 증거 / 비고 |
| -- | --------- | --------- | ----------- |
| F8 | PASS | PENDING 또는 PASS/HOLD | JUnit testcase 이름, commit, 실행 시각 |
| F9 | PASS | PENDING 또는 PASS/HOLD | `ERR_BITS`, 읽기별 `e_i`, 모델 조건 |

`sim/build/g1_status.md`는 개발 중 자동 상태표이고 Git에서 제외한다. G1 게이트 시점에는 같은
회귀의 JUnit·실행 로그·상태표를 `docs/results/captures/g1/`에 승격하고, 독립 리뷰 결과는
기존 위치인 `docs/spec/s3.g1_review.md`에 누적한다.

### 9.5 2026-09-18 F3·F4 검토 후 시험 범위 명시

초기 cocotb 구현을 독립 검토한 결과, F3의 page 0~16 시험은 주소와 시드의 기본 정합은
증명하지만 주소 바이트 carry를 검사하지 않았고, F4의 기존 smoke 계승 3 ns 간격은
"0~1UI 전 구간"이라는 표현에 비해 표본 간격이 명시되지 않았다. 기존 PASS 기준을 지우지
않고 다음 실행 범위를 보충한다.

- **F3**: Winbond 모델 메모리를 최소 512페이지로 구성하고 page 0~256을 연속 읽는다.
  실제 MOSI 주소가 `0x000000`부터 `0x010000`까지 page 단위로 증가해야 하며,
  특히 page 255의 `0x00FF00`에서 page 256의 `0x010000`으로 넘어가는 주소 바이트 carry를
  직접 확인한다. `B=16`으로 PRBS-15 시드 전체가 비교 데이터에 반영되게 하고 모든
  읽기의 오류가 0이어야 한다. 더 높은 N 경계와 full log buffer는 F10이 담당한다.
- **F4**: 25 MHz의 1UI=40 ns에서 `0.5 ns` 간격의 0.5~39.5 ns를 검사하고, 양 경계에
  가까운 0.1 ns와 39.9 ns를 추가한다(총 81점). 정확한 0 ns와 40 ns는 modulo 1UI로
  같은 위상이며 simulator의 동시 에지 delta-cycle 순서에 의존하므로 제외한다. 각 지점은
  독립 test case로 남기고, 하나라도 오류 또는 TIMEOUT이면 F4 전체를 FAIL로 판정한다.

이 범위는 연속시간 전체에 대한 수학적 증명이 아니라 명시된 격자에 대한 디지털 시뮬레이션
증거다. 실제 FPGA의 미세 위상 스텝과 아날로그 경계는 G0/G3 실측이 담당한다.

### 9.6 2026-09-19 F5 최초 실행으로 정정한 1UI 초과 판정

§5.1의 기존 F5 문구는 출력 지연이 1UI를 넘으면 **전 위상** BER이 약 0.5가 된다고
가정했다. 공식 Winbond 모델의 `tCLQV=6 ns` 뒤에 시험 전용 transport delay를 추가하고
25 MHz(`1UI=40 ns`)에서 실행한 결과, 유효 지연 50 ns에서는 다음 두 구간이 함께
나타났다.

```text
sample phase 0.1~9.5 ns  : e_i 약 191~194 / B=512
sample phase 10.0~39.9 ns: e_i = 0
```

따라서 `1UI 초과 = 전 위상 BER≈0.5`는 이 RTL의 세 후보 정렬기에는 맞지 않는다.
`flash_rx`가 `{t0+3,t0+4,t0+5}` 세 후보 중 최솟값을 선택하므로, 한 비트 밀림은 인접
후보가 흡수할 수 있고 샘플 위상을 옮기면 정상 바닥을 다시 찾을 수 있다. 이는 RTL 실패가
아니라 기존 시험 oracle의 오류다.

기존 행은 이력을 위해 삭제하지 않고 F5 실행 기준을 다음 세 증거로 보충한다.

1. 공식 모델의 고정 `tCLQV=6 ns`와 추가 경로 지연을 합친 유효 지연 6~38 ns를 스윕하고
   기준 위상에서 모든 읽기의 오류가 0인지 확인한다.
2. 유효 지연 50 ns, 위상 0.1 ns에서 높은 PRBS 오류가 나타나는지 확인하여 1UI 경계 뒤
   오류 벽이 실제로 이동했음을 확인한다.
3. 세 후보의 ±1비트 보정 범위를 확실히 벗어난 유효 지연 90 ns에서 0.1~39.9 ns의
   81개 위상을 검사한다. 모든 위상에서 각 `e_i/B`가 0.35~0.60이고, `ERR_BITS`가
   `sum(e_i)`, `ERR_READS=2`여야 한다. 단 하나라도 오류 0 바닥이 나타나면 F5 FAIL이다.

0.35~0.60 범위는 이상적인 무상관 BER 0.5를 유한 길이 PRBS와
`min(e0,e1,e2)` 구조에서 판정하기 위한 허용 범위다. F5는 아날로그 지터나 연속시간
파형을 증명하지 않으며, 공식 모델이 생성한 디지털 출력과 고정 transport delay에 대한
프레이밍 안전성만 검증한다.

### 9.7 2026-09-19 F2 타이밍 oracle 보강

초기 F2는 CS 경계의 mode-0 조건과 공식 모델의 `timing_error=0`을 확인했지만, SCLK의
high/low/period를 직접 재지 않았고 모델의 timing guard가 실제로 활성화됐다는 음성 대조가
없었다. 다음 조건을 F2의 필수 하위 시험으로 보충한다.

1. `N=3`, `B=64`의 모든 프레임에서 SCLK high≥18 ns, low≥18 ns, period≥40 ns,
   CS↓→첫 SCLK↑≥5 ns, 마지막 SCLK↑→CS↑≥3 ns, 프레임 사이 CS high≥10 ns를 wire에서
   직접 측정한다. CS↓·CS↑ 순간 SCLK=low 조건도 유지한다.
2. 공식 모델이 page 0과 page 1의 서로 다른 PRBS byte를 실제로 적재했는지 확인하고,
   정상 읽기 동안 `timing_error=0`, 읽기별 오류 0, `ERR_BITS=0`, `ERR_READS=0`을 요구한다.
3. 정상 벤더 시험이 모두 끝난 뒤 공식 모델에 2 ns SCLK high pulse를 고의 입력한다.
   모델의 sticky `timing_error`가 1이 되어야 한다. 이 음성 대조가 실패하면 정상 구간의
   `timing_error=0`도 유효한 증거로 인정하지 않는다.

2 ns 음성 대조 뒤에는 같은 모델 인스턴스의 sticky 오류를 지울 수 없으므로 runner에서
F2 음성 대조를 다른 정상 벤더 항목(F1, F3, F5) 뒤에 배치한다.

### 9.8 2026-09-19 F7 워치독 경계와 복구 기준 보강

기존 Verilog smoke는 `T_max`보다 200사이클 긴 guard 안에서 TIMEOUT이 보이는지만
확인해 정확한 경계의 off-by-one을 검출하지 못했다. cocotb F7을 작성하면서
`wd_cnt`가 START 다음 사이클부터 증가하는데 비교식이 `wd_cnt >= t_max`였음을 확인했다.
이 식은 계약의 `T_max`번째가 아니라 `T_max+1`번째 에지에서 종료할 수 있다.

`flash_ctrl.v`와 `flash_spi_ctrl.v`의 비교를 `wd_cnt >= t_max-1`로 고쳐 두 경로가 같은
R10 의미를 유지하게 했다. F7의 필수 판정은 다음과 같다.

1. `N=2`, `B=64`에서 `T_max=2×2×(64+64)=512`를 독립 계산한다.
2. 동기화된 `rx_done` 전달 경로를 시험 wrapper에서 0으로 차단한다.
3. START 승인 뒤 정확히 512번째 `clk_core` 사이클에서 `meas_done=1`과
   `meas_timeout=1`이 동시에 한 사이클 펄스로 발생해야 한다.
4. 같은 종료에서 `meas_busy=0`, `spi_cs_n=1`, `spi_sclk=0`, `cfg_err=0`이어야 한다.
5. fault를 해제하고 CDC가 idle로 돌아온 뒤 같은 `N=2`, `B=64` 정상 측정을 다시 시작한다.
   TIMEOUT 없이 완료하고 읽기별 오류 `[0,0]`, `ERR_BITS=0`, `ERR_READS=0`이어야 한다.

F7 단독 회귀에서 위 조건 1개 test case가 PASS했다. 이는 TIMEOUT 발생만이 아니라 정확한
마감 시각, 외부 핀의 안전 상태, 다음 측정 복구까지 포함한 결과다.

### 9.9 2026-09-20 W1 공식 모델의 invalid-opcode 정지 처리

W1 구현 전 Winbond `W25Q64JV.v` V0.6b의 명령 dispatch를 확인한 결과, 지원하지 않는
opcode의 기본 분기는 다음처럼 동작한다.

```verilog
$display("Invalid Opcode. (%0h)", cmd_byte);
$stop;
```

따라서 원본 모델을 그대로 실행하면 `0x0A` 또는 `0x1B`의 8번째 명령 비트를 받은 직후
시뮬레이터가 정지한다. §5.2의 기존 문구처럼 측정을 끝까지 진행해 BER 또는 TIMEOUT을
관측할 수 없지만, 이는 잘못된 명령을 정상 Fast Read로 침묵 수용한 것이 아니라 공식
모델이 명시적으로 거부한 더 강한 실패 반응이다.

기존 W1 행은 이력을 위해 삭제하지 않고 다음 관측 규칙을 보충한다.

1. 실제 Flash 모델 입력에서 `0x0B`의 한 비트만 바꾼 `0x0A`와 `0x1B`가 각각 관측돼야 한다.
2. 공식 모델의 invalid-opcode 분기가 각 프레임에서 실행되고, 모델이 기록한 마지막 opcode가
   주입값과 같아야 한다. 이 명시적 거부도 W1의 "침묵 통과 없음"을 만족하는 증거로 인정한다.
3. JUnit 결과를 남길 수 있도록 runner가 만드는 **실행용 사본에만** 원본 `$stop`을 sticky
   event·opcode·count 기록과 CS 해제 대기로 치환한다. 저장소 밖의 라이선스 원본은 수정하지
   않으며 명령 decode와 `Invalid Opcode` 메시지는 그대로 유지한다.
4. 공식 모델은 invalid opcode에서 payload를 구동하지 않으므로, 시험 wrapper가 그 구간의
   MISO를 0으로 고정해 DUT를 끝까지 실행한다. 이때 읽기별 오류는 F9와 같은 독립 PRBS
   기대값과 일치하고 `e_i/B=0.35~0.60`, `ERR_READS=N`이어야 한다. 이 BER은 실제 칩의
   아날로그 부동 레벨을 주장하는 값이 아니라, **정상 데이터가 돌아오지 않았을 때 DUT가
   조용한 성공을 만들지 않는지** 확인하는 결정적 no-response 대조다.

이 보충으로 W1은 벤더 모델의 실제 명령 판정과 DUT의 실패 가시성을 분리해 모두 확인한다.

### 9.10 2026-09-23 W2 tSHSL 정상·음성 대조 결과

W2는 Winbond 공식 모델 V0.6b의 `/CS` high 유지시간 검사를 대상으로 한다. 정상 대조는
60ns·100ns·150ns 간격을 사용했다. 이 값들은 모델의 읽기 기준 `tSHSL_R=10ns`와
비읽기 기준 `tSHSL_W=50ns`를 모두 넘으므로 정상 구간이다. 세 구간에서 timing error가
발생하지 않았고, 1ns 음성 대조에서는 tSHSL 위반이 검출됐다.

```text
W2 tSHSL: legal gaps 60/100/150 ns clean; 1 ns negative control detected
W2_vendor_tshsl_timing.test_W2_vendor_tshsl_clean_and_negative_control passed
```

W2를 포함한 누적 상태는 `PASS 12/21`, `FAIL 0`, `MISSING 9`, `EXCLUDED 2`이다. 남은
MISSING은 C1~C6와 I1~I3이며 W2와는 별개다. Icarus에서 공식 모델의 조건부 `specify
$width` notifier를 안정적으로 관측하기 어려운 부분은 원본 모델을 수정하지 않고 runner가
생성하는 무시된 runtime 사본의 호환 감시기로 보완했다.

### 9.11 2026-09-23 C/I 완료 및 승인 항목 최종 상태
