**A5 와 B 는 mock 이 실칩보다 많이 본다.** 실칩 100사이클은 §7 주기 동작이 한 번만 돌아

것이 된다.

## 3. 가짜 엔진이 주입해야 하는 고장

로그 41 `[D41-11]`. **축이 둘이다** — 진행이 멈추는 것과, 진행은 되는데 받은 바이트가
틀린 것. 고르는 기준은 빈도가 아니라 **「이 고장이 채점표를 틀리게 만드나」** 다.

### 3.1 중단 — 진행이 멈춘다

| 주입 항목 | 무엇을 하나 | 걸리는 판정 |
| --------- | ----------- | ----------- |
| 전원 차단 | 소거 중 / 프로그램 중 / tally 쓰는 중 / 사이클 사이에 죽는다 | B · A4 |
| 호스트 죽음 | 엔진은 계속 도는데 호스트만 멈춘다 — tally 만 는다 | B · §8.3 3 |
| 보드 행 | 응답을 주지 않는다 | 호스트 워치독 — **`running` 에서만**, 값은 M 트랙 실측 (로그 41 `[D41-19]`) |
| 연결 끊김·복귀 | 행 뭉텅이가 빠진 뒤 다시 붙는다 | A2 · **A5** · 재시도 **3회 상한** (`[D41-18]`) |
| SPI 무응답 | `blank_check` 가 전량 `0xFF`/`0x00` 으로 온다 | A3 · B |

**재시도는 전송·연결에만 3회이고 플래시 동작은 0회다**(`[D41-18]`) — P/E 는 비가역이라
플래시 재시도가 곧 마모이고, S-1 §10 의 「자동 재시도 금지」가 그대로 선다.

실물 근거: 전원 차단은 S-1 §13 B 가 시험 항목으로 명시 · 행 유실은
`docs/log/young/8.vivado_integration_and_sweep_sw.md` `[D8-6]` · SPI 무응답은
`docs/log/young/13.first_loopback_bathtub_and_linedead_fix.md`. 호스트 죽음과 보드 행은
겪은 기록이 없고 무인 6일 운용 판단에서 왔다 (2026-09-18, 한영웅).

### 3.2 전송 손상 — 진행은 되는데 받은 바이트가 틀리다

다섯이다. **앞 넷은 호스트 파서를 두드린다.** A2·A3·A5·A6·A7 이 호스트 파일로 판정되므로
**파서가 틀리면 채점표가 통째로 틀린다** — `docs/log/young/14.seeun_bringup_code_review.md`
의 `6/6 PASS` 가 그 자리였다. 마지막 하나는 파서가 아니라 규약을 본다 (아래).

| 주입 항목 | 파서가 틀리면 | 걸리는 판정 |
| --------- | ------------- | ----------- |
| 행 앞 쓰레기 바이트 | 유효 접두를 못 찾아 행을 버린다 | A2 · A3 |
| 행 잘림 | 잘린 행을 세느냐 마느냐로 행 수가 바뀐다 | **A2** |
| 두 행이 한 줄에 붙음 | 1 적게 세진다 | **A2** |
| 숫자 비트 반전 | **아무도 못 잡는다** | **A5** · 제안-4 |
| 호스트 버퍼 넘침 | 호스트가 오래 안 읽는 사이 중간이 통째로 빠진다 | **A5** · C |
| **명령 손상** | 호스트→보드 명령의 숫자 한 자리가 뒤집힌다 (`delta=300` → `delta=900`) | **J** · C — 체크포인트를 600 지나친다. `E_SUM` 으로 거부돼야 한다 |
| **명령 중복** | 같은 `req` 의 `wear_start`·`reerase` 가 두 번 도착한다 (응답 유실 뒤 재전송) | **A1** · **A5** — 파괴 동작이 두 번 실행되면 X축이 그만큼 민다. `E_DUP` 으로 거부돼야 한다 |

**명령 채널은 TB 가 처음 짜일 때 없던 표면이다** (경계가 Python 함수였다). 위 두 줄은 지민
회신 §7·§10-4 가 요구한 「손상 명령·중복 명령 음성 대조」이고 로그 44 `[D44-14]` 로 들어왔다.
UART 에 패리티가 없다는 사정은 출력 행과 같다.

앞 쓰레기 바이트는 이 리포에서 실제로 겪었고 대비가 세 군데 있다 —
`host/capture/sweep_uart_capture.py:164`(*"rst 쓰레기가 줄바꿈 없이 첫 줄에 붙어도 잡는다"*) ·
`host/run/run_sweep_chip.py:203`·`:266`. **`#WEAR` 경로에는 아직 없다.**

비트 반전은 `cycle=100` 이 `cycle=900` 으로 와도 행 수가 700 그대로라 A5 의 네 경로 중
하나만 조용히 틀린다. UART 에 패리티가 없다 — 제안-4(체크섬)의 근거다.

**주입은 숫자가 숫자로 남게 뒤집는다** (`^0x01` 은 `'1'↔'0'`·`'9'↔'8'`). 접두나 구분자를
때리면 파서가 알아서 버리므로 **체크섬이 없어도 잡히고**, 그러면 제안-4 의 근거를 두드린
것이 아니다. `test_bitflip_is_invisible_without_the_checksum` 이 체크섬을 끈 파서로
A2·A5 가 **둘 다 통과하는 것** 을 보인다 — 그것이 제안-4 가 필요한 이유의 전부다.

**버퍼 넘침이 증상 중복이 아닌 이유**는 그것이 두드리는 대상이 파서가 아니라
**`checkpoint_due` 규약** 이기 때문이다. UART 포트는 하나이고 §5 체크포인트는 분 단위라 그
사이 호스트는 `#WEAR` 를 읽지 못한다. `../interface/pe_engine.md` §2.1 이 *"엔진은 거기까지만
돌고 멈춘다"* 로 그것을 막고 있는데, **엔진이 안 멈추고 계속 뱉으면 버퍼가 넘친다.**
`[D41-6]` 이 지켜지는지를 이 주입이 본다.

### 3.3 범위 밖

**칩 물리** — 소거 시간 곡선 · 실제 부분 소거 · 마모 결함 진행 · 마모 상태의 `verify` 실패
(로그 41 `[U41-5]`). 전부 실칩 전용이다.

**측정 시점 오류(제안-10)의 절반** — 소거 뒤에 `0x00` 과 대조하면 값이 **전량(229,376)** 으로
나와 오히려 요란하다. 못 보는 것은 **구현자가 그 이상함을 덮어 `0` 으로 만든 뒤** 다.
신품 100사이클에서는 `0` 이 **정답** 이라, B 로그만 봐서는 「제대로 재고 0」과 「세는 경로가
죽어서 0」이 같아 보인다 — **관측값이 정답과 같으면 그 관측에는 정보가 없다.**

그래서 정보가 있는 자리를 따로 만든다. **체크포인트에서 호스트가 `blank_check` 를 부르면
`0xFF` 를 `0x00` 과 대조하는 것이라 전량이 나와야 한다** — 정답에서 제일 먼 값이다.
`0` 이면 경로가 죽은 것이고, 채점 항목 `probe` 가 그것을 본다. **루프의 어느 시점에 쟀는지**
는 여전히 경계 밖에서 안 보이므로, 그쪽은 §5.1 제안-10 의 순서 확정으로 막는다.

**호스트 교대 중 재개** — 한 칩을 도중에 다른 노트북으로 넘기지 않는다(로그 41 `[D41-17]`).
교대는 칩 경계에서만 일어나고 그때 tally 도 호스트 로그도 새로 시작하므로, 「이전 호스트
로그가 없는 재개」는 주입하지 않는다.

## 4. 경계 오용 — 가짜 엔진 없이 TB 가 직접 두드린다

| 넣는 값                                           | 기대           | 코드 (§5.2 기본값) | 근거                |
| ------------------------------------------------- | -------------- | ------------------ | ------------------- |
| `n_sectors = 0`                                 | 거부           | `E_NSECT0`       | —                  |
| 구간이 tally 섹터(512 · 1,536)와 겹침            | **거부** | `E_TALLY_OVERLAP`| S-1 §2.3 하드 가드 |
| `base_sector + n_sectors > 2,048`               | 거부           | `E_RANGE`        | —                  |
| `cycle + delta` 가 tally 용량(§8.1 409,600) 초과 | 거부         | `E_CAP`          | §8.1               |
| 구간이 근접·원격 대조군(파일럿 7~13 · 2,041~2,047)과 겹침 | **거부** | `E_CTRL_OVERLAP` | S-1 §2.3 · `[D44-2]` |
| `running` 중 `wear_start` 재호출              | 거부           | `E_RUNNING`      | `[D29-7]`         |
| tally 에 마크가 있는데 `cycle=0` 으로 신규 시작   | 거부           | `E_DIRTY`        | §8.3 · `[D44-10]` |
| `cycle` 이 tally×100 과 `d` 규칙(`0 ≤ d < 100`) 밖 | 거부       | `E_CYCLE`        | §8.3 · `[D44-10]` |
| 명령 체크섬 불일치                                | 거부           | `E_SUM`          | 제안-4 · `[D44-14]` |
| 이미 처리한 `req` 재도착                          | 거부 (재실행 없음) | `E_DUP`      | 지민 회신 §7 · `[D44-14]` |
| 상태에 맞지 않는 명령 (`recovering` 밖의 `reerase` 등) | 거부      | `E_STATE`        | `[D44-3]`         |

**거부의 모양이 경계에 없다** — §5.1 제안-2. 사유 문자열만 오면 「거부했다」는 알아도
**무엇을 거부했는지** 를 채점할 수 없다. `test_every_reject_has_a_case` 가 이 표와 케이스의
1:1 을 집행한다 (T3). 열한 줄이다 (2026-09-21, 여섯에서 늘었다).

`E_DIRTY` 가 인수 시험과 실험을 잇는 자물쇠다(§9). **자동으로 소거하지 않는 것이 핵심이다** —
재개를 신규로 착각해 tally 를 지우면 X축이 통째로 날아가고 되돌릴 수 없다. 다만 종전 문구
「tally 가 비어 있지 않으면 거부」는 **정상 진행의 두 번째 구간까지 잠갔다** (로그 44 §1).
자물쇠는 `cycle=0` 에만 건다. 이어서 돌리는 길은 `wear_resume()` 으로 원자료를 받아 호스트가
채택한 값을 `wear_start(cycle=채택값)` 으로 넣는 것이고, `E_CYCLE` 이 그 값이 tally 와 맞는지
엔진 쪽에서 한 번 더 본다. `E_DUP` 은 「이전 결과 반환」이 아니라 거부다 — 호스트는 응답을
잃으면 `wear_status()` 로 확인한다. 명령 손상·중복은 `E_SUM`·`E_DUP` 거부만으로 끝나지 않고
**플래시 명령이 한 번도 나가지 않았어야** 한다 — 가짜 엔진의 `worn_cycles` 가 그것을 센다.

## 5. 「제안-」 — 뼈대는 못 박고 디테일은 맡긴다

**명령 · 응답** (호스트 → 보드는 `WEAR`, 보드 → 호스트는 `OK`/`REJECT`, 실험 로그는 `#WEAR`)

```
WEAR START base=<n> n_sectors=<n> pattern=0x<2hex> cycle=<n> delta=<n> session=<n> req=<n> sum=<4hex>
WEAR STATUS req=<n> sum=<4hex>
WEAR RESUME req=<n> sum=<4hex>
WEAR BLANK base=<n> n_sectors=<n> req=<n> sum=<4hex>
WEAR TALLY req=<n> sum=<4hex>
WEAR DUMP req=<n> sum=<4hex>
WEAR UID req=<n> sum=<4hex>
WEAR REERASE base=<n> n_sectors=<n> req=<n> sum=<4hex>
WEAR HALT req=<n> sum=<4hex>

OK req=<n> <명령이 파싱한 핵심 인자와 반환값을 key=value 로> sum=<4hex>
REJECT req=<n> code=<E_*> sum=<4hex>
```

- 명령은 체크섬 → `req`(세션 안 단조, 재도착은 `E_DUP`) → 인자 범위 → 상태 순으로 검사하고
  **전부 통과한 뒤에만** 플래시 명령을 낸다. `OK` 는 파싱한 인자를 되돌려 호스트가 의도한
  명령으로 해석됐는지 확인한다
- `STATUS` 의 `OK` 는 `cycle= state= defect_seen= last_reject=` 다. `RESUME` 은
  `tally_a= tally_b= mismatch= next_byte= write_ok=`. `BLANK` 는 경계 4 의 여섯 값.
  `REERASE` 는 `ok= t_erase_us= resid_after=`
- `DUMP` 만 여러 줄이다 — `OK req=` 뒤에 `#WEAR D copy=<0|1> off=<n> hex=<256hex> sum=` 32행

**행**

```
#WEAR H session=<n> chip_id=<16hex> git_rev=<hex> base_sector=<n> n_sectors=<n> pattern=0x<2hex>
        cycle=<n> delta=<n> ts=<n> sum=<4hex>
#WEAR A cycle=<n> sector=<n> t_erase_us=<n> t_program_us=<n> ts=<n> sum=<4hex>
#WEAR B cycle=<n> erase_residual_bits=<n> program_fail_bits=<n>
        p_addr_count=<n> p_addrs=<p:b:k;...> p_worst_page=<n> p_worst_bits=<n>
        e_addr_count=<n> e_addrs=<p:b:k;...> e_worst_page=<n> e_worst_bits=<n>
        die_temp_mc=<n> uid_ok=<0|1> ts=<n> sum=<4hex>
#WEAR R kind=<reerase|wip_timeout|program_fail|erase_fail|uid_mismatch|halt>
        cycle=<n> sector=<n> op=<program|erase|> t_us=<n> ok=<0|1>
        resid_before=<n> resid_after=<n> ts=<n> sum=<4hex>
```

- **B 행의 두 count 는 서로 다른 두 읽기다** — `program_fail_bits`·`p_*` 는 프로그램 직후,
  `erase_residual_bits`·`e_*` 는 소거 직후 (지민 회신 §5·§10-1). 한 행에 두 벌을 싣는 이유는
  A3 「정확히 1행」을 지키면서 두 고장(전하가 안 들어감 · 안 빠짐)의 주소를 따로 보존하기
  위해서다 (`[D44-13]`). **두 count 의 합에 229,376 규칙을 적용하지 않는다**
- **R 행은 사건 1건에 1행이다.** 재소거(`kind=reerase`)는 카운터에도 `area_cumulative_cycles`
  에도 더하지 않는다 — 대신 이 행과 `docs/chip_pe.md` 의 증분 행(비고 「reerase · ±1」)이
  남는다 (`[D44-6]`, 지민 회신 §3.4). 정지 사유(`wip_timeout` 등)는 S-1 §10 이 「기록」만
  요구하고 자리가 없던 것이다. 쓰지 않는 필드는 빈 값이다 (`die_temp_mc` 와 같다)
- 정상 사이클은 A 행 7개만 낸다. 검사 사이클은 A 7행 뒤에 B 1행. `H` 는 `wear_start` 마다
  1행 — 세션이 여럿이면 H 도 여럿이고 호스트가 `session`·`cycle` 로 잇는다

### 5.3 경계 밖이라 이쪽에서 처리하는 것

스펙이 지적했거나 대조하다 나온 것 중 **경계에 닿지 않는 것** 은 회신을 기다리지 않는다 —
WIP 폴링이 시간이 아니라 반복 상한(`flash_prep.c:90`) · `COUNTS_PER_SECOND` 괄호 함정
(`:115`) · `flash_prep` 이 섹터 0–127 을 통째로 지우는 것과 **§9 의 TB 영역 하드 가드** ·
`docs/chip_pe.md` 머리말의 원격 대조군 표기(121–127 → 2,041–2,047) · `near_pe_actual` 의
초기값이 0 이 아닌 것 · 포트 기본값(`/dev/ttyUSB1` ↔ COM) · A 로그 2.1M행의 파일 분할.

**far=2041 스윕이 오늘 불가능한 것**(RTL 에 11비트 `BASE_SECTOR` 구현 0건, 수정안 #1 미승인)도
여기다 — 체크포인트는 호스트 도구라(`../interface/pe_engine.md` §3) 경계가 아니고, 막히는
것은 C 판정의 실칩 절반이다.

mock 은 함수로 두었다. 제안-1 이 닫혔으므로(§5.2) **UART 어댑터**가 같은 함수 서명을 실엔진의
명령 문자열로 옮긴다 — 채점표는 그대로이고 뒤에 붙는 것만 바뀐다.

**가짜 엔진의 시계는 상수다.** Hypothesis 로 차단 시점을 수백 번 뽑으려면 405ms 를 실제로
기다릴 수 없다. 그래서 `t_erase_us` 가 가짜이고, §2 표가 A6 를 mock 에서 `X` 로 둔 것과
같은 말이다.

## 7. 이 TB 자체의 인수 기준

| #  | 조건                                                                                                      |
| -- | --------------------------------------------------------------------------------------------------------- |
| T1 | §2 표의`mock` 열이 전부 실제 assertion 으로 존재하고 통과한다 — `test_score_table_covers_spec` 이 집행 |
| T2 | §3 의 주입 항목이 전부 케이스로 존재한다 — `test_every_fault_has_a_case` 가 집행 |
| T3 | §4 의 열한 줄이 전부 케이스로 존재한다 — `test_every_reject_has_a_case` 가 집행 |
| T4 | 한 명령으로 재실행된다                                                                                    |
| T5 | **구현자가 박지민 스펙을 열람하기 전에 커밋한다** — 로그 41 `[D41-1]`. 그 시점은 **`570a0c29`**(태그 `tb-pre-spec`)이고 GitHub 원격에 올라가 있다. 이후 어긋남은 **한영웅이 판단한다** (`[D41-24]`) |
| **T6** | **채점표가 실패하는 것을 확인한다** — 엔진에 버그를 하나씩 심어 지정한 항목이 반드시 깨지는지 본다. 안 깨지면 그 항목은 아무것도 재고 있지 않다. **양방향으로 집행한다** — `test_every_bug_has_a_case`(버그마다 케이스) · `test_every_score_item_has_a_bug`(채점 항목마다 그것을 깨뜨리는 버그) |

**T5 는 「스펙 도착보다 앞선다」였다.** 스펙은 이미 한영웅에게 와 있었고 지켜진 것은
**구현자의 열람 전** 이므로 문구를 사실에 맞췄다. 증거는 태그가 아니라 **커밋 해시와
push** 다 — 태그는 `-f` 로 옮길 수 있지만 해시는 못 옮기고, 원격에 올라간 것은 혼자
주장하는 것이 아니다.

**집행 장치가 있는 것과 없는 것을 가른다.** T1·T2·T3·T6 은 테스트가 표와 케이스의 1:1 을
스스로 확인하므로 표에서 한 줄이 빠지거나 케이스가 조용히 사라지면 빨간불이 난다. T4·T5 는
사람이 보는 것이다.

**T1 통과는 엔진이 §13 을 통과했다는 뜻이 아니다.** 가짜 엔진에 대고 잰 것이고, A6·A7 과
B 의 물리는 실칩에서만 닫힌다.

## 8. 작성 순서

로그 41 `[D41-14]`. **작성자와 판정자가 같은 사람이어도, 순서가 둘을 가른다.**

```
① 박지민이 P/E 엔진 설계 스펙을 한영웅에게 보낸다
② ─── 블랙박스 TB 를 커밋·push 한다 (570a0c29 · tb-pre-spec) ───
③ 한영웅과 그의 AI 가 첨삭하고 §5 「제안-」 을 첨부해 박지민에게 돌려보낸다
④ 박지민이 판단해 한영웅에게 돌려보낸다
⑤ 한영웅의 AI 가 엔진을 구현한다
```

**②의 선 앞에서 구현자는 스펙을 읽지 않는다.** TB 는 §1 의 원천 둘에만 대고 짜인다 —
로그 41 `[D41-1]`·`[D41-10]`. **선을 넘은 뒤에는 읽어도 된다** — 고친 자리가
`git diff tb-pre-spec -- host/tests/` 에 전부 드러나므로 방어가 태그로 넘어간다.
최종 판단은 한영웅이 한다 (`[D41-24]`).

## 9. 인수 시험을 어디서 돌리나

로그 41 `[D41-23]`. **파일럿 칩의 TB 전용 마모 섹터** 에서 돌린다 — 전용 칩을 따로 쓰지
않는다. 같은 칩·보드·배선·소켓으로 두드려야 *"그 칩에선 통과했는데"* 가 남지 않는다.

```
섹터     0 ~     6   마모 그룹        (실험)
섹터     7 ~    13   근접 대조군      (실험)
섹터   512           tally #1         (실험과 공용 — §8.1 초기화가 지운다)
섹터 1,000 ~ 1,006   **TB 전용 마모 영역**
섹터 1,536           tally #2         (실험과 공용)
섹터 2,041 ~ 2,047   원격 대조군      (실험)
```

- **tally 는 공용이다.** TB 가 남긴 `0x00` 은 §8.1 의 실험 개시 소거가 지운다 —
  원복이 별도 절차가 아니라 개시 절차 그 자체다. 안 지워지면 §4 의 마지막 줄이 잡는다
- **마모는 원복이 안 된다.** tally 는 소거하면 `0xFF` 로 돌아가지만 닳은 셀은 안 돌아온다.
  그래서 마모 영역만 따로 둔다
- **원격 대조군 옆은 안 된다.** S-1 §15 ③ 이 「인접 섹터 간섭이 존재하는가」를 파일럿의
  질문으로 두고 있어, 그 옆에서 100회를 돌리면 파일럿이 답할 질문을 파일럿이 오염시킨다.
  1,000 근처가 마모 그룹과 원격 대조군 양쪽에서 1,000섹터씩 떨어진 자리다
- **순서** — S-2 전수 신품 측정 → TB 인수 시험 → 파일럿 착수. S-2 가 *"마모를 한 번이라도
  하면 확보 불가"* 로 막아 놓은 것이 신품 소거 시간·신품 결함 비트다
- `flash_prep`·스캔의 **하드 가드에 TB 영역을 넣는다** (S-1 §2.3 이 tally 를 넣은 것과 같다)
- **B 시험 반복은 TB 영역만 닳린다.** 50회를 돌려도 5,000사이클 = 목표의 1.7% 이고
  실험 영역은 0 그대로다
