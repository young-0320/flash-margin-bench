## 3. 가짜 엔진이 주입해야 하는 고장

로그 41 `[D41-11]`. **축이 둘이다** — 진행이 멈추는 것과, 진행은 되는데 받은 바이트가
틀린 것. 고르는 기준은 빈도가 아니라 **「이 고장이 채점표를 틀리게 만드나」** 다.

### 3.1 중단 — 진행이 멈춘다

| 주입 항목 | 무엇을 하나 | 걸리는 판정 |
| --------- | ----------- | ----------- |
| 전원 차단 | 소거 중 / 프로그램 중 / tally 쓰는 중 / 사이클 사이에 죽는다 | B · A4 |
| 호스트 죽음 | 엔진은 계속 도는데 호스트만 멈춘다 — tally 만 는다 | B · §8.3 3 |
| 보드 행 | 응답을 주지 않는다 | 호스트 워치독 — **`running` 에서만**, 값은 M 트랙 실측 (로그 41 `[D41-19]`) |
| 연결 끊김·복귀 | 행 뭉텅이가 빠진 뒤 다시 붙는다 | A2 · **A5** · 재시도 **3회 상한** (`[D41-18]`) |
| SPI 무응답 | `blank_check` 가 전량 `0xFF`/`0x00` 으로 온다 | A3 · B |

**재시도는 전송·연결에만 3회이고 플래시 동작은 0회다**(`[D41-18]`) — P/E 는 비가역이라
플래시 재시도가 곧 마모이고, S-1 §10 의 「자동 재시도 금지」가 그대로 선다.

실물 근거: 전원 차단은 S-1 §13 B 가 시험 항목으로 명시 · 행 유실은
`docs/log/young/8.vivado_integration_and_sweep_sw.md` `[D8-6]` · SPI 무응답은
`docs/log/young/13.first_loopback_bathtub_and_linedead_fix.md`. 호스트 죽음과 보드 행은
겪은 기록이 없고 무인 6일 운용 판단에서 왔다 (2026-09-18, 한영웅).

### 3.2 전송 손상 — 진행은 되는데 받은 바이트가 틀리다

다섯이다. **앞 넷은 호스트 파서를 두드린다.** A2·A3·A5·A6·A7 이 호스트 파일로 판정되므로
**파서가 틀리면 채점표가 통째로 틀린다** — `docs/log/young/14.seeun_bringup_code_review.md`
의 `6/6 PASS` 가 그 자리였다. 마지막 하나는 파서가 아니라 규약을 본다 (아래).

| 주입 항목 | 파서가 틀리면 | 걸리는 판정 |
| --------- | ------------- | ----------- |
| 행 앞 쓰레기 바이트 | 유효 접두를 못 찾아 행을 버린다 | A2 · A3 |
| 행 잘림 | 잘린 행을 세느냐 마느냐로 행 수가 바뀐다 | **A2** |
| 두 행이 한 줄에 붙음 | 1 적게 세진다 | **A2** |
| 숫자 비트 반전 | **아무도 못 잡는다** | **A5** · 제안-4 |
| 호스트 버퍼 넘침 | 호스트가 오래 안 읽는 사이 중간이 통째로 빠진다 | **A5** · C |

앞 쓰레기 바이트는 이 리포에서 실제로 겪었고 대비가 세 군데 있다 —
`host/capture/sweep_uart_capture.py:164`(*"rst 쓰레기가 줄바꿈 없이 첫 줄에 붙어도 잡는다"*) ·
`host/run/run_sweep_chip.py:203`·`:266`. **`#WEAR` 경로에는 아직 없다.**

비트 반전은 `cycle=100` 이 `cycle=900` 으로 와도 행 수가 700 그대로라 A5 의 네 경로 중
하나만 조용히 틀린다. UART 에 패리티가 없다 — 제안-4(체크섬)의 근거다.

**버퍼 넘침이 증상 중복이 아닌 이유**는 그것이 두드리는 대상이 파서가 아니라
**`checkpoint_due` 규약** 이기 때문이다. UART 포트는 하나이고 §5 체크포인트는 분 단위라 그
사이 호스트는 `#WEAR` 를 읽지 못한다. `../interface/pe_engine.md` §2.1 이 *"엔진은 거기까지만
돌고 멈춘다"* 로 그것을 막고 있는데, **엔진이 안 멈추고 계속 뱉으면 버퍼가 넘친다.**
`[D41-6]` 이 지켜지는지를 이 주입이 본다.

### 3.3 범위 밖

**칩 물리** — 소거 시간 곡선 · 실제 부분 소거 · 마모 결함 진행 · 마모 상태의 `verify` 실패
(로그 41 `[U41-5]`). 전부 실칩 전용이다.

**호스트 교대 중 재개** — 한 칩을 도중에 다른 노트북으로 넘기지 않는다(로그 41 `[D41-17]`).
교대는 칩 경계에서만 일어나고 그때 tally 도 호스트 로그도 새로 시작하므로, 「이전 호스트
로그가 없는 재개」는 주입하지 않는다.

## 4. 경계 오용 — 가짜 엔진 없이 TB 가 직접 두드린다

| 넣는 값                                           | 기대           | 근거                |
| ------------------------------------------------- | -------------- | ------------------- |
| `n_sectors = 0`                                 | 거부           | —                  |
| 구간이 tally 섹터(512 · 1,536)와 겹침            | **거부** | S-1 §2.3 하드 가드 |
| `base_sector + n_sectors > 2,048`               | 거부           | —                  |
| `cycles` 가 남은 tally 용량(§8.1 409,600) 초과 | 거부           | §8.1               |
| `running` 중 `wear_start` 재호출              | 거부           | `[D29-7]`         |
| 기존 로그가 있는데 신규 시작                      | 거부           | §8.3               |

**거부의 모양이 경계에 없다** — §5 제안-2.

마지막 줄이 인수 시험과 실험을 잇는 자물쇠다(§9). **자동으로 소거하지 않는 것이 핵심이다** —
재개를 신규로 착각해 tally 를 지우면 X축이 통째로 날아가고 되돌릴 수 없다. 이어서 돌리는
길은 `wear_resume()` 하나다.

## 5. 「제안-」 — 경계에 없어서 아직 채점 못 하는 것

박지민에게 보낸다. **이것이 닫히기 전에는 TB 를 실행 가능한 형태로 못 짠다.**

| #      | 제안                                                                                          | 없으면                                      |
| ------ | --------------------------------------------------------------------------------------------- | ------------------------------------------- |
| 제안-1 | **호출면·응답 문법** — 경계 7개의 명령 문자열, 응답 형식, 유효 접두, 타임아웃         | TB 가 한 줄도 못 짜진다                     |
| 제안-2 | **거부 규약** — §4 표의 반환 형태 (오류 코드와 사유)                                  | §4 를 채점할 수 없다                       |
| 제안-3 | **S-1 §9 로그 행 문법 동결** — 구분자 · 헤더 · 단위 · `defect_addrs` 64개 인코딩 | A2·A3·A5·A6·A7 을 파싱할 수 없다        |
| 제안-4 | **로그 행의 체크섬 또는 단조 증가 검사**                                                | **숫자 비트 반전을 아무도 못 잡는다** |
| 제안-5 | **`wear_resume()` 이 채택하지 않는다** — tally 값과 증거만 돌려주고 「큰 쪽 채택」은 호스트가 한다 (로그 41 `[D41-20]`) | 엔진이 세 경우를 한 규칙으로 뭉갠다 |
| 제안-6 | **A 로그를 매 사이클 실시간으로 내보낸다** — §6 루프에 그 단계가 없다 | **A2 의 700행이 호스트에 닿는 경로가 없다** |

**제안-5 는 경계 3 의 서명 모순에서 나왔다.** `wear_resume() → (restored_cycle, source,
mismatch)` 인데 `source` 가 *"tally 에서 왔는지 호스트 로그에서 왔는지"* 다 — **엔진은 호스트
로그를 모른다.** 파라미터가 없다. 엔진은 재료만 주고 판단은 호스트가 하는 쪽이 맞다
(§8.3 1 의 「중단 판단은 호스트 몫」과 같은 원리).

**제안-6 은 `d` 규칙의 전제다.** 실시간이면 전원 차단 유실이 7행, 일괄이면 700행이다.
일괄이면 A 로그와 B 로그가 같은 버스트로 나가 **A5 의 네 경로 중 둘이 함께 유실되고**, 엔진이
42KB 버퍼를 들어야 해 `[D29-1]` 층위에 걸린다. 비용은 사이클당 4.6ms(1.1%)다.

제안-4 는 §3 의 주입 목록을 만들다 나왔다 — `cycle=100` 이 `cycle=900` 으로 와도 행 수는
700 그대로라 A5 의 네 경로 중 하나만 조용히 틀린다. 6일 무인 구동에 UART 는 패리티가 없다.
경위는 로그 41 §6.

## 6. TB 구조와 위치

`host/tests/` — **pytest + Hypothesis**, 의존성은 루트 `pyproject.toml` dev 그룹.
실행은 `uv run pytest host/tests/ -q`. 구조와 규약은 `host/tests/README.md`.

| 쓰는 것 | 무엇에 |
| ------- | ------ |
| pytest | 케이스 골격 · `parametrize` · 리포트 |
| **Hypothesis** | **§13 B 의 「임의 시점 전원 차단」** — 시점을 나열하지 않고 성질을 적는다 |
| pytest-timeout | 「보드 행」 케이스가 TB 를 멈추지 않게 — **실엔진을 붙일 때 도입**. mock 은 즉시 `raise` 라 필요 없다 |

**경계는 Python 함수다.** 제안-1 이 닫히기 전에 UART 문자열을 고르면 그것은 발명이고,
`../interface/pe_engine.md` §4 가 「층위와 무관하다」이므로 밖에서 보이는 모양만 맞춘다.
UART 어댑터는 제안-1 이 닫힌 뒤에 붙인다.

**가짜 엔진의 시계는 상수다.** Hypothesis 로 차단 시점을 수백 번 뽑으려면 405ms 를 실제로
기다릴 수 없다. 그래서 `t_erase_us` 가 가짜이고, §2 표가 A6 를 mock 에서 `X` 로 둔 것과
같은 말이다.

**T5 는 「스펙 도착보다 앞선다」였다.** 스펙은 이미 한영웅에게 와 있었고 지켜진 것은
**구현자의 열람 전** 이므로 문구를 사실에 맞췄다. 증거는 태그가 아니라 **커밋 해시와
push** 다 — 태그는 `-f` 로 옮길 수 있지만 해시는 못 옮기고, 원격에 올라간 것은 혼자
주장하는 것이 아니다.

**T1 통과는 엔진이 §13 을 통과했다는 뜻이 아니다.** 가짜 엔진에 대고 잰 것이고, A6·A7 과
B 의 물리는 실칩에서만 닫힌다.

## 9. 인수 시험을 어디서 돌리나

로그 41 `[D41-23]`. **파일럿 칩의 TB 전용 마모 섹터** 에서 돌린다 — 전용 칩을 따로 쓰지
않는다. 같은 칩·보드·배선·소켓으로 두드려야 *"그 칩에선 통과했는데"* 가 남지 않는다.

```
섹터     0 ~     6   마모 그룹        (실험)
섹터     7 ~    13   근접 대조군      (실험)
섹터   512           tally #1         (실험과 공용 — §8.1 초기화가 지운다)
섹터 1,000 ~ 1,006   **TB 전용 마모 영역**
섹터 1,536           tally #2         (실험과 공용)
섹터 2,041 ~ 2,047   원격 대조군      (실험)
```

- **tally 는 공용이다.** TB 가 남긴 `0x00` 은 §8.1 의 실험 개시 소거가 지운다 —
  원복이 별도 절차가 아니라 개시 절차 그 자체다. 안 지워지면 §4 의 마지막 줄이 잡는다
- **마모는 원복이 안 된다.** tally 는 소거하면 `0xFF` 로 돌아가지만 닳은 셀은 안 돌아온다.
  그래서 마모 영역만 따로 둔다
- **원격 대조군 옆은 안 된다.** S-1 §15 ③ 이 「인접 섹터 간섭이 존재하는가」를 파일럿의
  질문으로 두고 있어, 그 옆에서 100회를 돌리면 파일럿이 답할 질문을 파일럿이 오염시킨다.
  1,000 근처가 마모 그룹과 원격 대조군 양쪽에서 1,000섹터씩 떨어진 자리다
- **순서** — S-2 전수 신품 측정 → TB 인수 시험 → 파일럿 착수. S-2 가 *"마모를 한 번이라도
  하면 확보 불가"* 로 막아 놓은 것이 신품 소거 시간·신품 결함 비트다
