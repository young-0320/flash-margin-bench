## 3. 라벨링과 세션 규칙

### 3.1 라벨

- 물리 라벨 `chip01` \~ `chip10`. **칩 본체가 아니라 개별 보관 용기에 붙인다** (칩 표면
  라벨은 소켓 삽입 시 벗겨지거나 열에 상한다)
- 라벨은 **별칭**이고 정본 식별자는 UID다 (`chip_registry.md`). 라벨과 데이터가 어긋나면
  **UID가 진실**이다
- chip01은 이미 확정돼 있다 — 7월 게재 데이터의 원본 개체

### 3.2 세션 규칙 (필수)

> **칩 1개 = 1세션. 세션 안에서 칩을 바꾸지 않는다.**

`chip_registry.md`가 밝히듯 UID와 스윕 CSV의 연결은 **"같은 세션"이라는 절차적 근거에만**
의존한다 — 스윕 중에는 PS가 칩과 통신할 수 없어(스윕은 PL 경로, prep은 PS SPI 경로)
하드웨어가 보증해 주지 않는다.

**전수 측정은 정확히 칩을 갈아 끼우는 작업이므로 이 규칙이 깨지기 가장 쉬운 자리다.**

| 금지 | 왜 |
| ---- | -- |
| 10개에 `flash_prep`을 먼저 다 돌리고, 그 뒤 10개를 스윕 | UID가 세션에 남지 않아 **전부 뒤섞인다.** 되돌릴 수 없다 |
| 세션 중 캡처 스크립트 재시작 | 보관된 UID가 날아간다 → prep부터 다시 |

칩 하나의 세션은 §4의 1\~7을 끊지 않고 통과한다.

### 3.3 측정 구성 — **칩마다 배선이 따로 있다**

**칩 10개는 배선을 공유하지 않는다.** 칩 하나마다 점퍼 6가닥(VCC·GND·CS·DI·DO·CLK)이 딸려
있고, 그 끝의 핀헤더를 보드 JB 에 꽂는다. 칩을 바꾼다는 것은 **칩만 바꾸는 것이 아니라 칩과
배선을 한 벌로 바꿔 꽂는 것**이다. 아래에서 **칩별 배선**이라 부른다.

이 구성이 측정값의 해석을 바꾸므로 절차보다 먼저 적는다.

| | 이 구성의 결과 |
| --- | --- |
| **유리** | 한 칩이 t=0 부터 종점까지 **같은 배선**을 쓴다. 배선이 만드는 오프셋이 그 칩 안에서 상수이므로 **자기 t=0 대비 변화에서 상쇄**된다. 교정 곡선을 상대 변화로 세우기로 한 S-1 의 방침과 맞는다 |
| **유리** | 칩 본체를 손으로 다루지 않는다. ESD·핀 손상 위험이 줄고, 소켓 하나가 반복 삽입으로 마모되는 **공통 고장점이 없다** |
| **주의** | 칩 간 비교에서 얻는 산포는 칩만의 산포가 아니라 **칩 + 그 배선의 산포**다. §6 의 이상치 판정과 §9 의 "개체 산포 σ" 는 이 단서를 달고 읽어야 한다 |
| **주의** | 공유되는 것은 **보드 JB 헤더 · FPGA · 전원**뿐이다. §8 의 앵커가 재는 것도 원칙적으로 그 공유부인데, 앵커 칩의 배선과 핀헤더 접점은 공유부가 아니면서 앵커 값에 들어온다 |

**배선을 칩에서 뗄 수 있다**(납땜이 아니라 핀헤더). 따라서 **칩과 배선 중 어느 쪽이 값을 만드는지
교차로 가를 수 있다** — 칩 A 를 칩 B 의 배선에 꽂아 재면 된다. 절차는 §8 말미.

## 4. 칩당 절차 (chip02 \~ chip10)

```
1. 전원 차단 → 칩별 배선 교체 (핀헤더를 JB 에서 뽑고 다음 칩 것을 꽂는다) → ESD 확인 → 전원 인가
2. [터미널 1] 캡처 시작 (UID를 받아야 하므로 prep보다 먼저)
       .venv/bin/python host/capture/sweep_uart_capture.py --target chipNN
3. [터미널 2] prep 비트스트림 + ELF
       xsct ps/scripts/program_g2.tcl build/vitis_prep/flash_prep/build/flash_prep.elf
   확인:  #PREP JEDEC EF 40 17
          #PREP UID <16hex>
          #PREP BLANK pre  <n> bits            (§5)
          #PREP BLANK post <n> bits            (§5)
          #PREP ERASE <sector> <us> ...        (B-1)
          #PREP PASS
4. [터미널 2] 스윕 비트스트림 + ELF
       xsct ps/scripts/program_g3.tcl 25
5. 완주 확인:  #G3 SWEEP END valid=1 reason=complete     (~5분)
6. 분석:
       .venv/bin/python host/analysis/bathtub_analysis.py build/data/sweep_chipNN_<stamp>.csv
7. 기입: UID → docs/chip_registry.md, width·소거시간·blank → §7 집계표
```

- **`flash_jedec` 별도 실행은 불요하다.** `flash_prep`이 시작 시 `9Fh`를 읽어
  `#PREP JEDEC`을 출력하고 불일치면 스스로 중단한다(`ps/src/flash_prep.c:106`).
  칩당 앱 교체를 한 번 줄인다 — 10칩이면 무시할 수 없다
- 측정 조건은 **25MHz 고정 1회**. 클럭 사다리(45·75MHz)는 본 측정 범위 밖이다 —
  개체 산포는 한 조건에서 재야 조건 간 차이와 섞이지 않는다
- 3번에서 `#PREP FAIL`이 나오면 **스윕하지 않는다.** §6의 무효 처리로 간다

## 5. Blank check — 출고 시점 결함 (신품에만 가능)

`flash_prep`에 판독 2회를 추가한다 (B 트랙, 장세은).

| 시점 | 무엇을 세는가 | 이름 |
| ---- | ------------- | ---- |
| **소거 전** (칩을 꽂은 그대로) | `0xFF`가 아닌 비트 수 + 주소 | `blank_pre` |
| **소거 직후** (program 전) | `0xFF`가 아닌 비트 수 + 주소 | `blank_post` |

- `blank_post`가 S-1 §7의 `erase_residual_bits`와 같은 정의다. **같은 코드를 쓴다** —
  신품 기준선과 마모 후 값이 같은 자로 재져야 비교가 성립한다
- `blank_pre`를 따로 두는 이유: 소거는 비트를 1로만 되돌리므로 **소거 후 판독은 "출고
  상태가 원래 blank였는가"에 답하지 못한다.** 공장 테스트 패턴이 남아 있었는지,
  0으로 굳은 비트가 있는지는 소거 전에만 보인다
- 범위: **칩 전역**(페이지 0\~32,767). 읽기 전용이라 소거·기록보다 훨씬 싸다.
  → verify: 실측이 **1분을 넘으면** 측정 영역(섹터 0\~27 + 2,041\~2,047)으로 축소하고
    축소 사실을 로그에 남긴다
- 결함 비트 기록 규칙은 S-1 §7을 따른다 — 전량 기록, 64개 초과 시 처음 64개 + 총 개수
- **결함 비트가 발견돼도 그 칩을 빼지 않는다.** 개체 특성으로 기록하고 §7 집계에 남긴다.
  신품 결함률 자체가 보고할 값이다

## 6. 이상치 판정 — 사전 등록 규칙

**사후 해석 금지.** 데이터를 본 뒤에 기준을 만들면 원하는 결론이 나온다. 아래가 전부이며,
여기 없는 사유로 값을 빼려면 **사유를 로그에 적고 뺀 값도 함께 보고**한다.

### 6.1 무효 런 — 개체 특성이 아니다. 자동 재측정

계약 §6의 무효 정의를 그대로 쓴다: ① `TIMEOUT` ② `CFG_ERR` ③ 스윕 중 `MMCM_LOCKED`=0
④ R8 무결성 불일치 ⑤ 미완주·스텝 결측 ⑥ 종료 시 `CMD_ERR`=1. 여기에 셋을 더한다.

| 추가 | 서명 | 처리 |
| ---- | ---- | ---- |
| JEDEC 불일치 | `#PREP FAIL jedec mismatch` | 배선·전원·소켓 접촉. 재장착 후 재시도 |
| prep 검증 실패 | `#PREP FAIL <n> pages` | 재시도 1회. 반복되면 그 칩은 **예비로 교체**하고 사유 기록 |
| 전 위상 BER≈0.5 | 욕조 곡선이 아예 안 나옴 | 사전 쓰기 소실 또는 주소·시드 불일치(런북 3 표 E). `flash_prep` 후 재시도 |

무효 런은 `_invalid` 접미로 남기고 **집계에서 제외하되 파일은 지우지 않는다.**

### 6.2 유효 런의 이상치 — 재측정 1회, 판정은 재현성으로

n=10에서는 평균·표준편차가 이상치 하나에 끌려가므로 **중앙값과 MAD**를 쓴다.

```
로버스트 σ  =  1.4826 × MAD(width)
이상치 후보 =  |width − median(width)|  >  3 × 로버스트 σ
```

후보가 나오면 **그 칩만 재장착 후 1회 재측정**한다.

| 재측정 결과 | 해석 | 처리 |
| ----------- | ---- | ---- |
| 첫 값을 재현 (차이 < **3 × σ_repeat**) | **진짜 개체 특성** | 두 값 다 채택. 집계에 포함. 빼지 않는다 |
| 재현 안 됨 | 첫 측정의 접촉·정렬 문제 | 재측정값 채택, 첫 값은 `_invalid` + 사유 기록 |

#### 재현 기준 — 3ps 에서 `3 × σ_repeat` 로 (2026-09-20 개정)

> **종전 문구**: *"첫 값을 재현 (차이 < 3ps)"* · *"3ps 기준은 D 트랙의 드리프트 판정과 같은
> 값이다(0.61ps의 ≈3σ + 여유). 같은 자로 잰다"*

**전제가 실측으로 반증됐다.** 3ps 는 chip01 을 한 세션에서 **연속 5회**(빼지 않고) 재서 얻은
σ 0.61ps 에 3σ + 여유를 얹은 값이다. 그런데 §6.2 가 판정하려는 것은 **빼고 다시 꽂아 재기**이고,
그 절차의 σ 는 2026-09-20 실측 **13.86ps**(chip10 n=3)다 — 23 배다. 3ps 를 그대로 두면
정상 개체도 재현에 실패하게 되어 규칙이 항상 "첫 값을 버려라"로만 답한다.

**현행 값: `3 × 13.86 ≈ 41.6 ps`.**

- **이 수는 상수가 아니다.** σ_repeat 은 그 조립체가 **몇 번 꽂혔느냐에 따라 커진다** — 같은 날
  chip02 는 같은 절차로 137.33ps 였다(§3.3 의 칩별 배선, 앵커라 삽입 횟수가 가장 많다).
  기준을 박아 두지 말고 **그 세션의 σ_repeat 로 다시 계산한다**
- σ_repeat 은 **정상으로 판단되는 조립체**의 재장착 반복에서 낸다. 흔들리는 개체의 산포를
  분모로 쓰면 그 개체의 고장이 전체의 합격선을 넓힌다
- 계수 통계의 바닥은 0.25ps 다(229,376 bits/step · 벽 기울기 0.78 decade/step 에서 계산).
  0.61ps 가 거기 붙어 있다는 것은 **측정 자체는 이론 한계까지 정밀하다**는 뜻이고, 남는 산포는
  전부 꽂는 행위에서 온다
- **재측정 상한 2개 칩.** 3개 이상이 후보로 뜨면 개체가 아니라 **절차나 장비를 의심**한다
  → 전수 측정을 중단하고 D를 다시 돌린다. 10개 중 3개가 이상치인 분포는 이상치 분포가
  아니라 그냥 넓은 분포다

### 6.3 개체 산포가 측정 노이즈에 묻히면 — 1회 측정으로 끝내지 않는다

칩당 1회 스윕의 근거는 **측정 노이즈(0.61ps, n=5, 재장착 없음)가 개체 산포보다 훨씬
작을 것**이라는 예상이다. 그러나 **개체 산포는 아직 모르는 값**이고, 그것을 재는 것이
이 측정이다. 예상이 틀릴 경우의 규칙을 미리 등록한다.

```
집계 후:  σ_between (10칩 width 표준편차)  vs  σ_repeat (§8 재장착 편차)

σ_between  >  3 × σ_repeat   →  1회 측정으로 충분. 종료
σ_between  ≤  3 × σ_repeat   →  분해 불가. 10칩 전부 3회 반복으로 재측정
```

- 분모를 §8의 **재장착 편차**로 쓰는 이유: 전수 측정은 칩을 갈아 끼우며 재므로 그것이
  실제 노이즈 플로어다. 연속 반복의 0.61ps는 재장착 성분이 빠져 있어 **분모로 쓰면
  노이즈를 과소평가**한다
- 재측정 비용은 10칩 × 2회 추가 ≈ 100분. 미리 등록해 두는 이유는, 결과를 본 뒤에
  정하면 "산포가 작게 나왔으니 그냥 쓰자"는 유혹이 생기기 때문이다

## 7. 소거 시간 기준선

- `flash_prep`이 섹터마다 WIP-busy 지속시간을 기록한다 (B-1)
- 집계: 칩별 **중앙값**과 **최댓값**을 §9 표에 남긴다. 섹터 간 산포도 함께 본다
- → verify: 값이 데이터시트 범위 안에 든다 (W25Q64JV 4KB sector erase **typ 45ms**)
- 이 값이 S-1 §12 시간 예산의 입력이다. 마모 루프 시간이 실측 기반으로 재산정된다

**마모를 시작하면 신품 소거 시간은 영원히 확보 불가능하다.** G-b가 게이팅인 이유다.

## 8. 재장착 MSA — 측정 순서에 끼워 넣는다

전수 측정은 어차피 칩을 10번 갈아 끼운다. **별도 실험 없이** 재장착 편차가 나온다.

```
별도 일자 (2026-09-15)    chip02  ①  ×3    ← 일자 간 성분. 아래와 섞지 않는다
─────────────────────────────────────────
전수 측정 세션 (하루)
   처음                   chip02  ②
   ...                    chip03 ~ chip06
   중간                   chip02  ③
   ...                    chip07 ~ chip10
   마지막                 chip02  ④
```

- **②③④ 3회로 재장착 σ를 낸다.** 워크플로 5 S-2 3번은 "처음과 마지막 각 1회"였으나
  **2회는 표준편차가 아니라 차이 하나**다. 자유도 1로는 §6.3의 분모를 쓸 수 없다.
  중간 1회를 더해 자유도 2를 만든다 — 비용은 스윕 1회(**59초**, S-1 §12 개정)
- **①을 섞지 않는다.** D는 다른 날 측정이라 일자 간 드리프트가 들어 있다. ②③④의
  세션 내 재장착 성분과 합치면 노이즈 플로어가 부풀고, §6.3 판정이 느슨해진다.
  ①은 `④ − ①`로 **일자 간 성분**을 따로 보는 데 쓴다 (①은 2026-09-15 3회,
  평균 39,630.2ps · 표준편차 4.65ps — 다만 ①은 재장착이 없는 세션 간 성분이다)
- 중간 지점을 chip06 뒤로 둔 이유: 세션 전반·후반을 가른다. 소켓 마모나 발열 드리프트가
  있으면 ②③④가 단조 이동으로 드러난다
- **앵커는 prep 없이 잰다** — `run_sweep_chip.py --mode sweep --mhz 25 --chip 2`.
  ②③④는 **재장착 성분만** 보는 절차인데 prep(소거·정답지 재작성)을 끼우면 재장착·쓰기·
  마모가 한 값에 섞여 σ_repeat 가 무엇의 산포인지 알 수 없게 된다. P/E 도 매번 오른다.
  2026-09-16 에 재장착 + prep 이 함께 든 측정이 기준 대비 **−67ps** 로 나왔다 — 원인이
  무엇이든 그 값은 앵커로 쓸 수 없다 (로그 36 §2-10)
- **재장착 노이즈가 개체차보다 클 수 있다.** 같은 날 관측된 칩 개체차는 58ps(chip02·03·04)
  인데 재장착 1회의 변화가 70ps 였다. n=1 이라 σ 가 아니지만, **②③④가 바로 이 값을 재는
  절차**이므로 전수 측정에서 빠뜨리면 §6.3 의 분모가 없는 채로 판정하게 된다

### 앵커가 재는 것의 한계 (2026-09-20 추가)

**칩별 배선 구성(§3.3)에서 앵커는 공유부만 재지 못한다.** 앵커 칩을 다시 꽂는다는 것은 그 칩의
배선과 핀헤더 접점을 다시 꽂는다는 뜻이고, 그 접점은 다른 칩과 공유되지 않는다. 그래서
앵커 값에는 **공유부(JB 헤더·FPGA·전원)의 변화**와 **앵커 칩 배선 자체의 변화**가 함께 들어온다.

따라서 앵커가 흔들렸을 때 결론은 둘로 갈린다 — *"측정계가 틀어졌다"* 와 *"앵커 칩의 배선이
상했다"*. 앵커 하나로는 이 둘을 가르지 못하며, **가르는 절차가 아래 교차 시험**이다.

**앵커 칩은 가장 자주 꽂았다 빼는 개체**이므로 그 배선의 핀헤더가 가장 먼저 상한다는 점도
함께 둔다 — 앵커 역할 자체가 앵커를 망가뜨리는 구조다.

### 교차 시험 — 값을 만드는 것이 칩인가 배선인가

배선이 핀헤더로 분리되므로 서로 바꿔 꽂을 수 있다. 두 칩 A·B 를 고르고 네 조합을 잰다.

| # | 칩 | 배선 | 목적 |
| - | -- | ---- | ---- |
| 1 | A | A | 기준 (이미 있음) |
| 2 | B | B | 기준 (이미 있음) |
| 3 | A | **B** | 값이 칩을 따라가나 |
| 4 | B | **A** | 배선을 따라가나 |

판정:

- **값이 칩을 따라간다** (3 ≈ 1, 4 ≈ 2) → 개체 특성이다. §6 의 이상치 판정이 그대로 성립한다
- **값이 배선을 따라간다** (3 ≈ 2, 4 ≈ 1) → 지금까지의 "개체 산포" 는 배선 산포였다.
  §9 산출물 2 의 정의부터 다시 써야 한다
- **둘 다 아니다** (네 값이 제각각) → 꽂는 행위 자체의 산포가 지배적이다. 조합마다 반복이 필요하다

**차이가 큰 두 칩을 고른다** — 벽이 가장 얇은 칩과 가장 두꺼운 칩. 차이가 작은 쌍을 고르면
어느 쪽을 따라가는지 분간이 안 된다. 스윕만 하면 되므로 prep 은 돌리지 않는다(P/E 불변).

### 앵커 교체 (2026-09-16 개정)

**앵커는 chip01 이었으나 chip02 로 바꾼다.** chip01 이 팀원에게 가 있어 세션 안에 끼워 넣을 수
없고, 앵커가 없으면 §6.3 의 분모(σ_repeat)가 생기지 않아 전수 측정 전체가 해석 불능이 된다.

바꿔도 논리는 그대로다 — **"한 칩을 반복해 노이즈 플로어를 만든다"가 요구사항이고 개체 지정은
수단**이다. chip02 는 2026-09-15 에 3회 측정분(세션 간 σ 4.65ps)을 이미 갖고 있어 자격이 된다.

부수 효과 둘:

- **기준값이 갱신된다.** 종전 G-a 기준 39,737.3ps 는 chip01 의 2024.2·N=100·115200 측정값이라
  현행 조건(2025.2·N=112·921600)에 그대로 쓸 수 없었다. 어차피 갱신이 필요했다
- **로그 29 D5 조건 ②가 해소된다.** 파일럿으로 chip01 을 300k 태우면 드리프트 기준 개체가
  사라지므로 "대체 개체를 신품 중에서 지정"하라는 조건이 걸려 있었다 — chip02 가 그 지정이다

남는 빚: chip01 이 돌아오면 **같은 조건으로 1회 재측정**해 chip01↔chip02 의 106ps 차이가
개체 차이인지 세대(2024.2↔2025.2) 차이인지 가른다. 그 전까지 두 값을 같은 축에 놓지 않는다.
