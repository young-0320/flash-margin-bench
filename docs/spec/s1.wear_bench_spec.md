## 1. 1사이클 정의

| 항목 | 값 |
| ---- | -- |
| 구성 | ① 0x00 프로그램 112페이지 → ② 7섹터 소거 |
| 마모 패턴 | **파라미터** (`WEAR_PAT_EVEN`/`WEAR_PAT_ODD` 레지스터 2개). **파일럿 고정값 `0x00`** — 아래 |
| 시간 (typ) | 7 × 45ms + 112 × 0.8ms = **405ms** |
| 계수 | 프로그램+소거 1쌍 = 1사이클. 체크포인트의 소거+PRBS 기록은 **영역별 누적(`area_cumulative_cycles`)에만** 넣고, **엔진의 사이클 카운터는 마모 루프만 센다** |

> **2026-09-19 개정 — 카운터는 마모 루프만 센다.** 전에는 체크포인트의 소거+PRBS 도
> 「1사이클로 계수」였는데, §13 A5 의 통과 조건이 *"카운터 / A행수÷7 / B의 cycle /
> tally×100 이 전부 100"* 이고 **tally 는 마모 루프만 센다.** 카운터가 체크포인트까지
> 세면 네 경로가 서로 다른 것을 세게 되어 A5 가 성립하지 않는다. 체크포인트 P/E 도 **실제
> 마모이므로 X축(`area_cumulative_cycles`, §9 C)에는 그대로 들어간다** — 빼는 것이 아니라
> **두 숫자를 가르는 것** 이다 (2026-09-19, 한영웅 · 로그 42 `[D42-8]` 계열).
>
> **2026-09-18 개정 — 마모 패턴은 파라미터다.** 2026-09-15 3인 회의에서 체커보드
> (`0x55`/`0xAA` 교대)도 **채택**해 본 실험은 여러 패턴으로 읽고 쓴다. 다만
> **파일럿은 마모 그룹이 하나뿐(§2.1)이라 패턴도 하나**이고 `0x00` 으로 확정했다
> (2026-09-18, 한영웅). 레지스터 설계와 "한 wear 그룹 안에서 패턴 변경 금지"는
> `docs/log/young/29.pe_engine_layer_decisions.md` `[D29-7]`.
>
> **보류 둘** (2026-09-18, 한영웅).
> ① **본 실험 3그룹(§2.2)에 패턴과 목표 사이클을 어떻게 배정하나** — 축이 둘인데 그룹이
> 셋이라 하나를 고정하거나 그룹을 늘려야 한다.
> ② **패턴 간 비교를 사이클 수로 맞추나 누적 1→0 전이 수로 맞추나** — `0x00` 은 셀당
> 8비트, `0x55` 는 4비트가 1→0 이라 같은 300k 면 스트레스가 2배 다르다.

## 2. 영역 배치

### 2.1 파일럿 (확정)

```
섹터     0 ~     6   마모 그룹      BASE_SECTOR = 0
섹터     7 ~    13   근접 대조군    BASE_SECTOR = 7
섹터 2,041 ~ 2,047   원격 대조군    BASE_SECTOR = 2,041
섹터   512           tally #1       측정 안 함
섹터 1,536           tally #2       측정 안 함
```

### 2.2 본 실험 (잠정 — §15 파일럿 후 확정)

```
섹터     0 ~     6   마모 그룹 1    BASE_SECTOR = 0
섹터     7 ~    13   마모 그룹 2    BASE_SECTOR = 7
섹터    14 ~    20   마모 그룹 3    BASE_SECTOR = 14
섹터    21 ~    27   근접 대조군    BASE_SECTOR = 21
섹터 2,041 ~ 2,047   원격 대조군    BASE_SECTOR = 2,041
섹터   512 / 1,536   tally ×2       측정 안 함
```

**그룹 수·그룹별 목표 사이클·그룹별 패턴은 미정** (§1 개정 주석 · §15).

### 2.3 영역 규칙

| 영역 | 크기 | 소거 반복 | 스윕 측정 | PRBS 기록 |
| ---- | ---- | --------- | --------- | --------- |
| 마모 그룹 | 7섹터 = 112페이지 | O | O | 체크포인트마다 |
| 대조군 (근접·원격) | 7섹터 | X | O | **체크포인트마다** |
| tally | 1섹터 × 2 | X (초기 소거 1회) | X | X |

- 완충 섹터를 두지 않는다
- 대조군은 체크포인트마다 소거+PRBS 재기록 → 대조군 누적 마모 = 체크포인트 수
- `flash_prep`·스캔 코드는 tally 섹터를 **하드 가드**로 제외한다
- tally는 실험 종료 시 해제한다 (§8.4)

## 4. 초기화 (실험 시작 시 1회)

```
1. UID 읽기 (4Bh) → 등록부 대조. 미등록이면 중단
2. tally 섹터 2개 소거 → 전체 0xFF 확인
3. 대조군 전 영역에 PRBS15 프로그램 → verify
4. 마모 그룹 전 영역에 PRBS15 프로그램 → verify
5. 신품 blank check 1회 → 출고 시점 결함 비트 기록 (주소 포함)
6. 체크포인트 0 측정
```

## 5. 체크포인트 절차

### 5.1 마모 그룹 (그룹마다)

```
1. 그룹 7섹터 소거
2. PRBS15 프로그램 112페이지 → verify
3. 스윕 (N=112, BASE_SECTOR=그룹 시작) × 반복 횟수
4. 사이클 카운터 +1
```

### 5.2 대조군 (근접·원격 각각)

```
1. 7섹터 소거
2. PRBS15 프로그램 112페이지 → verify
3. 스윕 (N=112, BASE_SECTOR=21 또는 2,041) × 반복 횟수
4. 해당 대조군의 누적 사이클 +1 (로그에 기록)
```

## 6. 마모 루프

```
반복 {
    ① 0x00 프로그램 112페이지          → t_program_us 기록
   ①' 검사 주기 사이클이면 여기서       → program_fail_bits (§7)
        112페이지를 읽어 기대 패턴 대조     ※ 소거 전이라야 한다
    ② 7섹터 소거                        → 섹터별 t_erase_us 기록
    ③ 사이클 카운터 +1                  ※ 마모 루프만 센다 (§1)
    ④ 검사 주기 도달 시 (§7):
         - blank check                   → erase_residual_bits
         - tally 바이트 기록 (2벌 모두)
         - 다이 온도 읽기
         - UID 재확인
         - 호스트로 #WEAR 행 출력
    ⑤ 체크포인트 도달 시 → §5, 다음 체크포인트 산정 → §11
}
```

> **2026-09-19 개정 — 검사 사이클만 「프로그램 → 검사 → 소거」로 분기한다(①').**
> 전에는 검사가 ④ 한 곳에 있었는데, §7 이 `program_fail_bits` 를 *"프로그램 직후"* 에
> 재라고 한다. ④ 는 소거가 끝난 뒤라 **기대 패턴이 이미 사라져** 그 문장이 실행될 수
> 없었다 — §6 과 §7 이 서로 어긋나 있었다. 검사 주기(100사이클)에만 읽기가 한 번 늘고
> 나머지 99사이클은 그대로다 (2026-09-19, 한영웅 · 로그 42 `[U42-3]`).

소거 시간은 **WIP 비트가 서 있는 구간의 지속시간**을 XTime으로 측정한다.

## 7. 무결성 검사 (blank check)

```
소거 직후    : 112페이지 읽기 → 0xFF가 아닌 비트    = erase_residual_bits
프로그램 직후: 112페이지 읽기 → 기대 패턴과 다른 비트 = program_fail_bits
```

| 항목 | 값 |
| ---- | -- |
| 기본 주기 | **100사이클** |
| 조밀화 주기 | **10사이클** |
| 조밀화 트리거 | 결함 비트 **1회 검출** |
| 1회 비용 | 약 176ms (실측 확인 대상) |

- 결함 비트의 **주소를 기록**한다. 초기엔 전량, 한 검사에서 64개 초과 시 처음 64개 + 총 개수
- 영구/일시 판정은 하지 않는다. 재현 횟수는 사후 분석에서 다룬다
- **두 숫자는 부를 때 실제로 읽어서 센다.** 마지막 결과를 캐시해 두지 않는다. 같은 읽기에서
  기준만 달리해 나오므로 `erase_residual_bits + program_fail_bits = 전량(112×2,048 =
  229,376)` 이 항상 성립하고, 호스트는 이것으로 **세는 경로가 살아 있는지** 를 본다
  (2026-09-19 추가 · 로그 42 §8)

> **왜 이 한 줄이 필요한가.** 신품 100사이클에서는 `program_fail_bits = 0` 이 **정답** 이라,
> 「제대로 재고 0」과 「세는 경로가 죽어서 0」이 로그에서 같아 보인다. 체크포인트(소거 직후)에
> 호스트가 blank check 를 부르면 `program_fail_bits` 가 **전량** 이어야 하므로, 거기서
> `0` 이 나오면 경로가 죽은 것이다 — 정답에서 제일 먼 값이 나오는 자리를 일부러 고른 것이다.

## 8. 카운트 영속화 (tally)

### 8.1 방식

| 항목 | 값 |
| ---- | -- |
| 초기화 | 실험 시작 시 tally 섹터 2개를 각 1회 소거 → 전체 `0xFF` |
| 기록 | 100사이클마다 다음 바이트 하나에 `0x00` (2벌 동일하게) |
| 판독 | 누적 = `0x00` 바이트 수 × 100 |
| 용량 | 4,096바이트 → **409,600 사이클** |
| 기록 비용 | 0.004% (2벌 합산) |
| 바이트 재기록 | **금지** — 각 바이트를 딱 한 번만 쓴다 |

### 8.2 판독 규칙

| 값 | 처리 |
| -- | ---- |
| `0x00` | 센다 |
| `0xFF` | 안 씀 |
| 그 외 | 세지 않되 **±1 불확실**로 기록 |

**2벌 병합** — 두 벌이 불일치하면 **차이의 크기**로 가른다.

| 차이 | 처리 |
| ---- | ---- |
| ≤ 1바이트 (100사이클) | 큰 쪽으로 병합 + **불일치를 로그에 기록** |
| > 100사이클 | **중단하고 사람을 부른다** — 한쪽만 1바이트 넘게 밀리는 것은 정상 동작으로 설명되지 않는다 |

> **2026-09-19 개정 — 「큰 쪽 채택」을 2벌 사이로 한정하고 상한을 걸었다.** 전에는
> 조건 없이 「큰 쪽 채택」이었다. 2벌은 같은 시점에 같이 쓰므로 차이가 날 수 있는 폭은
> **기록 도중 차단 = 1바이트** 뿐이고, 그보다 크게 벌어졌다면 설명되지 않는 상태라
> 계속 돌리면 X축이 조용히 틀어진다 (2026-09-19, 한영웅 · 로그 41 `[D41-20]`).
>
> **호스트 로그와의 대조는 여기가 아니라 §8.3 이다.** 전에는 §8.3 3번도 같은
> 「큰 쪽 채택」이었는데, tally 는 해상도가 100 이라 **`tally < 호스트로그` 가 늘 참** 이어서
> 부등호로는 아무것도 안 갈렸다.

### 8.3 재개 절차

```
1. UID 읽기 → 등록부 대조. 불일치면 중단        (판독은 엔진 · 대조와 중단은 호스트)
2. tally 2벌 판독 → §8.2 로 병합                 (판독은 엔진 — 엔진이 고르지 않는다)
3. 호스트 로그의 최대 cycle 과 대조 → d 규칙     (호스트)
4. blank check → 부분 소거면 해당 섹터 재소거    (엔진)
5. 이어서 진행                                   (호스트 판단)
```

**`d` 규칙** (3번) — `d = (A 로그의 최대 cycle) − (tally × 100)`

| `d` | 뜻 | 동작 |
| --- | -- | ---- |
| `0 ≤ d < 100` | 정상 | 호스트 로그 채택 |
| `d < 0` | **호스트만 죽었다** — A 가 멈추고 tally 만 앞섰다 | tally×100 채택 + **결손 구간 기록** |
| `d ≥ 100` | tally 가 안 는다 | 채택하지 않고 **tally 의 다음 바이트**를 본다 (아래) |

`d ≥ 100` 의 갈래 — 마모 루프는 tally 를 먼저 쓰고 행을 나중에 내보내므로 **A 행은 받았는데
tally 쓰기 전에 끊기는 창**이 있다. 그것은 정상 차단이라 사람을 부르면 과하다.

| 다음 바이트 | 뜻 | 동작 |
| ----------- | -- | ---- |
| `0xFF` | 아직 안 썼다 — 정상 차단 | 호스트 로그 채택하고 계속 |
| 그 외 값 | 쓰다 끊겼다 | §8.2 의 **±1 불확실**로 기록하고 계속 |
| write 시험 실패 | **플래시가 안 써진다** | 중단하고 사람을 부른다 |

복원 불확실성: 최대 100사이클 (+소거 중 차단 시 ±1)

> **2026-09-19 개정 — 3번의 「큰 쪽 채택」을 폐기하고 `d` 규칙으로 바꿨다.** tally 는
> 100사이클마다 1바이트라 **해상도가 100** 이다. 147사이클 시점에서 `tally×100 = 100`,
> 호스트 로그 `= 147` 이므로 `tally < 호스트로그` 는 **늘 참** 이고, 부등호로는
> 「호스트만 죽었다」와 「정상 중단」이 구분되지 않았다. 가르는 것은 **차이의 크기** 다.
>
> **판단 주체도 같이 못 박았다 — 채택은 호스트가 한다.** 엔진은 호스트 로그를 모르므로
> (파라미터가 없다) 3번을 엔진이 할 수 없고, 1번의 「불일치면 중단」도 사람을 불러야 하는
> 일이라 엔진이 혼자 정하면 호스트가 이유를 모른다
> (2026-09-19, 한영웅 · 로그 41 `[D41-20]`·`[D41-21]` · `../interface/pe_engine.md` §2).


### 8.5 파일럿에서 검증할 것

파일럿 종료 시 tally 섹터를 전량 읽어 `0x00`/`0xFF` 외의 값이 있는지 확인한다.
있으면 마크 간격 또는 페이지당 기록 바이트 수를 조정한다.

## 10. 중단·경고 조건

| 조건 | 동작 |
| ---- | ---- |
| 결함 비트 > **46** | θ=10⁻⁴ 무효 표시, 계속 |
| 결함 비트 > **459** | θ=10⁻³ 무효 표시, 계속 |
| 결함 비트 > **4,588** | θ=10⁻² 무효 → **정지** |
| 소거 시간 > **400ms** | 경고 기록, 계속 |
| WIP 미해제 > **2초** (잠정) | **정지** + 대기시간 기록. **자동 재시도 금지** |
| UID 불일치 | **정지** |

- 결함 비트 한계 = 위상 무관 에러 플로어가 θ를 넘는 지점.
  `0.5 × D / (112 × 2,048) < θ`
- 워치독 2초는 잠정값. **M 트랙 신품 소거 시간 실측 후 확정**

## 12. 시간 예산

| 단위 | 값 |
| ---- | -- |
| 1사이클 | 405ms (typ) |
| 스윕 1회 | **59초** (실측 2026-09-15, chip02 25MHz·N=112·921600) |
| 체크포인트 1점 — 파일럿 | 3영역 × 1회 = **약 3분** |
| 체크포인트 1점 — 본 실험 | 5영역 × 3회 = **약 15분** |
| 사이클링 300k (1그룹) | **33.7h** |

| 실험 | 사이클링 | 측정 | 합계 |
| ---- | -------- | ---- | ---- |
| 파일럿 (1그룹 300k) | 33.7h | 점 수 × 3분 | 점 수에 따라 34~35h |
| 본 실험 | 그룹별 목표 사이클 합 × 405ms | 점 수 × 15분 | §15 확정 후 산정 |

**개정 근거 (2026-09-16).** 종전 값 5.6분은 115200bps·N=112 계산치였고 "실측 확인 대상"으로
열어 두었던 항목이다. 2026-09-15 보 레이트를 921600으로 올려(로그 30 §10.3) 실측 59초를
얻었다 — UART 전송이 지배 항이었고 순수 측정 시간은 약 23초다. 체크포인트 비용이 5.6배
싸졌으므로 **§11 적응적 조밀화에서 점을 더 촘촘히 박을 여유가 생긴다**(종전엔 본 실험
점당 84분이 1차 비용 동인이었다 — 로그 17 §3.9). 사이클링 33.7h는 tSE가 지배하는 칩 물리라
불변이며, 이제 전체 일정의 95% 이상이 사이클링이다.

tSE는 칩 내부 고전압 펄스 시간이라 SPI 클럭으로 줄일 수 없다. 소켓 1개, 전 과정 직렬.
