## 0. 이 측정이 답하는 것

졸업논문 NAND 절은 **사용량 추정이 아니라 방법의 전제 점검**이다(문서 15 머리말 11/24). 이 명세가 내는 것:

1. 칩마다 **블록 1,024개의 신품 소거 시간 분포** — 칩 안 소거 시간 비 지표가 쓸 만한 분해능을 갖나(§9 판정 규칙)
2. 출고 상태 기록 — 불량 블록 표, 전 페이지 raw 0 비트 수
3. 범위 prep 의 PRBS 기준 — 뒤의 마모 · raw 비트 에러의 x = 0
4. 파일럿 칩에서 ECC 경로 · 무시된 소거의 서명 · 반복성(σ_repeat)

**되돌릴 수 없다.** 출고 상태와 첫 소거 값은 소거 한 번으로 사라진다(S-2 머리말과 같은 사정). 그래서 읽기 전용 단계(N1 · N2)와
소거 단계(N3)를 다른 실행으로 가르고, N3 는 호스트의 진행 확인 없이 시작하지 않는다.

## 1. 단계 · 실행 단위

| 단계 | 하는 일 | 칩을 바꾸나 | P/E |
| --- | --- | --- | --- |
| **N1 식별** | 리셋 · JEDEC · SR 덤프 · UID · 파라미터 페이지 | 아니다 | 0 |
| **N2 스캔 · blank** | 불량 블록 스캔 2회 · 전 페이지 raw 읽기 | 아니다 | 0 |
| **N3 소거** | 보호 해제 · 정상 블록 전부 소거하며 시간 측정 · 블록 0-127 blank 확인 | **예** | 정상 블록 +1 |
| **N4 범위 prep** | 지정 블록 범위 소거(시간) · PRBS 기록 · 두 방식 되읽기 | 예 | 범위 +1 |

- **신품 실행** = N1 → N2 → (호스트 진행 토큰) → N3. **UID 당 한 번**이다. 호스트는 이미 신품 실행이 끝난 UID 면 N3 를 거부한다(R11)
- **N4 는 따로 돈다** — 범위는 N3 분포를 본 뒤 칩마다 정한다(R 별도 절 C). 기본값 블록 0-127 은 잠정이다. 중단 뒤 다시 할 수 있는 것은 N4 뿐이다
- 펌웨어는 N1 · N2 · N3 · N4 를 이 순서로 만든다 — 앞 두 단계는 칩을 바꾸지 않아 일정이 밀려도 손해가 없다(R19)

## 2. 시료 · 라벨

| 용도 | 개수 | 비고 |
| --- | --- | --- |
| 파일럿 | 1 | 첫 칩. 신품 실행에 §8 추가 시험을 더한다 — **영웅님 확인 필요** |
| 신품 전수 | 8 | 파일럿 결과로 §6 의 정지 경계 · §9 규칙을 확정한 뒤 |
| 보류 | 1 | 마지막 칩. 앞 칩들의 분석 뒤에 꽂는다(R13) — **영웅님 확인 필요** |

라벨은 `nand01`-`nand10` 을 UID 에 붙인다(등록부는 NOR 와 따로 절을 둔다). 정본은 UID 다.

## 3. 장비 전제

- WSON-8 8×6 클램셸 소켓 → DIP8 → 브레드보드 → Pmod. 핀 배치 DS p6: 1 /CS · 2 DO · 3 /WP · 4 GND · 5 DI · 6 CLK · 7 /HOLD · 8 VCC
- **/WP · /HOLD 는 10kΩ 로 VCC 풀업, /CS 10kΩ 풀업, VCC-GND 0.1µF 를 소켓 가까이**(DS p7 §4.3-4.4, R15). 첫 통전 전에 도통 확인
- 칩 교체는 **전원을 끊고** 한다 — /CS 가 VCC 를 따라가야 하고 쓰기 명령은 tPUW 뒤에 받는다(DS p12 · p49, R22)
- PS SPI0 · 약 2.6MHz(`flash_io.c` 의 분주 64)로 시작한다. 클럭을 올리는 것은 파일럿 뒤의 별도 결정
- g2 비트스트림(NOR `flash_prep` 과 같은 경로)

## 4. N1 식별 (읽기 전용)

1. 66h + 99h(리셋) → 500µs 대기 → BUSY = 0 확인(DS p28 · p53 tRST, R10)
2. JEDEC: 9Fh + 더미 8클럭 + 3바이트 = 5바이트 전송, `EF AE 21` 과 대조(DS p25 · p30, R22). NOR 루틴(4바이트)을 쓰지 않는다
3. SR-1 · SR-2 · SR-3 덤프(0Fh + A0h / B0h / C0h, DS p31). 대조:
   - SR-1: BP3-0 · TB = 1 (전원 인가 보호, DS p13 · p29). WP-E · SRP 는 0
   - SR-2: OTP-L · OTP-E · SR1-L = 0, ECC-E = 1. **H-DIS 는 가리고 비교한다** — 기본값이 문서 안에서 엇갈린다(그림 11 대 §8.2.4, R10). 파일럿에서 전원 재인가 직후 값으로 확정
   - SR-3: S5-S0 만 비교(S7 · S6 예약). BUSY = 0
   - 하나라도 다르면 `#NAND FAIL` 로 끝낸다. **소거 · 프로그램 명령을 내지 않는다**
4. UID(R1): SR-2 의 OTP-E = 1 로 쓰고 되읽기 → 13h(페이지 00h) → BUSY = 0 → 03h 로 읽기, **3회 읽어 일치할 때만** 채택 →
   OTP-E = 0 쓰고 되읽어 **SR-2 상위 3비트(OTP-L · OTP-E · SR1-L) = 000** 확인(DS p45 §8.2.18). 이것이 확인되기 전에는 10h · D8h 를 내지 않는다
   (OTP 주소 02h-0Bh 가 블록 0 페이지 2-11 과 같은 숫자다). UID 페이지의 사본 형식은 데이터시트에 없다 — 파일럿에서 512B 덤프로 확정
5. 파라미터 페이지를 같은 방식으로 한 번 읽어 남긴다(§8.2.19) — 「ONFI」 서명이 13h → 03h 경로의 양성 대조다(R23)

**SR 쓰기 규칙(전 단계 공통, R15)**: 읽기 → 해당 비트만 고침 → 쓰기 → 되읽어 **전 비트** 일치 확인. 불일치면 정지.
WP-E · SRP1-0 · OTP-L · SR1-L 은 어느 단계에서도 쓰지 않는다.

## 5. N2 스캔 · blank (읽기 전용, ECC-E = 0)

ECC-E = 0 으로 쓰고 되읽는다(SR 쓰기 규칙). 모든 페이지 읽기는 **[13h → BUSY = 0 → 03h]** 이다(DS p38 · p53 — ECC 는 13h 에서 걸린다, R5).

1. **스캔 두 번**: 블록마다 첫 페이지의 000h(본 데이터 첫 바이트) **와** 800h(스페어 첫 바이트)를 읽어 원값을 남긴다. 하나라도 FFh 가 아니면 불량(DS p55 §10.2, R7).
   두 번째 스캔은 첫 번째가 끝난 뒤 전 블록을 다시 돈다
2. 블록마다 JEDEC 재확인(정답 FFh 가 DO 가 뜬 버스 값과 같다 — R8)
3. **정지 조건**(소거 전이라 비용 없음, 재장착 뒤 N1 부터):
   - 두 스캔이 다르다
   - 불량이 20개를 넘는다(Nvb 최소 1,004, DS p55)
   - 블록 0-7 · 1020-1023 에서 불량이 나온다(출고 유효 보장, DS p5 · p55)
4. **불량 블록**: 소거 · 프로그램 대상에서 뺀다(결정 1). 다만 첫 페이지 2,144B 를 한 번 읽어 남긴다 — 공장 표시의 실제 값의 기록(R9)
5. **blank 읽기**: 정상 블록 전 페이지 2,144B. 블록마다 한 줄 — 0 비트 수 합 · 페이지별 섹터당 0 비트 최댓값 · 0 비트가 있는 페이지 수
6. blank 정지 규칙(R12): 표시 없는 블록에 **섹터당 0 비트가 4개를 넘는 페이지**가 하나라도 있으면 N3 로 가지 않는다(이 칩은 신품이 아닐 수 있다 — 칩은 구매가 아니라 받은 것). 4개 이하는 기록하고 그 블록의 소거 시간 행에 플래그를 붙인다
7. 끝에 요약 줄(불량 수 · 목록 · blank 플래그 블록 수)을 찍고 **호스트의 진행 토큰을 기다린다**(R2). 토큰 없이 N3 로 가지 않는다

## 6. N3 소거 (첫 비가역 단계)

시작 조건: N2 요약을 호스트가 받아 저장했고, UID 가 신품 실행 이력에 없고, 진행 토큰이 왔다.

1. **타이머 자기검증**(R2): 알려진 지연(예: 1ms 바쁜 대기)을 소거 시간과 같은 함수로 재어 범위 밖이면 정지 — NOR 에서 4배 작게 찍힌 버그 · 타이머 미가동을 재prep 으로 되잡았지만 여기서는 되잡을 수 없다
2. **보호 해제**(R3): SR-1 의 BP3-0 · TB = 0 (SR 쓰기 규칙). ③ 까지는 출고 보호가 안전망이라 이 단계 직전에 한다
3. **순서**: 짝수 블록 전부 → 홀수 블록 전부(R17 — 시간 드리프트는 짝 · 홀 단차로, 위치 구조는 양쪽에 같은 모양으로)
4. **블록마다**(R3):
   06h → SR-3 WEL = 1 확인 → D8h(블록 주소) → BUSY 폴링(경과 µs) → **E-FAIL = 0** 확인 → JEDEC 재확인(`EF AE 21` — 0 도 FF 도 아닌 양성 대조) →
   시간이 [하한, 상한] 밖이면 **다음 블록을 지우기 전에 정지**
   - 경계는 파일럿 §8 ①로 확정한다. 확정 전 잠정 [0.5ms, 20ms] (typ 2 · max 10ms, DS p53)
   - 폴링 한 번은 약 3바이트 ≈ 9µs + 드라이버(R21). 폴링 횟수도 같이 남긴다
5. 소거 시간은 **RAM 에도 둔다**(1,024 × 4B). 끝난 뒤 재출력 명령에 같은 값을 다시 보낸다(R2)
6. **파일럿만**: 블록 64개(짝수 32 · 홀수 32)를 먼저 지우고 멈춘다 — 사람이 값이 2-10ms 대인지 본 뒤 나머지
7. 소거 뒤 블록 0-127 만 blank 확인(ECC-E = 0, 약 1분, R19)
8. 장부: 호스트가 `chip_pe.md` 에 NAND 행(UID · 블록 범위 · +1)을 쓴다(R11)

## 7. N4 범위 prep (지정 범위, 기본 블록 0-127 — 잠정)

1. ECC-E = **1** 로 쓰고 되읽기(결정 4 — 파일럿 §8 ③이 통과해야 확정. 불통과면 이 절의 ECC-E 는 전부 0)
2. 범위의 정상 블록을 §6 ④ 와 같은 방식으로 소거(시간 기록 — 「PRBS → 소거」 눈금, 신품 「빈 → 소거」 와 따로 적는다, R16)
3. 블록 안 페이지 0 → 63 순서로(DS p37 · p56, 순차 기록): **02h, 열 0, 2,048B** PRBS 적재(84h 금지 — 직전 페이지 스페어가 따라 써진다, R14) → 06h → WEL 확인 → 10h → BUSY(경과) → **P-FAIL = 0**.
   프로그램 시간은 블록(64페이지) 합으로 기록(R21). 스페어는 쓰지 않는다 — FFh 로 남는다
4. PRBS: NOR 규약 그대로 — PRBS-15, 시드 `{1, page[13:0]}`, MSB-first(`flash_prep.c`). 범위가 페이지 16,384(블록 256) 미만이어야 시드가 겹치지 않는다 — **빌드 타임 검사**로 막는다(R20)
5. **되읽기 두 번**(페이지마다, R5): [ECC-E = 1 설정 · 되읽기 → 13h → BUSY → 03h 2,144B → SR-3 의 ECC-1/0 · BFR(40h · 50h) · MBF(30h)] 와
   [ECC-E = 0 설정 · 되읽기 → 13h → BUSY → 03h 2,144B]. 행에 `ecc_e` 열. 끈 읽기의 불일치는 13h 부터 한 번 더 읽어 같은 비트인지 남긴다(셀 오류 대 전송 오류)
6. **합격**(R6): 켠 읽기가 PRBS 와 전부 일치 · ECC 상태 10(정정 불가) 0건 · P-FAIL 0건. **raw 불일치는 판정에 쓰지 않는다** — 블록별 개수 · 위치로 기록한다(정상 블록도 섹터당 4비트 이내의 불량 비트를 가질 수 있다, DS p55 §10.1)
7. 끈 읽기에서 800h-83Fh 가 전부 FFh 인지 확인(R14)
8. 끝에 블록 0-127 의 000h 가 `0x80 | (블록 >> 1)` 인지 본다 — 주소 경로의 양성 대조(R8 (d))

## 8. 파일럿 칩 추가 시험

모두 파일럿 한 칩에서만, 표시한 단계 안에서. 소모는 블록 수십 개다. **결과가 나오기 전에는 나머지 칩의 N3 를 하지 않는다.**

| # | 시험 | 단계 | 무엇을 확정하나 |
| --- | --- | --- | --- |
| ① | 보호된 블록(BP 전부 1)에 06h + D8h, 그리고 WEL 없이 D8h — SR-3 와 경과 시간 | N3 ② 직전 (칩 불변) | 무시된 소거의 서명 · §6 하한 |
| ② | 전원 재인가 직후 SR 덤프 · 66h+99h 전후 덤프 | N1 | SR-2 기대값(H-DIS) · 리셋이 BP · ECC-E 를 기본으로 돌리는지 |
| ③ | **ECC 경로 오류 주입**(R4): 버릴 블록 1개(범위 밖, 예 1016)에 ECC-E = 1 로 PRBS 4페이지 기록 → ECC-E = 0 으로 같은 페이지에 「한 섹터의 1 비트 k 개만 0」 덮어 프로그램(NoP 2/4, 패리티 바이트는 FFh), 페이지마다 k = 1 · 3 · 4 · 5 | N4 앞 | 기대: 끈 읽기 k 개 다름 · 켠 읽기 원본 + 상태 01(k ≤ 4) / 10(k = 5) + BFR = k. **통과 = 결정 4 확정**, 아니면 ECC 끔으로 |
| ④ | 반복 소거: 범위 밖 16블록(예 1000-1015)을 N3 뒤 4번 더 소거 | N3 뒤 | σ_repeat · 첫 소거 대 재소거(R13) |
| ⑤ | 800h = 00h 를 버릴 블록(예 1017) 첫 페이지에 쓰고 스캔 루틴이 불량으로 잡는지 | N4 뒤 | 스캔의 800h 경로 양성 대조(R8 (d)) |
| ⑥ | ECC-E = 1 로 쓴 페이지의 840h-85Fh 를 ECC-E = 0 으로 읽어 FFh 가 아닌지 · 지워진 페이지를 ECC-E = 1 로 읽을 때의 상태 | ③ 과 같이 | 패리티 열 가독성(문서 안에서 엇갈림 — DS p8 대 p35 · p38) |
| ⑦ | 소거 1회 동안 상태 레지스터 연속 읽기가 갱신되는지 · 폴링 한 번의 실제 주기 | N3 | 소거 시간 분해능(R21) |

①-⑦ 의 블록 소거 · 프로그램은 장부에 적는다.

## 9. 판정 규칙 — 데이터를 보기 전에 적는다

신품 소거 시간(N3)에 대해, 칩마다:

- **분포 있음**: 블록 간 로버스트 σ(MAD × 1.4826)가 **3 × σ_repeat** 를 넘는다(S-2 의 판정 꼴과 같다). σ_repeat 은 파일럿 §8 ④
- **양자화**: 소거 시간 군집 사이 간격이 군집 폭의 **10배**를 넘는다 → 「양자화」 로 적고 값 대신 **계단 수**로 서술한다
- **첫 소거 대 재소거**: §8 ④ 의 블록 16개에서 첫 소거 중앙값과 재소거 중앙값의 차가 3 × σ_repeat 을 넘으면 「다르다」 — 이때는 파일럿 뒤 칩마다 블록 1018-1023 을 N3 에서 지우지 않고 남긴다(출고 상태 대조군)
- 선행 연구(Sakib 2018, raw SLC NAND)는 약 1ms 펄스 계단을 보고했다 — 이 칩에서 2ms 바닥이면 10ms 까지 많아야 8단이고, 「칩 안 분포가 거의 한 점」 이 그 자체로 결과일 수 있다(리뷰 별도 절 4.2)

## 10. 출력

UART 줄 접두는 `#NAND`. 한 줄 한 사실, 호스트 파서가 CSV 로 옮긴다. 최소 줄 종류:
`BEGIN`(단계 · git_rev) · `JEDEC` · `SR`(1/2/3) · `UID` · `PARAM` · `BAD`(블록 · 000h · 800h · 스캔 회차) · `BLANK`(블록 · 0 비트 합 · 섹터 최대 · 페이지 수 · 플래그) ·
`SUMMARY` · `WAIT`(토큰 대기) · `ERASE`(블록 · µs · 폴링 수 · SR-3 · 순서 번호) · `PROGRAM`(블록 · µs 합) · `VERIFY`(페이지 · ecc_e · 불일치 수 · ECC 상태 · BFR) ·
`FAIL`(사유) · `END`. 정확한 필드는 구현 PR 에서 이 절에 추기한다.

## 11. 인수 기준

- **보드 없이**: `ps/sim` 의 가짜 NAND 모델(블록 · 페이지 · 버퍼 · SR · OTP · BUSY 시간)로 — N1-N4 정상 경로, 그리고 정지해야 할 입력 각각에서 정지하는지:
  JEDEC 불일치 · SR 불일치 · UID 3회 불일치 · OTP-E 되읽기 실패 · 두 스캔 불일치 · 불량 > 20 · 블록 0-7 불량 · blank 섹터당 > 4 · 토큰 없음 · 타이머 이상 ·
  WEL = 0 · E-FAIL = 1 · DO 고착(0x00 · 0xFF) · 소거 시간 경계 밖 · P-FAIL = 1 · 범위 > 페이지 16,384(빌드 실패)
- **보드**: 파일럿 칩의 N1 → N2 → §8 → N3 → N4 를 이 문서대로 완주하고, §8 ③ 판정이 나온다
- 리뷰: 구현 전에 이 명세를 리뷰 → 구현 뒤 코드 리뷰 → `ps/` 소유자(장세은) PR 검토
