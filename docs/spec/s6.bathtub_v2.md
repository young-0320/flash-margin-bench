# S-6. 욕조 v2 측정 명세 — 훑기 → 벽 집중

- **상태: 초안 (2026-11-11).** 계약에 닿는 부분(레지스터 · 규약 · 파일)은 [수정안 #4](../interface/amendments/4.edge_counter_bathtub_v2.md) 가 정본이다. 이 문서는 측정 절차 · 파라미터 · 시험을 정한다
- **근거**: [로그 55](../log/young/55.professor_feedback_bathtub_2026-11-02.md) [D55-3] - [D55-13] · [D55-18] - [D55-21] · 설계 리뷰 2(§10) · 개념 [16 에지 계수기](../concepts/16.edge_counter.md)
- **범위**: 졸업논문 「기각한 지표와 그 이유」 장([D55-8]) — 벽이 에지 방향으로 갈리고(DCD), 그 시간 차가 마모와 무관함을 보이는 데까지. 마모 체크포인트 스윕은 v1 그대로다([D55-10])

## 1. 무엇을 재나

v1 은 위상 2,520스텝 전부를 같은 N(112)으로 읽어 바닥까지 같은 깊이로 본다. v2 는 **바닥을 1회 훑기로만 지나가고, 벽과 그 바깥에 읽기를 몰아** 벽의 꼬리를 깊게 본다. 그리고 에지 계수기로 벽을 상승 에지 · 하강 에지로 나눈다.

## 2. 파라미터

아래 상수는 **25MHz 값** 이다. 75MHz(수정안 #4 A5)는 표 아래 묶음을 쓴다.

| 이름 | 값 | 근거 |
| ---- | -- | ---- |
| SCLK | 25MHz (UI 40,000ps · 2,520스텝 · 15.87ps) | [D55-7] — 마모 체크포인트 386런과 연속 |
| 훑기 N | 1 (스텝당 2,048비트) | 로그 55 §6 — 천장은 1회로 100% 잡힌다 |
| 천장 판정 | 읽기당 오류 ≥ 205 (BER ≥ 0.1) | [D55-4] |
| 천장 N | 112 (한 묶음) | [D55-4] — 천장은 매번 같은 값이다 |
| 벽 N — 표준 `std` | 8,064 = 112 × 72 (START 72번) | [D55-5] — 보통 칩에서 v1 과 같은 시간 |
| 벽 N — 초심부 `deep` | 2,064,384 = 112 × 18,432 (START 18,432번) | [D55-11] — 0 오류면 BER 7e-10 아래(95%) |
| K (멈춤) | 5 — 벽 N 으로 0 오류 스텝이 5개 연속이면 그 방향을 멈춘다 | [D55-4] |
| 바깥 상한 | 훑기 덩어리 경계에서 바깥으로 64스텝(약 1,000ps) | [D55-4] — 넘으면 무효 ⑩ `wall_cap` |
| 덩어리 정의 | 가장 긴 원형 0 구간(바닥)의 여집합. 안쪽 0 틈이 K 미만이면 같은 덩어리, K 이상이면 무효 ⑨ `multi_block` | [D55-4] |
| 바닥 최소 | 128스텝 — 미만이면 무효 ⑭ `short_floor` | 좌우 바깥 걷기(각 최대 64)가 겹치지 않게 |
| 이력 범위 | 덩어리 중심 스텝 580-760 — 밖이면 `block_out_of_range` 표시 | v1 386런 594-746 에 여유. A4 뒤 다시 맞춘다 |
| 끝 훑기 | 벽 집중이 끝난 뒤 훑기를 한 번 더 — 천장 양 끝이 1스텝 넘게 다르면 `drift` 표시 | 리뷰 §9 확인 필요 1(초심부 수 시간의 표류) · 설계 리뷰 2 M4 |
| N 은 실행 때 덮어쓴다 | `std` · `deep` 는 같은 ELF, 변수만 다르다(`g_uart_baud` 와 같은 방식, 로그 49) | [D55-5] |

N 은 한 START 에 2,048 이하(계약 R6 · R11)라 벽 N 은 **112회 START 를 반복** 해서 채운다. 묶음마다 `e_i` 와 정렬별 여섯 값 버퍼를 다음 START 전에 회수한다(R3). 읽기 번호 `read_idx` 는 묶음마다 0-111 이고 읽은 쪽은 `base_sector × 16 + read_idx` 다. 스텝 합은 u64 로 더한다(수정안 #4 §2.4).

**75MHz 묶음 (A5 전용)** — 위의 25MHz 상수를 그대로 쓰면 UI 스텝 수가 틀리고, 덩어리 중심이 늘 범위 밖이며, 선반(BER 약 0.125 = 읽기당 약 256)이 천장 문턱 205 를 넘어 `ceil` 로 분류된다. 75MHz 빌드는 v1 사다리 ELF 처럼 빌드 때 치환(`ps/scripts/build_g3_sweep.py` 방식)으로 아래 값을 쓴다.

| 이름 | 75MHz 값 | 근거 |
| ---- | -------- | ---- |
| UI | 13,333ps · 840스텝 | 위상 한 칸은 VCO 가 정해 15.87ps 그대로 |
| 천장 판정 | 읽기당 오류 ≥ 410 (BER ≥ 0.2) | 선반 약 0.125 와 천장 약 0.247 사이 |
| 이력 범위 | 덩어리 중심 스텝 600-750 | v1 75MHz 15런 613.5-735.5 에 25MHz 와 같은 여유 |
| 나머지 | 훑기 N · 천장 N · 벽 N · K · 바깥 상한 64 · 바닥 최소 128 그대로 | 스텝 단위 상수라 같다. v1 75MHz 덩어리는 최대 131스텝이라 바닥이 700스텝 넘는다 |

## 3. 절차

```
① 시작     FEATURE bit0 == 1 확인 (아니면 무효 ⑪ no_feature) · PHASE_POS == 0 확인 · BEGIN 줄
② 훑기     스텝 0 → 2519, 스텝마다 START 1회(N = 1). 행 pass=scan
            v1 의 무반응 검사(⑦ line_dead)를 여기서 한다
③ 덩어리   훑기 결과로 바닥(가장 긴 원형 0 구간)과 덩어리를 정한다
            · 오류 0 스텝 없음 → 무효 ⑧ no_window
            · 전 스텝 오류 0 → 무효 ⑬ no_block
            · 안쪽 0 틈 ≥ K → 무효 ⑨ multi_block
            · 바닥 < 128스텝 → 무효 ⑭ short_floor
            · 중심이 이력 범위 밖 → flags 에 block_out_of_range
④ 천장     덩어리 안에서 훑기 오류 ≥ 205 인 스텝 → 112회 한 묶음. 행 pass=ceil
⑤ 벽 집중  덩어리 안의 나머지 스텝(벽) → 벽 N. 행 pass=wall
            왼쪽 경계에서 바깥(스텝 감소)으로 한 스텝씩 벽 N — 0 오류가 K 연속이면 멈춘다
            오른쪽 경계에서 바깥(스텝 증가)으로 같은 방식
            바깥 스텝의 한 묶음이라도 읽기당 평균 오류 ≥ 205 → 그 자리에서 무효 ⑫ contact_collapse
            어느 쪽이든 64스텝을 넘으면 무효 ⑩ wall_cap
⑥ 끝 훑기  ② 를 한 번 더. 행 pass=rescan
            · 천장 양 끝(오류 ≥ 205 인 첫 · 끝 스텝)이 ② 와 1스텝 넘게 다름 → flags 에 drift
            · 덩어리가 둘 이상 → flags 에 rescan_multi_block (무효 아님)
⑦ 끝       END 줄에 main_rows · reads_rows · mode · flags
```

- 위상 이동은 `PHASE_INC` · `PHASE_DEC` 만 쓴다. 이동은 측정 사이(R2)다. 펌웨어는 기대 누적 위치를 int32 로 세고(INC +1 · DEC −1), 측정마다 `PHASE_POS`(signed 32)와 **정확히** 비교한다 — 다르면 무효(`phase_pos_mismatch`, 현행 검사와 같은 이름). 시작 때 `PHASE_POS` 가 0 이 아니어도 같은 무효다. 스텝 번호는 `((pos mod 2520) + 2520) mod 2520` 이다 — 덩어리가 2519 → 0 경계에 걸쳐도 같은 절차다.
- ⑤ 에서 「0 오류 K 연속」 은 벽 N 으로 잰 결과로 판정한다. 훑기 결과로 판정하지 않는다 — 1회 훑기는 경계를 안쪽으로 최대 7스텝 놓친다(로그 55 §6).
- ⑤ 의 무효 ⑫ 는 바깥 스텝에만 적용한다. 바닥이던 자리가 천장 높이로 튀면 벽이 아니라 접촉 붕괴라, 64스텝까지 걸어 봐야 시간만 쓴다.
- ⑥ 의 표류는 천장 끝으로 본다. 1회 읽기의 덩어리 경계는 BER 1e-4 근처라 같은 장착에서도 흔들린다.

| ---- | --------------------- | -------- |
| `std` | 약 20 | 약 1-2분 + 훑기 두 번 |
| `deep` | 약 20 | **약 6시간** — UART 로 읽기 기록 약 1.7GB 를 921,600baud 로 보내는 데 약 5.1시간 + SPI 읽기 약 1시간 |

초심부는 UART 가 병목이다. R 줄에서 `pass` 를 빼(캡처가 순서로 붙인다 — 수정안 #4 §2.5) 줄이 조금 짧아진다. 첫 `deep` 실측에서 시간을 바꾼다. JV 칩은 천장이 길지만 천장은 한 묶음이라 벽 스텝 수는 비슷하다.

## 5. 분석 (호스트)

- **입력**: `bathtub2_*` 만. v1 분석기는 v2 파일을 읽지 않는다(접두사 · `n_reads` 섞임 검사 — 로그 55 §9 R6). `flags` 에 `reads_gap` 이 붙은 스텝은 메인 행(스텝 집계)만 쓰고 읽기별 값은 쓰지 않는다.
- **그림**: 끊긴 축(P1), 한쪽 W = 1,000ps, 바닥 길이는 화살표와 수치([D55-3]). 바닥 구간은 `scan` 행으로 그리고 「1회 훑기 — 깊이 다름」 을 표시한다.
- **에지별 곡선** — 「승자」 를 쓰지 않는다([D55-19]).
  1. 구조(수정안 #4 R14): 같은 샘플을 정렬 c − 1 은 정렬 c 보다 한 비트 뒤의 정답과 맞댄다 — 「다음 비트」 정렬 = 「지금 비트」 정렬 − 1
  2. 읽기마다 이웃 짝 (c − 1, c) 중 `e_(c−1) + e_c` 가 그 쪽의 전이 수와 같은 짝을 고른다. 지금 비트 정렬은 셔터보다 먼저 온 전이를, 다음 비트 정렬은 아직 안 온 전이를 세므로 둘의 합이 쪽 안의 전이 전부다(쪽 끝 전이는 먼저 왔을 때만 「지금 비트」 창에 들어 0 또는 1 이 더해진다 — 창 끝 규약은 A2 에서 고정한다). 어긋난 쪽 정렬은 약 절반이 틀려 다른 짝은 합이 크게 다르다. 짝 번호는 위상에 따라 옮겨 가므로(`t0` 는 `pay` CDC 지연이 정한다) 번호로 고르지 않는다
  > **2026-11-11 — 2번의 「짝」 규칙을 고친다 (AI 기록, 영웅님 확인 필요 · 수정안 #4 A2 추기 · 로그 55 §11).** 합에서 쪽 안 전이 수를 뺀 값이 0-2 인 짝을 받는다. 둘 다 맞으면(오류 0 정렬이 1 인 바닥과 꼬리에서 흔하다) 훑기 덩어리 중심의 왼쪽은 「지금 비트」 = 정렬 1, 오른쪽은 정렬 2 로 정한다. 셋째 줄의 「쪽 경계 몫 0-1」 도 0-2 다
  3. 짝의 「지금 비트」 정렬 c 에서 **정답 0 오류 = 셔터보다 먼저 온 상승, 정답 1 오류 = 먼저 온 하강** 이다. 위상마다 상승의 「먼저 온 비율」 = (`e_c − e1_c`) ÷ 쪽 상승 수, 하강 = `e1_c` ÷ 쪽 하강 수 — 쪽 수는 `base_sector` 로 계산한다. 「다음 비트」 정렬의 두 값은 그 나머지라 검산에 쓴다
  4. 이 읽기는 천장을 포함한 모든 위상에서 성립한다. 천장에서는 두 정렬이 모든 읽기에서 비긴다(쪽 경계 전이 몫 0-1 차이) — 예상된 일이고, 해석에 어느 쪽이 이겼는지가 필요 없다
  5. 위상 축의 비율 곡선이 에지별 누적분포이고, 미분이 에지별 pdf 다. 해석은 A2(시뮬레이션) · A4 · A5(실칩 대조)를 통과한 뒤에만 쓴다
- **원본 다루기**: 초심부 원본은 스윕당 약 1.7GB, 한 칩 20-60회면 수십 GB 다. `data/bathtub2/<chip>/` 아래에 따로 두고, 받은 자리에서 정제(요약 CSV)까지 한 번에 끝낸다. 원본은 커밋하지 않는다(`data/` 원본은 원래 커밋 대상이 아니다).
- **BER 상한**: 벽 바깥 0 오류 스텝은 「BER < 3 ÷ (N × 2,048)」(95%)로 적는다 — `deep` 이면 7e-10.

## 7. 아직 안 정한 것

- 이력 범위 580-760(75MHz 600-750) — 새 비트스트림에서 덩어리 위치가 옮겨 가면 A4 뒤 다시 맞춘다
- A2 의 허용 오차(되찾은 에지별 평균 · 폭이 주입값과 얼마나 맞아야 통과인가) — 시뮬레이션 전에 적는다
  > **2026-11-11 — 시뮬레이션을 먼저 돌려 버렸다 (AI).** 오늘 밤 A2 를 허용 오차 없이 돌려 결과만 보고했다(관측 최대 평균 0.146ps · σ 0.086ps). 허용 오차는 이 결과를 보지 않은 척 정할 수 없으므로, 통계 표준오차(약 0.04-0.06ps)의 배수처럼 결과와 무관한 근거로 정한다 — 영웅님 결정
- `FEATURE` 의 루프백 비트스트림 값 — **정했다** (2026-11-11, AI): bit1(base_sector)은 루프백에서 0 이다. 루프백은 base sector 가 0 고정이라서다 — 빌드 파라미터로 둔다
- 수정안 #1 A1 의 기준 — **정했다** (2026-11-11, AI): 7월 기준값(39,737.3ps ± 2ps) 대신 같은 장착 A/B(옛 → 새 → 옛)의 옛-옛 반복 산포를 쓴다. 7월 값은 다른 장착 · 다른 세대라 비교 기준으로 약하다. 7월 값은 이력으로 둔다
- 「한 칸 앞」 이 이기는 경우의 해석 — **닫았다** (2026-11-11, [D55-19]). 「승자」 를 쓰지 않고 합으로 고른 짝의 「지금 비트」 정렬로 읽으므로, 어느 번호가 이기는지는 해석에 끼지 않는다
