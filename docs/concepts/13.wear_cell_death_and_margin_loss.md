# 13. 마모의 두 얼굴 — 셀이 죽는 것과 여유가 줄어드는 것

플래시를 계속 지우고 쓰면 망가진다. 그런데 **망가지는 방식이 둘이고, 뜻이 아주 다르다.**
이 프로젝트가 무엇을 재고 왜 재는지가 전부 이 구분 위에 서 있다.

욕조 곡선·위상 스윕 자체는 [개념 1](1.monte_carlo.md)·[개념 2](2.phase_sweep_and_mmcm.md),
BER 눈금 감각은 [개념 11](11.ber_scales_tails_and_ruler.md) 에 있다. 여기서는 **마모가 그 그림을 어떻게 바꾸는가** 만 다룬다.
벽 안에서 실제로 무슨 일이 일어나는가(프로그램·소거의 물리와 왜 소거 시간이 먼저 늙는가)는 [개념 14](14.nor_program_erase_and_wear.md) 에 있다.

---

## 1. 마모란 물리적으로 무슨 일인가

플래시 셀은 전자를 가두는 작은 상자다. 상자 벽(터널 산화막)에 전자를 억지로 밀어 넣고(프로그램) 억지로 빼내는(소거) 일을 반복한다.

**벽을 통과시킬 때마다 벽이 조금씩 상한다.** 문을 여닫을수록 경첩이 헐거워지는 것과 같다.
한 번으로는 아무 일도 없지만 10만 번, 30만 번이면 다르다.

그 손상이 겉으로 드러나는 방식이 둘이다.

---

## 2. 두 얼굴

### ① 셀이 죽는다 — 전자를 아예 못 가둔다

벽이 새기 시작하면 전자가 머물지 못한다. 값을 써도 안 써진다. **그 비트는 끝이다.**
경첩이 부러진 문이라 아무리 잘 밀어도 안 닫힌다.

### ② 여유가 줄어든다 — 가두긴 하는데 아슬아슬하다

전자는 여전히 갇히는데 양이 줄거나 흩어진다. 값은 들어 있지만 **읽어 낼 때 여유가 없다.**
문틀이 헐거워져 살살 밀면 안 닫히고 정확히 밀어야 닫히는 상태다.

|                | ① 셀 죽음                  | ② 여유 축소                |
| -------------- | --------------------------- | --------------------------- |
| 값이 들어 있나 | **아니다**            | 들어 있다                   |
| 범위           | **국소적**으로 완전히 | **전역적**으로 조금씩 |
| 고칠 수 있나   | **없다**              | **있다** — 아래 §3  |
| 언제 나타나나  | 늦게                        | **일찍**              |

---

## 3. 왜 "고칠 수 있나"가 갈리나

②는 **읽는 타이밍**의 문제다.

기차에서 던지는 우편물을 플랫폼에서 받는다고 하자. 받을 수 있는 순간이 있고, 그 순간이 **창(window)** 이다. 창이 넓으면 대충 손을 뻗어도 받힌다. 좁아지면 정확한 순간에만 받아진다.

마모로 창이 좁아져도 **정확히 그 순간에 손을 뻗으면 여전히 받힌다.** 실제 시스템에서는 클럭을 낮추거나 더미 사이클을 늘려서 그렇게 한다. 그래서 ②는 **설계 여유로 흡수된다.**

①은 다르다. **우편물 자체가 안 실려 있다.** 언제 손을 뻗어도 없다. 타이밍을 아무리 잘 잡아도 소용없다.

> **그래서 ①과 ②는 "많이 망가졌나 적게 망가졌나"의 차이가 아니다.**
> **"방법이 있나 없나"의 차이다.**

---

## 4. 욕조 곡선에서 어떻게 보이나

위상(읽는 시점)을 옮겨 가며 틀린 비트를 세면 욕조 모양이 나온다. 가운데가 낮고 양쪽 끝이 높다. 가운데가 넓을수록 여유가 크다.

```
신품
 BER
1e-2 │*                              *
1e-3 │  *                          *
1e-4 │    *                      *
     │        (점이 없다)              ← 틀린 비트가 0. 그릴 것이 없다
     └───────────────────────────────
             ├──── 폭 ────┤
```

**바닥에 점이 없는 것이 정상이다.** 애초에 설계 상, 1e-9보다 깊게, 플로어를 측정해낼 수가 없다.

### ①은 바닥을 들어올린다

```
1e-4 │    *  ******************  *      ← 점이 차오른다
```

죽은 셀은 **어느 위상에서 읽어도** 틀린다. 그래서 모든 위상에 똑같이 깔린다. 이 깔린 값을 **플로어(바닥)** 라고 부른다.

### ②는 벽을 완만하게 만든다

```
신품    │*                *      벽이 거의 수직
마모    │  *            *        벽이 눕는다 → 창이 좁아진다
```

벽의 기울기를 숫자 하나로 요약한 것이 **σⱼ(경계 지터)** 다
([개념 1](1.monte_carlo.md) 파라미터 사전).

---

## 5. 그래서 지표가 셋이다

| 지표          | 무엇을 보나            | 신품에서                | 마모되면            |
| ------------- | ---------------------- | ----------------------- | ------------------- |
| `floor_ber` | **① 셀 죽음**   | **0**             | 값이 생긴다         |
| `sigma_j`   | **② 여유 축소** | **못 잰다** (§6) | 측정되기 시작한다   |
| `width@θ`  | 둘의**혼합**     | 약 39,700 ps            | 준다 — 원인은 모름 |

**둘 다 「없음 → 생김」이 신호다.** 그리고 폭은 둘을 합친 종합 지표라 **단독으로는 원인을
말하지 못한다.** 폭만 보고 "마진이 나빠졌다"고 하면, 사실은 셀이 죽어서 바닥이 들린 것일 수 있다.

---

## 6. 재는 데 한계가 있다 — 숫자로

### 점 하나의 한계

한 위상에서 읽는 비트 수는 **읽기 횟수 × 페이지당 비트** 다. 신품 기준선 측정값으로는
`100 × 2,048 = 204,800` 이다(마모 실험은 읽기 112회 계획이라 229,376 이 된다). 그러니 **틀린 비트가 하나** 여도 BER 은 이렇게 된다.

```
1 / 204,800 = 4.9e-6
```

**그래프의 가장 깊은 점이 1e-5~1e-6 근처인 것은 측정이 아니라 눈금의 한계다.** 1비트냐 2비트냐가 거기서 갈린다. 그 아래는 0 이라 안 그려진다.

### 바닥 전체를 합치면

플로어는 **위상과 무관한 성분**이다. 어느 위상에서 세든 같은 값이므로 **바닥 구간을 전부
한 통에 부어도 된다.**

```
바닥 약 1,500 스텝 × 204,800 ≈ 3억 비트
1 / 3억 ≈ 3e-9
```

실제 산출물이 `floor_ber = 0, floor_bound = 2.9e-9` 인 것은 **3억 비트를 읽어 하나도 안
틀렸다** 는 뜻이다. 위상에 따라 변하는 성분(②)은 이렇게 합칠 수 없다.

> 동전을 한 번 던져 앞면이 안 나왔다고 "앞면은 안 나온다"고 할 수 없다.
> 1억분의 1을 말하려면 1억 번을 던져야 한다.

### 왜 신품에서 σⱼ 를 못 재나

벽이 너무 가파르다. BER 이 1e-4 에서 1e-2 로 **100배** 오르는 데 위상이 **12 ps** 밖에 안 움직인다. 그런데 위상 스텝 간격이 **15.87 ps** 다.

```
전이 구간 12 ps ÷ 스텝 15.87 ps = 0.76 개
```

**눈금보다 좁은 것은 못 잰다.** 자의 눈금이 1 cm 인데 0.76 cm 짜리 물건을 재는 셈이다. 그래서
`check1_gaussian` 이 늘 `SKIP(적합점 부족)` 으로 나오고 σⱼ 가 비어 있다.
[개념 11](11.ber_scales_tails_and_ruler.md) 의 「자의 해상도와 절벽 착시」가 같은 이야기다.

**이것은 고장이 아니라 신품이라는 증거다.** 마모로 벽이 누우면 저절로 값이 나온다.

## 7. 이 프로젝트가 하려는 것 — ②로 ①까지의 거리를 잰다

여기가 핵심이다.

타이어를 생각하자. 터질 때까지 기다렸다가 "이 타이어는 여기까지였다"고 말하는 것은 쓸모가 없다. 대신 **홈 깊이를 재서 "앞으로 몇 km"** 를 말한다.

| 타이어       | 플래시                    |
| ------------ | ------------------------- |
| 홈 깊이      | **마진 (②)**       |
| 터짐         | **셀 죽음 (①)**    |
| "몇 km 남음" | **남은 P/E 사이클** |

데이터시트가 말하는 10만 P/E 는 **①이 터지는 지점** 이다. 그런데 **②는 그보다 한참 먼저 움직인다.** 그래서 ②를 재면 ①이 오기 전에 **예측** 할 수 있다.

```
②(마진) 를 재서  →  ①(죽음) 까지 얼마나 남았나를 역산
```

**늦은 신호(①)는 확인이고, 이른 신호(②)가 기여다.**

### 그런데 한 번은 끝까지 가 봐야 한다

"홈 깊이 3 mm = 앞으로 1만 km" 라는 관계를 세우려면 **터질 때까지 가 본 타이어**가 있어야 한다. 마찬가지로 ②와 ①의 관계를 세우려면 **①이 실제로 일어난 데이터**가 필요하다.

그래서 마모는 **칩이 죽을 때까지** 돌린다. 30만이라는 숫자는 예측일 뿐이고, 안 죽었으면 계속 간다. 「죽었다」의 정의는 사양서에 있다 — 결함 비트가 4,588 을 넘으면 정지
(`docs/spec/s1.wear_bench_spec.md` §10).

끝까지 못 가면 그것도 결과다. *"보장치의 몇 배를 돌려도 기능 실패가 오지 않았고 마진은
X% 줄었다"* 는 그 자체로 보고할 값이다. 다만 **역산의 끝점이 없으므로 외삽임을 명시** 해야 한다.

---

## 8. 그 역산이 되는지를 어떻게 검증하나 — 블라인드

역산 공식을 만든 사람이 직접 검증하면 믿을 수 없다. 답을 알고 맞히는 것이기 때문이다.

그래서 **칩 몇 개는 마모 횟수를 숨긴 채** 만든다. 측정자는 곡선만 보고 "이 칩은 몇 번
닳았다"를 말하고, 나중에 봉인을 열어 맞혀 본다.

> 나이테로 나무의 나이를 맞히는 방법이 되는지 보려면,
> **나이를 모르는 나무**로 해 봐야 한다.

배분은 `docs/spec/s2.newchip_protocol.md` §1 에 있다.

---

## 9. 가로축이 목숨인 이유

역산은 결국 **(사이클 수, 마진)** 쌍을 모아 곡선을 세우는 일이다.

세로축(마진)이 한 점 틀리면 **그 점 하나** 가 틀린다. 버리면 된다.

가로축(누적 사이클 수)이 틀리면 **곡선 전체가 그만큼 밀린다.** 그리고 **되돌릴 수 없다** —
칩은 이미 그만큼 닳았고, 몇 번 닳았는지 다시 세어 볼 방법이 없다.

**칩에는 "나는 몇 번 마모됐다"가 적혀 있지 않다.** 우리가 센 것이 전부다. 그래서 같은 숫자를 **네 군데서 따로 구해 대조** 하고(카운터 · 로그 행 수 · 무결성 로그 · 칩 안의 tally),
칩 안의 기록은 **두 벌**을 쓴다. 전원이 끊겨도 살아남게 하려는 것이다.

자세한 것은 `docs/spec/s1.wear_bench_spec.md` §8·§13 과
`docs/interface/pe_engine.md` §5.

## 10. 한 장 요약

```
마모
 ├─ ① 셀 죽음      → 바닥이 들린다   → floor_ber      → 늦다. 수명의 끝
 └─ ② 여유 축소    → 벽이 눕는다     → sigma_j        → 이르다. 예측의 근거
                     둘 다 폭을 줄인다 → width@θ (혼합)

②를 재서 ①까지의 거리를 역산한다  ← 이 프로젝트의 논지
  · 관계를 세우려면 ①까지 한 번은 가 봐야 한다   → 죽을 때까지 마모
  · 역산이 되는지는 답을 가리고 검증한다          → 블라인드 시료
  · 가로축이 틀리면 전부 틀린다                   → 네 경로 대조 + tally 2벌
```
